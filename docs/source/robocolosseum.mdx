# RoboColosseum

[RoboColosseum](https://robocolosseum.ai/) is a distributed real-world benchmark for evaluating general-purpose robot policies on physical robots deployed in the wild. Evaluations run on standardized setups: Unitree G1 humanoids, bimanual YAM, Franka arms in the DROID setup, and SO-101. Every evaluation run, failures included, is published on the Hugging Face Hub in LeRobot format.

This page covers how to prepare a LeRobot policy for its two evaluation tracks. To have a policy evaluated, apply on the RoboColosseum website.

- Website: [robocolosseum.ai](https://robocolosseum.ai/)
- Hugging Face organization: [RoboColosseum](https://huggingface.co/RoboColosseum)
- Fine-tune Track datasets: [RoboColosseum Datasets collection](https://huggingface.co/collections/RoboColosseum/robocolosseum-datasets)

## Evaluation tracks

| Track           | Protocol                                                                                                                       | Trains on RoboColosseum data      |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------ | --------------------------------- |
| Fine-tune Track | Every policy is fine-tuned on the same 100 demonstrations of a fixed task, then makes 25 attempts.                             | Yes, on the task's demonstrations |
| Open Track      | Two anonymized policies attempt the same new instruction in the same scene; the evaluator picks the better run or calls a tie. | No, the checkpoint is frozen      |

## Fine-tune Track

The Fine-tune Track provides task demonstrations for adapting a policy to a fixed robot embodiment and task before physical evaluation. Each task is a separate LeRobot `v3.0` dataset on the Hub, recorded with 100 episodes:

| Embodiment     | Datasets                                                                                                                                                                                                                                                                                                                                                                                                                                                                     | Cameras                              |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------ |
| Bimanual YAM   | [`yam-cups`](https://huggingface.co/datasets/RoboColosseum/yam-cups), [`yam-drawer`](https://huggingface.co/datasets/RoboColosseum/yam-drawer), [`yam-dustpan`](https://huggingface.co/datasets/RoboColosseum/yam-dustpan), [`yam-microwave`](https://huggingface.co/datasets/RoboColosseum/yam-microwave), [`yam-tray`](https://huggingface.co/datasets/RoboColosseum/yam-tray)                                                                                             | `top`, `left`, `right`               |
| Franka (DROID) | [`droid-close-laptop`](https://huggingface.co/datasets/RoboColosseum/droid-close-laptop), [`droid-mug-on-coaster`](https://huggingface.co/datasets/RoboColosseum/droid-mug-on-coaster), [`droid-open-drawer`](https://huggingface.co/datasets/RoboColosseum/droid-open-drawer), [`droid-put-marker-pen`](https://huggingface.co/datasets/RoboColosseum/droid-put-marker-pen), [`droid-towel-in-basket`](https://huggingface.co/datasets/RoboColosseum/droid-towel-in-basket) | `left_image`, `right_image`, `wrist` |
| SO-101         | [`so101-cube-drawer`](https://huggingface.co/datasets/RoboColosseum/so101-cube-drawer), [`so101-remove-screwdriver`](https://huggingface.co/datasets/RoboColosseum/so101-remove-screwdriver), [`so101-stack-bowls`](https://huggingface.co/datasets/RoboColosseum/so101-stack-bowls), [`so101-stack-cubes`](https://huggingface.co/datasets/RoboColosseum/so101-stack-cubes), [`so101-upright-bottle`](https://huggingface.co/datasets/RoboColosseum/so101-upright-bottle)   | `front`, `wrist`                     |
| Unitree G1     | [`g1-carry-box`](https://huggingface.co/datasets/RoboColosseum/g1-carry-box), [`g1-fold-towel`](https://huggingface.co/datasets/RoboColosseum/g1-fold-towel), [`g1-hang-keys`](https://huggingface.co/datasets/RoboColosseum/g1-hang-keys), [`g1-load-clothes-washing-machine`](https://huggingface.co/datasets/RoboColosseum/g1-load-clothes-washing-machine), [`g1-plate-into-rack`](https://huggingface.co/datasets/RoboColosseum/g1-plate-into-rack)                     | `head`, `left_wrist`, `right_wrist`  |

All datasets are under the `RoboColosseum/` namespace. Load one with `LeRobotDataset`, which downloads it on first use:

```python
from lerobot.datasets import LeRobotDataset

dataset = LeRobotDataset("RoboColosseum/so101-stack-bowls")
```

The Franka, SO-101 and Unitree G1 datasets store `observation.state` and `action`, and work with `lerobot-train` directly:

```bash
lerobot-train \
  --dataset.repo_id=RoboColosseum/so101-stack-bowls \
  --policy.type=<policy_type> \
  --policy.repo_id=${HF_USER}/<policy_type>_robocolosseum_so101-stack-bowls \
  --output_dir=./outputs/<policy_type>_robocolosseum_so101-stack-bowls
```

The exact policy configuration, camera mapping, action representation and training recipe depend on the policy being adapted. If your policy expects different camera names, map them with [`--rename_map`](./rename_map).

## Open Track

The Open Track evaluates a frozen checkpoint on real-world tasks. No training is performed on RoboColosseum Open Track evaluation data.

If your policy does not yet support the target embodiment, first adapt it on public robot data for that embodiment, then freeze the resulting checkpoint before evaluation. Recommended public bootstrap datasets:

| Target embodiment | Public bootstrap data                                                                                            |
| ----------------- | ---------------------------------------------------------------------------------------------------------------- |
| SO-100 / SO-101   | [`allenai/MolmoAct2-SO100_101-Dataset`](https://huggingface.co/datasets/allenai/MolmoAct2-SO100_101-Dataset)     |
| Franka (DROID)    | [DROID](https://droid-dataset.github.io/)                                                                        |
| Bimanual YAM      | [`allenai/MolmoAct2-BimanualYAM-Dataset`](https://huggingface.co/datasets/allenai/MolmoAct2-BimanualYAM-Dataset) |

`allenai/MolmoAct2-SO100_101-Dataset` lists the SO-100 and SO-101 LeRobot datasets used to train MolmoAct2, with per-episode language annotations. Download the list of source repositories with:

```bash
hf download allenai/MolmoAct2-SO100_101-Dataset repo_list.json \
  --repo-type dataset \
  --local-dir ./data/molmoact2_so100_101
```

Each entry in `repo_list.json` is a Hub dataset ID prefixed with `lerobot:` (for example `lerobot:<user>/<dataset>`). Select compatible SO-100 / SO-101 datasets from the list and train on those. Many of them use the LeRobot `v2.1` format: convert them to `v3.0` before loading (see [Using LeRobotDataset](./lerobot-dataset-v3)).

DROID is released in the RLDS format. Convert it to a LeRobot dataset by following the DROID example in [Porting Large Datasets](./porting_datasets_v3), then train on the converted dataset with `lerobot-train`.

The Bimanual YAM dataset works with `lerobot-train` directly:

```bash
lerobot-train \
  --dataset.repo_id=allenai/MolmoAct2-BimanualYAM-Dataset \
  --policy.type=<policy_type> \
  --policy.repo_id=${HF_USER}/<policy_type>_bimanual_yam \
  --output_dir=./outputs/<policy_type>_bimanual_yam
```

The bootstrap stage only makes the policy compatible with the target embodiment. The checkpoint submitted to the Open Track stays frozen during evaluation.
