# LingBot-VA

LingBot-VA 是一个基于 **Wan2.2** 视频扩散框架构建的**自回归视频-动作世界模型策略**。它在一个自回归序列中交错预测未来的**视频潜变量**和**机器人动作**（"VA" = Video-Action）。LeRobot 集成将 LingBot-VA 接入标准的训练、评估和处理器接口。

## 模型概述

LingBot-VA 是一个**双流"混合 Transformer"**：一个视频/潜变量流
（`patch_embedding_mlp → blocks → proj_out`）和一个动作流
（`action_embedder → blocks → action_proj_out`）共享相同的 30 个 Transformer 块和文本条件。

| 组件                       | 类                      | 角色                                           |
| -------------------------- | ----------------------- | ---------------------------------------------- |
| DiT 骨干网络（可训练）     | `WanTransformer3DModel` | ~50 亿参数双流 Transformer                     |
| VAE（冻结）                | `AutoencoderKLWan`      | Wan2.2 VAE，`z_dim=48`。从源仓库延迟拉取       |
| 文本编码器（冻结）         | `UMT5EncoderModel`      | UMT5-XXL，`d_model=4096`。从源仓库延迟拉取     |

在推理时，策略按块运行自回归循环：它使用两个独立的流匹配调度器对视频潜变量流（CFG，~20 步）和动作流（~50 步）进行去噪，同时维护跨块的 KV 缓存。在块执行期间，真实观测的关键帧被反馈回 KV 缓存（闭环世界建模）。

### LeRobot 集成涵盖的内容

- 通过 LeRobot 使用标准 `policy.type=lingbot_va` 配置。
- Hub 上可用的 LeRobot 格式检查点（从发布的上游检查点转换而来）。
- 在标准 `select_action` 接口后面的自回归双流推理（单环境评估，`--eval.batch_size=1`）。
- 可选的评估/训练期间保存策略**预测（想象的）视频**。
- 使用 `lerobot-eval` 在 LIBERO 和 RoboTwin 上评估。
- 通过双流流匹配损失（`policy.forward`）进行训练/微调，见下文。

## 安装

1. 按照[安装指南](./installation)安装 LeRobot。
2. 安装 LingBot-VA 附加依赖：

```bash
pip install -e ".[lingbot_va]"
```

## 检查点

已发布的上游检查点已转换为 LeRobot 格式并推送到 Hub：

| 变体                   | LeRobot 检查点                     |
| ---------------------- | ---------------------------------- |
| LIBERO-Long 后训练     | `lerobot/lingbot_va_libero_long`   |
| RoboTwin 后训练        | `lerobot/lingbot_va_robotwin`      |
| 预训练基础             | `lerobot/lingbot_va_base`          |

只有可训练的 ~50 亿 Transformer 被存储在 LeRobot
`model.safetensors` 中。冻结的 VAE + UMT5 + 分词器（~20 GB）在加载时从
`config.wan_pretrained_path` 拉取（默认为源 `robbyant/*` 仓库）。
UMT5-XXL 文本编码器默认在 CPU 上运行（`config.text_encoder_device`），因此 50 亿
Transformer + VAE 可以装入单个 24–32 GB GPU。

## 评估（LIBERO）

```bash
lerobot-eval \
    --policy.path=lerobot/lingbot_va_libero_long \
    --policy.device=cuda \
    --env.type=libero --env.task=libero_10 \
    --env.observation_height=128 --env.observation_width=128 \
    --eval.n_episodes=50 --eval.batch_size=1 \
    --output_dir=outputs/eval/lingbot_va_libero
```

LingBot-VA 的流式推理（KV 缓存 + 观测关键帧反馈）适用于单环境评估；使用 `--eval.batch_size=1`。

## 评估（RoboTwin）

RoboTwin 2.0 需要 SAPIEN + CuRobo 仿真器栈。你可以使用基准测试 Docker 镜像
（`docker/Dockerfile.benchmark.robotwin`，还需要 `warp-lang==1.3.1` 和根据 GPU 计算能力设置 `TORCH_CUDA_ARCH_LIST` 构建的 CuRobo）。RoboTwin 使用**末端执行器位姿控制**，因此使用 `--env.action_mode=ee` 运行：策略预测每臂 `xyz+四元数+夹爪`
增量（`robotwin_tshape` 潜变量布局），这些增量组合到 episode 的初始 eef 位姿上并通过 CuRobo IK 执行。

```bash
lerobot-eval \
    --policy.path=lerobot/lingbot_va_robotwin \
    --policy.device=cuda \
    --env.type=robotwin --env.task=beat_block_hammer --env.action_mode=ee \
    --eval.n_episodes=10 --eval.batch_size=1 \
    --output_dir=outputs/eval/lingbot_va_robotwin
```

### 保存预测（想象的）视频

设置 `--policy.save_predicted_video=true` 以额外 VAE 解码预测的视频潜变量并在环境渲染的 `eval_episode_*.mp4` 视频旁边写入 `pred_episode_*.mp4`。该标志同样适用于 `lerobot-train` 期间的定期评估。

## 训练 / 微调

`LingBotVAPolicy.forward(batch)` 实现了论文中的双流**流匹配**损失
（`latent_loss + action_loss`，时间步加权，动作掩码）：它将相机片段 VAE 编码为视频潜变量，UMT5 编码任务，对两个流加噪，运行 Transformer 的块因果训练通道并返回 `(loss, metrics)`。优化器预设为 AdamW，采用线性预热后恒定学习率调度（与上游一致）。

要求：

- 块因果掩码使用 PyTorch **flex-attention**，因此训练时使用
  `--policy.attn_mode=flex` 构建策略（默认的 `torch` SDPA 仅用于推理）。
- 完整的 50 亿 DiT 在 AdamW 下无法装入单个 24–32 GB GPU；使用 **LoRA** 微调
  （`--policy.use_peft=true`）和/或优化器卸载。`get_optim_params` 只返回可训练（如适配器）参数；VAE + UMT5 文本编码器保持冻结。

```bash
lerobot-train \
  --policy.path=lerobot/lingbot_va_libero_long --policy.attn_mode=flex \
  --policy.use_peft=true \
  --dataset.repo_id=<your LeRobot-format dataset> \
  --batch_size=1 --steps=... --output_dir=outputs/train/lingbot_va
```

数据集必须提供相机片段（每个相机的时间窗口，VAE 编码为
`frame_chunk_size` 潜变量帧）以及每个样本 `frame_chunk_size * action_per_frame` 个动作步。

## 数据格式（动作通道和相机顺序）

LingBot-VA 是一个**末端执行器（笛卡尔）位姿**策略，它预测 EEF 位姿 + 夹爪，而不是关节位置。动作位于固定的多具身 **30 维**布局中；将你的机器人动作维度映射到这些通道并用 `0` 填充其余部分（`used_action_channel_ids` 选择给定检查点实际使用的通道）：

| 通道    | 含义                                         |
| ------- | -------------------------------------------- |
| 0–6     | 左臂末端执行器位姿                           |
| 7–13    | 右臂末端执行器位姿                           |
| 14–20   | 左臂关节（已发布的检查点未使用）             |
| 21–27   | 右臂关节（已发布的检查点未使用）             |
| 28      | 左夹爪                                       |
| 29      | 右夹爪                                       |

- **LIBERO** 使用通道 `0–6`：6-DoF EEF 增量（xyz + 旋转）+ 夹爪（单臂）。
- **RoboTwin** 使用通道 `[0–6, 28, 7–13, 29]`：左 EEF（xyz + 四元数）+ 左夹爪 +
  右 EEF + 右夹爪（16 维）。环境通过 CuRobo IK 将这些位姿转换为关节轨迹——从不预测关节。

关节空间数据集（或不同的 EEF 约定）必须在微调这些检查点之前映射到此模式。

**相机顺序是固定的且对顺序敏感**，每个相机的潜变量按
`obs_cam_keys` 顺序在空间上连接，因此物理相机→槽位的映射必须与训练匹配：

| 基准测试 | `obs_cam_keys`（按顺序）                                                                                | `camera_layout`                                           |
| -------- | ------------------------------------------------------------------------------------------------------- | --------------------------------------------------------- |
| LIBERO   | `observation.images.image`（agentview / 第三人称），`observation.images.image2`（eye-in-hand 手腕）     | `width_concat`（潜变量在宽度上连接）                      |
| RoboTwin | `observation.images.head_camera`，`observation.images.left_camera`，`observation.images.right_camera`   | `robotwin_tshape`（下方全分辨率头部，上方两个半分辨率手腕）|

第一个相机是外部/头部视角，其余是手腕视角。

## 推理超参数（LIBERO）

| 键                                     | 值                                                                              |
| -------------------------------------- | ------------------------------------------------------------------------------- |
| 高度 × 宽度                            | 128 × 128                                                                       |
| 相机                                   | `observation.images.image`（agentview），`observation.images.image2`（eye-in-hand）|
| 使用的动作通道                         | 0–6（7-DoF 臂 + 夹爪）                                                          |
| action_per_frame / frame_chunk_size    | 4 / 4                                                                           |
| attn_window                            | 30                                                                              |
| 视频 / 动作去噪步数                    | 20 / 50                                                                         |
| guidance_scale / action_guidance_scale | 5 / 1                                                                           |
| snr_shift / action_snr_shift           | 5.0 / 0.05                                                                      |

这些是 `LingBotVAConfig` 的默认值；通过 `--policy.<name>=...` 覆盖任何值。

## 说明

- **注意力后端：** 推理使用 `torch` SDPA 后端（始终可用）。
  `flashattn` 和 `flex` 后端是可选的；`flex` 仅在训练时需要。
- **模型大小：** DiT 约 50 亿参数，冻结的 VAE+UMT5 增加约 20 GB；推理大约需要 18–24 GB VRAM。
