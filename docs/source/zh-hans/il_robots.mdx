本教程将解释如何训练一个神经网络来自主控制真实机器人。

**你将学到：**

1. 如何记录并可视化你的数据集。
2. 如何使用你的数据训练策略（policy），并为其评估做好准备。
3. 如何评估你的策略（policy）并可视化结果。

按照这些步骤，你将能够以高成功率复现任务，例如抓起一块乐高积木并将其放入箱子中，如下方视频所示。

## 遥操作[[teleoperate]]

在本示例中，我们将演示如何遥操作 SO101 机器人。对于每个命令，我们还提供了对应的 API 示例。

请注意，与机器人关联的 `id` 用于存储校准文件。在同一套设置中进行遥操作、记录和评估时，使用相同的 `id` 非常重要。

<hfoptions id="teleoperate_so101">
<hfoption id="Command">
```bash
lerobot-teleoperate \
    --robot.type=so101_follower \
    --robot.port=/dev/tty.usbmodem58760431541 \
    --robot.id=my_awesome_follower_arm \
    --teleop.type=so101_leader \
    --teleop.port=/dev/tty.usbmodem58760431551 \
    --teleop.id=my_awesome_leader_arm
```
</hfoption>
<hfoption id="API example">

<!-- prettier-ignore-start -->
```python
from lerobot.teleoperators.so_leader import SO101Leader, SO101LeaderConfig
from lerobot.robots.so_follower import SO101Follower, SO101FollowerConfig

robot_config = SO101FollowerConfig(
    port="/dev/tty.usbmodem5AB90687491",
    id="my_follower_arm",
)

teleop_config = SO101LeaderConfig(
    port="/dev/tty.usbmodem5AB90689011",
    id="my_leader_arm",
)

robot = SO101Follower(robot_config)
teleop_device = SO101Leader(teleop_config)
robot.connect()
teleop_device.connect()

while True:
    action = teleop_device.get_action()
    robot.send_action(action)
```

import time
from lerobot.teleoperators.so_leader import SO101Leader, SO101LeaderConfig
from lerobot.robots.so_follower import SO101Follower, SO101FollowerConfig
from lerobot.cameras.opencv import OpenCVCameraConfig
from lerobot.utils.visualization_utils import init_visualization, log_visualization_data, shutdown_visualization

robot_config = SO101FollowerConfig(
    port="/dev/tty.usbmodem5AB90687491",
    id="my_follower_arm",
    cameras={
        "wrist": OpenCVCameraConfig(index_or_path=0, width=640, height=480, fps=30),
        "top": OpenCVCameraConfig(index_or_path=1, width=640, height=480, fps=30)
    }
)

teleop_config = SO101LeaderConfig(
    port="/dev/tty.usbmodem5AB90689011",
    id="my_leader_arm",
)

init_visualization("rerun", session_name="teleoperation")  # 传入 "foxglove" 可改为流式传输到 Foxglove

robot = SO101Follower(robot_config)
teleop_device = SO101Leader(teleop_config)
robot.connect()
teleop_device.connect()

TARGET_HZ = 30
TIME_PER_FRAME = 1.0 / TARGET_HZ

while True:
    start_time = time.perf_counter()

    observation = robot.get_observation()
    action = teleop_device.get_action()
    robot.send_action(action)
    log_visualization_data("rerun", observation=observation, action=action)

    elapsed_time = time.perf_counter() - start_time
    sleep_time = TIME_PER_FRAME - elapsed_time
    if sleep_time > 0:
        time.sleep(sleep_time)

## 记录数据集[[record-a-dataset]]

一旦你熟悉了遥操作，就可以记录你的第一个数据集。

我们使用 Hugging Face Hub 功能来上传你的数据集。如果你以前没有使用过 Hub，请确保可以通过 CLI 使用具有写入权限的令牌登录；该令牌可以从 [Hugging Face 设置](https://huggingface.co/settings/tokens)生成。

运行以下命令将令牌添加到 CLI：

```bash
hf auth login --token ${HUGGINGFACE_TOKEN} --add-to-git-credential
```

然后将你的 Hugging Face 仓库名称存储到变量中：

```bash
HF_USER=$(NO_COLOR=1 hf auth whoami | awk -F': *' 'NR==1 {print $2}')
echo $HF_USER
```

现在你可以记录数据集了。要记录 5 个回合并将数据集上传到 Hub，请针对你的机器人调整下面的代码，并执行命令或 API 示例。

<hfoptions id="record">
<hfoption id="Command">
```bash
lerobot-record \
    --robot.type=so101_follower \
    --robot.port=/dev/tty.usbmodem585A0076841 \
    --robot.id=my_awesome_follower_arm \
    --robot.cameras="{ front: {type: opencv, index_or_path: 0, width: 1920, height: 1080, fps: 30}}" \
    --teleop.type=so101_leader \
    --teleop.port=/dev/tty.usbmodem58760431551 \
    --teleop.id=my_awesome_leader_arm \
    --display_data=true \
    --dataset.repo_id=${HF_USER}/record-test \
    --dataset.num_episodes=5 \
    --dataset.single_task="Grab the black cube" \
    --dataset.streaming_encoding=true \
    --dataset.encoder_threads=2
# 可选：--dataset.rgb_encoder.vcodec=auto
```
</hfoption>
<hfoption id="API example">

<!-- prettier-ignore-start -->
```python
from lerobot.cameras.opencv import OpenCVCameraConfig
from lerobot.datasets.lerobot_dataset import LeRobotDataset
from lerobot.utils.feature_utils import hw_to_dataset_features
from lerobot.robots.so_follower import SO101Follower, SO101FollowerConfig
from lerobot.teleoperators.so_leader.config_so_leader import SO101LeaderConfig
from lerobot.teleoperators.so_leader.so_leader import SO101Leader
from lerobot.common.control_utils import init_keyboard_listener
from lerobot.utils.utils import log_say
from lerobot.utils.visualization_utils import init_visualization
from lerobot.scripts.lerobot_record import record_loop
from lerobot.processor import make_default_processors

NUM_EPISODES = 5
FPS = 30
EPISODE_TIME_SEC = 60
RESET_TIME_SEC = 10
TASK_DESCRIPTION = "My task description"

def main():
    # 创建机器人配置
    robot_config = SO101FollowerConfig(
        port="/dev/tty.usbmodem5AB90687491",
        id="my_follower_arm",
        cameras={
            "wrist": OpenCVCameraConfig(index_or_path=0, width=640, height=480, fps=30),
            "top": OpenCVCameraConfig(index_or_path=1, width=640, height=480, fps=30)
        }
    )

    teleop_config = SO101LeaderConfig(
        port="/dev/tty.usbmodem5AB90689011",
        id="my_leader_arm",
    )

    # 初始化机器人和遥操作设备
    robot = SO101Follower(robot_config)
    teleop = SO101Leader(teleop_config)

    # 配置数据集特征
    action_features = hw_to_dataset_features(robot.action_features, "action")
    obs_features = hw_to_dataset_features(robot.observation_features, "observation")
    dataset_features = {**action_features, **obs_features}

    # 创建数据集
    dataset = LeRobotDataset.create(
        repo_id="<hf_username>/<dataset_repo_id>",
        fps=FPS,
        features=dataset_features,
        robot_type=robot.name,
        use_videos=True,
        image_writer_threads=4,
    )

    # 初始化键盘监听器和 rerun 可视化
    _, events = init_keyboard_listener()
    init_visualization("rerun", session_name="recording")

    # 连接机器人和遥操作设备
    robot.connect()
    teleop.connect()

    # 创建所需的处理器
    teleop_action_processor, robot_action_processor, robot_observation_processor = make_default_processors()

    episode_idx = 0
    while episode_idx < NUM_EPISODES and not events["stop_recording"]:
        log_say(f"Recording episode {episode_idx + 1} of {NUM_EPISODES}")

        record_loop(
            robot=robot,
            events=events,
            fps=FPS,
            teleop_action_processor=teleop_action_processor,
            robot_action_processor=robot_action_processor,
            robot_observation_processor=robot_observation_processor,
            teleop=teleop,
            dataset=dataset,
            control_time_s=EPISODE_TIME_SEC,
            single_task=TASK_DESCRIPTION,
            display_data=True,
        )

        # 如果未停止或未重新录制，则重置环境
        if not events["stop_recording"] and (episode_idx < NUM_EPISODES - 1 or events["rerecord_episode"]):
            log_say("Reset the environment")
            record_loop(
                robot=robot,
                events=events,
                fps=FPS,
                teleop_action_processor=teleop_action_processor,
                robot_action_processor=robot_action_processor,
                robot_observation_processor=robot_observation_processor,
                teleop=teleop,
                control_time_s=RESET_TIME_SEC,
                single_task=TASK_DESCRIPTION,
                display_data=True,
            )

        if events["rerecord_episode"]:
            log_say("Re-recording episode")
            events["rerecord_episode"] = False
            events["exit_early"] = False
            dataset.clear_episode_buffer()
            continue

        dataset.save_episode()
        episode_idx += 1

    # 最终确定数据集
    log_say("Finalizing dataset...")
    dataset.finalize()
    # 清理
    log_say("Stop recording")
    robot.disconnect()
    teleop.disconnect()
    dataset.push_to_hub()


if __name__ == "__main__":
    main()
```

#### 数据集上传[[dataset-upload]]

在本地，你的数据集存储在以下文件夹中：`~/.cache/huggingface/lerobot/{repo-id}`。数据记录结束时，你的数据集将上传到你的 Hugging Face 页面（例如 `https://huggingface.co/datasets/${HF_USER}/record-test`），你可以通过运行以下命令获取该地址：

```bash
echo https://huggingface.co/datasets/${HF_USER}/record-test
```

你的数据集会自动打上 `LeRobot` 标签，方便社区轻松找到它；你也可以添加自定义标签（例如本例中的 `tutorial`）。

你可以通过搜索 `LeRobot` [标签](https://huggingface.co/datasets?other=LeRobot)在 Hub 上查找其他 LeRobot 数据集。

你也可以运行以下命令，手动将本地数据集推送到 Hub：

```bash
hf upload ${HF_USER}/record-test ~/.cache/huggingface/lerobot/{repo-id} --repo-type dataset
```

#### record 函数[[record-function]]

`record` 函数提供了一套工具，用于在机器人运行期间捕获和管理数据：

##### 1. 数据存储[[1-data-storage]]

- 数据使用 `LeRobotDataset` 格式存储，并在记录期间保存在磁盘上。
- 默认情况下，数据集会在记录后推送到你的 Hugging Face 页面。
  - 如需禁用上传，请使用 `--dataset.push_to_hub=False`。

##### 2. 检查点与恢复[[2-checkpointing-and-resuming]]

- 记录期间会自动创建检查点。
- 如果出现问题，或者你想在同一个数据集中记录更多回合，可以通过使用 `--resume=true` 重新运行同一命令来恢复。恢复记录时，`--dataset.num_episodes` 必须设置为**要额外记录的回合数**，而不是数据集中目标总回合数！请确保同时设置 `--dataset.root="local_path"`，这是用于保存数据集新增部分的本地路径，也是恢复所必需的。
- 要从头开始记录，请**手动删除**数据集目录。

##### 3. 记录参数[[3-recording-parameters]]

使用命令行参数设置数据记录流程：

- `--dataset.episode_time_s=60`
  每个数据记录回合的时长（默认：**60 秒**）。
- `--dataset.reset_time_s=60`
  每个回合后重置环境的时长（默认：**60 秒**）。
- `--dataset.num_episodes=50`
  要记录的回合总数（默认：**50**）。

##### 4. 记录期间的键盘控制[[4-keyboard-controls-during-recording]]

使用键盘快捷键控制数据记录流程：

- 按 **右箭头（`→`）** 或 **`n`**：提前停止当前回合或重置时间，并进入下一个。
- 按 **左箭头（`←`）** 或 **`r`**：取消当前回合并重新记录。
- 按 **Escape（`ESC`）** 或 **`q`**：立即停止会话，编码视频，并上传数据集。

<Tip>

这些控制流程快捷键可在 **X11、Wayland 和无头/SSH** 会话中使用。当没有全局键盘后端可用时（Wayland、无头机器，或未授予辅助功能权限的 macOS），`lerobot-record` 会自动从终端读取相同的按键——请从交互式终端启动并保持其处于焦点状态。你也可以使用字母等效键 **`n`**（下一个，与 `→` 相同）、**`r`**（重新记录，与 `←` 相同）和 **`q`**（退出，与 `ESC` 相同）。无需设置 `$DISPLAY`。

这仅适用于记录控制流程。键盘**遥操作**（用键盘驱动机器人）仍然需要全局按键后端，因此只能在 X11 会话、Windows 桌面，或已授予辅助功能/输入监控权限的 macOS 上使用——不能在 Wayland 或无头会话中使用。

</Tip>

#### 采集数据的技巧[[tips-for-gathering-data]]

当你熟悉数据记录后，就可以创建更大的数据集用于训练。一个不错的入门任务是抓取位于不同位置的物体并将其放入箱子。我们建议至少记录 50 个回合，每个位置 10 个回合。保持摄像头固定，并在整个记录过程中保持一致的抓取行为。同时确保你正在操作的物体在摄像头画面中可见。一个经验法则是，你仅通过查看摄像头图像就应该能够自己完成该任务。

在接下来的章节中，你将训练神经网络。在获得可靠的抓取性能后，你可以开始在数据采集期间引入更多变化，例如更多抓取位置、不同的抓取技巧以及更改摄像头位置。

避免过快地加入过多变化，因为这可能会妨碍你的结果。

如果你想深入了解这个重要主题，可以查看我们关于什么构成好数据集的[博客文章](https://huggingface.co/blog/lerobot-datasets#what-makes-a-good-dataset)。

#### 节奏报告[[cadence-reporting]]

`lerobot-record` 会按 `--dataset.fps` 控制循环节奏，并报告实际达到的效果：对你保留的每个回合输出一行摘要，并在记录结束时为整个会话输出一个块——包括在 `Ctrl-C` 时。

```
Cadence (episode 0): 29.88 Hz vs 30 Hz target · 600 ticks, 20.0 s measured · 8/599 ticks over the 33.3 ms budget (work mean 18.4 ms, worst 45.1 ms)
Cadence (episode 1): 29.88 Hz vs 30 Hz target · 600 ticks, 20.0 s measured · 8/599 ticks over the 33.3 ms budget (work mean 18.4 ms, worst 45.1 ms)
Cadence summary — whole run, 2 episodes · target 30 Hz (33.3 ms budget per tick): 1200 ticks, 1198 judged
  effective cadence: 29.88 Hz over 40.1 s measured
  ticks over the 33.3 ms work budget: 16/1198 (1.3%) — work mean 18.4 ms, worst 45.1 ms
  loop-body steps (share of measured work):
    observe      mean  13.65 ms · worst  40.20 ms ·  74.4% of work · 1200 calls
    process_obs  mean   0.30 ms · worst   0.30 ms ·   1.6% of work · 1200 calls
    teleop       mean   1.80 ms · worst   1.80 ms ·   9.8% of work · 1200 calls
    send         mean   0.90 ms · worst   0.90 ms ·   4.9% of work · 1200 calls
    record       mean   1.70 ms · worst   1.90 ms ·   9.3% of work · 1200 calls
  pacing headroom: 15.1 ms slept per tick on average (max 16.7 ms) — near zero means the loop is saturated
```

在基于该数据集训练之前，这值得一读。一帧的时间戳由其索引推导而来，因此一个以 25 Hz 运行的会话仍会生成一个*声称*为 30 的数据集——记录的运动只是比现实更快。在上面的输出中，`observe` 占循环工作量的 74%，其 `worst` 为 40 ms，而预算是 33.3 ms：正是摄像头让那 16 个 tick 超支。**节奏余量**接近零意味着已经没有余量来吸收一个慢 tick。

回合之间的重置阶段也以相同方式控制节奏，但有意不包含在这些数字中，因为它们不记录任何内容。`lerobot-teleoperate` 和 `lerobot-replay` 以相同方式报告，而 `lerobot-rollout` 会添加[节奏报告](./inference#cadence-reporting)中描述的插值相关行。

#### 故障排查：[[troubleshooting]]

- 在 Linux 上，只要 `lerobot-record` 在交互式终端中运行，记录控制流程按键（方向键、Escape）就能在 X11、Wayland 和无头/SSH 会话中工作——无需设置 `$DISPLAY`。如果按键没有效果，请确保你处于交互式（TTY）终端中，而不是管道/非 TTY 会话，并且该终端处于焦点状态；字母等效键 `n` / `r` / `q` 也可用。键盘*遥操作*（与记录控制流程不同）仍然需要全局按键后端——X11 会话、Windows 桌面，或已授予辅助功能/输入监控权限的 macOS——并且在 Wayland 或无头机器上不可用。参见 [pynput 限制](https://pynput.readthedocs.io/en/latest/limitations.html#linux)。

## 回放回合[[replay-an-episode]]

一个有用的功能是 `replay` 函数，它允许你回放你记录的任何回合，或任何现有数据集中的回合。此功能可帮助你测试机器人动作的可重复性，并评估同一型号机器人之间的可迁移性。

你可以使用下面的命令或 API 示例在机器人上回放第一个回合：

<hfoptions id="replay">
<hfoption id="Command">
```bash
lerobot-replay \
    --robot.type=so101_follower \
    --robot.port=/dev/tty.usbmodem58760431541 \
    --robot.id=my_awesome_follower_arm \
    --dataset.repo_id=${HF_USER}/record-test \
    --dataset.episode=0 # 选择要回放的回合
```

import time

from lerobot.robots.so_follower import SO100Follower, SO100FollowerConfig

## 训练策略[[train-a-policy]]

要训练一个策略（policy）来控制你的机器人，请使用 [`lerobot-train`](https://github.com/huggingface/lerobot/blob/main/src/lerobot/scripts/lerobot_train.py) 脚本。需要提供几个参数。以下是一个示例命令：

```bash
lerobot-train \
  --dataset.repo_id=${HF_USER}/record-test \
  --policy.type=act \
  --output_dir=outputs/train/act_so101_test \
  --job_name=act_so101_test \
  --policy.device=cuda \
  --wandb.enable=true \
  --policy.repo_id=${HF_USER}/my_policy
```

让我们解释一下该命令：

1. 我们通过 `--dataset.repo_id=${HF_USER}/record-test` 提供了之前记录的数据集作为参数。
2. 我们通过 `policy.type=act` 提供了策略（policy）。这会从 [`configuration_act.py`](https://github.com/huggingface/lerobot/blob/main/src/lerobot/policies/act/configuration_act.py) 加载配置。重要的是，该策略会自动适应你数据集中保存的机器人电机状态、电机动作和摄像头数量（例如 `laptop` 和 `phone`）。
3. 我们提供了 `policy.device=cuda`，因为我们正在 Nvidia GPU 上训练，但你也可以使用 `policy.device=mps` 在 Apple silicon 上训练。
4. 我们提供了 `wandb.enable=true`，以使用 [Weights and Biases](https://docs.wandb.ai/quickstart) 可视化训练曲线。这是可选的，但如果你使用它，请确保通过运行 `wandb login` 登录。

训练应该需要几个小时。你会在 `outputs/train/act_so101_test/checkpoints` 中找到检查点。

要从检查点恢复训练，下面是一个从 `act_so101_test` 策略（policy）的 `last` 检查点恢复的示例命令：

```bash
lerobot-train \
  --config_path=outputs/train/act_so101_test/checkpoints/last/pretrained_model/train_config.json \
  --resume=true
```

`--config_path` 也接受 **Hub repo id**：如果某次运行将检查点推送到了 Hub（使用 `--save_checkpoint_to_hub=true`），你可以直接从该仓库恢复——其最新检查点会被下载，训练继续，并恢复优化器、调度器、步数计数器和数据顺序：

```bash
lerobot-train --config_path=${HF_USER}/my_policy --resume=true
```

如果你不想在训练后将模型推送到 Hub，请使用 `--policy.push_to_hub=false`。

此外，你可以通过添加以下内容为模型提供额外的 `tags`、指定 `license`，或将模型仓库设为 `private`：`--policy.private=true --policy.tags=\[ppo,rl\] --policy.license=mit`

#### 使用 Google Colab 训练[[train-using-google-colab]]

如果你的本地计算机没有强大的 GPU，可以按照 [ACT 训练 notebook](./notebooks#training-act)使用 Google Colab 训练模型。

#### 使用 Hugging Face Jobs 训练[[train-using-hugging-face-jobs]]

Hugging Face Jobs 让你可以轻松选择硬件并在云端运行训练。因此，如果你没有强大的 GPU、需要更多 VRAM，或者只是想让模型训练快得多，请使用 HF Jobs！它是按需付费的，你只需为使用的每一秒付费；你可以在[这里](https://huggingface.co/docs/hub/jobs)查看定价和更多信息。

`lerobot-train` 默认在本地运行。要在 HuggingFace GPU 上运行，请传入带有硬件规格名称的 `--job.target`：

```bash
lerobot-train \
  --dataset.repo_id=${HF_USER}/record-test \
  --policy.type=act \
  --policy.repo_id=${HF_USER}/my_policy \
  --job.target=a10g-small
```

使用 `hf jobs hardware` 列出可用的规格和定价。运行会将日志流式传输到你的终端；按 Ctrl-C 可分离（任务会继续在云端运行）。重新附加或取消：

```bash
hf jobs logs <job-id>
hf jobs cancel <job-id>
```

如果你的数据集只存在于本地（尚未在 Hub 上），它会自动推送到一个**私有** Hub 仓库，以便任务可以通过 `repo_id` 下载它（不会公开任何内容）。训练好的模型会在运行结束时推送到模型仓库。如果还要在每次保存中间检查点时都将其推送到 Hub（以便你在运行中途监控进度），请添加 `--save_checkpoint_to_hub=true`——这需要包含此功能的运行时镜像。

每个任务（以及该运行推送的任何数据集）都会打上 `lerobot` 标签，以便在 Hub 上轻松找到。使用 `--job.tags '["my-tag"]'` 添加你自己的标签。

默认情况下，任务的最长墙钟时间为 `2d`（48 小时）。可以使用 HF Jobs 的时长字符串覆盖它，例如 `--job.timeout=4h` 以更快失败，或 `--job.timeout=7d` 进行更长时间的运行。

> **注意：** 模型仓库会预先创建（其中保存任务运行所依据的暂存训练配置）。如果运行在模型推送之前失败，该仓库会留在 Hub 上供你检查——它不会被自动删除，因此反复失败可能会留下空仓库。使用 `hf repo delete <repo-id>` 删除一个仓库。

**先决条件：** 在提交之前运行 `hf auth login`。对于 Weights & Biases 集成，请运行 `wandb login`，或在你的机器上设置 `WANDB_API_KEY`——密钥会自动转发到任务。

**在任务上恢复。** 向恢复命令添加 `--job.target` 会在云端运行恢复——同一命令既可在本地运行，也可在远程运行。检查点仓库是唯一事实来源，新检查点会在同一仓库中延续谱系：

```bash
# 在任务上恢复 Hub 运行（其检查点已在 Hub 上）
lerobot-train --config_path=${HF_USER}/my_policy --resume=true --job.target=a10g-small

# 在任务上恢复本地运行——检查点会先上传到私有 Hub 仓库，
# 然后任务从中恢复（仅本地的数据集也以相同方式上传）
lerobot-train \
  --config_path=outputs/train/act_so101_test/checkpoints/last/pretrained_model/train_config.json \
  --resume=true \
  --job.target=a10g-small
```

任务设置来自当前命令，因此请根据需要覆盖 `--job.target`、`--job.timeout` 等；为了让恢复后的运行之后本身仍可恢复，请保留 `--save_checkpoint_to_hub=true`。

#### 上传策略检查点[[upload-policy-checkpoints]]

训练完成后，使用以下命令上传最新检查点：

```bash
hf upload ${HF_USER}/act_so101_test \
  outputs/train/act_so101_test/checkpoints/last/pretrained_model
```

你也可以使用以下命令上传中间检查点：

```bash
CKPT=010000
hf upload ${HF_USER}/act_so101_test${CKPT} \
  outputs/train/act_so101_test/checkpoints/${CKPT}/pretrained_model
```

## 运行推理并评估你的策略[[run-inference-and-evaluate-your-policy]]

使用 `lerobot-rollout` 在机器人上部署训练好的策略（policy）。你可以根据需求选择不同的策略（strategy）：

下面的示例从 `--policy.path` 加载模型。要固定到某个已推送的特定版本——当 `--save_checkpoint_to_hub=true` 已提交多个检查点后这很有用——请添加带有提交哈希、分支或标签的 `--policy.pretrained_revision`。每个推送的检查点都会以其步数打标签（例如 `--policy.pretrained_revision=010000`），因此你可以按步数恢复检查点，而无需查找其提交 sha。

<hfoptions id="eval">
<hfoption id="Base mode (no recording)">
```bash
lerobot-rollout \
  --strategy.type=base \
  --policy.path=${HF_USER}/my_policy \
  --robot.type=so100_follower \
  --robot.port=/dev/ttyACM1 \
  --robot.cameras="{ up: {type: opencv, index_or_path: /dev/video10, width: 640, height: 480, fps: 30}, side: {type: intelrealsense, serial_number_or_name: 233522074606, width: 640, height: 480, fps: 30}}" \
  --task="Put lego brick into the transparent box" \
  --duration=60
```
</hfoption>
<hfoption id="Sentry mode (with recording)">
```bash
lerobot-rollout \
  --strategy.type=sentry \
  --strategy.upload_every_n_episodes=5 \
  --policy.path=${HF_USER}/my_policy \
  --robot.type=so100_follower \
  --robot.port=/dev/ttyACM1 \
  --robot.cameras="{ up: {type: opencv, index_or_path: /dev/video10, width: 640, height: 480, fps: 30}, side: {type: intelrealsense, serial_number_or_name: 233522074606, width: 640, height: 480, fps: 30}}" \
  --dataset.repo_id=${HF_USER}/eval_so100 \
  --dataset.single_task="Put lego brick into the transparent box" \
  --duration=600
```
</hfoption>
</hfoptions>

`--strategy.type` 标志用于选择执行模式：

- `base`：不记录数据的自主 rollout（适用于快速评估）
- `sentry`：带自动上传的连续记录（适用于大规模评估）
- `highlight`：带按键保存的环形缓冲区记录（适用于捕获有趣事件）
- `dagger`：人在回路的数据采集（参见 [HIL 数据采集](./hil_data_collection)）
- `episodic`：面向回合的策略（policy）记录，并在回合之间包含重置阶段

所有策略（strategy）都支持 `--inference.type=rtc`，以便在慢速 VLA 模型（Pi0、Pi0.5、SmolVLA）下实现平滑执行。
