# SARM：阶段感知奖励建模

SARM（Stage-Aware Reward Modeling）是一个基于视频的奖励建模框架，用于长时域机器人操作任务。本指南介绍如何训练 SARM 奖励模型，以及如何将其与奖励对齐行为克隆（RA-BC）配合使用。

**论文**：[SARM: Stage-Aware Reward Modeling for Long Horizon Robot Manipulation](https://arxiv.org/abs/2509.25358)

## 为什么需要奖励模型？

标准行为克隆对所有演示帧一视同仁，但真实世界的机器人数据集往往很混乱——包含犹豫、纠正和质量参差不齐的轨迹。奖励模型通过学习演示中**任务进度**的可泛化概念来解决这个问题：给定视频帧和任务描述，预测机器人离完成任务还有多远（0→1）。这种学到的"进度信号"有多种用途，其中两个有前景的应用是：（1）**加权模仿学习**（RA-BC），高进度帧在策略训练中获得更大权重；（2）**强化学习**，奖励模型为在线或离线策略改进提供密集奖励。

## 概述

SARM 具有以下特点：

1. **阶段感知架构**：联合预测高层任务阶段和每个阶段内的细粒度进度
2. **子任务标注**：使用自然语言子任务标注来推导一致的进度标签
3. **时间比例**：计算每个子任务的数据集级先验（α̅\_k），用于归一化不同长度演示的进度

SARM 为每帧训练一个紧凑的**阶段+tau**目标：

- **阶段（stage）**：整数阶段索引 `k ∈ {0, ..., K-1}`
- **τ（tau）**：阶段内进度 `τ ∈ [0, 1]`
- **目标编码**：`y = k + τ`（这就是数据集处理器生成的内容）

在推理时（以及下游 RA-BC 中），SARM 使用数据集级**时间比例** `α̅_k`（存储在 `meta/temporal_proportions_*.json` 中）将原始 `k + τ` 值转换为 `[0, 1]` 范围内的**归一化进度**。

这与论文中的**公式（2）**一致：

```
progress_t = P_{k-1} + α̅_k × τ_t
```

其中：

- `τ_t = (t - s_k) / (e_k - s_k)` 是子任务内归一化时间
- `P_{k-1}` 是累积先验（前面子任务比例的总和）
- `α̅_k` 是子任务 k 的时间比例

这确保了相同的任务状态映射到一致的进度值，即使在不同长度的演示中也是如此。

## 输入和目标（新代码的要求）

SARM 通过其处理器（`src/lerobot/rewards/sarm/processor_sarm.py`）进行训练，该处理器：

- **编码**图像和任务文本，使用 CLIP（ViT-B/32）生成 `video_features` 和 `text_features`
- **填充/截断**机器人状态为 `state_features`（最多 `max_state_dim`）
- **构建目标**为 `sparse_targets`（以及 `dense_only`/`dual` 模式下的 `dense_targets`），使用阶段+tau 编码 `y = k + τ`
- **遮蔽回退帧**，使用每个样本的 `lengths` 张量（回退是训练时的数据增强）

每个训练样本至少需要：

- `task`（字符串）：任务描述
- `policy.image_key` 图像和 `policy.state_key` 状态，来自数据集

## 标注模式

你可以从 **3 种标注模式**中选择，它们决定了进度标签的计算方式：

| 模式           | 需要的标注       | 预测头                       | 使用场景                                                   |
| -------------- | ---------------- | ---------------------------- | ---------------------------------------------------------- |
| `single_stage` | 无               | 仅稀疏                       | 简单任务、快速实验，不需要 VLM                             |
| `dense_only`   | 密集（VLM）      | 双头（稀疏自动生成）         | 详细的子任务跟踪，无需定义高层阶段                         |
| `dual`         | 稀疏+密集（VLM） | 双头                         | 完整的 SARM 论文设置，同时使用两种粒度                     |

### 模式详情

<hfoptions id="mode_explanation">
<hfoption id="single_stage">

**不需要标注。**整个 episode 被视为一个名为 `"task"` 的单一阶段，进度在 episode 持续时间内从 0 线性增长到 1。

- **稀疏头**：1 个阶段（"task"），线性进度
- **密集头**：未使用
- **最适合**：简单任务、快速实验，或没有 VLM 标注可用时

## 步骤 5（可选）：使用 RA-BC 训练策略

奖励对齐行为克隆（RA-BC）使用训练好的 SARM 模型根据预测的进度改进来加权训练样本。这需要两个步骤：

1. **预计算所有帧的进度值**，使用训练好的 SARM 模型
2. **使用 RA-BC 加权训练策略**，利用预计算的进度值

### RA-BC 的工作原理

对于每个训练样本，RA-BC 计算进度增量：

```
r_i = φ(o_{t+Δ}) - φ(o_t)
```

其中 `φ` 是 SARM 进度预测，`Δ` 是策略的 `chunk_size`。正进度（好的演示）的样本获得更高权重，而负进度或零进度的样本被降权。

加权方式遵循论文中的**公式 8-9**：

- **软权重**：`w̃_i = clip((r_i − (μ − 2σ)) / (4σ + ε), 0, 1)`
- **最终权重**：`w_i = 𝟙{r_i > κ} + 𝟙{0 ≤ r_i ≤ κ} × w̃_i`

### 步骤 5a：计算 SARM 进度值

首先，在数据集的所有帧上运行 SARM 模型来计算进度值：

```bash
python -m lerobot.rewards.sarm.compute_rabc_weights \
  --dataset-repo-id your-username/your-dataset \
  --reward-model-path your-username/sarm-model \
  --head-mode sparse \
  --num-visualizations 5 \
  --push-to-hub
```

此脚本：

- 处理所有帧并计算进度值
- 将进度值保存到磁盘上数据集旁边的 parquet 文件（默认为 `<dataset_root>/sarm_progress.parquet`）
- 生成前 N 个 episode 的可视化（默认：5）

**参数：**

| 参数                   | 描述                                                         | 默认值     |
| ---------------------- | ------------------------------------------------------------ | ---------- |
| `--reward-model-path`  | 训练好的 SARM 模型路径                                       | （必需）   |
| `--head-mode`          | 使用的 SARM 头：`sparse`、`dense` 或 `both`                  | `sparse`   |
| `--device`             | 推理设备                                                     | `cuda`     |
| `--visualize-only`     | 仅可视化预测（不计算 RA-BC）                                 | `false`    |
| `--num-visualizations` | 要可视化的 episode 数量（默认：5，设为 0 跳过）              | `5`        |

**输出格式**（`sarm_progress.parquet`）：

| 列名              | 描述                                       |
| ----------------- | ------------------------------------------ |
| `index`           | 数据集中的全局帧索引                       |
| `episode_index`   | Episode 编号                               |
| `frame_index`     | Episode 内的局部帧索引                     |
| `progress_sparse` | 稀疏头进度值 [0, 1]                        |
| `progress_dense`  | 密集头进度值 [0, 1]（如果已计算）          |

### 步骤 5b：使用 RA-BC 训练策略

获得进度文件后，使用 RA-BC 加权训练策略。如果未显式提供，进度文件会从数据集路径（`sarm_progress.parquet`）自动检测。目前 PI0、PI0.5 和 SmolVLA 支持 RA-BC：

```bash
lerobot-train \
  --dataset.repo_id=your-username/your-dataset \
  --policy.type=pi0 \
  --sample_weighting.type=rabc \
  --sample_weighting.head_mode=sparse \
  --sample_weighting.kappa=0.01 \
  --output_dir=outputs/train/policy_rabc \
  --batch_size=32 \
  --steps=40000
```

训练脚本会自动：

- 从 parquet 文件加载预计算的进度值
- 使用策略的 `chunk_size` 计算进度增量（Δ）
- 基于进度改进计算样本权重
- 在训练期间应用加权损失

**RA-BC 参数：**

| 参数                               | 描述                                                 | 默认值                  |
| ---------------------------------- | ---------------------------------------------------- | ----------------------- |
| `--sample_weighting.type`          | 加权策略类型（`rabc` 或 `uniform`）                  | `rabc`                  |
| `--sample_weighting.progress_path` | 进度 parquet 文件路径                                | `sarm_progress.parquet` |
| `--sample_weighting.head_mode`     | 使用哪个 SARM 头的进度：`sparse` 或 `dense`          | `sparse`                |
| `--sample_weighting.kappa`         | 高质量样本的阈值 κ                                   | `0.01`                  |
| `--sample_weighting.epsilon`       | 数值稳定性的小常数                                   | `1e-6`                  |

### 调优 RA-BC Kappa

`kappa` 参数是决定哪些样本获得满权重（w=1）的阈值。理解如何调优它对 RA-BC 的有效工作至关重要。

**加权方式：**

| 条件                | 权重                  |
| ------------------- | --------------------- |
| `delta > kappa`     | 1.0（硬阈值）         |
| `0 ≤ delta ≤ kappa` | 公式 8 的软权重       |
| `delta < 0`         | 0.0（负进度）         |

**诊断 kappa 问题：**

在训练期间监控这些 WandB 指标：

| 指标                          | 健康范围    | 问题指示                      |
| ----------------------------- | ----------- | ----------------------------- |
| `sample_weight_mean_weight`   | 0.3 - 0.8   | ≈ 1.0 表示 kappa 太低         |
| `sample_weighting/delta_mean` | > 0         | 应为正值                      |
| `sample_weighting/delta_std`  | > 0         | 数据质量的方差                |

**如果 `sample_weight_mean_weight ≈ 1.0`：**kappa 太低了。大多数样本的 `delta > kappa`，完全绕过了软加权。RA-BC 退化为普通 BC。

**根据你的数据设置 kappa：**

默认 `kappa=0.01` 是针对论文中 T 恤折叠任务（约 90 秒的 episode，30fps）调优的。对于你的数据集，检查记录的 `sample_weighting/delta_mean` 和 `sample_weighting/delta_std`：

```
# 如果 delta_mean ≈ 0.03 且 delta_std ≈ 0.02：
# 大多数 delta 落在 [0.01, 0.05] 范围内

# 方案 1：设置 kappa = delta_mean（中等选择性）
--sample_weighting.kappa=0.03

# 方案 2：设置 kappa = delta_mean + delta_std（高选择性）
--sample_weighting.kappa=0.05

# 方案 3：设置 kappa = delta_mean + 2*delta_std（非常严格）
--sample_weighting.kappa=0.07
```

**RA-BC 可能无效的情况：**

如果你的数据集已经是高质量的（所有演示的进度一致），RA-BC 不会带来太多好处，因为没有什么需要过滤的。

## 技巧与最佳实践

### 选择模式

- **从 `single_stage` 开始**进行快速实验 - 没有标注开销
- 当需要详细进度跟踪但任务没有明确的高层阶段时，使用 **`dense_only`**
- 对于粗粒度和细粒度进度都有意义的复杂任务，使用 **`dual`**

### 标注质量

1. **子任务名称要具体**：用"抓住近侧向中心折叠"代替"折叠"
2. **用可视化验证**：训练前总是检查几个 episode
3. **命名一致**：在所有 episode 中使用相同的子任务名称

### RA-BC

1. **先训练 SARM**：RA-BC 的质量完全取决于 SARM 的质量
2. **监控 `sample_weight_mean_weight`**：如果 ≈ 1.0，增大 kappa（参见[调优 RA-BC Kappa](#tuning-ra-bc-kappa)）
