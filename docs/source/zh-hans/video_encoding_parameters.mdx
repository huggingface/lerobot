# 视频编码参数[[video-encoding-parameters]]

当启用视频存储时，LeRobot 会将每个摄像头流存储为一个 **MP4** 文件，而不是为每个时间步保存一个图像文件。视频编码会跨时间进行压缩，与一大堆 PNG 相比通常能减小数据集大小和 I/O，同时保留 MP4——一种每个播放器和加载器都能理解的格式。

将帧编码为 MP4 是一个完整的 FFmpeg 流水线：编码器选择、像素格式、GOP/关键帧、质量与速度的权衡，以及可选的额外编码器标志。这些调节项大多可通过 `rgb_encoder` 由用户调整，它是一个嵌套的 `RGBEncoderConfig`（`lerobot.configs.video.RGBEncoderConfig`），通过 PyAV 传递。

你可以通过 CLI 使用 `--dataset.rgb_encoder.<field>` 设置这些参数（例如使用 `lerobot-record` 或 `lerobot-rollout`）。同一个配置块会应用于该次运行中的每个摄像头视频流。

> [!TIP]
> 必须开启视频存储，`rgb_encoder` 才会生效——
> 在 Python API 中设置 `use_videos=True`，或在 CLI 上设置 `--dataset.video=true`（录制默认值）。关闭视频后，输入仍保持为图像，`rgb_encoder` 会被忽略。

关于帧**何时**写入与编码（流式还是片段后）、队列以及其他顶层 `--dataset.*` 开关的详细信息，请参阅[流式视频编码](./streaming_video_encoding)。有关编码参数对比和实验，请参阅 [video-benchmark Space](https://huggingface.co/spaces/lerobot/video-benchmark)。

## 示例[[example]]

```bash
lerobot-record \
    --robot.type=so100_follower \
    --robot.port=/dev/tty.usbmodem58760431541 \
    --robot.cameras="{laptop: {type: opencv, index_or_path: 0, width: 640, height: 480, fps: 30}}" \
    --robot.id=black \
    --teleop.type=so100_leader \
    --teleop.port=/dev/tty.usbmodem58760431551 \
    --teleop.id=blue \
    --dataset.repo_id=<my_username>/<my_dataset_name> \
    --dataset.num_episodes=2 \
    --dataset.single_task="Grab the cube" \
    --dataset.streaming_encoding=true \
    --dataset.encoder_threads=2 \
    --dataset.rgb_encoder.vcodec=h264 \
    --dataset.rgb_encoder.preset=fast \
    --dataset.rgb_encoder.extra_options={"tune": "film", "profile:v": "high", "bf": 2} \
    --display_data=true
```

## 调优参数[[tuning-parameters]]

> [!WARNING]
> 默认值经过调优，以在典型机器人数据集上平衡**压缩率**、**视觉质量**和**解码/跳转速度**。更改它们可能会同时影响录制（CPU 负载、丢帧）和训练（解码吞吐量、图像质量）。
>
> 只有在你有明确理由时才覆盖这些参数，并在依赖新设置之前测量它们对流水线的影响。

下面所有标志在 CLI 上都带有 `--dataset.rgb_encoder.` 前缀。

| 参数            | 类型             | 默认值        | 描述                                                                                                                                                                         |
| --------------- | ---------------- | ------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `vcodec`        | `str`            | `"libsvtav1"` | 视频编解码器名称。`"auto"` 会从固定偏好列表中选择第一个可用的硬件编码器，否则回退到 `libsvtav1`。                                                                            |
| `pix_fmt`       | `str`            | `"yuv420p"`   | 输出像素格式。所选编解码器必须在你的 FFmpeg 构建中支持它。                                                                                                                   |
| `g`             | `int`            | `2`           | GOP 大小——每 `g` 帧一个关键帧。作为 FFmpeg 选项 `g` 输出。                                                                                                                   |
| `crf`           | `int` 或 `float` | `30`          | 抽象质量值，按编解码器映射（参见[映射](https://github.com/huggingface/lerobot/blob/main/src/lerobot/configs/video.py#L197)）。在映射单调的情况下，越低 → 质量越高/输出越大。 |
| `preset`        | `int` 或 `str`   | `12` \*       | 编码器速度预设；其含义取决于编解码器。<br/>\* 未设置且 `vcodec=libsvtav1` 时，LeRobot 默认为 `12`。                                                                          |
| `fast_decode`   | `int`            | `0`           | `libsvtav1`：`0–2`，通过 `svtav1-params` 传递。<br/>`h264` / `hevc`（软件）：如果 `>0`，则设置 `tune=fastdecode`。<br/>其他编解码器：通常不使用。                            |
| `video_backend` | `str`            | `"pyav"`      | 目前视频编码仅实现了 `"pyav"`。                                                                                                                                              |
| `extra_options` | `dict`           | `{}`          | 额外的 FFmpeg 或编解码器特定选项，会在上述结构化字段之后合并。不能覆盖这些字段已设置的键。                                                                                   |

## 深度流[[depth-streams]]

通过一个并行的 **`depth_encoder`** 块（`DepthEncoderConfig`）配置深度流水线。它共享所有 `RGBEncoderConfig` 字段（`vcodec`、`pix_fmt`、`crf`、……），并新增四个量化器调节项，可通过 `--dataset.depth_encoder.<field>` 设置：

```bash
lerobot-record \
    ... \
    --dataset.depth_encoder.vcodec=hevc \
    --dataset.depth_encoder.depth_min=0.05 \
    --dataset.depth_encoder.depth_max=5.0 \
    --dataset.depth_encoder.use_log=true
```

| 参数            | 类型    | 默认值                          | 描述                                                                                                    |
| --------------- | ------- | ------------------------------- | ------------------------------------------------------------------------------------------------------- |
| `vcodec`        | `str`   | `"hevc"`                        | HEVC Main 12（一种支持 12 位的编解码器，兼容 MP4）。                                                    |
| `extra_options` | `dict`  | `{"x265-params": "lossless=1"}` | **深度默认无损**（精确往返）；`crf` 会被忽略。传入 `extra_options={}` 并设置 `crf` 可获得更小的有损流。 |
| `pix_fmt`       | `str`   | `"gray12le"`                    | 用于承载量化编码的单通道 12 位像素格式。                                                                |
| `depth_min`     | `float` | `0.01`                          | 映射到量化级 `0` 的深度（以米为单位）。低于该值会在解码时被截断。                                       |
| `depth_max`     | `float` | `10.0`                          | 映射到量化级 `4095` 的深度（以米为单位）。高于该值会在解码时被截断。                                    |
| `shift`         | `float` | `3.5`                           | 用于对数量化、在接近零时保持数值稳定性的对数前偏移（米）。必须满足 `depth_min + shift > 0`。            |
| `use_log`       | `bool`  | `True`                          | 如果为 `true`，在对数空间中进行量化（推荐用于典型深度传感器）。设置为 `false` 可进行均匀/线性量化。     |

> [!TIP]
> `depth_min`、`depth_max` 和 `shift` 始终以**米**为单位解释，无论输入深度的单位是什么。输入会自动检测：整型数组（例如直接来自 RealSense 的 `uint16` 毫米值）会被视为毫米，浮点数组会被视为米。
> 选择 `depth_min` / `depth_max` 来覆盖传感器的实际工作范围——超出该范围的量化值会饱和，这可能会压碎边界处的细节。

深度特征会在 `meta/info.json` 中标记为 `"is_depth_map": true`，并且其量化器设置（`video.depth_min`、`video.depth_max`、`video.shift`、`video.use_log`）会被持久化——这正是加载时能够将深度**反量化回物理单位**的原因。

### 加载时的输出单位[[output-unit-at-load-time]]

`depth_encoder` 是**录制时**关注的内容。深度图在*加载*时（例如训练期间）反量化成的单位，由读取时标志 `--dataset.depth_output_unit` 单独设置：

```bash
lerobot-train \
    --dataset.repo_id=<my_username>/<my_dataset_name> \
    --dataset.depth_output_unit=m \
    --policy.type=act
```

| 参数                | 类型  | 默认值 | 描述                                                             |
| ------------------- | ----- | ------ | ---------------------------------------------------------------- |
| `depth_output_unit` | `str` | `"mm"` | 深度图在加载时反量化到的物理单位：`"mm"`（毫米）或 `"m"`（米）。 |

> [!TIP]
> 这纯粹是解码时的呈现选择——它**不会**更改已存储的视频或其元数据，因此同一数据集可以以 `mm` 或 `m` 读取，而无需重新编码。它对没有深度摄像头的数据集没有影响。

## 数据集元数据中的持久化[[persistence-in-dataset-metadata]]

视频流的第一个片段编码后，编码器配置会被**持久化到数据集元数据**（`meta/info.json`）中每个视频特征下，并与从文件本身探测到的值放在一起。对于视频特征 `observation.images.<camera>`，`info.json` 中的布局为：

```json
{
  "features": {
    "observation.images.laptop": {
      "dtype": "video",
      "shape": [480, 640, 3],
      "info": {
        "video.height": 480,
        "video.width": 640,
        "video.codec": "h264",
        "video.pix_fmt": "yuv420p",
        "video.fps": 30,
        "video.channels": 3,
        "is_depth_map": false,
        "video.g": 2,
        "video.crf": 30,
        "video.preset": "fast",
        "video.fast_decode": 0,
        "video.video_backend": "pyav",
        "video.extra_options": { "tune": "film", "profile:v": "high", "bf": 2 }
      }
    }
  }
}
```

`info` 块由两个来源提供：

| 来源           | 来自何处                                         | 字段                                                                                                                    |
| -------------- | ------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------- |
| **流派生**     | 使用 PyAV 从编码后的 MP4 读回。                  | `video.height`, `video.width`, `video.codec`, `video.pix_fmt`, `video.fps`, `video.channels`, `is_depth_map`, `audio.*` |
| **编码器派生** | 取自 `RGBEncoderConfig` / `DepthEncoderConfig`。 | `video.g`, `video.crf`, `video.preset`, `video.fast_decode`, `video.video_backend`, `video.extra_options`               |

> [!IMPORTANT]
> 该块会**填充一次**，来自**第一个**片段。它假定数据集中的每个
> 片段都使用相同的 `rgb_encoder` 编码。不支持在录制过程中途更改
> 编码器设置——`info.json` 只会反映第一个片段所用的
> 参数。

## 合并数据集[[merging-datasets]]

使用 `merge_datasets` 聚合数据集时，视频文件会按原样拼接（不重新编码），并且 `info.json` 中的编码器字段会按键合并：

| 合并规则     | 字段                                                                               | 行为                                                                                                                            |
| ------------ | ---------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| **必须匹配** | `video.codec`, `video.pix_fmt`, `video.height`, `video.width`, `video.fps`         | 流派生字段必须在各来源之间匹配，否则 FFmpeg 的 concat demuxer 会失败。                                                          |
| **宽松合并** | `video.g`, `video.crf`, `video.preset`, `video.fast_decode`, `video.extra_options` | 编码器调优字段。如果所有来源都一致，则保留该值；如果不一致，则设置为 `null`（对于 `video.extra_options` 为 `{}`），并记录警告。 |
