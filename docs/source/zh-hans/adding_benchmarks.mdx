# 添加新基准测试

本指南将带你逐步向 LeRobot 添加新的仿真基准测试。请按顺序完成以下步骤，并参考现有的基准测试作为模板。

LeRobot 中的基准测试是一组 [Gymnasium](https://gymnasium.farama.org/) 环境，它们将第三方仿真器（如 LIBERO 或 Meta-World）封装在标准的 `gym.Env` 接口后面。然后 `lerobot-eval` CLI 可以在所有基准测试上统一运行评估。

## 现有基准测试概览

在开始之前，先看看已经集成的基准测试：

| 基准测试       | 环境文件            | 配置类             | 任务                | 动作维度     | 处理器                       |
| -------------- | ------------------- | ------------------ | ------------------- | ------------ | ---------------------------- |
| LIBERO         | `envs/libero.py`    | `LiberoEnv`        | 5 个套件共 130 个    | 7            | `LiberoProcessorStep`        |
| Meta-World     | `envs/metaworld.py` | `MetaworldEnv`     | 50 个 (MT50)         | 4            | 无                           |
| IsaacLab Arena | Hub 托管            | `IsaaclabArenaEnv` | 可配置              | 可配置       | `IsaaclabArenaProcessorStep` |

参考 `src/lerobot/envs/libero.py` 和 `src/lerobot/envs/metaworld.py` 作为实现示例。

## 整体架构

### 数据流

在评估过程中，数据经过四个阶段：

```
1. gym.Env  ──→  原始观测值（numpy 字典）

2. 预处理  ──→  标准 LeRobot 键 + 任务描述
   (preprocess_observation in envs/utils.py, env.call("task_description"))

3. 处理器  ──→  环境特定然后策略特定的转换
   (env_preprocessor, policy_preprocessor)

4. 策略  ──→  select_action()  ──→  动作张量
   然后反向：policy_postprocessor → env_postprocessor → numpy 动作 → env.step()
```

大多数基准测试只需要关注第 1 阶段（以正确的格式生成观测值），以及可选的第 3 阶段（如果需要环境特定的转换）。

### 环境结构

`make_env()` 返回一个嵌套的向量化环境字典：

```python
dict[str, dict[int, gym.vector.VectorEnv]]
#    ^套件名称     ^任务 ID
```

单任务环境（如 PushT）看起来像 `{"pusht": {0: vec_env}}`。
多任务基准测试（如 LIBERO）看起来像 `{"libero_spatial": {0: vec0, 1: vec1, ...}, ...}`。

### 评估运行方式

所有基准测试都通过 `lerobot-eval` 以相同的方式进行评估：

1. `make_env()` 构建嵌套的 `{suite: {task_id: VectorEnv}}` 字典。
2. `eval_policy_all()` 遍历每个套件和任务。
3. 对于每个任务，通过 `rollout()` 运行 `n_episodes` 次 rollout。
4. 结果按层次聚合：episode、任务、套件、总体。
5. 指标包括 `pc_success`（成功率）、`avg_sum_reward` 和 `avg_max_reward`。

关键点：你的环境必须在每次 `step()` 调用时在 `info` 字典中返回 `info["is_success"]`。这是评估循环判断任务是否完成的方式。

## 你的环境必须提供什么

LeRobot 不强制执行严格的观测模式，而是依赖所有基准测试遵循的一组约定。

### 环境属性

你的 `gym.Env` 必须设置以下属性：

| 属性                 | 类型  | 原因                                                 |
| -------------------- | ----- | ---------------------------------------------------- |
| `_max_episode_steps` | `int` | `rollout()` 使用这个来限制 episode 长度               |
| `task_description`   | `str` | 作为语言指令传递给 VLA 策略                          |
| `task`               | `str` | 如果未设置 `task_description` 时的回退标识符         |

### 成功报告

你的 `step()` 和 `reset()` 必须在 `info` 字典中包含 `"is_success"`：

```python
info = {"is_success": True}   # 或 False
return observation, reward, terminated, truncated, info
```

### 观测值

最简单的方法是将仿真器的输出映射到 `preprocess_observation()` 已经理解的标准键。在你的 `gym.Env` 中完成这个映射（例如在 `_format_raw_obs()` 辅助函数中）：

| 你的环境应该输出       | LeRobot 映射到              | 说明                                  |
| ---------------------- | --------------------------- | ------------------------------------- |
| `"pixels"` (单个数组)  | `observation.image`         | 单个相机图像，HWC uint8               |
| `"pixels"` (字典)      | `observation.images.<cam>`  | 多个相机，每个都是 HWC uint8          |
| `"agent_pos"`          | `observation.state`         | 本体感知状态向量                      |
| `"environment_state"`  | `observation.env_state`     | 完整环境状态（如 PushT）              |
| `"robot_state"`        | `observation.robot_state`   | 嵌套的机器人状态字典（如 LIBERO）     |

如果你的仿真器使用不同的键名，你有两个选择：

1. **推荐：** 在你的 `gym.Env` 封装器中将它们重命名为标准键。
2. **替代方案：** 编写一个环境处理器在 `preprocess_observation()` 运行后转换观测值（见下方步骤 4）。

### 动作

动作是 `gym.spaces.Box` 中的连续 numpy 数组。维度取决于你的基准测试（LIBERO 为 7，Meta-World 为 4 等）。策略通过它们的 `input_features` / `output_features` 配置适应不同的动作维度。

### 特性声明

每个 `EnvConfig` 子类声明两个字典，告诉策略期望什么：

- `features` — 将特性名称映射到 `PolicyFeature(type, shape)`（例如动作维度、图像形状）。
- `features_map` — 将原始观测键映射到 LeRobot 约定键（例如 `"agent_pos"` 到 `"observation.state"`）。

## 逐步指南

<Tip>
  至少需要两个文件：一个 **gym.Env 封装器** 和一个带有 `create_envs()` 覆盖的 **EnvConfig 子类**。
  其他内容都是可选的或文档。不需要修改 `factory.py`。
</Tip>

### 检查清单

| 文件                                     | 必需 | 原因                                                         |
| ---------------------------------------- | ---- | ------------------------------------------------------------ |
| `src/lerobot/envs/<benchmark>.py`        | 是   | 将仿真器封装为标准 gym.Env                                   |
| `src/lerobot/envs/configs.py`            | 是   | 注册你的基准测试及其 `create_envs()` 供 CLI 使用             |
| `src/lerobot/processor/env_processor.py` | 可选 | 自定义观测值/动作转换                                        |
| `src/lerobot/envs/utils.py`              | 可选 | 仅当你需要新的原始观测键时                                   |
| `pyproject.toml`                         | 是   | 声明基准测试特定的依赖                                       |
| `docs/source/<benchmark>.mdx`            | 是   | 面向用户的文档页面                                           |
| `docs/source/_toctree.yml`               | 是   | 将你的页面添加到文档侧边栏                                   |

### 1. gym.Env 封装器 (`src/lerobot/envs/<benchmark>.py`)

创建一个 `gym.Env` 子类来封装第三方仿真器：

```python
class MyBenchmarkEnv(gym.Env):
    metadata = {"render_modes": ["rgb_array"], "render_fps": <fps>}

    def __init__(self, task_suite, task_id, ...):
        super().__init__()
        self.task = <task_name_string>
        self.task_description = <natural_language_instruction>
        self._max_episode_steps = <max_steps>
        self.observation_space = spaces.Dict({...})
        self.action_space = spaces.Box(low=..., high=..., shape=(...,), dtype=np.float32)

    def reset(self, seed=None, **kwargs):
        ...  # 返回 (observation, info) — info 必须包含 {"is_success": False}

    def step(self, action: np.ndarray):
        ...  # 返回 (obs, reward, terminated, truncated, info) — info 必须包含 {"is_success": <bool>}

    def render(self):
        ...  # 返回 numpy 数组格式的 RGB 图像

    def close(self):
        ...
```

**基于 GPU 的仿真器（如使用 EGL 渲染的 MuJoCo）：** 如果你的仿真器在 `__init__` 期间分配 GPU/EGL 上下文，请将分配延迟到第一次 `reset()`/`step()` 时调用的 `_ensure_env()` 辅助函数中。这可以避免 `AsyncVectorEnv` 生成工作进程时继承过时的 GPU 句柄。参考 `LiberoEnv._ensure_env()` 了解这个模式。

同时提供一个工厂函数，返回嵌套的字典结构：

```python
def create_mybenchmark_envs(
    task: str,
    n_envs: int,
    gym_kwargs: dict | None = None,
    env_cls: type | None = None,
) -> dict[str, dict[int, Any]]:
    """为 MyBenchmark 创建 {suite_name: {task_id: VectorEnv}}。"""
    ...
```

参考 `create_libero_envs()`（多套件、多任务）和 `create_metaworld_envs()`（按难度分组的任务）作为示例。

### 2. 配置 (`src/lerobot/envs/configs.py`)

注册一个配置数据类，以便用户可以使用 `--env.type=<name>` 选择你的基准测试。每个配置通过两个方法拥有其环境创建和处理器逻辑：

- **`create_envs(n_envs, use_async_envs)`** — 返回 `{suite: {task_id: VectorEnv}}`。基类默认使用 `gym.make()` 用于单任务环境。多任务基准测试覆盖这个方法。
- **`get_env_processors()`** — 返回 `(preprocessor, postprocessor)`。基类默认返回恒等（无操作）管道。如果你的基准测试需要观测值/动作转换，则覆盖这个方法。

```python
@EnvConfig.register_subclass("<benchmark_name>")
@dataclass
class MyBenchmarkEnvConfig(EnvConfig):
    task: str = "<default_task>"
    fps: int = <fps>
    obs_type: str = "pixels_agent_pos"

    features: dict[str, PolicyFeature] = field(default_factory=lambda: {
        ACTION: PolicyFeature(type=FeatureType.ACTION, shape=(<action_dim>,)),
    })
    features_map: dict[str, str] = field(default_factory=lambda: {
        ACTION: ACTION,
        "agent_pos": OBS_STATE,
        "pixels": OBS_IMAGE,
    })

    def __post_init__(self):
        ...  # 根据 obs_type 填充 features

    @property
    def gym_kwargs(self) -> dict:
        return {"obs_type": self.obs_type, "render_mode": self.render_mode}

    def create_envs(self, n_envs: int, use_async_envs: bool = True):
        """为多任务基准测试或自定义环境创建覆盖此方法。"""
        from lerobot.envs.<benchmark> import create_<benchmark>_envs
        return create_<benchmark>_envs(task=self.task, n_envs=n_envs, ...)

    def get_env_processors(self):
        """如果你的基准测试需要观测值/动作转换，覆盖此方法。"""
        from lerobot.processor import PolicyProcessorPipeline
        from lerobot.processor.env_processor import MyBenchmarkProcessorStep
        return (
            PolicyProcessorPipeline(steps=[MyBenchmarkProcessorStep()]),
            PolicyProcessorPipeline(steps=[]),
        )
```

关键点：

- `register_subclass` 名称是用户在 CLI 上传递的内容（`--env.type=<name>`）。
- `features` 告诉环境产生什么。
- `features_map` 将原始观测键映射到 LeRobot 约定键。
- **不需要修改 `factory.py`** — 工厂自动委托给 `cfg.create_envs()` 和 `cfg.get_env_processors()`。

### 3. 环境处理器（可选 — `src/lerobot/processor/env_processor.py`）

仅当你的基准测试需要 `preprocess_observation()` 处理之外的观测转换时（例如图像翻转、坐标转换）才需要。在这里定义处理器步骤，并在你的配置中的 `get_env_processors()` 中返回它（见步骤 2）：

```python
@dataclass
@ProcessorStepRegistry.register(name="<benchmark>_processor")
class MyBenchmarkProcessorStep(ObservationProcessorStep):
    def _process_observation(self, observation):
        processed = observation.copy()
        # 在这里进行你的转换
        return processed

    def transform_features(self, features):
        return features  # 如果形状改变则更新

    def observation(self, observation):
        return self._process_observation(observation)
```

参考 `LiberoProcessorStep` 了解完整示例（图像旋转、四元数到轴角转换）。

### 4. 依赖 (`pyproject.toml`)

添加一个新的可选依赖组：

```toml
mybenchmark = ["my-benchmark-pkg==1.2.3", "lerobot[scipy-dep]"]
```

版本锁定规则：

- **始终锁定** 基准测试包到确切版本以保证可重复性（例如 `metaworld==3.0.0`）。
- **在需要时添加平台标记**（例如 `; sys_platform == 'linux'`）。
- **锁定已知的脆弱传递依赖**（例如 Meta-World 的 `gymnasium==1.1.0`）。
- **在基准测试文档页面中记录约束**。

用户安装方式：

```bash
pip install -e ".[mybenchmark]"
```

## 验证你的集成

完成上述步骤后，确认一切正常工作：

1. **安装** — `pip install -e ".[mybenchmark]"` 并验证依赖组安装正常。
2. **冒烟测试环境创建** — 在 Python 中使用你的配置调用 `make_env()`，检查返回的字典是否具有预期的 `{suite: {task_id: VectorEnv}}` 形状，并且 `reset()` 返回带有正确键的观测值。
3. **运行完整评估** — `lerobot-eval --env.type=<name> --env.task=<task> --eval.n_episodes=1 --policy.path=<any_compatible_policy>` 端到端地练习整个管道。（`batch_size` 默认为基于 CPU 核心数自动调整；传递 `--eval.batch_size=1` 可强制使用单个环境。）
4. **检查成功检测** — 验证当任务实际完成时 `info["is_success"]` 是否翻转为 `True`。这是评估循环用来计算成功率的依据。

## 编写基准测试文档页面

每个基准测试 `.mdx` 页面应包括：

- **标题和描述** — 1-2 段关于基准测试测试什么以及为什么重要的内容。
- **链接** — 论文、GitHub 仓库、项目网站（如有）。
- **概览图片或 GIF。**
- **可用任务** — 任务套件表格，包括数量和简要描述。
- **安装** — `pip install -e ".[<benchmark>]"` 以及任何额外步骤（环境变量、系统包）。
- **评估** — 推荐的 `lerobot-eval` 命令，包括用于可重复结果的 `n_episodes`。`batch_size` 默认为自动；仅在需要时指定。如果适用，包括单任务和多任务示例。
- **策略输入和输出** — 带有形状的观测键、动作空间描述。
- **推荐评估 episode 数** — 每个任务的标准 episode 数。
- **训练** — `lerobot-train` 命令示例。
- **复现已发表结果** — 链接到预训练模型、评估命令、结果表格（如有）。

参考 `docs/source/libero.mdx` 和 `docs/source/metaworld.mdx` 了解完整示例。
