# 流式视频编码指南

## 1. 概述

流式视频编码消除了视频 dataset 录制过程中传统的 PNG 中转步骤。不再是：

1. 捕获帧 -> 写入 PNG 到磁盘 -> （episode 结束时）读取 PNG -> 编码为 MP4 -> 删除 PNG

帧可以在捕获过程中实时编码：

1. 捕获帧 -> 排入编码器线程 -> 直接编码为 MP4

这使得 `save_episode()` 几乎瞬间完成（视频在 episode 结束时已经编码好了），并消除了之前在 episode 之间出现的阻塞等待，特别是在长 episode 使用多个摄像头时。

## 2. 调优参数

| 参数                    | CLI 标志                            | 类型          | 默认值        | 描述                                                          |
| ----------------------- | --------------------------------- | ------------- | ------------- | ----------------------------------------------------------------- |
| `streaming_encoding`    | `--dataset.streaming_encoding`    | `bool`        | `True`        | 启用捕获过程中的实时编码                                          |
| `vcodec`                | `--dataset.rgb_encoder.vcodec`    | `str`         | `"libsvtav1"` | 视频编解码器。`"auto"` 自动检测最佳硬件编码器                      |
| `encoder_threads`       | `--dataset.encoder_threads`       | `int \| None` | `None`（自动） | 每个编码器实例的线程数。`None` 由编解码器自行决定                   |
| `encoder_queue_maxsize` | `--dataset.encoder_queue_maxsize` | `int`         | `30`          | 每个摄像头的最大缓冲帧数（30fps 时约 1 秒）。消耗内存               |

## 3. 性能注意事项

流式编码意味着 CPU **在**捕获循环**期间**编码视频，而不是之后。这产生了一个 CPU 预算，需要在以下之间共享：

- **控制循环**（读取摄像头、控制机器人、写入非视频数据）
- **编码器线程**（每个摄像头一个线程池）
- **Rerun 可视化**（如果启用）
- **操作系统和其他进程**

### 分辨率和摄像头数量的影响

| 配置                        | 吞吐量（px/sec）  | CPU 编码负载 | 说明                           |
| ------------------------- | ------------------- | ----------------- | ------------------------------ |
| 2 摄像头 x 640x480x3 @30fps   | 55M                 | 低               | 大多数系统可运行                |
| 2 摄像头 x 1280x720x3 @30fps  | 165M                | 中等             | 现代系统运行流畅                |
| 2 摄像头 x 1920x1080x3 @30fps | 373M                | 高               | 需要强大的高端 CPU              |

### `encoder_threads` 调优

此参数控制每个编码器实例内部使用多少线程：

- **较高值**（例如 4-5）：编码更快，但每个摄像头使用更多 CPU 核心。适合核心数较多的高端系统。
- **较低值**（例如 1-2）：每个摄像头占用较少 CPU，为捕获和可视化释放核心。适合低分辨率图像和性能较好的 CPU。
- **`None`（默认）**：由编解码器自行决定。信息可在编解码器日志中查看。

### 背压和丢帧

每个摄像头有一个有界队列（`encoder_queue_maxsize`，默认 30 帧）。当编码器跟不上时：

1. 队列填满（消耗内存）
2. 新帧被**丢弃**（不阻塞）— 捕获循环继续不受影响
3. 记录警告日志：`"Encoder queue full for {camera}, dropped N frame(s)"`
4. Episode 结束时，报告每个摄像头的总丢帧数

### 编码器跟不上的症状

- **系统感觉卡顿和冻结**：所有 CPU 都在 100%
- 日志中出现**丢帧警告**或录制的 dataset 中帧数/FPS 低于预期
- **机器人运动不流畅**：如果 CPU 严重过载，甚至捕获循环也可能受到影响
- **Rerun 可视化延迟累积**：可视化落后于实时

## 4. 硬件加速编码

### 何时使用

在以下情况下使用硬件编码：

- CPU 是瓶颈（丢帧、机器人卡顿、Rerun 延迟）
- 你有兼容的硬件（GPU 或专用编码器）
- 你在高吞吐量下录制（高分辨率或使用多个摄像头）

### 选择编解码器

| 编解码器               | CPU 使用率 | 文件大小      | 质量 | 说明                                                             |
| --------------------- | --------- | -------------- | ------- | ---------------------------------------------------------------- |
| `libsvtav1`（默认）    | 高      | 最小           | 最佳    | 默认选项。压缩率最好但 CPU 消耗最大                                |
| `h264`                | 中等    | 大约大 30-50%  | 好    | 软件 H.264。较低的 CPU 消耗                                       |
| 硬件编码器             | 非常低  | 最大           | 好    | 卸载到专用硬件。最适合 CPU 受限的系统                              |

### 可用的硬件编码器

| 编码器               | 平台          | 硬件                                                                                         | CLI 值                                           |
| ------------------- | ------------- | ------------------------------------------------------------------------------------------------ | ------------------------------------------------ |
| `h264_videotoolbox` | macOS         | Apple Silicon / Intel                                                                            | `--dataset.rgb_encoder.vcodec=h264_videotoolbox` |
| `hevc_videotoolbox` | macOS         | Apple Silicon / Intel                                                                            | `--dataset.rgb_encoder.vcodec=hevc_videotoolbox` |
| `h264_nvenc`        | Linux/Windows | NVIDIA GPU                                                                                       | `--dataset.rgb_encoder.vcodec=h264_nvenc`        |
| `hevc_nvenc`        | Linux/Windows | NVIDIA GPU                                                                                       | `--dataset.rgb_encoder.vcodec=hevc_nvenc`        |
| `h264_vaapi`        | Linux         | Intel/AMD GPU                                                                                    | `--dataset.rgb_encoder.vcodec=h264_vaapi`        |
| `h264_qsv`          | Linux/Windows | Intel Quick Sync                                                                                 | `--dataset.rgb_encoder.vcodec=h264_qsv`          |
| `auto`              | 任意          | 探测系统中可用的硬件编码器。如未找到硬件编码器则回退到 `libsvtav1`                                | `--dataset.rgb_encoder.vcodec=auto`              |

> [!NOTE]
> 为了使用硬件加速编码器，你可能需要升级 GPU 驱动。

> [!NOTE]
> `libsvtav1` 是默认选项，因为它提供最佳的训练性能；其他编解码器可以降低 CPU 使用率且更快，但通常会产生更大的文件并可能影响训练时间。

## 5. 故障排除

| 症状                                                             | 可能原因                                   | 修复方法                                                                                                                                                                                                                                                                                              |
| ------------------------------------------------------------------ | -------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 系统冻结或机器人运动不流畅或 Rerun 可视化延迟                        | CPU 不足（100% 负载）                       | 关闭其他应用，降低编码吞吐量，降低 `encoder_threads`，使用 `h264`，使用 `display_data=False`。如果 CPU 仍然持续 100%，则可能不足以支持你的配置，考虑 `--dataset.streaming_encoding=false` 或硬件编码（`--dataset.rgb_encoder.vcodec=auto`）                                                            |
| "Encoder queue full" 警告或 dataset 中丢帧                        | 编码器跟不上（队列溢出）                     | 如果 CPU 未满 100%：增加 `encoder_threads`，增加 `encoder_queue_maxsize` 或使用硬件编码（`--dataset.rgb_encoder.vcodec=auto`）。                                                                                                                                                                    |
| 内存使用过高                                                       | 队列填充速度快于编码速度                     | `encoder_threads` 过低或 CPU 不足。降低 `encoder_queue_maxsize` 或使用硬件编码                                                                                                                                                                                                                       |
| 视频文件过大                                                       | 使用了硬件编码器或 H.264                     | 预期的权衡。如果 CPU 允许，切换到 `libsvtav1`                                                                                                                                                                                                                                                        |
| `save_episode()` 仍然慢                                           | `streaming_encoding` 为 `False`              | 设置 `--dataset.streaming_encoding=true`                                                                                                                                                                                                                                                            |
| 编码器线程崩溃                                                     | 编解码器不可用或设置无效                     | 检查 `vcodec` 是否已安装，尝试 `--dataset.rgb_encoder.vcodec=auto`                                                                                                                                                                                                                                   |
| 录制的 dataset 丢帧                                                | CPU/GPU 不足或偶发负载峰值                   | 如果约 5% 的帧丢失，你的系统可能过载——请遵循上述建议。如果丢失的帧较少（约 2%），可能是由于偶发的瞬时负载峰值（通常在启动时），可以视为正常现象。                                                                                                                                                      |

## 6. 推荐配置

这些估计值较为保守；建议在你的配置上测试——从低负载开始，逐步增加。

### 高端系统：现代 12+ 核（24+ 线程）

250-500M px/sec 的吞吐量在 CPU 上应该可以舒适运行。如需更好的效果，可以尝试硬件编码（如果可用）。

```bash
# 3 摄像头 x 1280x720x3 @30fps：默认设置效果良好。可选择增加编码器并行度。
# 2 摄像头 x 1920x1080x3 @30fps：默认设置效果良好。可选择增加编码器并行度。
lerobot-record --dataset.encoder_threads=5 ...

# 3 摄像头 x 1920x1080x3 @30fps：可能需要一些调优。
```

### 中端系统：现代 8+ 核（16+ 线程）或 Apple Silicon

80-300M px/sec 的吞吐量在 CPU 上应该可以运行。

```bash
# 3 摄像头 x 640x480x3 @30fps：默认设置效果良好。可选择降低编码器并行度。
# 2 摄像头 x 1280x720x3 @30fps：默认设置效果良好。可选择降低编码器并行度。
lerobot-record --dataset.encoder_threads=2 ...

# 2 摄像头 x 1920x1080x3 @30fps：可能需要一些调优。
```

### 低资源系统：现代 4+ 核（8+ 线程）或 Raspberry Pi 5

在非常受限的系统上，流式编码可能与捕获循环竞争过于激烈。禁用它后回退到基于 PNG 的方式，编码在 episode 之间进行（阻塞，但不干扰捕获）。或者，以较低的吞吐量录制以降低捕获和编码负载。还可以考虑将编解码器切换为 `h264` 并使用批量编码。

```bash
# 2 摄像头 x 640x480x3 @30fps：需要一些调优。

# 使用 H.264，禁用流式编码，考虑批量编码
lerobot-record --dataset.rgb_encoder.vcodec=h264 --dataset.streaming_encoding=false ...
```

## 7. 结语

性能最终取决于你的具体配置——帧率、分辨率、CPU 核心数和负载、可用内存、episode 长度以及你选择的编码器。始终以目标工作负载进行测试，注意 CPU 和系统能力，合理调优 `encoder_threads`、`encoder_queue_maxsize` 和 `vcodec`。话虽如此，一个常见的实用配置（适用于许多应用场景）是三个摄像头 640×480x3 @30fps；在现代系统上使用默认的流式视频编码设置通常可以正常运行。始终通过比较视频时长与 CLI episode 时长并确认行数等于 FPS × CLI 时长来验证录制的 dataset 是否健康。
