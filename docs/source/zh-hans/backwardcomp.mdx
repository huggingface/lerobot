# 向后兼容

## 策略归一化迁移（PR #1452）

**破坏性变更**：LeRobot 策略的权重中不再内置归一化层。归一化现由外部 `PolicyProcessorPipeline` 组件处理。

### 有哪些变化？

|                  | PR #1452 之前                          | PR #1452 之后                                                |
| ---------------- | -------------------------------------- | ------------------------------------------------------------ |
| **归一化的位置** | 嵌入模型权重中（`normalize_inputs.*`） | 外部 `PolicyProcessorPipeline` 组件                          |
| **模型状态字典** | 包含归一化统计值                       | **仅包含模型权重**，不包含归一化参数                         |
| **使用方式**     | `policy(batch)` 处理所有步骤           | `preprocessor(batch)` → `policy(...)` → `postprocessor(...)` |

### 对现有模型的影响

- 在 PR #1452 **之前**训练的模型，其权重中嵌入了归一化信息
- 这些模型需要迁移才能与新的 `PolicyProcessorPipeline` 系统配合使用
- 迁移过程会提取归一化统计值，并创建独立的处理器流水线

### 迁移旧模型

使用迁移脚本转换内置归一化层的模型：

```shell
python src/lerobot/processor/migrate_policy_normalization.py \
    --pretrained-path lerobot/act_aloha_sim_transfer_cube_human \
    --push-to-hub \
    --branch migrated
```

该脚本会：

1. 从模型权重中**提取**归一化统计值
2. **创建**外部预处理器和后处理器流水线
3. 从模型权重中**移除**归一化层
4. **保存**仅含模型权重的模型和处理器流水线
5. **推送**到 Hub，并自动创建 PR

### 使用迁移后的模型

```python
# 新的使用方式（迁移后）
from lerobot.policies import make_policy, make_pre_post_processors

# 分别加载模型和处理器
policy = make_policy(config, ds_meta=dataset.meta)
preprocessor, postprocessor = make_pre_post_processors(
    policy_cfg=config,
    dataset_stats=dataset.meta.stats
)

# 通过流水线处理数据
processed_batch = preprocessor(raw_batch)
action = policy.select_action(processed_batch)
final_action = postprocessor(action)
```

## 硬件 API 重新设计

PR [#777](https://github.com/huggingface/lerobot/pull/777) 改进了 LeRobot 的校准机制，但**不向后兼容**。下面概述主要变化，以及如何继续使用在该 PR 之前创建的数据集。

### 有哪些变化？

|                           | PR #777 之前                    | PR #777 之后                                      |
| ------------------------- | ------------------------------- | ------------------------------------------------- |
| **关节范围**              | 角度 `-180...180°`              | **归一化范围**：关节 `–100...100`；夹爪 `0...100` |
| **零位（SO100 / SO101）** | 机械臂完全水平伸展              | **各关节活动范围的中点**                          |
| **边界处理**              | 通过软件保护机制检测 ±180° 回绕 | 由于零位位于范围中点，无需回绕逻辑                |

---

### 对现有数据集的影响

- 如果直接加载 PR #777 **之前**录制的轨迹，回放结果会不正确：
  - 关节角度存在偏移，且归一化方式不正确。
- 直接用旧数据微调或训练的模型，需要转换其输入和输出。

### 使用旧校准系统创建的数据集

我们在 `examples/backward_compatibility/replay.py` 中提供了一个迁移示例脚本，用于回放使用旧校准系统录制的 episode。
下面介绍该示例脚本所做的修改，以便旧校准系统下的数据集能够正常使用。

```diff
+   key = f"{name.removeprefix('main_')}.pos"
    action[key] = action_array[i].item()
+   action["shoulder_lift.pos"] = -(action["shoulder_lift.pos"] - 90)
+   action["elbow_flex.pos"] -= 90
```

下面逐项说明。
新版本代码使用 `.pos` 后缀表示位置观测值，并移除了 `main_` 前缀：

<!-- prettier-ignore-start -->
```python
key = f"{name.removeprefix('main_')}.pos"
```
<!-- prettier-ignore-end -->

对于 `"shoulder_lift"`（id = 2），与旧校准方式和代码相比，零位偏移了 -90 度，方向也反转了。

<!-- prettier-ignore-start -->
```python
action["shoulder_lift.pos"] = -(action["shoulder_lift.pos"] - 90)
```
<!-- prettier-ignore-end -->

对于 `"elbow_flex"`（id = 3），与旧校准方式和代码相比，零位偏移了 -90 度。

<!-- prettier-ignore-start -->
```python
action["elbow_flex.pos"] -= 90
```
<!-- prettier-ignore-end -->

要使用角度归一化，还需将 `--robot.use_degrees` 选项设为 `true`。

```diff
python examples/backward_compatibility/replay.py \
    --robot.type=so101_follower \
    --robot.port=/dev/tty.usbmodem5A460814411 \
    --robot.id=blue \
+   --robot.use_degrees=true \
    --dataset.repo_id=my_dataset_id \
    --dataset.episode=0
```

### 使用旧校准系统训练的策略

策略输出的 action 与数据集采用相同的格式（`torch.Tensors`），因此也应执行相同的转换。

要确定这些转换，建议先按照上节的方法，回放一个用于训练该策略的数据集 episode。
然后，将相同的转换添加到推理脚本中（此处以 `record.py` 脚本为例）：

```diff
action_values = predict_action(
    observation_frame,
    policy,
    get_safe_torch_device(policy.config.device),
    policy.config.use_amp,
    task=single_task,
    robot_type=robot.robot_type,
    )
    action = {key: action_values[i].item() for i, key in enumerate(robot.action_features)}

+   action["shoulder_lift.pos"] = -(action["shoulder_lift.pos"] - 90)
+   action["elbow_flex.pos"] -= 90
    robot.send_action(action)
```
