# Datasets

[`LeRobotDataset`] is the format every LeRobot script reads and writes. It is episode-aware, decodes video
observations on the fly, and round-trips to the Hugging Face Hub.

See [Using LeRobotDataset](../lerobot-dataset-v3) for the format and the common operations,
[Porting Large Datasets](../porting_datasets_v3) for migration, and [Tools](../tools) for the CLI.

## Paimon datasets

Paimon stores LeRobot frames and companion metadata as lake tables. The Paimon backend reads
these tables through the standard `LeRobotDataset` and `lerobot-train` interfaces.

```bash
pip install 'lerobot[paimon]'
```

Import a LeRobot v3 dataset and pin its table group, then prepare a small local metadata directory:

```python
import pypaimon.multimodal as pm
from lerobot.datasets.paimon_backend import prepare_paimon_dataset

catalog_options = {"warehouse": "/data/robot_lake"}
conn = pm.connect(options=catalog_options)
conn.load_from_lerobot("robot_frames", "/data/lerobot_v3")
conn.create_lerobot_tag("robot_frames", "training-v1")

prepare_paimon_dataset(
    "/data/paimon_training",
    table="robot_frames",
    catalog_options=catalog_options,
    tag_name="training-v1",
)
```

The directory contains standard `meta/` files and `paimon.json` with the catalog, table and tag.
Frame rows and media remain in Paimon. Catalog options also support remote catalogs and warehouses;
provide credentials through the runtime environment, since the options are saved in `paimon.json`.
Use a new table-group tag and metadata directory for each training version.

```python
from lerobot.datasets.lerobot_dataset import LeRobotDataset

dataset = LeRobotDataset("robot/frames", root="/data/paimon_training")
frame = dataset[0]
```

```bash
lerobot-train \
  --dataset.repo_id=robot/frames \
  --dataset.root=/data/paimon_training \
  --policy.type=act \
  --policy.push_to_hub=false \
  --output_dir=outputs/paimon-act
```

Episode selection, temporal windows, RGB transforms and DataLoader workers use the normal LeRobot
interfaces. This backend is read-only and supports RGB images/video, numeric state/action and task
text; depth conversion, structured language and subtask metadata are not supported. Streaming mode
is unnecessary for remote map-style reads and is not supported by this backend.
