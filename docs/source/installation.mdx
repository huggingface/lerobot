# Install LeRobot

Installing LeRobot takes three steps and about 10 minutes: create a Python environment, install `ffmpeg`, then install LeRobot with the extras for what you want to do.

> [!TIP]
> **Which version should I install?** The latest release from PyPI (Step 3), unless you want to contribute to LeRobot. These docs exist for every release: pick yours in the version menu at the top of the sidebar, because commands can change between versions. `lerobot-info` tells you which version you have.

## Platform requirements

- **Python 3.12 or newer.**
- **macOS:** on Apple Silicon, PyTorch needs **macOS 14 or newer**, and GPU acceleration (MPS) **macOS 15 or newer**. On macOS 14, LeRobot runs on the CPU.
- **Linux:** the default PyTorch wheels need an NVIDIA driver **580.65 or newer**. For older drivers, see [PyTorch CUDA variant](#pytorch-cuda-variant-linux-only).
- **Windows:** works in PowerShell or in WSL (Windows Subsystem for Linux). In WSL, also install `evdev` (see Step 1).

## Step 1: Create a Python environment

A virtual environment keeps LeRobot and its dependencies separate from the rest of your system. We recommend `conda` (through miniforge); `uv` works too.

<!-- prettier-ignore-start -->

<hfoption id="conda">

```bash
curl -L -O "https://github.com/conda-forge/miniforge/releases/latest/download/Miniforge3-$(uname)-$(uname -m).sh"
bash Miniforge3-$(uname)-$(uname -m).sh
conda create -y -n lerobot python=3.12
```

</hfoption>

## Step 2: Install `ffmpeg` (for video)

LeRobot stores camera recordings as videos and uses [TorchCodec](https://github.com/meta-pytorch/torchcodec) to read them, which requires `ffmpeg`.

> [!NOTE]
> **Platform support:** TorchCodec is **not available** on macOS Intel (x86_64) or Linux armv7l. On these platforms, LeRobot automatically falls back to `pyav` — so you do not need to install `ffmpeg` and can skip to Step 3.
>
> **Jetson (aarch64 + CUDA):** video decoding runs on CPU by default. [`docker/Dockerfile.jetson`](https://github.com/huggingface/lerobot/blob/main/docker/Dockerfile.jetson) builds `torch`/`torchcodec` from source with CUDA support for JetPack 6.2 — community-maintained, see [`ravediamond/lerobot-jetson`](https://github.com/ravediamond/lerobot-jetson) for the prebuilt image and issue [#819](https://github.com/huggingface/lerobot/issues/819) for background.

If your platform supports TorchCodec, install `ffmpeg` using one of the methods below:

<!-- prettier-ignore-start -->

<hfoptions id="install_ffmpeg">
<hfoption id="conda (any PyTorch version)">

Install `ffmpeg` in your conda environment. This works with **all PyTorch versions** and is **required for PyTorch < 2.10**:

```bash
conda install ffmpeg -c conda-forge
```

> [!TIP]
> This usually installs `ffmpeg 8.X` with the `libsvtav1` encoder. If you run into issues (e.g. `libsvtav1` missing — check with `ffmpeg -encoders` — or a version mismatch with `torchcodec`), you can explicitly install `ffmpeg 7.1.1` using:
>
> ```bash
> conda install ffmpeg=7.1.1 -c conda-forge
> ```

</hfoption>
<hfoption id="uv (PyTorch >= 2.10 only)">

Starting with **PyTorch >= 2.10** (TorchCodec ≥ 0.10), TorchCodec can dynamically link to a system-wide `ffmpeg` installation. This is useful when using `uv` or other non-`conda` environment managers:

```bash
# Ubuntu/Debian
sudo apt install ffmpeg

# macOS (Apple Silicon)
brew install ffmpeg
```

> [!IMPORTANT]
> System-wide `ffmpeg` is **only supported with PyTorch >= 2.10** (TorchCodec ≥ 0.10). For older PyTorch versions, you **must** use `conda install ffmpeg -c conda-forge` instead.

</hfoption>
</hfoptions>
<!-- prettier-ignore-end -->

## Step 3: Install LeRobot 🤗

The base `lerobot` package is small on purpose. You add **extras**, named in square brackets, for what you want to do. Pick your line:

| You want to                                  | Install                                                                                                                                        |
| -------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| Follow the tutorial with an SO-100 or SO-101 | `pip install 'lerobot[core_scripts,training,feetech]'`                                                                                         |
| Follow the tutorial with a Koch or OMX arm   | `pip install 'lerobot[core_scripts,training,dynamixel]'`                                                                                       |
| Follow the tutorial with another robot       | `pip install 'lerobot[core_scripts,training]'`, plus your robot's extra from [Your robot's settings](./setup_your_robot)                       |
| Try LeRobot without a robot                  | `pip install 'lerobot[dataset,pusht,diffusion,evaluation]'` (see [Try it without a robot](./quickstart))                                       |
| Train a policy on a dataset from the Hub     | `pip install 'lerobot[training]'`, plus the policy's extra if its page lists one (for example `smolvla`)                                       |
| Evaluate policies on a simulation benchmark  | `pip install 'lerobot[evaluation]'`, plus the benchmark's extra and the policy's extra (for example `'lerobot[evaluation,metaworld,smolvla]'`) |
| Everything                                   | `pip install 'lerobot[all]'`                                                                                                                   |

With `uv`, write `uv pip install` instead of `pip install`. You can add extras later by running `pip install` again with the new ones.

<details>
<summary>All extras</summary>

**Feature extras:**

| Extra      | What it adds                                | Typical use case                    |
| ---------- | ------------------------------------------- | ----------------------------------- |
| `dataset`  | `datasets`, `av`, `torchcodec`, `jsonlines` | Loading & creating datasets         |
| `training` | `dataset` + `accelerate`, `trackio`         | Training policies                   |
| `hardware` | `pynput`, `pyserial`, `deepdiff`            | Connecting to real robots           |
| `viz`      | `rerun-sdk`, `foxglove-sdk`                 | Visualization during recording/eval |

**Composite extras** combine feature extras for common commands:

| Extra          | Includes                       | Typical use case                                        |
| -------------- | ------------------------------ | ------------------------------------------------------- |
| `core_scripts` | `dataset` + `hardware` + `viz` | `lerobot-record`, `lerobot-replay`, `lerobot-calibrate` |
| `evaluation`   | `av`                           | `lerobot-eval` (add policy + env extras as needed)      |
| `dataset_viz`  | `dataset` + `viz`              | `lerobot-dataset-viz`, `lerobot-imgtransform-viz`       |

**Policy, simulation and hardware extras** add the dependencies of one policy, simulator or robot:

```bash
pip install 'lerobot[pi]'             # π₀, π₀.₅ and π₀-FAST
pip install 'lerobot[smolvla]'        # SmolVLA
pip install 'lerobot[diffusion]'      # Diffusion Policy (diffusers)
pip install 'lerobot[aloha,pusht]'    # ALOHA and PushT simulations
pip install 'lerobot[libero]'         # LIBERO (Linux only)
pip install 'lerobot[metaworld]'      # Meta-World
pip install 'lerobot[feetech]'        # Feetech motors: SO-100, SO-101, LeKiwi, Moss
pip install 'lerobot[dynamixel]'      # Dynamixel motors: Koch, OMX
```

Feetech and Dynamixel motors both talk to your computer through [rustypot](https://github.com/pollen-robotics/rustypot). For the full list of extras, see `pyproject.toml`.

</details>

### Install from source (to contribute or use unreleased features)

Clone the repository and install it in editable mode, so your changes to the code take effect right away:

```bash
git clone https://github.com/huggingface/lerobot.git
cd lerobot
```

pip install -e ".[training]"      # For training policies
pip install -e ".[all]"           # Everything (all policies, envs, hardware, dev tools)

The same extras as above work here: `pip install -e ".[core_scripts,training,feetech]"`. To contribute, also add `dev` and `test`, and see the [contributing guide](./contributing).

### PyTorch CUDA variant (Linux only)

On Linux, `torch` and `torchvision` come from PyPI, whose default wheels are CUDA 13 builds (driver floor **580.65**). macOS and Windows installs use the PyPI default wheels and can skip this section.

For an older driver or GPU, install PyTorch from the matching [PyTorch index](https://pytorch.org/get-started/locally/) first, then LeRobot. PyPI's Linux TorchCodec is a CUDA 13 build too, so take it from the CPU index (with torch below 2.11, pick the matching release from the [TorchCodec compatibility table](https://github.com/meta-pytorch/torchcodec#installing-torchcodec)):

```bash
pip install --index-url https://download.pytorch.org/whl/cu126 torch torchvision
pip install --index-url https://download.pytorch.org/whl/cpu torchcodec
pip install -e ".[all]"          # source
# — or —
pip install lerobot              # from PyPI
```

> [!NOTE]
> `cu126` is the build PyTorch keeps for drivers that only support CUDA 12. torch 2.15 has no CUDA 12 build, so this index installs torch 2.14, and staying on CUDA 12 means staying on torch 2.14 or older.

With `uv pip`, `--torch-backend` selects the index in one step, e.g. `uv pip install --torch-backend cu126 lerobot`. `uv sync` always installs the committed lock: to change the CUDA build there, add the index to `[tool.uv.index]` and `[tool.uv.sources]` in `pyproject.toml` and re-run `uv lock`.

## Check it worked

```bash
lerobot-info
```

It prints your LeRobot version and the parts of your system it depends on: Python, PyTorch, your GPU, `ffmpeg`. Copy this output when you ask for help on [Discord](https://discord.gg/s3KuuzsPFb) or report a bug.

## Troubleshooting

If you encounter build errors, you may need to install additional system dependencies: `cmake`, `build-essential`, and `ffmpeg libs`.
To install these for Linux run:

```bash
sudo apt-get install cmake build-essential python3-dev pkg-config libavformat-dev libavcodec-dev libavdevice-dev libavutil-dev libswscale-dev libswresample-dev libavfilter-dev
```

For other systems, see: [Compiling PyAV](https://pyav.org/docs/develop/overview/installation.html#bring-your-own-ffmpeg)

More problems and their fixes are in [Troubleshooting & FAQ](./troubleshooting).

## Experiment tracking

[Trackio](https://huggingface.co/docs/trackio) is included in the `training` extra. Local runs need no account or login: they are stored in a local SQLite database under `~/.cache/huggingface/trackio`. Open the dashboard with:

```bash
trackio show --project lerobot
```

To sync runs to a Hugging Face Space (created if missing), run `hf auth login` and pass `--trackio.space_id=<user>/<space>`. Remote jobs (`--job.target`) with tracking enabled require `space_id`, because the pod's local database is lost when the job ends.

Space privacy defaults to `None`: new Spaces are public unless the organization's default is private. Pass `--trackio.private=true` to create a private Space.

Each run records the command that launched it and its console output (prints, logs, tracebacks), both shown on the run's page in the dashboard. On a Space they are as visible as the Space itself; pass `--trackio.capture_console=false` to keep the console output out of the run.

### Migrating from Weights & Biases

| W&B setting                     | Trackio setting                                                                                  |
| ------------------------------- | ------------------------------------------------------------------------------------------------ |
| `--wandb.enable=true`           | `--trackio.enable=true`                                                                          |
| `--wandb.project=<project>`     | `--trackio.project=<project>`                                                                    |
| `--wandb.disable_artifact=true` | Already the default; use `--trackio.disable_artifact=false` to opt in                            |
| `--wandb.entity=<team>`         | Choose `--trackio.space_id=<user-or-org>/<space>` for hosted logging                             |
| `--wandb.run_id=<id>`           | Use `--trackio.run_name=<name>` for an existing **Trackio** run                                  |
| `--wandb.mode=offline`          | Omit `space_id` for local logging; also unset `TRACKIO_SPACE_ID` and `TRACKIO_SERVER_URL` if set |
| `--wandb.mode=disabled`         | `--trackio.enable=false`                                                                         |
| `--wandb.console=off`           | `--trackio.capture_console=false`                                                                |
