# FineRobotics runtime: live acceptance

The exploratory runtime passed bounded laptop, science Slurm CPU/H100 and personal
HF Jobs CPU/A100 checks. This report concerns the processing engine, not completion
of the FineRobotics source inventory, production scaling or an annotation accuracy
benchmark. The [design](data_processing_design) explains those boundaries.

## What ran

Tests ran on macOS 15.6.1 ARM64/Python 3.12.11 and science Linux/Python 3.12.14.
The controlled fixture has four episodes, two cameras, 96 frames at 12 fps, native
six-dimensional actions/state and two deliberately black frames. Real data comes
from the first three SO-100 pick-and-place episodes: 1,342 frames, two cameras,
30 fps, 44.73 physical seconds. Conversion letterboxes to 512×512, uses current
LeRobot AV1 parameters and MP4 faststart, and does not change native actions.

Local and Slurm numbers time their full processing calls, excluding fixture setup,
source download and external model-service cold start. Slurm includes arrays and
finalizers. HF Jobs numbers are service-reported job durations, including code/client

timing is one bounded trial, not a statistical benchmark. Tiny parallel runs are
slower because startup and durable I/O dominate.

0.90 GB RSS, with no swaps; successful cached/partial-schema runs peaked at
0.49/0.48 GB. Fresh-success peak RSS was not captured. Heavy source/model downloads
and restoration stayed on the cluster; the local inspection dataset is about 16 MB.

## Verified invariants

- Fresh 1/2-worker conversion has matching native arrays and video hashes. Within
  the same Linux environment, local/Slurm part and video hashes match exactly.
  Mac/Linux codec bytes differ; cross-platform byte identity is not promised.
- The real converted subset matches source action/state, timestamps, frame index,
  episode index and index values exactly. Images are 512×512; recorded geometry
  preserves aspect ratio. MP4 `moov` precedes `mdat`.
- Quality detects both inserted black frames; encoder produces 40 finite vectors
  for the correct camera/frame references. CPU/H100 maximum absolute difference
  is `2.98e-8` with `atol=1e-6`, `rtol=1e-5`. This tiny seeded convolution is a
  real inference fixture, not a pretrained semantic-quality evaluation.
- Cached encoder execution creates no new checkpoints. Holding one owned quality
  artifact aside caused selective recomputation and a complete valid result in
  0.590s; the held original is recoverable. Unit tests additionally cover corrupt
  outputs, retries, incomplete coverage and interrupted materialization.
- Real subtasks, plans, memory, paraphrases, interjections/speech and camera-specific
  count/bounding-box VQA passed structural validation: three episodes, zero errors
  and warnings. Annotation leaves native columns and video bytes unchanged.
- The standard LeRobot reader loads the enriched three-episode sample. Partial
  annotation now supplies typed empty language columns to untouched files, without
  generating labels there or changing native values. Already consistent untouched
  files are not rewritten.
- HF CPU conversion was checksum-restored locally. The HF annotation release was
  checksum-restored on the cluster and loads all 19,631 native frames/50 episodes;
  only the selected three carry generated labels. Native arrays and source video
  hashes match. Source videos are pinned references, not duplicate uploads.
- Final HF resume retained identical file artifacts and source references, without
  starting a model. Slurm resume also passed after its external H100 service stopped.

Fresh A100 and H100 labels differ. A fixed seed/temperature is not a promise of
bitwise VLM determinism. Structural validation does not measure grounding or accuracy:
colour descriptions vary, subtask boundaries are approximate, and generated speech
is not a human recording. The A100 run also logged a truncated describe-pass JSON
reply after retry; segmentation still produced validated subtasks. Inspect these
outputs before treating them as training ground truth.

## Failures that improved the implementation

The first HF CPU job failed because the official uv-created Python environment has
no pip. Installation now uses `uv pip` against the active interpreter, with pip
fallback. A subsequent real CPU job passed. The GPU image lacks the annotation
OpenAI client; acceptance supplies explicit small-package pins without replacing
CUDA dependencies. Its uv installation lacks the `uvx` convenience executable;
the service command uses `uv tool run --from vllm==0.17.0` instead. Two failed GPU
attempts are accounted for; one was canceled promptly after detecting the issue.

Two H100 service starts failed on home-directory cache quota. Explicit task-storage
paths for vLLM, FlashInfer, Triton and Torch caches fixed startup. No existing user
files or environments were deleted.

Real annotations exposed zero-padded time badges copied as invalid JSON numbers
such as `002.52`. Badges now use `2.52`, and JSON retries explicitly describe valid
numeric formatting. The parser remains strict; module versions invalidate old
outputs. A second live finding was partial annotation breaking the ordinary reader
when other files lack nested JSON language columns; schema-only padding fixes this.
The focused regression fails with the old functional implementation and passes with
the fix. Existing source cards/notices are now preserved by the v3 source adapter.

## Remaining limits

No 1,024-CPU or 32-H100 throughput run, no 500–1,000× claim, no full repository
all-extras/GPU/E2E run, and no benchmark of hand/value/SLAM or human-to-robot generation.
Generic multi-pod groups and public dataset promotion have simulated integration
coverage, not live acceptance. Pair-link validation is tested but does not generate
physically aligned examples. The shipped new-source recipes are v3 LeRobot and
NPY/video archives, not every MCAP/HDF5/raw source in the proposal.

Before scale-out, measure image spooling, serial assembly, full-video hashing/decoding,
model-service utilization and small-object upload latency. Batch/checkpoint granularity
and persistent warm environments matter: this one-item-per-batch acceptance deliberately
favors failure isolation over throughput. Cached cloud jobs still pay source/bootstrap,
verification, materialization and retention overhead. Human annotation-quality review
and an independent maintainer architecture review remain necessary before a main merge.
