# Being-H0.5

Being-H0.5 is a **vision-language-action policy for cross-embodiment robot
learning** from [BeingBeyond](https://github.com/BeingBeyond/Being-H). The
LeRobot integration provides standard policy, processor, training, checkpoint,
and action-selection interfaces for the released base and RoboCasa models.

## Model Overview

Being-H0.5 combines visual observations, robot state, and a natural-language
task to predict a chunk of robot actions with flow matching.

| Component         | Implementation                                   | Role                                       |
| ----------------- | ------------------------------------------------ | ------------------------------------------ |
| Vision encoder    | Transformers `InternVLVisionModel`               | Encodes 224 × 224 multi-camera images      |
| Language backbone | Qwen3-1.7B family with Being-H0.5 MoT layers     | Fuses vision, language, and robot context  |
| Action expert     | Being-H0.5 mixture-of-transformers action stream | Conditions action generation on context    |
| Action head       | Flow-matching encoder and decoder                | Predicts 16-step action chunks             |
| Processors        | LeRobot preprocessor and postprocessor pipelines | Maps robot data to and from semantic slots |

LeRobot owns the complete runtime implementation. The tokenizer, Qwen3
projections, MLPs, normalization and rotary embeddings, and InternVL vision
tower reuse Transformers components. The checkpoint-specific packed MoT
attention, connector, semantic packing, and flow-action modules live in
`lerobot.policies.being_h05`.

### What the LeRobot Integration Covers

- Loading the released base and RoboCasa checkpoints from the Hub.
- Training and fine-tuning through `lerobot-train`.
- Inference through `predict_action_chunk` and `select_action`.
- Three ordered camera inputs and natural-language task instructions.
- Fixed semantic 200D state and action representations with validity masks.
- The released four-step flow-matching sampler.

## Installation Requirements

Install LeRobot by following the [installation guide](./installation), then
install the Being-H0.5 extra:

```bash
pip install -e ".[being_h05]"
```

No source checkout, `PYTHONPATH` change, or separate Being-H installation is
required.

## Checkpoints

| Variant  | LeRobot checkpoint                                                                | Intended use                        |
| -------- | --------------------------------------------------------------------------------- | ----------------------------------- |
| Base     | [`lerobot/being_h05_base`](https://huggingface.co/lerobot/being_h05_base)         | Cross-embodiment fine-tuning        |
| RoboCasa | [`lerobot/being_h05_robocasa`](https://huggingface.co/lerobot/being_h05_robocasa) | RoboCasa evaluation and fine-tuning |

The checkpoints include the policy configuration, tokenizer, serialized
preprocessor and postprocessor, and model weights.

## Usage

Load a converted checkpoint through the standard LeRobot policy path:

```bash
--policy.path=lerobot/being_h05_base
```

The packaged preprocessor and postprocessor restore the checkpoint's camera
order, semantic slots, normalization, and inverse action mapping. They consume
the named state and action fields from the released Being-H0.5 contract; an
environment-specific vector adapter is not included.

## Training

`BeingH05Policy.forward` implements the released mixture-of-flow objective.
During training, the preprocessor:

1. resizes and normalizes each configured camera;
2. formats the natural-language task prompt;
3. maps robot state and actions into their semantic 200D slots;
4. builds state/action validity masks; and
5. packs the vision, language, state, and action tokens for the model.

### Training Command Example

```bash
lerobot-train \
  --policy.path=lerobot/being_h05_base \
  --dataset.repo_id=your_name/your_dataset \
  --batch_size=1 \
  --steps=3000 \
  --output_dir=outputs/train/being_h05 \
  --job_name=being_h05 \
  --policy.device=cuda \
  --wandb.enable=true
```

The default optimizer is AdamW with learning rate `2e-5`, followed by a cosine
decay schedule with 1,000 warmup steps. These values can be overridden with
`--policy.optimizer_lr`, `--policy.optimizer_weight_decay`,
`--policy.scheduler_warmup_steps`, and `--policy.scheduler_decay_steps`.

<Tip>

Full AdamW fine-tuning of the complete model requires more than 32 GB of GPU
memory. Use optimizer sharding/offload or freeze the vision and language
backbones in a custom training setup when training on a smaller GPU.

</Tip>

## Data Requirements

A training dataset must provide:

- the camera features listed in `policy.image_keys`;
- a natural-language task string for each sample;
- the named state fields expected by the checkpoint;
- 12D action chunks ordered as EEF translation, EEF rotation, gripper, base
  motion, and control mode; and
- at least `policy.chunk_size` action steps per training sample.

Map a dataset's native robot representation to these named fields before
training or inference. Missing semantic modalities remain masked instead of
being treated as meaningful zero-valued inputs.

## Evaluation and Inference

Load a checkpoint through the standard LeRobot policy interface:

```python
from lerobot.policies.being_h05.modeling_being_h05 import BeingH05Policy

policy = BeingH05Policy.from_pretrained("lerobot/being_h05_base")
policy.to("cuda").eval()
```

The policy predicts 16 actions at a time and executes the first
`n_action_steps` actions before sampling another chunk. The released
checkpoints use four flow-matching inference steps.

Evaluate a checkpoint after providing an environment adapter that emits the
required named fields:

```bash
lerobot-eval \
  --policy.path=lerobot/being_h05_base \
  --policy.device=cuda \
  --env.type=<environment> \
  --env.task=<task> \
  --eval.batch_size=1 \
  --eval.n_episodes=10
```

Reset the policy and its processor pipelines at every episode boundary when
using a custom evaluation loop.

## Key Configuration Parameters

| Option                | Default | Description                           |
| --------------------- | ------: | ------------------------------------- |
| `chunk_size`          |      16 | Number of actions generated per chunk |
| `n_action_steps`      |       8 | Actions executed before replanning    |
| `num_inference_steps` |       4 | Flow-matching sampling steps          |
| `image_size`          |     224 | Required input image size             |

## Semantic data convention

Being-H0.5 uses named locations inside its fixed 200D state and action spaces:

| Signal                             | Semantic slots    |
| ---------------------------------- | ----------------- |
| State EEF position / rotation      | `0:3` / `3:6`     |
| State gripper joints               | `44:46`           |
| State base position / rotation     | `70:73` / `73:76` |
| Action EEF translation / rotation  | `0:3` / `3:6`     |
| Action gripper                     | `18:19`           |
| Action base command / control mode | `70:74` / `74:75` |

Only gripper and control mode are binarized by the released processor. EEF and
mobile-base actions retain their original values.
