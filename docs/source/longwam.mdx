# Long-WAM

[Long-WAM](https://nvlabs.github.io/LongLive/Long-WAM/) is a world-action model
that conditions action prediction on an extended observation history. This
integration exposes it as `policy.type=longwam` through LeRobot's training,
pretrained-policy, and processor interfaces.

Both **IDM** (video imagination followed by action denoising) and **COD**
(joint video/action denoising) use native LeRobot training and checkpoint APIs.
Inference supports Long-WAM's synchronous/asynchronous scheduling and optional
streaming VAE encoding. Convert existing `model.pt` bundles before using
`--policy.path`.

## Installation

Use Python 3.12 and a clean virtual environment. From this LeRobot checkout:

```bash
pip install -e ".[longwam,training]"
# Add the simulator dependencies when evaluating LIBERO:
pip install -e ".[longwam,libero]"
```

No external Long-WAM checkout is needed at runtime. Initial model downloads use
the Hugging Face cache. Configure authentication yourself if an asset requires
it; no credentials are included in this integration.

## Data and configuration

The initial adapter targets LIBERO-style, horizontally concatenated cameras.
Datasets must include the configured RGB cameras, `observation.state`, `action`,
and a language `task`. Camera order is explicit in `camera_keys`; it must match
the checkpoint. Use LeRobot v3-format data; convert older datasets with LeRobot's
dataset tools first. Images enter the processor as floats in `[0,1]`.

| Parameter                  | Meaning                                         | Default          |
| -------------------------- | ----------------------------------------------- | ---------------- |
| `past_obs_steps`           | History in raw dataset/control ticks            | `48`             |
| `video_stride`             | Raw ticks between sampled video frames          | `4`              |
| `future_video_steps`       | Future video supervision in raw ticks           | `32`             |
| `action_horizon`           | Supervised action chunk length                  | `32`             |
| `inference_action_horizon` | Optional inference-only chunk length            | Training horizon |
| `n_action_steps`           | Control ticks before chunk handoff              | `10`             |
| `camera_size`              | Height and width of each resized camera         | `[224,224]`      |
| `denoising`                | IDM or co-denoising                             | `idm`            |
| `execution`                | Long-WAM action scheduler                       | `sync`           |
| `streaming_vae`            | Incremental encoding of each observation window | `false`          |

History duration is `past_obs_steps / dataset_fps` seconds. Training requests raw
observations from `-past_obs_steps` through `future_video_steps`, inclusive, and
actions from `0` through `action_horizon - 1`. Padding masks are retained.
Inference receives only the current observation and maintains its own history.

State/action MIN_MAX normalization, constant-channel handling, and clipping
match the reference implementation. Statistics are saved with the processors.
`toggle_action_dimensions` must match the checkpoint's action convention; it is
not inferred from the environment name. Non-LIBERO camera layouts and
embodiment-specific transforms require separate validation.

## Training

### Fine-tune a native checkpoint

Convert a release bundle as described below, then load its saved experts without
reinitializing them:

```bash
lerobot-train \
  --policy.path=/path/to/native-libero-checkpoint \
  --policy.device=cuda \
  --policy.use_gradient_checkpointing=true \
  --policy.push_to_hub=false \
  --dataset.repo_id=your-org/your-dataset \
  --dataset.video_backend=pyav \
  --batch_size=1 \
  --steps=1000 \
  --save_freq=1000 \
  --env_eval_freq=0 \
  --wandb.enable=false \
  --save_checkpoint_to_hub=false \
  --output_dir=outputs/longwam
```

For local data, also pass `--dataset.root=/path/to/dataset`. The converted LIBERO
checkpoint uses `observation.images.image` and `observation.images.image2`.
If the dataset calls the second camera `observation.images.wrist_image`, add
`--rename_map='{"observation.images.wrist_image":"observation.images.image2"}'`.
Dataset statistics are updated for fine-tuning; resume retains the saved statistics.

```bash
lerobot-train \
  --config_path=outputs/longwam/checkpoints/001000/pretrained_model/train_config.json \
  --resume=true \
  --steps=2000
```

Batch size 1, BF16 weights, and gradient checkpointing used about 68.6 GB of peak
allocated GPU memory in the short full-weight check below. These values are an
interface example, not a benchmark recipe or a memory guarantee. Single-process
training and resume are the configuration exercised in this guide.

Both modes also have CPU training/save/resume tests with LeRobot's map-style
and streaming dataset readers. Select the latter with `--dataset.streaming=true`.

### Fresh initialization

Fresh initialization uses **LongLive2.0-Robot-S** for the video expert. Wan assets
supply the frozen VAE/text encoder and tokenizer, not the video initialization.
The default mapped ActionDiT requires an explicit compatible weight file:

```bash
lerobot-train \
  --policy.type=longwam \
  --policy.device=cuda \
  --policy.action_init_path=/path/to/mapped-action-dit.pt \
  --policy.camera_keys='[observation.images.image,observation.images.wrist_image]' \
  --policy.action_dim=7 \
  --policy.proprio_dim=8 \
  --policy.past_obs_steps=48 \
  --policy.action_horizon=32 \
  --dataset.repo_id=your-org/your-dataset \
  --batch_size=1 \
  --steps=1000 \
  --env_eval_freq=0 \
  --policy.push_to_hub=false \
  --wandb.enable=false \
  --output_dir=outputs/longwam-fresh
```

These batch-size/step values illustrate the interface, not a benchmark
reproduction recipe. A missing mapped-action file fails explicitly;
`--policy.action_init=random` is an opt-in alternative, not an automatic fallback.

Full-weight training validation used converted LIBERO-IDM and LIBERO-COD
checkpoints, separately from the fresh-initialization example above.

## Inference and evaluation

### Convert a released LIBERO checkpoint

The converter reads a local release bundle containing `model.pt`, `config.yaml`,
and `dataset_stats.json`. It validates the supported camera/normalization layout
and strictly loads the released experts, without reinitializing them. Conversion
runs on CPU and includes the frozen VAE, text encoder, tokenizer, and saved
processors in a native checkpoint; allow approximately 120 GB of host RAM and
24 GB of output storage. The output directory must not already exist.

```bash
python examples/longwam/convert_checkpoint.py \
  --bundle /path/to/released-libero-bundle \
  --backbone /path/to/Wan2.2-TI2V-5B \
  --tokenizer-model /path/to/Wan2.1-T2V-1.3B \
  --output /path/to/native-libero-checkpoint
```

The backbone directory must contain `Wan2.2_VAE.pth` and
`models_t5_umt5-xxl-enc-bf16.pth`; the tokenizer directory must contain
`google/umt5-xxl/`. Conversion does not upload any artifacts.

### Synchronous inference

**IDM is the default:** video imagination in latent space is followed by action
denoising conditioned on the video features. COD jointly denoises video and action.

Use `select_action` on **every control tick**, including ticks that consume a
previously predicted chunk. Call `reset()` between episodes. The initial
integration requires one environment per policy and a fixed instruction within
each episode.

```python
from lerobot.policies import make_pre_post_processors
from lerobot.policies.longwam.modeling_longwam import LongWAMPolicy

checkpoint = "/path/to/native-checkpoint"
with LongWAMPolicy.from_pretrained(checkpoint) as policy:
    policy.eval()
    preprocessor, postprocessor = make_pre_post_processors(
        policy.config, pretrained_path=checkpoint
    )
    policy.reset()
    # observation contains camera tensors, observation.state, and task.
    action = postprocessor(policy.select_action(preprocessor(observation)))
```

For a compatible native LIBERO checkpoint, the standard evaluation interface is:

```bash
lerobot-eval \
  --policy.path=/path/to/native-libero-checkpoint \
  --policy.device=cuda \
  --policy.execution=sync \
  --env.type=libero \
  --env.task=libero_10 \
  --env.max_parallel_tasks=1 \
  --eval.batch_size=1 \
  --eval.n_episodes=10 \
  --eval.use_async_envs=false
```

Use the checkpoint's camera, action, horizon, and denoising settings. Conversion
preserves its published `eval_num_inference_steps` (LIBERO-IDM: 10; COD: 4).
COD requires
both `denoising=cod` and `imagine_sigma=0`. Changing these is not a substitute for
loading the corresponding weights. The command above uses LeRobot's default
simulator settings, not the paired validation protocol below. Its standard CLI
path has been checked on the 12 cases listed below. LeRobot's evaluator records
sample videos in the output directory; remove unwanted recordings after review.

### Asynchronous scheduling and streaming VAE

The same per-tick `select_action` interface supports both options:

```bash
lerobot-eval \
  --policy.path=/path/to/native-libero-checkpoint \
  --policy.device=cuda \
  --policy.execution=async \
  --policy.streaming_vae=true \
  --env.type=libero \
  --env.task=libero_10 \
  --env.max_parallel_tasks=1 \
  --eval.batch_size=1 \
  --eval.n_episodes=10 \
  --eval.use_async_envs=false
```

The scheduler requests the next chunk before handoff and selects the correct
elapsed offset. A late result waits at the handoff boundary. Streaming VAE
incrementally encodes each planning window with the same causal padding as
full-window encoding; it works with both IDM and COD, in either scheduler mode.
For robot control, retain LeRobot's inline `--inference.type=sync` engine and
select the Long-WAM scheduler with `--policy.execution`.

### Paired reference evaluation

For the validated comparison, use the same release bundle and frozen assets as
conversion, plus a reference Long-WAM checkout:

```bash
python examples/longwam/evaluate_libero.py \
  --native-checkpoint /path/to/native-libero-checkpoint \
  --bundle /path/to/released-libero-bundle \
  --reference-root /path/to/LongLive/Long-WAM \
  --backbone /path/to/Wan2.2-TI2V-5B \
  --tokenizer-model /path/to/Wan2.1-T2V-1.3B \
  --output outputs/longwam-libero-sync/paired \
  --all-suites --episodes 5 --task-limit 10 --trace-steps 61
```

This requires a CUDA GPU and working EGL rendering. Under Slurm, the script
shards tasks using `SLURM_PROCID` and `SLURM_NTASKS`; allocate one GPU per task.
It saves progress after every episode and resumes only an identical protocol
and implementation. It does not record videos or upload artifacts. A separate
reference checkout is needed only for this comparison, not normal inference.
Add `--execution async` and/or `--streaming-vae` to compare those modes.
The reference uses an inline transport with the original scheduler; separate
scripted and CUDA lifecycle tests cover genuinely pending worker requests.

### Runtime boundaries

Synchronous chunk scheduling is the default. The optional Long-WAM scheduler
(`execution=async`) preserves its observation anchors and elapsed chunk offsets;
it is **not** LeRobot's generic async/RTC interface. `predict_action_chunk`,
generic RTC, and mid-episode task changes are explicitly unsupported.

One ordered worker thread shares the policy's parameters, preserving observation
ordering without a duplicate model in a subprocess.
`close()` waits for running work; a timed-out thread cannot forcibly terminate
a hung inference. Use the context manager above or call `close()` explicitly.
`train()` closes an existing inference worker before optimization.
