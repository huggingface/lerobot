# RynnValue

RynnValue is a language-conditioned robotic value model that predicts the remaining time, in seconds, until a task is completed. The native LeRobot API preserves that temporal-distance meaning. Offline and online consumers may derive the higher-is-better potential used by the paper:

```text
potential = -remaining_time
```

**Paper**: [RynnValue: Scaling Robotic Value Foundation Models with Temporal Distance](https://arxiv.org/abs/2608.09853)
**Original code**: [github.com/alibaba-damo-academy/RynnValue](https://github.com/alibaba-damo-academy/RynnValue)
**Checkpoints**: [lerobot/RynnValue-4B](https://huggingface.co/lerobot/RynnValue-4B), [lerobot/RynnValue-8B](https://huggingface.co/lerobot/RynnValue-8B)

## LeRobot integration

The integration ports the released architecture into LeRobot rather than executing checkpoint code with `trust_remote_code`. It preserves:

- Interleaved image, `<relative_value>`, and `<value>` query groups.
- Eight-token grouped representations concatenated before each value head.
- Distributional absolute and relative temporal heads.
- Symlog-spaced, two-hot value decoding.
- Value-isolation attention during inference.

The integration is inference-only. It does not reproduce the paper's 7,000-hour data mixture, temporal sampling augmentations, or training pipeline.

## Installation

From a source checkout:

```bash
uv sync --extra rynnvalue
```

Or with pip:

```bash
pip install -e ".[rynnvalue]"
```

The 4B checkpoint is approximately 10 GB, the 8B approximately 19 GB. A CUDA GPU with enough memory for the selected checkpoint is strongly recommended.

## Loading

The LeRobot checkpoints are self-contained: `config.json` embeds the native architecture configuration as `model_config`, `model.safetensors` holds the weights, and the `processor` folder holds the tokenizer and image processor.

`RynnValueConfig` defaults to `pretrained_path="lerobot/RynnValue-4B"`, so `make_reward_model` and `lerobot-score --reward_model.type=rynnvalue` load it. For the 8B model, pass `--reward_model.path=lerobot/RynnValue-8B`.

```python
from lerobot.configs.rewards import RewardModelConfig
from lerobot.rewards.rynnvalue import RynnValueRewardModel

config = RewardModelConfig.from_pretrained(
    "lerobot/RynnValue-4B",
    cli_overrides=[
        "--device=cuda",
        "--robot_description=a single-arm robot",
        "--camera_description=a third-person workspace camera",
    ],
)
model = RynnValueRewardModel.from_pretrained("lerobot/RynnValue-4B", config=config)
```

## Inputs and outputs

The preprocessor reads:

- `observation.images.top` by default, as one frame or a chronological frame sequence.
- `task` as the natural-language instruction.
- Fixed robot and camera descriptions through `robot_description` and `camera_description`.

The released checkpoints have metadata prompting enabled. Provide at least one robot or camera description unless you deliberately set `use_meta=False` for an ablation.

As in the official inference, the processor passes `max_frames` evenly spaced frames from the full history, including its first and last frames, and repeats frames when the trajectory is shorter (default 8). It shrinks frames so their longer side is at most `max_image_side` pixels (default 640).

`predict_remaining_time()` returns a `lerobot.rewards.RemainingTimeOutput` with one value per trajectory:

- `prediction.remaining_time_s` contains `v_end`, the final queried frame's predicted remaining time.
- The tensor stays on the model device.
- Potential, progress normalization, interpolation, and thresholding belong to workflow consumers.

If a checkpoint has multiple absolute-value heads, LeRobot averages them before selecting the final frame.

## Usage

With `config` and `model` loaded as above:

```python
import torch

from lerobot.rewards import make_reward_pre_post_processors

preprocessor, _ = make_reward_pre_post_processors(config)

batch = {
    "observation.images.top": frames,  # (T,C,H,W) or (B,T,C,H,W)
    "task": "put the cube in the drawer",
}
model.eval()
with torch.inference_mode():
    prediction = model.predict_remaining_time(preprocessor(batch))
remaining_time_s = prediction.remaining_time_s
```

`predict_remaining_time()` changes neither the model mode nor gradients, so call it in `eval()` mode under `torch.inference_mode()` for inference.

## Success and task match

`predict_success()` generates the model's analysis of each trajectory, as the official inference does: a video description, whether the video matches the task, and whether the agent completed it.

```python
with torch.inference_mode():
    analysis = model.predict_success(preprocessor(batch))
analysis.success  # 1.0 for "Yes", 0.0 for "No", NaN if the analysis omits the answer
analysis.match
analysis.description
```

It decodes up to `max_new_tokens` tokens per trajectory (default 128), so it is slower than `predict_remaining_time()`.

## Offline dataset scoring

Use the shared scoring command rather than a RynnValue-specific dataset script:

```bash
uv run lerobot-score \
    --dataset_repo_id=lerobot/example-dataset \
    --dataset_root=/path/to/local/dataset \
    --reward_model.path=lerobot/RynnValue-4B \
    --reward_model.device=cuda \
    --reward_model.robot_description="a single-arm robot" \
    --reward_model.camera_description="a fixed third-person camera"
```

RynnValue runs on the trajectory prefix ending at about one frame per second of the dataset, set with `--reward_model.inference_fps` (default 1), each with `max_frames` evenly spaced frames, set with `--reward_model.max_frames` (default 8). The scorer runs `--batch_size` prefixes per forward pass (default 1), interpolates linearly between the frames RynnValue runs on, and writes the dataset score `rynnvalue` with one signal, `reward.rynnvalue.remaining_time_s`, in seconds, lower is better. RA-BC needs a higher-is-better progress signal, so it can't weight samples with this score.

From Python, build the scorer, score the dataset and load the result:

```python
from lerobot.datasets.scores import load_scores
from lerobot.rewards import make_frame_scorer, score_dataset

score_dataset(dataset, make_frame_scorer(model))
scores = load_scores(dataset, "rynnvalue")
```

See [Reward Scoring](./reward_scoring) for resuming, uploading and parallel scoring.

## Reward shaping

The potential derived from remaining time is a state potential, not a complete transition reward. Apply potential-based shaping in the RL loop:

```text
r_shape = gamma * potential_next - potential
```

The paper combines this term with a sparse task reward, such as the success answer from `predict_success()`.

## Limitations

- Inference uses eager custom attention; Flash Attention and SDPA do not implement RynnValue's prediction-slot isolation.
- The current API scores complete supplied histories and is not a streaming KV-cache reward server.
- Training RynnValue from scratch is outside this integration.
