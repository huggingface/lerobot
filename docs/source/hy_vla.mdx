# Hy-Embodied-0.5-VLA

Hy-Embodied-0.5-VLA (Hy-VLA) is Tencent's bimanual
vision-language-action policy. It combines the
[Hy-Embodied-0.5](https://huggingface.co/tencent/HY-Embodied-0.5)
vision-language model with a compact flow-matching action expert.

## Model Overview

Hy-VLA combines a Hunyuan vision-language model, temporal multi-camera vision
encoding, and a flow-matching action expert. The released checkpoints use a
dual-arm pose representation and generate action chunks conditioned on images,
robot state, and a natural-language task.

### What the LeRobot Integration Covers

The LeRobot integration provides:

- ready-to-use UMI and RoboTwin checkpoints on the Hugging Face Hub;
- training and inference through `lerobot-train` and `lerobot-eval`;
- serializable preprocessing for the released dual-arm mappings;
- checkpoint save/resume through standard LeRobot APIs; and
- native Hunyuan VLM, MoT, video-attention, and flow-action components.

The author repository is not required at runtime.

## Installation Requirements

1. Install LeRobot by following the [installation guide](./installation).
2. Install the Hy-VLA dependencies:

```bash
uv sync --locked --extra hy_vla
```

<Warning>

The Hy-VLA extra uses LeRobot's standard Transformers dependency, so it can be
installed alongside other policy extras. Hy-VLA uses eager attention, which
needs more GPU memory than fused attention implementations.

</Warning>

## Checkpoints

The converted checkpoints contain byte-identical copies of all 1,628 tensors
from their official counterparts. Their model cards record the source
revisions and checksums.

| Variant  | LeRobot checkpoint                                                          | Action chunk                           | Image history |
| -------- | --------------------------------------------------------------------------- | -------------------------------------- | ------------: |
| UMI      | [`lerobot/hy_vla_umi`](https://huggingface.co/lerobot/hy_vla_umi)           | 50 relative actions at 10 Hz           |       1 frame |
| RoboTwin | [`lerobot/hy_vla_robotwin`](https://huggingface.co/lerobot/hy_vla_robotwin) | 20 relative + 20 absolute model tokens |      6 frames |

Use the UMI checkpoint as the starting point for fine-tuning. Use the
RoboTwin checkpoint for the RoboTwin evaluation setup below. The inference
configuration, processor state, normalization statistics, and tokenizer are
stored with each checkpoint and load automatically.

## Usage

Load the checkpoint that matches the target contract with the standard policy
path:

```bash
--policy.path=lerobot/hy_vla_umi
```

Use `lerobot/hy_vla_umi` for UMI-compatible fine-tuning and
`lerobot/hy_vla_robotwin` for the documented RoboTwin evaluation protocol. Do
not interchange their image-history, action-representation, or decoding
settings.

## Training

Hy-VLA supports the standard LeRobot training pipeline:

```bash
lerobot-train \
  --policy.path=lerobot/hy_vla_umi \
  --policy.device=cuda \
  --dataset.repo_id=<user/dataset> \
  --batch_size=1 \
  --steps=<steps> \
  --output_dir=outputs/train/hy_vla
```

The policy optimizes a flow-matching objective over the action chunk and uses
the task string from the dataset as its language instruction. LeRobot
checkpoints save the model, optimizer, scheduler, tokenizer, and processor
state, so normal checkpoint resume works without a separate conversion step.

## Data Requirements

The released UMI checkpoint expects three cameras:

| Camera role   | Dataset feature                 |
| ------------- | ------------------------------- |
| Exterior/head | `observation.images.top_head`   |
| Left wrist    | `observation.images.hand_left`  |
| Right wrist   | `observation.images.hand_right` |

Its native state and action are both 16D:

```text
left xyz(3), quaternion xyzw(4), gripper(1),
right xyz(3), quaternion xyzw(4), gripper(1)
```

Datasets with different camera names can use the training
[`rename_map`](./rename_map). A dataset with a
different robot state or action contract needs an explicit embodiment adapter;
it must not be treated as a truncated dual-arm vector.

<Tip>

Start with `--batch_size=1` and
`--policy.freeze_vision_encoder=true --policy.train_expert_only=true` for a
lower-memory fine-tuning run. Increase the batch size or unfreeze components
only after measuring available GPU memory and held-out performance.

</Tip>

## Evaluation

### RoboTwin

RoboTwin requires its SAPIEN and CuRobo simulator dependencies. The Hy-VLA
checkpoint uses absolute end-effector control, so select `ee_absolute` and
rename the simulator camera features to the checkpoint's camera names:

```bash
LEROBOT_ROBOTWIN_OFFICIAL_INSTRUCTION=1 \
LEROBOT_ROBOTWIN_INSTRUCTION_TYPE=unseen \
lerobot-eval \
  --policy.path=lerobot/hy_vla_robotwin \
  --policy.device=cuda \
  --env.type=robotwin \
  --env.task=beat_block_hammer \
  --env.action_mode=ee_absolute \
  --env.obs_type=pixels_agent_pos \
  --eval.n_episodes=10 \
  --eval.batch_size=1 \
  --eval.use_async_envs=false \
  --output_dir=outputs/eval/hy_vla_robotwin \
  '--rename_map={"observation.images.head_camera":"observation.images.top_head","observation.images.left_camera":"observation.images.hand_left","observation.images.right_camera":"observation.images.hand_right"}'
```

The RoboTwin policy samples a 20-action physical chunk, executes 7 actions,
and then replans. It uses 6 observation frames sampled at an interval of 5
environment steps. These values are already stored in the published
checkpoint.

Use `--eval.batch_size=1`. If you build a custom rollout loop that loads the
policy, preprocessor, and postprocessor separately, reset all three at every
episode boundary. Standard LeRobot synchronous and RTC inference already do
this.

## State and Action Representation

The released checkpoints operate on a native 16D bimanual pose but use a 20D
representation inside the model:

```text
left xyz(3), rotation-6D rows(6), gripper(1),
right xyz(3), rotation-6D rows(6), gripper(1)
```

Processors packaged with the checkpoint convert quaternions to and from the
6D rotation representation, apply normalization, pad the model input to 32D,
and restore native environment actions.

The UMI checkpoint predicts 50 relative actions. RoboTwin uses 40 action
tokens: 20 relative poses followed by 20 absolute poses. Its postprocessor
combines the paired predictions into 20 physical actions. Do not override a
checkpoint's `embodiment`, action representation, or decoding mode unless you
are implementing and validating a new adapter.

## Key Configuration Parameters

| Option                     | Description                                                                    |
| -------------------------- | ------------------------------------------------------------------------------ |
| `embodiment`               | Data/action adapter: `umi_dual_arm` or `robotwin_dual_arm`.                    |
| `freeze_vision_encoder`    | Freezes the vision encoder during fine-tuning.                                 |
| `train_expert_only`        | Trains the action expert and projections while keeping the VLM frozen.         |
| `execution_horizon`        | Number of physical actions served before the policy samples a new chunk.       |
| `action_decode_mode`       | Decodes relative, absolute, or blended actions when supported by a checkpoint. |
| `attention_implementation` | Selects the attention backend; published checkpoints default to `eager`.       |

## Limitations

- The released checkpoints are bimanual policies and expect the documented
  dual-arm state and action contract.
- The integration includes the model runtime and standard LeRobot training
  path, but not the author's dataset-preparation pipeline or distributed
  launcher.
