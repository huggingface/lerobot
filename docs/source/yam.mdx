# YAM

The `yam_follower` and `bi_yam_follower` integrations support one or two standard YAM v1 arms with linear DM4310 grippers on Linux SocketCAN. Like [reBot B601](rebot_b601), they use `motorbridge.Controller` and its Damiao motor API. Each arm needs its own classic CAN interface at 1 Mbit/s: motor IDs 1–7, feedback IDs 17–23, three 4340 motors followed by four 4310 motors. Other grippers and modified encoder zeros need separate validation.

## Install and calibrate

```bash
uv sync --locked --extra yam --extra molmoact2 --extra dataset
```

Prepare each SocketCAN interface at 1 Mbit/s classic CAN before calibration or control. For one arm:

```bash
uv run --no-sync lerobot-setup-can \
  --mode=setup --interfaces=can0 \
  --bitrate=1000000 --use_fd=false
```

For two arms:

```bash
uv run --no-sync lerobot-setup-can \
  --mode=setup --interfaces=can0,can1 \
  --bitrate=1000000 --use_fd=false
```

`--mode=setup` brings each Linux CAN interface down, configures it, and brings it back up. It sends no motor commands. Run it only when no robot controller is using the interfaces.

For a bimanual setup, verify which physical arm each interface controls. `expected_adapter_serial` can detect left/right adapter swaps when the robot connects.

A motor-reported `0xD` (communication lost) is different from an interface being down. Do not mask it by automatically clearing faults or restarting the CAN bus during control.

With each arm supported, measure its gripper endpoints. For one arm:

```bash
uv run --no-sync lerobot-calibrate \
  --robot.type=yam_follower --robot.id=yam \
  --robot.port=can0
```

For two arms:

```bash
uv run --no-sync lerobot-calibrate \
  --robot.type=bi_yam_follower --robot.id=bimanual_yam \
  --robot.left_arm_config.port=can0 --robot.right_arm_config.port=can1
```

Follow the closed/open prompts; each prompt names the arm it is measuring. A bimanual calibration handles the left arm and then the right arm. When a calibration is already saved, `lerobot-calibrate` asks whether to keep it or measure again. Calibration reads feedback only: it does not enable torque, move the grippers, or change the factory joint zeros. The bimanual robot saves one standard single-arm calibration record for each side, using the derived IDs `bimanual_yam_left` and `bimanual_yam_right`. Each record stores the raw motor angles of the two gripper stops in whole degrees. Without `--robot.id`, the bimanual robot uses `bi_yam_follower`. Either raw gripper polarity is supported. Explicit `gripper_closed_deg` and `gripper_open_deg` (raw motor degrees) override the saved endpoints.

## Control and units

For one arm, the observation and action order is `joint_1.pos` through `joint_6.pos`, then `gripper.pos`. The bimanual robot prefixes the same fields with `left_` and `right_`; top-level cameras keep their names and per-arm cameras are prefixed. By default joints are **absolute degrees** and each gripper goes from **0 (closed) to 100 (open)**, like other LeRobot arms. Set `use_degrees=false` for **radians** and a **0–1 gripper**, the units of I2RT and MolmoAct2 data. `use_velocity_and_torque=true` adds `.vel` and `.torque` features for each motor. Actions slightly past a joint limit or the gripper stroke are clipped; non-finite actions are rejected. End-effector policies require a separately configured IK processor.

Each arm's `read_only` defaults to `true`. With `read_only=false`, connecting validates every configured arm and camera before enabling impedance control at the measured pose. This begins holding immediately; interactive `/start` begins policy actions. There is no automatic startup homing. By default, the six joints must be within 11.5° of the factory folded zero pose; gripper opening is unrestricted within its calibrated stroke. Set `initial_position_deg` and `initial_tolerance_deg` for a verified alternative starting pose.

Each arm has a robot-owned servo loop that maintains position stiffness and gravity feed-forward while inference runs. It limits joint/gripper target speed, joint tracking error, and gripper proportional torque. If commands expire, it captures and holds the measured position once. A fault or missing feedback stops the arm; in a bimanual setup it stops both arms. This can remove their support. A return motion is never attempted using stale feedback.

Measured joints may exceed the model's command limits by up to 0.15 rad, and the gripper calibration by 10% of its stroke, before being treated as implausible feedback. Commands still use the tighter limits. Verify these feedback margins against your hardware before powered operation.

Motorbridge 0.5 returns cached positions without timestamps. A receive-only `python-can` subscriber therefore checks kernel receive timestamps for all seven motors. It sends no packets and does not decode positions; motorbridge owns motor communication and position decoding. The Python servo is not a hard real-time controller. When the servo starts, it freezes objects already tracked by cyclic GC to reduce model-related pauses; ordinary reference counting still works. This affects the whole process until the last YAM disconnects. Set `--robot.freeze_gc=false` if your application manages GC itself. Feedback requests wait for fresh replies within `feedback_timeout_s`; the foreground check allows two such intervals plus one servo period. Long scheduling stalls can still stop the servo and disable torque.

Gravity feed-forward uses the bundled inertial-only I2RT model, including the linear gripper. The original MIT notice is retained inside the XML. `gravity_factors` scale its six joint torques. Added cameras/payloads are not modeled, and this model provides no collision detection.

## MolmoAct2 rollout

Use a **LeRobot-format** checkpoint directory with its saved processors, not the original model repository as `policy.path`. For `allenai/MolmoAct2-BimanualYAM`, the original embodiment tag is `yam_dual_molmoact2`: absolute joint pose, the 14 features above, and camera order **top, left, right**. It was trained on radians and a 0–1 gripper, so set `use_degrees=false` on both arms, as below. Keep the released quantile statistics and `normalize_gripper=false`; the two gripper dimensions are excluded from quantile normalization. Do not estimate replacement statistics from live observations. See [MolmoAct2](molmoact2) for policy loading.

For an already converted checkpoint, configure your three RGB camera paths and run:

```bash
uv run --no-sync lerobot-rollout \
  --robot.type=bi_yam_follower --robot.id=bimanual_yam \
  --robot.left_arm_config.port=can0 --robot.right_arm_config.port=can1 \
  --robot.left_arm_config.read_only=false --robot.right_arm_config.read_only=false \
  --robot.left_arm_config.use_degrees=false --robot.right_arm_config.use_degrees=false \
  --robot.cameras='{"top":{"type":"opencv","index_or_path":"/dev/v4l/by-id/TOP_CAMERA","width":640,"height":480,"fps":30},"left":{"type":"opencv","index_or_path":"/dev/v4l/by-id/LEFT_CAMERA","width":640,"height":480,"fps":30,"fourcc":"MJPG"},"right":{"type":"opencv","index_or_path":"/dev/v4l/by-id/RIGHT_CAMERA","width":640,"height":480,"fps":30,"fourcc":"MJPG"}}' \
  --policy.path=/path/to/molmoact2-bimanual-yam \
  --inference.type=rtc --inference.rtc.mode=guided \
  --inference.rtc.execution_horizon=20 --inference.queue_threshold=20 \
  --device=cuda --fps=30 --interpolation_multiplier=2 \
  --duration=0 --interactive=true --play_sounds=false \
  --return_to_initial_position=true \
  --task="Pick up the red block and place it in the green bin"
```

Both arms default to `gripper_kp=5`, `gripper_kd=0.005`, and `max_gripper_speed_s=12` (normalized full strokes per second). With the 0.5 Nm proportional torque cap, `Kp=5` allows a motor-position target up to 0.1 rad ahead of the measured position. These settings apply to both opening and closing and can be overridden per arm. Command generation has been checked in both directions and with either calibration polarity, but the resulting physical speed has not been measured. Actual speed depends on policy targets, load, and motor response.

Type `/start` to begin policy execution, `/subtask <text>` to change the instruction, and `/reset` to request a return to the captured startup pose. `duration=0` means no episode time limit. This integration leaves standard rollout controls unchanged: its return trajectory has a fixed duration and does not verify that the arms have settled at home. The YAM speed/tracking limits still apply, so do not interpret completion of that trajectory as measured arrival. Support the arms before disconnecting; torque is disabled on disconnect.
