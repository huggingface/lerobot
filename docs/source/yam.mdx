# Bimanual YAM

`bi_yam_follower` supports two standard YAM v1 arms with linear DM4310 grippers. All CAN communication uses LeRobot's `DamiaoMotorsBus`. The adapter does not require an I2RT controller or Portal server. MuJoCo computes gravity compensation from the bundled inertial model; its source attribution and MIT notice are embedded in the XML.

## Installation and CAN interfaces

```bash
uv sync --locked --extra yam
```

Each arm needs a separate classic SocketCAN channel at **1 Mbit/s**. Both arms reuse motor IDs 1–7 and feedback IDs 17–23: motors 1–3 are DM4340, and 4–7 are DM4310. Do not select CAN FD or attach both arms to the same channel.

Bring up the verified interfaces, substituting the names on your computer:

```bash
sudo ip link set can0 type can bitrate 1000000
sudo ip link set can0 up
sudo ip link set can1 type can bitrate 1000000
sudo ip link set can1 up
```

Confirm which channel belongs to each physical arm. The optional `expected_adapter_serial` field binds each arm to its USB adapter and rejects swapped Linux interface assignments. Camera names and ports are installation-specific; do not infer them from enumeration order.

## Gripper calibration

Support both arms, then use the standard calibration command with a unique robot ID:

```bash
lerobot-calibrate \
  --robot.type=bi_yam_follower \
  --robot.id=my_yam \
  --robot.left_arm.port=can0 \
  --robot.right_arm.port=can1
```

The command prompts for both grippers fully closed, then fully open. Move them gently **by hand**, release them before confirming each measurement, and stop if a mechanism resists. Calibration only requests feedback: it does not enable torque, open cameras, reset encoders, or write motor settings. Both endpoints must be stable and each stroke plausible before a new file replaces the previous calibration.

Measurements are saved in the standard robot calibration directory under the robot ID. The two gripper records store the native 16-bit MIT position counts and opening polarity. Rollout automatically loads these records when given the same `robot.id` and calibration directory. Explicit `gripper_closed_rad` / `gripper_open_rad` configuration values override saved measurements.

Policy grippers are continuous **0 = closed, 1 = open**, independently mapped for either motor polarity:

```text
policy_gripper = (motor_rad - closed_rad) / (open_rad - closed_rad)
```

Do not interpret gripper actions as percentages, binary flags, motor radians, or finger separation in meters. Recalibrate after changing a gripper or its encoder frame. Missing calibration prevents normal connection and instructs the operator to run `lerobot-calibrate`.

## Observations and actions

The exact 14-value order is:

```text
left_joint_0.pos ... left_joint_5.pos, left_gripper.pos,
right_joint_0.pos ... right_joint_5.pos, right_gripper.pos
```

Joints are **absolute radians** in the factory encoder frame. Conversion to the bus's internal degrees happens at the robot boundary. Factory joint zeros are retained; only use `joint_signs` / `joint_offsets_rad` for an explicitly verified frame conversion. End-effector actions require a separate IK pipeline. The rollout compatibility check rejects an incompatible MolmoAct2 control mode, state/action ordering, or camera configuration before connecting.

Configure cameras using ordinary LeRobot camera configs, preferably persistent `/dev/v4l/by-path/...` paths. Select RGB nodes, confirm physical camera roles, and check all streams simultaneously. For MolmoAct2 BimanualYAM, the roles are `top`, `left`, and `right`; use the checkpoint's saved processors and normalization statistics. Policy preparation and inference are covered by the [MolmoAct2 guide](molmoact2).

## Startup and control

The adapter defaults to `read_only=true`. Explicitly set `robot.read_only=false` to enable control after validating the installation. At startup, cameras must deliver frames and both arms must pass feedback, calibration, and pose checks before either is enabled. A camera first-frame timeout is retried once using a fresh connection, before opening either motor bus. A second timeout aborts startup; camera failures during control are not automatically retried. Each joint must be within `initial_tolerance_rad` (default 0.2 radians) of `initial_position_rad` (default six zeros). Optionally set each arm's `initial_gripper_position=1.0` to require open grippers. These are assertions, not automatic homing commands.

A separate servo loop per arm (default 200 Hz) supplies gravity compensation and bounded targets. Defaults are 0.3 rad/s joint target speed, 0.5 gripper strokes/s, and a 0.15 rad tracking-error bound. The gripper's proportional torque contribution is limited to 0.5 Nm; damping adds torque, so this is not a contact-force guarantee. `send_action` returns the accepted target; observations contain measured positions.

After one second without a fresh policy target, each servo holds fresh measured position instead of progressing toward an old target. Missing, malformed, or faulted motor feedback stops both workers. Disconnect disables torque. Keep the arms supported and the hardware e-stop accessible; communication or power failure can prevent software stopping from working.

This is an experimental adapter. Gravity compensation uses the standard arm/gripper inertias and excludes added camera/payload mass. There is no collision avoidance. Validate control, loading, stopping behavior, and task performance on the installation before normal use. For initial rollout testing, set `return_to_initial_position=false` to avoid an unvalidated automatic return motion.

## Communication faults

Feedback errors include the CAN interface and motor name. A motor reporting `0xD` has latched a communication-loss fault. Stop rollout, support the arms, and address the transport/control interruption before resetting motor power. The adapter never automatically clears a fault or resumes motion. Saved gripper calibration is retained across power cycles.

The bus collects queued replies even if Python was briefly descheduled past the receive timeout. This does not permit cached feedback: strict reads still reject missing, malformed, or faulted replies, and a servo read exceeding `feedback_timeout_s` stops control before another command is sent. Keep the motor firmware communication watchdog enabled.
