# Bimanual YAM

`bi_yam_follower` controls two standard YAM v1 arms with linear DM4310 grippers through LeRobot's `DamiaoMotorsBus`. No external controller or Portal server is required. Each arm has an independent servo thread; MuJoCo supplies gravity compensation from the bundled inertial model.

## Installation

```bash
uv sync --locked --extra yam
```

Each arm needs its own **classic SocketCAN channel at 1 Mbit/s**. Both arms use motor IDs 1–7 and feedback IDs 17–23. Motors 1–3 are DM4340; motors 4–7 are DM4310. Do not put both arms on one channel or enable CAN FD.

After identifying the adapters, bring up their interfaces:

```bash
sudo ip link set can0 type can bitrate 1000000
sudo ip link set can0 up
sudo ip link set can1 type can bitrate 1000000
sudo ip link set can1 up
```

USB reconnects can recreate these interfaces in the down state. Check their configuration again before rollout. Set each arm's optional `expected_adapter_serial` to reject swapped adapter assignments; interface numbering alone does not identify the physical arm.

## Calibrate the grippers

Support both arms and choose a persistent robot ID:

```bash
lerobot-calibrate \
  --robot.type=bi_yam_follower \
  --robot.id=my_yam \
  --robot.left_arm.port=can0 \
  --robot.right_arm.port=can1
```

The prompts ask for both grippers fully closed, then fully open. Move them gently by hand, release them before confirming, and stop if they resist. Calibration requests feedback only: no torque enable, cameras, encoder reset, or persistent motor writes. Stable, plausible endpoints are saved atomically in the standard robot calibration directory. Factory joint zeros remain unchanged.

Use the same `robot.id` for rollout. Explicit `gripper_closed_rad` and `gripper_open_rad` override saved endpoints. Missing calibration prevents connection. Recalibrate after changing the gripper or encoder frame.

## Observations and actions

The 14 features are ordered as follows:

```text
left_joint_0.pos ... left_joint_5.pos, left_gripper.pos,
right_joint_0.pos ... right_joint_5.pos, right_gripper.pos
```

Joints use **absolute radians** in the factory encoder frame; the adapter converts to the bus's degrees. Grippers use continuous **0 = closed, 1 = open**, for either encoder polarity:

```text
policy_gripper = (motor_rad - closed_rad) / (open_rad - closed_rad)
```

Use `joint_signs` and `joint_offsets_rad` only for verified frame conversions. End-effector actions need a separate validated IK pipeline. The rollout compatibility check rejects unsupported MolmoAct2 action/state layouts, control modes and camera keys before connecting hardware.

Configure ordinary LeRobot cameras with verified RGB device paths and physical roles. Prefer persistent `/dev/v4l/by-path/` paths. Test all streams together; on cameras affected by USB autosuspend, configure power management for those specific devices. Observations use the latest frame with a 200 ms freshness limit, allowing interpolated commands between camera exposures while rejecting stalled streams.

For [MolmoAct2 BimanualYAM](molmoact2), provide `top`, `left` and `right` views and retain the checkpoint's saved processors and normalization. The existing guided RTC backend supports background inference. See [rollout configuration](inference) for policy, camera, recording and interpolation options; changing playback FPS also changes action timing.

## Control and startup

The adapter defaults to `read_only=true`. After verifying the installation, set `--robot.read_only=false` to allow control. Before either arm is enabled, the adapter checks both arms' fresh feedback, calibration and initial poses. Cameras must produce initial frames; a first-frame timeout is retried once before opening the motor buses.

By default, each joint must be within 0.2 radians of the six-zero folded reference pose. Grippers may start anywhere within their calibrated stroke. These are assertions, not homing commands. Set an arm's `initial_position_rad=null` to accept its current valid pose, or set `initial_gripper_position` to require a particular opening. Joint limits and feedback checks always apply.

For interactive rollout, `--robot.defer_torque_enable=true` leaves torque off until `/start`. Support the arms while idle. Starting control rechecks both poses and seeds targets from fresh measured positions. Without this option, control starts at connection.

| Setting                  | Default | Meaning                                            |
| ------------------------ | ------- | -------------------------------------------------- |
| `control_frequency`      | 200 Hz  | Per-arm servo rate                                 |
| `max_joint_speed_rad_s`  | 0.3     | Joint target speed limit                           |
| `max_gripper_speed_s`    | 0.5     | Gripper target strokes per second                  |
| `max_tracking_error_rad` | 0.15    | Command offset from measured joint position        |
| `gripper_torque_limit`   | 0.5 Nm  | Proportional gripper torque cap                    |
| `feedback_timeout_s`     | 0.1 s   | Maximum motor feedback age                         |
| `command_timeout_s`      | 1 s     | Time before capturing a fixed measured hold target |

Per-arm gains and `gravity_factors` are configurable. Target speed is not measured speed: gripper damping opposes motion, and changing it affects braking and settling. The proportional torque cap does not bound total contact force. The gravity model excludes added camera/payload mass and provides no collision avoidance. Its source attribution and required MIT notice are embedded in the XML.

## Returns and faults

`/reset` returns to the pose captured at connection, including gripper openings. `--return_to_initial_position=true` also requests this return on shutdown. Before first activation, a deferred session does not command a return. Disconnect disables torque, so support the arms before ending a session.

YAM returns through its bounded servo targets and motor feedback, independently of cameras. Success requires both arms within 0.03 radians and grippers within 0.05 of the target for 0.2 seconds. `return_timeout_s` defaults to 30 seconds and can be increased. Small encoder deviations at joint boundaries are clamped within the existing feedback tolerance; larger violations reject the return. A failed return reports failure and normal shutdown still disconnects. Clear the joint-space return path; returning a gripper to its starting opening can release an object.

Missing, malformed, stale or faulted feedback stops both workers. The adapter never automatically clears motor faults or restarts the policy. A motor reporting `0xD` has latched a communication-loss fault; support the arms and resolve the interruption before resetting motor power. Keep the firmware communication watchdog enabled.

`recover_on_feedback_timeout=true` optionally permits a return after a transient freshness timeout. It requires prior control activation, stopped workers and 0.5 seconds of healthy feedback from all 14 motors with torque disabled. Missing feedback, motor faults or disable failures prohibit reactivation. A second fault aborts the return; software cannot guarantee home after communication or power loss.

To reduce Python scheduling pauses, connected YAM instances share a process-wide freeze of the preloaded heap. New objects remain collectable. If YAM created the freeze, it releases it after the last disconnect; a pre-existing freeze is extended and left for its original owner to release. Disabled GC remains untouched. This does not make Python a hard real-time controller or relax the feedback deadline.
