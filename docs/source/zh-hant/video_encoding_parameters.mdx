# 影片編碼參數[[video-encoding-parameters]]

啟用影片儲存時，LeRobot 會將每個相機串流儲存為 **MP4** 檔案，而不是每個時間步儲存一個影像檔。影片編碼會跨時間壓縮，相較於一大堆 PNG，通常能縮減資料集大小與 I/O，同時保留 MP4 這種所有播放器與載入器都支援的格式。

將影格編碼為 MP4 是一整套 FFmpeg 管線：編碼器的選擇、像素格式、GOP／關鍵影格（keyframe）、品質與速度的取捨，以及可選的額外編碼器旗標。這些設定大多可以透過 `rgb_encoder` 調整；它是一個巢狀的 `RGBEncoderConfig`（`lerobot.configs.video.RGBEncoderConfig`），會透過 PyAV 傳入。

你可以在 CLI 上以 `--dataset.rgb_encoder.<field>` 設定這些參數（例如搭配 `lerobot-record` 或 `lerobot-rollout`）。同一組設定會套用到該次執行中的每一個相機影片串流。

> [!TIP]
> 必須啟用影片儲存，`rgb_encoder` 才會有作用：
> 在 Python API 中設定 `use_videos=True`，或在 CLI 上設定 `--dataset.video=true`
> （錄製時的預設值）。若停用影片，輸入會維持為影像，`rgb_encoder`
> 也會被忽略。

關於影格**何時**寫入、何時編碼（串流或回合結束後）、佇列，以及其他頂層 `--dataset.*` 開關的細節，請參閱[串流影片編碼](./streaming_video_encoding)。編碼參數的比較與實驗，請參閱 [video-benchmark Space](https://huggingface.co/spaces/lerobot/video-benchmark)。

## 範例[[example]]

```bash
lerobot-record \
    --robot.type=so100_follower \
    --robot.port=/dev/tty.usbmodem58760431541 \
    --robot.cameras="{laptop: {type: opencv, index_or_path: 0, width: 640, height: 480, fps: 30}}" \
    --robot.id=black \
    --teleop.type=so100_leader \
    --teleop.port=/dev/tty.usbmodem58760431551 \
    --teleop.id=blue \
    --dataset.repo_id=<my_username>/<my_dataset_name> \
    --dataset.num_episodes=2 \
    --dataset.single_task="Grab the cube" \
    --dataset.streaming_encoding=true \
    --dataset.encoder_threads=2 \
    --dataset.rgb_encoder.vcodec=h264 \
    --dataset.rgb_encoder.preset=fast \
    --dataset.rgb_encoder.extra_options={"tune": "film", "profile:v": "high", "bf": 2} \
    --display_data=true
```

## 調校參數[[tuning-parameters]]

> [!WARNING]
> 預設值是為了在典型的機器人資料集上，兼顧**壓縮比**、**畫質**與**解碼／跳轉速度**而調校的。變更這些值可能同時影響錄製（CPU 負載、掉影格）與訓練（解碼吞吐量、影像品質）。
>
> 只有在你有明確的理由時才覆寫這些參數，並在採用新設定之前，先量測它對你的管線有什麼影響。

以下所有旗標在 CLI 上都要加上 `--dataset.rgb_encoder.` 前綴。

| 參數            | 型別             | 預設值        | 說明                                                                                                                                                                                                       |
| --------------- | ---------------- | ------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `vcodec`        | `str`            | `"libsvtav1"` | 影片編解碼器（codec）名稱。`"auto"` 會從固定的偏好清單中，挑選第一個可用的硬體編碼器，找不到時退回使用 `libsvtav1`。                                                                                       |
| `pix_fmt`       | `str`            | `"yuv420p"`   | 輸出的像素格式。必須是你的 FFmpeg 版本中，所選編解碼器支援的格式。                                                                                                                                         |
| `g`             | `int`            | `2`           | GOP 大小，也就是每 `g` 個影格插入一個關鍵影格。會以 FFmpeg 選項 `g` 傳入。                                                                                                                                 |
| `crf`           | `int` 或 `float` | `30`          | 抽象的品質值，會依編解碼器對應到實際參數（請參閱[對應方式](https://github.com/huggingface/lerobot/blob/main/src/lerobot/configs/video.py#L197)）。在對應關係為單調的情況下，數值越低，品質越高、輸出越大。 |
| `preset`        | `int` 或 `str`   | `12` \*       | 編碼器的速度預設組態，意義依編解碼器而定。<br/>\* 未設定且 `vcodec=libsvtav1` 時，LeRobot 預設為 `12`。                                                                                                    |
| `fast_decode`   | `int`            | `0`           | `libsvtav1`：`0–2`，透過 `svtav1-params` 傳入。<br/>`h264` / `hevc`（軟體）：若 `>0`，會設定 `tune=fastdecode`。<br/>其他編解碼器：通常不會使用。                                                          |
| `video_backend` | `str`            | `"pyav"`      | 目前影片編碼只實作了 `"pyav"`。                                                                                                                                                                            |
| `extra_options` | `dict`           | `{}`          | 額外的 FFmpeg 或編解碼器專屬選項，會在上述結構化欄位之後合併。無法覆寫那些欄位已經設定的鍵名。                                                                                                             |

## 深度串流[[depth-streams]]

深度的處理流程透過平行的 **`depth_encoder`** 區塊（`DepthEncoderConfig`）設定。它與 `RGBEncoderConfig` 共用所有欄位（`vcodec`、`pix_fmt`、`crf`……），並多了四個量化器的設定，可透過 `--dataset.depth_encoder.<field>` 設定：

```bash
lerobot-record \
    ... \
    --dataset.depth_encoder.vcodec=hevc \
    --dataset.depth_encoder.depth_min=0.05 \
    --dataset.depth_encoder.depth_max=5.0 \
    --dataset.depth_encoder.use_log=true
```

| 參數            | 型別    | 預設值                          | 說明                                                                                                             |
| --------------- | ------- | ------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| `vcodec`        | `str`   | `"hevc"`                        | HEVC Main 12（支援 12 位元、與 MP4 相容的編解碼器）。                                                            |
| `extra_options` | `dict`  | `{"x265-params": "lossless=1"}` | **深度預設為無損**（可完整還原）；`crf` 會被忽略。傳入 `extra_options={}` 並設定 `crf`，即可得到較小的有損串流。 |
| `pix_fmt`       | `str`   | `"gray12le"`                    | 用來承載量化數值的單通道 12 位元像素格式。                                                                       |
| `depth_min`     | `float` | `0.01`                          | 對應到量化值 `0` 的深度（公尺）。低於此值的深度在解碼時會被截斷。                                                |
| `depth_max`     | `float` | `10.0`                          | 對應到量化值 `4095` 的深度（公尺）。高於此值的深度在解碼時會被截斷。                                             |
| `shift`         | `float` | `3.5`                           | 對數量化時，取對數之前加上的偏移量（公尺），用來確保接近零時的數值穩定。必須滿足 `depth_min + shift > 0`。       |
| `use_log`       | `bool`  | `True`                          | 若為 `true`，會在對數空間中量化（建議用於一般的深度感測器）。設為 `false` 則改為均勻／線性量化。                 |

> [!TIP]
> 無論輸入深度的單位為何，`depth_min`、`depth_max` 與 `shift` 一律以**公尺**解讀。輸入的單位會自動偵測：整數陣列（例如直接來自 RealSense 的 `uint16` 毫米值）視為毫米，浮點數陣列則視為公尺。
> 請將 `depth_min` / `depth_max` 設定為涵蓋感測器實際的工作範圍；超出範圍的量化值會飽和，可能使邊界附近的細節消失。

深度特徵會在 `meta/info.json` 中標記為 `"is_depth_map": true`，量化器的設定（`video.depth_min`、`video.depth_max`、`video.shift`、`video.use_log`）也會一併儲存，因此載入時才能將深度**反量化回物理單位**。

### 載入時的輸出單位[[output-unit-at-load-time]]

`depth_encoder` 只影響**錄製時**的處理。深度圖在*載入*時（例如訓練期間）要反量化成什麼單位，則由讀取時的旗標 `--dataset.depth_output_unit` 另外設定：

```bash
lerobot-train \
    --dataset.repo_id=<my_username>/<my_dataset_name> \
    --dataset.depth_output_unit=m \
    --policy.type=act
```

| 參數                | 型別  | 預設值 | 說明                                                             |
| ------------------- | ----- | ------ | ---------------------------------------------------------------- |
| `depth_output_unit` | `str` | `"mm"` | 載入時深度圖反量化成的物理單位：`"mm"`（毫米）或 `"m"`（公尺）。 |

> [!TIP]
> 這純粹是解碼時的呈現方式，**不會**改變儲存的影片或其中繼資料，因此同一個資料集可以讀成 `mm` 或 `m`，不需要重新編碼。對沒有深度相機的資料集則沒有任何影響。

## 儲存在資料集的中繼資料中[[persistence-in-dataset-metadata]]

影片串流的第一個回合（episode）編碼完成後，編碼器的設定會**儲存到資料集的中繼資料**（`meta/info.json`）中，放在各個影片特徵底下，並附上從檔案本身探測到的數值。以影片特徵 `observation.images.<camera>` 為例，`info.json` 中的結構如下：

```json
{
  "features": {
    "observation.images.laptop": {
      "dtype": "video",
      "shape": [480, 640, 3],
      "info": {
        "video.height": 480,
        "video.width": 640,
        "video.codec": "h264",
        "video.pix_fmt": "yuv420p",
        "video.fps": 30,
        "video.channels": 3,
        "is_depth_map": false,
        "video.g": 2,
        "video.crf": 30,
        "video.preset": "fast",
        "video.fast_decode": 0,
        "video.video_backend": "pyav",
        "video.extra_options": { "tune": "film", "profile:v": "high", "bf": 2 }
      }
    }
  }
}
```

`info` 區塊的內容有兩個來源：

| 來源           | 取得方式                                         | 欄位                                                                                                                    |
| -------------- | ------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------- |
| **來自串流**   | 以 PyAV 從編碼後的 MP4 讀回。                    | `video.height`、`video.width`、`video.codec`、`video.pix_fmt`、`video.fps`、`video.channels`、`is_depth_map`、`audio.*` |
| **來自編碼器** | 取自 `RGBEncoderConfig` / `DepthEncoderConfig`。 | `video.g`、`video.crf`、`video.preset`、`video.fast_decode`、`video.video_backend`、`video.extra_options`               |

> [!IMPORTANT]
> 這個區塊只會在**第一個**回合時寫入**一次**，並假設資料集中的每個
> 回合都是以相同的 `rgb_encoder` 編碼。不支援在錄製途中
> 變更編碼器設定，
> `info.json` 只會反映第一個回合所使用的參數。

## 合併資料集[[merging-datasets]]

以 `merge_datasets` 合併資料集時，影片檔案會直接串接（不會重新編碼），`info.json` 中的編碼器欄位則會逐鍵合併：

| 合併規則     | 欄位                                                                               | 行為                                                                                                                             |
| ------------ | ---------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| **必須一致** | `video.codec`、`video.pix_fmt`、`video.height`、`video.width`、`video.fps`         | 來自串流的欄位在所有來源中都必須一致，否則 FFmpeg 的 concat demuxer 會失敗。                                                     |
| **寬鬆合併** | `video.g`、`video.crf`、`video.preset`、`video.fast_decode`、`video.extra_options` | 編碼器調校相關的欄位。若所有來源都一致，就保留該值；若不一致，則設為 `null`（`video.extra_options` 則為 `{}`），並記錄一則警告。 |
