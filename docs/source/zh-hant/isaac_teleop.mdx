# Isaac Teleop[[isaac-teleop]]

使用 NVIDIA [Isaac Teleop](https://github.com/NVIDIA/IsaacTeleop) 控制你的機器人。這是一個
多模態的遙操作框架，可以用各種輸入裝置驅動同一個 `TeleopSession`：
XR（VR）控制器、手部追蹤、全身追蹤、Manus 手套、腳踏板
等。

在 LeRobot 中，Isaac Teleop 以一個獨立完整的範例提供，位於
[`examples/isaac_teleop_to_so101/`](https://github.com/huggingface/lerobot/tree/main/examples/isaac_teleop_to_so101)。
每一種 Isaac Teleop 輸入裝置，在範例的 `isaac_teleop` 套件中
都是各自的 `Teleoperator` 子類別，共用同一套工作階段生命週期（見 `IsaacTeleopTeleoperator`）。
目前可用的裝置有 **XR 控制器**（`XRController`），以及可反向驅動（back-drivable）的
**SO-101 主臂**（`SO101LeaderArm`）；Manus 手套與手部／全身追蹤則是
接下來自然會支援的裝置。本指南聚焦在 XR 控制器；SO-101 主臂的用法則簡述於
[執行範例](#step-3-run-the-example)中。

**在本指南中，你將學到：**

- Isaac Teleop 裝置如何驅動機器人末端執行器（end effector，EE）的目標
- _離合器_（clutch，XR 控制器上的握把按壓）如何在手臂不突然跳動的情況下啟動遙操作
- 如何執行 SO‑101 遙操作範例，並調校動作／夾爪／IK

## 安裝[[installation]]

這個範例位於 LeRobot 儲存庫中（不屬於 `lerobot` pip 套件），因此
請 clone 儲存庫並從原始碼安裝。最權威、隨時保持最新的安裝與使用
說明，請見範例的
[`README.md`](https://github.com/huggingface/lerobot/tree/main/examples/isaac_teleop_to_so101/README.md)；
簡單來說：

```bash
git clone https://github.com/huggingface/lerobot.git
cd lerobot
uv pip install -e ".[feetech,kinematics,dataset]" "huggingface_hub>=1.5"
uv pip install "isaacteleop[cloudxr,retargeters-lite]~=1.3.131" "scipy>=1.14"
```

`isaacteleop` 已發布在公開的 PyPI 上（僅限 Linux）。`cloudxr` 額外套件提供 CloudXR
執行環境的綁定；`retargeters-lite` 是以 scipy 為基礎的重定向器（retargeter），在
x86_64 與 ARM 上都能安裝（在 aarch64 上，例如 DGX Spark，完整的 `retargeters` 額外套件
會因為 `dex-retargeting`/`nlopt` 的版本固定而無法安裝，所以這裡不以它為預設）。在
x86_64 上，你還可以另外安裝完整的重定向器套件：

```bash
uv pip install "isaacteleop[retargeters]~=1.3.131"
```

### 設定 CloudXR 並連接頭戴式裝置[[set-up-cloudxr-and-connect-a-headset]]

Isaac Teleop 透過 **NVIDIA CloudXR** 將頭戴式裝置串流到你的電腦，CloudXR 提供了
工作階段所連接的 OpenXR 執行環境。預設情況下，呼叫 `teleop_device.connect()` 時，
LeTeleop **會自動幫你啟動 CloudXR 執行環境**，你不必再另外開一個 shell 執行 `python -m
isaacteleop.cloudxr` 與 `source cloudxr.env`。你只需要連接支援的
頭戴式裝置，並開放 CloudXR 的防火牆連接埠。頭戴式裝置的配對與防火牆細節，請參閱 Isaac Teleop 的
[快速開始](https://nvidia.github.io/IsaacTeleop/main/getting_started/quick_start.html)
說明。

**第一次執行（EULA）。** 第一次啟動時必須接受 NVIDIA CloudXR 的 EULA。自動啟動會
**透過 stdin** 詢問，因此在沒有顯示器的機器上，它會卡住等待輸入。請先以互動方式
執行一次以下指令，接受 EULA：

```bash
python -m isaacteleop.cloudxr --accept-eula   # 只需執行一次：接受 CloudXR EULA
```

之後，`connect()` 就會以非互動的方式啟動執行環境。啟動時**會阻塞約 30 秒**，
直到執行環境就緒。

**設定。** `IsaacTeleopConfig`（所有裝置共用）中有兩個欄位控制這項行為：

- `auto_launch_cloudxr`（預設 `True`）：`connect()` 是否要啟動執行環境。如果 CloudXR
  已經在外部執行，請設為 `False`。
- `cloudxr_env_file`（預設 `None`）：可選的 CloudXR 裝置設定檔 `.env`，用來選擇
  頭戴式裝置的傳輸方式（例如 Apple Vision Pro 的設定檔）。這是啟動器的**輸入**，而不是
  舊的手動流程要你 `source` 的 `~/.cloudxr/run/cloudxr.env` **輸出**檔。`None`
  會維持預設的 auto-WebRTC 設定檔；不過除非你傳入 `--teleop.cloudxr_env_file`，
  否則 SO-101 範例會改用與 `teleoperate.py` 放在一起的 `default.env`。

**不使用自動啟動。** 若要略過自動啟動（CloudXR 已經在執行），可以設定
`auto_launch_cloudxr=False`，或匯出環境變數：

```bash
export LEROBOT_CLOUDXR_SKIP_AUTOLAUNCH=1
```

**環境變數的優先順序高於設定欄位**：只要設定了 `LEROBOT_CLOUDXR_SKIP_AUTOLAUNCH=1`，
即使 `auto_launch_cloudxr=True` 也會略過自動啟動。這個變數與 Isaac Lab 的
`ISAACLAB_CXR_SKIP_AUTOLAUNCH` **彼此獨立**，設定其中一個不會影響
另一個。

**每個行程（process）只能有一個遙操作器。** CloudXR 執行環境會以整個行程為範圍設定環境（單例），
因此每個行程只能執行一個 Isaac Teleop 遙操作器。

**結束程式。** 結束時務必呼叫 `teleop_device.disconnect()`，按下 Ctrl-C 時也一樣。請將
遙操作迴圈包在 `try/finally` 中，並在 `finally` 裡呼叫 `disconnect()`。這樣會先關閉
OpenXR 工作階段，**再**關閉 CloudXR 執行環境，這是必要的順序；啟動器的
`atexit` hook 只會回收執行環境，不會執行工作階段的 `__exit__`，因此如果沒有明確呼叫
`disconnect()`，被中斷的執行就會以錯誤的順序關閉。

```python
teleop_device.connect()
try:
    while True:
        action = teleop_device.get_action()
        # ……操控機器人……
finally:
    teleop_device.disconnect()
```

支援的作業系統、GPU、CloudXR 版本與頭戴式裝置，請參閱
[系統需求](https://nvidia.github.io/IsaacTeleop/main/references/requirements.html)。

## 運作方式[[how-it-works]]

XR 控制器是 Isaac Teleop 的一種**輸入**裝置。`XRController` 刻意設計成只負責讀取：
它提供**原始的**控制器握把姿態（已經以靜態方式轉換到機器人
基座座標系），以及握把按壓與扳機的類比值。它本身**沒有**重定向器，也**沒有**
離合器的邏輯。離合器（啟動時鎖定原點，並將增量轉換到 EE 上）與夾爪的
對應，都放在下游的範例迴圈中，迴圈再將結果送入 LeRobot 既有的閉迴路
笛卡兒 IK 管線，也就是手機遙操作器所用的同一套。裝置專屬的部分只有
`XRController`、迴圈中的 `Clutch`，以及 `MapXRControllerActionToRobotAction`；下游的其他部分
（`EEBoundsAndSafety`、`InverseKinematicsEEToJoints`）都是共用的，未來的新裝置（例如 Manus
手套）只需要換上自己的 `teleop_<device>.py` 與處理器，其餘都可以沿用。

`XRController._build_pipeline` 會接上 Isaac Teleop 的 `ControllersSource`，並透過原生的
`ControllerTransform`（`base_T_anchor`）以靜態方式轉換到機器人基座座標系，再原封不動地提供
轉換後的控制器串流。`get_action()` 會直接從中讀取握把姿態、按壓值與扳機值；
工作階段一律以 `RUNNING` 推進（因為沒有需要把關的離合器重定向器）。

`Clutch` 類別（位於 `examples/isaac_teleop_to_so101/isaac_teleop/clutch.py`，由
`common.py` 中的迴圈驅動）仿照 Isaac Teleop 的 `SO101ClutchRetargeter`，但放在迴圈中，讓
裝置可以維持只負責讀取的角色：

- 它會在握把按壓的**啟動瞬間**（按壓值第一次超過 `clutch_threshold` 的影格）鎖定啟動原點，
  並以它為基準轉換位置與方向，因此啟動時手臂不會突然
  瞬移。`Clutch.rebase` 會以 `(pos, quat)` 的形式回傳基座座標系中的絕對目標，
  迴圈再將它串接成 7D 的 `ee_pose`，送入處理器。
- 類比扳機會轉換為 `[0, 1]` 之間的夾爪閉合度 `closedness`（0 = 張開，1 = 閉合），
  與扳機按下的程度成正比，`MapXRControllerActionToRobotAction` 再將它對應到夾爪的目標開合。

請參閱 Isaac Teleop 的
[重定向介面](https://nvidia.github.io/IsaacTeleop/main/references/retargeting/index.html)
與[架構概覽](https://nvidia.github.io/IsaacTeleop/main/overview/architecture.html)，
了解來源節點與重定向器如何組合。

```text
  VR controller (OpenXR)
        │
        ▼
  XRController.get_action()          ── raw base-frame grip_pos / grip_quat + squeeze + trigger
        │                                (TeleopSession always stepped RUNNING; clutch lives downstream)
        ▼
  Clutch.rebase(grip_pos, grip_quat) ── engage-relative delta applied to the EE home (pos + orient)
        │  ee_pose (7) / closedness       → absolute ee_pose; closedness = trigger
        ▼
  MapXRControllerActionToRobotAction ── absolute ee.x/y/z; ee.w* = orientation rotvec target;
        │  ee.x/y/z / ee.w* / ee.gripper_pos   ee.gripper_pos = (1 - closedness) * 100
        ▼
  EEBoundsAndSafety                ── workspace clip + per-frame step clamp (clamp+warn)
        │
        ▼
  InverseKinematicsEEToJoints      ── closed-loop Placo IK; position + soft-orientation
        │  (orientation_weight=0.01)   (passes ee.gripper_pos → gripper.pos)
        ▼
  SO-101 follower joint targets
```

### 離合器：由範例迴圈負責[[the-clutch-owned-by-the-example-loop]]

手機的管線會把離合器的功能分散在 `MapPhoneActionToRobotAction` 與
`EEReferenceAndDelta` 中；XR 的離合器則完全放在範例迴圈的 `Clutch` 類別裡。它輸出的是
**絕對的** EE 姿態，因此處理器中沒有 `EEReferenceAndDelta` 階段，也不會累積增量；
`MapXRControllerActionToRobotAction` 是單純、沒有狀態、逐影格的對應。

離合器會在握把按壓的**啟動瞬間**（按壓值超過 `clutch_threshold` 的那一刻）鎖定啟動原點，
並以*相對於*原點的移動驅動 EE，因此啟動時手臂不會
瞬移。**每次**啟動時，無論是開始時或任務途中重新按下離合器，起始
*位置*都會根據手臂**量測到的關節**以正向運動學計算並鎖定，因此即使手臂在離合器放開時移動過，
起始位置也等於手臂實際所在的位置，啟動時就不會跳動。起始
*方向*則保留最後一次命令的旋轉：5 自由度的手臂只會柔性地追蹤方向，
因此如果鎖定量測到的腕部方向，每次重新按下離合器時，都會把追蹤誤差
帶進命令中。

## 操作方式[[controls]]

- **握把按壓**：**離合器**（安全開關）。按壓超過 `clutch_threshold` 即可啟動
  遙操作，放開則暫停。每次啟動都會重新擷取原點，因此你可以在暫停時移動手的位置，
  再重新啟動，手臂也不會跳動（類似滑鼠拿起再放下的操作方式）。
- **扳機**：**夾爪**，以**類比**方式控制。夾爪會依扳機按下的程度
  成比例開合（扳機按一半，夾爪就閉合一半），透過 `[0, 1]` 之間的閉合度
  （0 = 張開，1 = 閉合）對應到絕對的夾爪關節目標。
- **控制器方向**：**腕部**。離合器會將控制器的方向
  （相對於啟動時、基座座標系）轉換為柔性的 IK 方向目標，讓腕部在追蹤位置的同時跟著轉動。
  在 5 自由度的 SO‑101 上，腕部依設計只會部分跟隨手的方向，詳見下方的
  `orientation_weight`。

## 開始使用[[get-started]]

### 步驟 1：建立遙操作器[[step-1-create-the-teleoperator]]

```python
# 從儲存庫根目錄執行，讓 `examples` 套件可以匯入。
from examples.isaac_teleop_to_so101.isaac_teleop import XRController, XRControllerConfig

teleop_config = XRControllerConfig(
    hand_side="right",      # "left" 或 "right" 控制器
    clutch_threshold=0.5,   # 握把按壓值超過此門檻時，離合器會啟動
)
teleop_device = XRController(teleop_config)
```

`XRController.get_action()` 回傳的是基座座標系中**原始的**控制器姿態，而不是經過離合器轉換的
目標：機器人基座座標系中的 `grip_pos`（3,）`[x, y, z]` [m] 與 `grip_quat`（4,）`[qx, qy, qz, qw]`，
以及 `[0, 1]` 之間的純量類比值 `squeeze` 與 `trigger`。範例迴圈的 `Clutch`
會將它們轉換為絕對的 `ee_pose`，迴圈也會以
`clutch_threshold` 判斷握把按壓是否達到啟動門檻。

### 步驟 2：連線[[step-2-connect]]

呼叫 `teleop_device.connect()` 時，會先自動啟動 CloudXR 執行環境（除非你選擇不使用，
請見[設定 CloudXR 並連接頭戴式裝置](#set-up-cloudxr-and-connect-a-headset)；這會阻塞約
30 秒，第一次執行時還會透過 stdin 詢問是否接受 EULA），接著啟動 Isaac Teleop 的
[`TeleopSession`](https://nvidia.github.io/IsaacTeleop/main/getting_started/teleop_session.html)
（開啟 OpenXR 工作階段並偵測控制器）。XR 控制器會自行校正，因此
不需要手動校正，每次啟動時離合器都會重新對準中心。請將
`connect()` 搭配會呼叫 `disconnect()` 的 `try/finally`，讓結束或按下 Ctrl-C 時，
工作階段會在執行環境之前先關閉。

### 步驟 3：執行範例[[step-3-run-the-example]]

這個範例假設你已經設定好機器人（SO‑101 從臂），並設定了正確的序列埠。

第一次執行時，**機器人的 URDF 與網格檔會自動下載**：XR 裝置會從
以下位置下載 SO-101 的 URDF：
[`lerobot/robot-urdfs` Hugging Face bucket](https://huggingface.co/buckets/lerobot/robot-urdfs/tree/so101)，
存放到 LeRobot 快取（`HF_LEROBOT_HOME/robot-urdfs/so101/`）中，之後會直接沿用，因此不需要
另外下載：

```bash
python -m examples.isaac_teleop_to_so101.teleoperate --robot.type=so101_follower --robot.port=/dev/ttyACM0 \
    --robot.id=so101_follower_arm --teleop.type=xr_controller
```

CLI 的風格與 `lerobot-teleoperate` 相同（draccus）：`--robot.*` 設定 SO-101 從臂，
`--teleop.type` 選擇 Isaac 的輸入裝置（`xr_controller` | `so101_leader`），
`--teleop.*` 則是裝置的各項設定。`--teleop.type=xr_controller` 會執行上面說明的 XR 控制器流程。
啟動時的安全機制：預設會在 `--reset_duration` 秒內，將所有關節平順地移動到預設的重設姿態
（`--reset_to_origin=false` 則讓手臂停在原處），接著以手臂量測到的姿態作為離合器的起始位置，
讓第一次啟動不會跳動；只有在離合器啟動時，才會對從臂下達
命令。

**自訂重設姿態。** 重設姿態有內建的預設值（一個舒適的中間姿態），直接就能使用，
**不需要**另外錄製任何東西。若要依你的環境調整，
請用手將手臂推到想要的姿態，然後執行
`python -m examples.isaac_teleop_to_so101.override_reset_pose --id <robot.id>`；它會將
目前的關節位置寫入 LeRobot 快取中每支手臂各自的檔案
（`HF_LEROBOT_HOME/reset_poses/<robot.name>/<robot.id>.json`，命名方式與校正檔相同），下次執行時
就會優先於內建的預設值。由於它存放在使用者本機的快取中（而不是
儲存庫），你的覆寫設定只會留在你的電腦上；只要以相同的 `--robot.id` 啟動，
`teleoperate` 與 `record` 都會套用它。

另一種裝置 `--teleop.type=so101_leader`，會讓從臂 1:1 跟隨一支可反向驅動的
SO-101 _主臂_，主臂的關節由 Isaac Teleop 原生的 `so101_leader` 外掛串流（不使用
離合器，也不使用 IK，因為主臂與從臂的 SO-101 運動學相同）。

`so101_leader_plugin` 執行檔是 C++ 外掛，**不**包含在 `isaacteleop` pip
套件中，必須從 Isaac Teleop 的原始碼建置。請依照
[從原始碼建置 Isaac Teleop](https://nvidia.github.io/IsaacTeleop/main/getting_started/build_from_source/index.html)
操作（簡單來說，在 Isaac Teleop 的 checkout 中執行：`cmake -B build && cmake --build build --parallel &&
cmake --install build`）；建置完成後，外掛會安裝在 `<IsaacTeleop>/install/plugins/` 底下，因此
執行檔會位於 `install/plugins/so101_leader/so101_leader_plugin`，也就是下方 `--launch_plugin` 的路徑。
序列埠與校正的細節，請參閱外掛本身的 `README.md`（與執行檔放在一起）。

將 `--teleop.port` 指向實體主臂的序列埠，並將 `--launch_plugin` 指向這個外掛的
執行檔，腳本就會在 CloudXR 啟動後執行它：

```bash
python -m examples.isaac_teleop_to_so101.teleoperate --robot.type=so101_follower --robot.port=/dev/ttyACM0 \
    --robot.id=so101_follower_arm --teleop.type=so101_leader \
    --teleop.port=/dev/ttyACM1 --teleop.id=so101_leader_arm \
    --launch_plugin=/code/Teleop/install/plugins/so101_leader/so101_leader_plugin
```

（請注意，這裡的 `so101_leader` 是 _Isaac_ 的主臂，會從 Isaac Teleop 的裝置
登錄表中解析，與 `lerobot-teleoperate` 中以序列埠連接的 `so101_leader` 不同。）設定了
`--teleop.port` 時，外掛的 tick→radian 校正會依 `--teleop.id` 推得，並作為外掛的
第三個位置引數傳入，也就是位於
`HF_LEROBOT_CALIBRATION/teleoperators/so_leader/<id>.json` 的 LeRobot 格式 JSON，與以序列埠連接的 SO-101 主臂
使用同一個檔案（`lerobot-calibrate --teleop.type=so101_leader --teleop.id=<id>`）。如果檔案不存在，腳本
會發出警告，外掛則使用內建的預設值。執行 `python -m examples.isaac_teleop_to_so101.teleoperate --help` 可查看所有旗標。它
啟動時的安全機制：預設會在 `--align_duration` 秒內，
將從臂平順地移動到主臂的第一筆讀數（`--align=false` 可略過），
讓手臂在開始跟隨時不會猛然跳動；當主臂的串流資料過期時，從臂會
維持在量測到的姿態。

下載 URDF 時，會使用 `huggingface_hub`（LeRobot 已有的相依套件）存取公開的
`lerobot/robot-urdfs` bucket，因此不需要登入。檔案會快取在
`HF_LEROBOT_HOME/robot-urdfs/so101/`；刪除這個資料夾即可強制重新下載。

接著在頭戴式裝置中：按住握把即可啟動，移動控制器來驅動手臂，
轉動或傾斜控制器來調整腕部方向，按下扳機則會閉合夾爪
（依按下的程度成比例閉合，放開即張開）。

若要錄製資料集（而不只是遙操作），請使用同一個資料夾中的 `record.py`。它和 `teleoperate.py` 一樣，
會依 `--teleop.type`（`xr_controller` | `so101_leader`）選擇裝置，因此兩種裝置都能
驅動從臂，並將命令的關節位置儲存為 LeRobot 資料集（使用與 `lerobot-record` 相同的
`--dataset.*` 旗標）。完整的 CLI 與錄製用的鍵盤快捷鍵，請參閱它的模組 docstring。

## 重要的管線步驟與選項[[important-pipeline-steps-and-options]]

離合器已經產生基座座標系中的絕對姿態，因此處理器這一端只是一條精簡的
**絕對姿態**路徑：沒有座標系轉換、沒有增量累積，也沒有
`EEReferenceAndDelta` 階段。

- `MapXRControllerActionToRobotAction` 是從裝置輸出到 IK 輸入契約、沒有狀態的逐影格
  對應。它會寫入基座座標系中的絕對位置，將絕對方向編碼為 rotvec 目標，
  並將閉合度反轉為馬達的夾爪目標：

  ```python
  action["ee.x"], action["ee.y"], action["ee.z"] = ee_pose[:3]   # 絕對值，基座座標系 [m]
  action["ee.wx"], action["ee.wy"], action["ee.wz"] = orient_rotvec  # 方向目標（rotvec）
  action["ee.gripper_pos"] = (1 - closedness) * 100   # 馬達單位；SO-101 校正後 100 = 張開
  ```

  夾爪的方向（`100 = 張開，0 = 閉合`）是原始碼中依硬體校正而定的慣例；如果夾爪該閉合時反而張開，請在原始碼中將它反轉。

- `EEBoundsAndSafety` 會將 EE 限制在工作空間內，並限制每個影格的跳動速率。由於離合器
  不會讓手臂瞬移，每個影格的變化都很小，所以 `max_ee_step_m` 主要是用來攔截控制器追蹤時的
  短暫異常。z 的下限為 `0.0`（桌面），避免異常的目標讓 EE 低於
  桌面；x/y 則維持寬鬆的 `[-1, 1]` m 範圍。請設定 `raise_on_jump=False`，讓超過限制的影格
  被**截斷並發出警告**，而不是拋出例外，因為迴圈中途當機會讓手臂失去控制：

  ```python
  EEBoundsAndSafety(
      end_effector_bounds={"min": [-1.0, -1.0, 0.0], "max": [1.0, 1.0, 1.0]},
      max_ee_step_m=0.10,
      raise_on_jump=False,
  )
  ```

- `InverseKinematicsEEToJoints(initial_guess_current_joints=False, orientation_weight=0.01)` 會求解
  閉迴路的 Placo IK。SO‑101 是 5 自由度的手臂，因此 IK 以位置為主；較小的
  `orientation_weight` 讓它能柔性地追蹤 `ee.w*` 中的方向目標，使腕部跟著手轉動，
  而自由度不足的滾轉依設計只會部分跟隨。這裡**沒有**
  `GripperVelocityToJoint`：絕對的 `ee.gripper_pos` 會直接傳給 `gripper.pos`。
  `initial_guess_current_joints=False` 會以**前一次的 IK 解**作為每次求解的起點，
  而不是從量測到的關節重新開始，因此關節軌跡在影格之間
  能保持連續。請在實機上調整 `orientation_weight`：太高會干擾位置追蹤，太
  低則會忽略方向命令。

範例也在迴圈層級把關安全：啟動時的重設移動（預設開啟，
傳入 `--reset_to_origin=false` 則讓手臂停在原處）完成後，**只有在離合器啟動時**
才會對機器人下達命令；離合器放開時，會重新送出量測到的關節位置，因此放開
離合器時，手臂會停在原地。

若要將管線調整為適用於其他機器人，請參閱[機器人與遙操作器的處理器](./processors_robots_teleop)
指南。

## 疑難排解[[troubleshooting]]

- **`ModuleNotFoundError: isaacteleop`**：目前的環境沒有安裝 `isaacteleop` 套件。
  請重新執行本指南開頭的安裝指令：
  `uv pip install "isaacteleop[cloudxr,retargeters-lite]~=1.3.131"`。
- **找不到控制器**：請確認 CloudXR 執行環境正在執行、防火牆連接埠已加入
  允許清單，且頭戴式裝置已連接（請參閱
  [設定 CloudXR 並連接頭戴式裝置](#set-up-cloudxr-and-connect-a-headset)與 Isaac
  Teleop 的[快速開始](https://nvidia.github.io/IsaacTeleop/main/getting_started/quick_start.html)）。
- **CloudXR 自動啟動失敗**：如果執行環境沒有在啟動逾時內就緒，`connect()` 會拋出
  `RuntimeError`。請檢查 `~/.cloudxr/logs` 底下的啟動器記錄。常見的
  原因：從未接受 EULA（請以互動方式執行一次 `python -m isaacteleop.cloudxr --accept-eula`，
  因為自動啟動會透過 stdin 詢問，在沒有顯示器的環境下會卡住），或執行環境已經
  在外部執行（請設定 `LEROBOT_CLOUDXR_SKIP_AUTOLAUNCH=1` 或 `auto_launch_cloudxr=False`
  略過自動啟動）。
- **手臂沒有動作**：離合器是安全開關，你必須按住握把，且按壓超過
  `clutch_threshold`。如果你的控制器回報的按壓值偏低，請調低這個門檻。
- **動作方向感覺不對**：請確認頭戴式裝置與遊玩空間的方向。控制器串流
  會由 `XRControllerConfig` 中的 `base_T_anchor` 轉換到機器人基座座標系
  （預設：標準的 OpenXR → 機器人座標軸慣例）；如果你的錨點座標系不同，請調整它。
