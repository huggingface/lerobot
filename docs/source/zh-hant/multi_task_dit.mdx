# 多任務 DiT 策略[[multitask-dit-policy]]

多任務擴散 Transformer（Multitask Diffusion Transformer，DiT）策略（policy）是原始 Diffusion Policy 架構的進化版，利用一個大型 DiT，以文字與視覺為條件進行多任務的機器人學習。這個實作支援以擴散與流匹配（flow matching）兩種目標函數生成動作（action），讓機器人能依據語言指令執行多樣的操作任務。

## 模型概覽[[model-overview]]

這個模型使用：

- **CLIP 視覺編碼器**：處理來自多個相機視角的 RGB 影像
- **CLIP 文字編碼器**：編碼語言任務指令（權重凍結，搭配可學習的投影層）
- **Diffusion Transformer**：以觀測（observation）與語言為條件，預測動作序列
- **兩種目標函數**：支援以擴散（DDPM/DDIM）與流匹配兩種方式生成動作

這個模型令人振奮之處在於：只要約 4.5 億個參數，就能達到極高的靈巧度，
表現足以和數十億參數的 VLA 匹敵，所需的訓練量也少得多。

## 安裝需求[[installation-requirements]]

多任務 DiT 策略需要額外的相依套件。請使用以下指令安裝：

```bash
pip install lerobot[multi_task_dit]
```

這會安裝所有必要的相依套件，包括 CLIP 模型所需的 HuggingFace Transformers 函式庫。

## 使用方式[[usage]]

若要在 LeRobot 設定中使用多任務 DiT，請將策略類型指定為：

```python
policy.type=multi_task_dit
```

## 訓練[[training]]

### 基本訓練指令[[basic-training-command]]

以下是在你的資料集上訓練多任務 DiT 的完整指令：

```bash
lerobot-train \
  --dataset.repo_id=YOUR_DATASET \
  --output_dir=./outputs/multitask_dit_training \
  --batch_size=32 \
  --steps=5000 \
  --save_freq=500 \
  --log_freq=100 \
  --policy.type=multi_task_dit \
  --policy.device=cuda \
  --policy.repo_id="HF_USER/multitask-dit-your-robot" \
  --wandb.enable=true
```

### 建議的超參數與資料集細節（30 Hz 控制頻率）[[recommended-hyperparameters-and-dataset-details-30hz-control-frequency]]

為了取得穩定的效能，建議先從以下預設超參數開始：

```bash
lerobot-train \
  --dataset.repo_id=YOUR_DATASET \
  --output_dir=./outputs/mutitask_dit_training \
  --batch_size=320 \
  --steps=30000 \
  --policy.type=multi_task_dit \
  --policy.device=cuda \
  --policy.horizon=32 \
  --policy.n_action_steps=24 \
  --policy.objective=diffusion \
  --policy.noise_scheduler_type=DDPM \
  --policy.num_train_timesteps=100 \
  --policy.repo_id="HF_USER/multitask-dit-your-robot" \
  --wandb.enable=true
```

**主要參數：**

- **批次大小**：192-320——如果你的 GPU 能夠負荷，訓練效果會最好
- **Horizon**：32——要預測的動作步數，在 30 Hz 下約為 1.0 秒
- **n_action_steps**：24——在 30 Hz 下約為 0.8 秒
- **目標函數**：`diffusion`——建議先從擴散開始，若生成品質不佳再嘗試流匹配
- **訓練步數**：單一任務建議超過 30k 步

### 訓練設定參數[[training-configuration-parameters]]

#### 目標函數選擇[[objective-selection]]

在擴散與流匹配之間擇一：

```bash
# 擴散目標函數（預設）
--policy.objective=diffusion \
--policy.noise_scheduler_type=DDPM \  # 或 "DDIM"
--policy.num_train_timesteps=100 \
--policy.num_inference_steps=10 \  # 加速推論
--policy.beta_schedule=squaredcos_cap_v2 \  # 雜訊排程類型
--policy.prediction_type=epsilon \  # "epsilon"（預測雜訊）或 "sample"（預測乾淨樣本）
--policy.clip_sample=true \  # 在去雜訊過程中裁切樣本
--policy.clip_sample_range=1.0  # 裁切範圍 [-x, x]

# 流匹配目標函數
--policy.objective=flow_matching \
--policy.timestep_sampling_strategy=beta \  # 或 "uniform" | 實務上 beta 取樣明顯表現更好
--policy.num_integration_steps=100 \
--policy.integration_method=euler \  # 或 "rk4"
--policy.sigma_min=0.0  # 流插值路徑中的最小雜訊
```

#### Transformer 架構[[transformer-architecture]]

依資料集大小調整模型容量：

```bash
# 小型資料集（< 100 個範例）
--policy.num_layers=4 \
--policy.hidden_dim=512 \
--policy.num_heads=8  # 理想情況下應為 hidden_dim // 64

# 中型資料集（100-5k 個範例）- 預設值
--policy.num_layers=6 \
--policy.hidden_dim=512 \
--policy.num_heads=8  # 理想情況下應為 hidden_dim // 64

# 大型資料集（> 5k 個範例）
--policy.num_layers=8 \
--policy.hidden_dim=512 \
--policy.num_heads=8   # 理想情況下應為 hidden_dim // 64
```

**位置編碼選項：**

模型支援兩種動作序列的位置編碼方式：

```bash
# 旋轉位置嵌入（Rotary Position Embedding, RoPE）- 預設，建議使用
--policy.use_rope=true \
--policy.rope_base=10000.0  # RoPE 的基礎頻率

# 絕對位置編碼
--policy.use_positional_encoding=true  # 設為 true 時停用 RoPE
```

**其他 Transformer 參數：**

```bash
--policy.dropout=0.1  # DiT 區塊的 dropout 率（0.0-1.0）
--policy.timestep_embed_dim=256  # 時間步嵌入維度
```

#### 視覺編碼器設定[[vision-encoder-configuration]]

```bash
# 使用不同的 CLIP 模型以獲得更強的表達力，但會犧牲推論速度
# 根據任務複雜度與資料集大小，嘗試使用更大或更小的模型
--policy.vision_encoder_name=openai/clip-vit-large-patch14

# 為每個相機使用獨立的視覺編碼器
# 當相機特性差異顯著時可能有用，
# 但請注意 VRAM 佔用會增加
--policy.use_separate_rgb_encoder_per_camera=true

# 影像前處理
--policy.image_resize_shape=[XXX,YYY] \ # 你可能需要調整影像大小以加速推論
--policy.image_crop_shape=[224,224] \
--policy.image_crop_is_random=true  # 訓練時隨機裁切，推論時中心裁切
```

#### 文字編碼器設定[[text-encoder-configuration]]

```bash
# 使用不同的 CLIP 文字編碼器模型
# 與視覺編碼器相同：根據任務複雜度與資料集大小
# 嘗試使用更大或更小的模型
--policy.text_encoder_name=openai/clip-vit-large-patch14
```

#### 學習率設定[[learning-rate-configuration]]

視覺編碼器使用獨立的學習率倍率，建議以 1/10 作為理想的起點：

```bash
--policy.optimizer_lr=2e-5 \
--policy.vision_encoder_lr_multiplier=0.1  # 視覺編碼器學習率 = 0.1 * optimizer_lr
```

### 訓練調校指南[[training-tuning-guidelines]]

#### 1. 搭配 Beta 取樣的流匹配[[1-flow-matching-with-beta-sampling]]

這裡原始的擴散實作，是根據 [TRI 的 LBM 論文](https://arxiv.org/abs/2507.05331)中描述的方法。

此外，我們也實作了流匹配的目標函數，其概念在 [Boston Dynamics 的部落格文章](https://bostondynamics.com/blog/large-behavior-models-atlas-find-new-footing/)中有概略說明。

建議嘗試流匹配的目標函數，並評估它在你的任務上的效能差異：

```bash
--policy.objective=flow_matching \
--policy.timestep_sampling_strategy=beta \
--policy.timestep_sampling_alpha=1.5 \
--policy.timestep_sampling_beta=1.0 \
--policy.timestep_sampling_s=0.999
```

這並不是適用於所有情況的萬靈丹，但有時確實能讓動作更流暢、更一致。

#### 2. Transformer 層數[[2-number-of-transformer-layers]]

依你的資料集大小調整模型容量：

- **小型資料集**（< 100 個範例）：減少為 4 層
- **大型資料集**（> 5k 個範例）：增加為 8 層

#### 3. `horizon` 調校[[3-horizon-tuning]]

模型可能對你選擇的時域（horizon）相當敏感。建議依你的控制頻率，從約 1 秒的時域開始：

- **30 Hz 頻率**：`horizon=30`
- **10 Hz 頻率**：`horizon=10`

接著再從這個基礎往上增加。時域決定了模型會預測多遠之後的動作。

#### 4. `n_action_steps` 敏感度[[4-nactionsteps-sensitivity]]

模型對 `n_action_steps` 也可能非常敏感。建議依你的控制頻率，從約 0.8 秒開始調整：

- **數值較低**：反應更靈敏，但在長時程（long-horizon）任務上可能較不穩定
- **數值較高**：較適合長時程的執行，但開迴路執行時出錯，較難回復

### 推論調校[[inference-tuning]]

若要加速推論，請使用 DDIM 並減少取樣步數：

```bash
--policy.noise_scheduler_type=DDIM \
--policy.num_inference_steps=10
```

### 接續訓練[[resuming-training]]

從檢查點（checkpoint）接續（resume）訓練：

```bash
lerobot-train \
  --config_path=./outputs/mutitask_dit_training/checkpoints/last/pretrained_model/train_config.json \
  --resume=true
```

檢查點目錄中應包含 `model.safetensors` 與 `config.json` 檔案（訓練時會自動儲存）。接續訓練時，設定會從檢查點載入，因此不需要再指定其他參數。

## 常見失敗模式與除錯[[common-failure-modes-and-debugging]]

這類模型的訓練可能相當棘手。以下是常見的失敗模式與除錯方法：

### 靜止不動／無動作[[idling-no-motion]]

模型在推論時可能會「崩潰」，導致完全靜止、沒有任何動作。可能的原因包括：

1. **訓練資料不足**：如果你只有 20-50 個範例，請試著把資料集擴大到約兩倍。若超過 300 個範例後仍然出現這個問題，可能是任務太過複雜。

2. **多個相似的任務**：當資料集中有多個相似的任務（例如抓取 2 種不同的物體），模型可能過度依賴語言條件，而語言描述可能不夠豐富。

**除錯建議：**

- 增加資料集大小（持續翻倍，直到超過 300 個範例）
- 延長訓練，最多到 100k 步，即使損失已經不再下降
- 確認模型收到的語言指令正確，或增加指令的多樣性

### 執行錯誤的任務[[executing-the-wrong-task]]

有時機器人會完全忽略你的指令，去執行其他任務。這通常只會在你訓練了多個任務時發生。

**可能的原因：**

- 語言指令模稜兩可
- 特定任務的訓練資料不足
- 模型混淆了多任務資料集中相似的任務

**除錯建議：**

- 確認語言指令夠具體，尤其是多個任務的描述很相似時
- 檢查訓練資料集中的任務分布，並對失敗或被忽略的任務加重權重
- 考慮針對特定任務進行微調（fine-tuning）

### 訓練不穩定[[training-instability]]

如果訓練損失不穩定或發散：

- 試著將學習率調整在 `1e-5` 到 `3e-4` 之間
- 盡可能增加批次大小
- 檢查資料集的正規化是否正確
- 確認影像前處理正常運作

## 效能考量[[performance-considerations]]

### GPU 需求[[gpu-requirements]]

- **推論**：建議至少使用 RTX 5070 Ti（或同等級的 GPU），才能有合理的速度
- **訓練**：理想上需要足夠的 VRAM 以支援大於 64 的批次大小，實際需求會因影像觀測的數量等因素而異

### 批次大小建議[[batch-size-recommendations]]

- **最小值**：64（低於此值可能導致訓練不穩定）
- **建議值**：256-320（最佳效能，需要較大的 GPU）
