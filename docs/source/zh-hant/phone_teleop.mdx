# 手機[[phone]]

使用你的手機（iOS 或 Android）控制機器人。

**在本指南中，你將學到：**

- 如何連接 iOS／Android 手機
- 手機的姿態（pose）如何對應到機器人末端執行器（end effector，EE）的目標
- 如何調整安全限制、夾爪控制與 IK 設定

若要用手機控制機器人，請以下列指令安裝相關的相依套件：

```bash
pip install lerobot[phone]
```

## 開始使用[[get-started]]

### 支援的平台[[supported-platforms]]

- iOS：使用 HEBI Mobile I/O app（ARKit 姿態 + 按鈕）。請先下載並開啟這個 app，範例程式就會在網路上找到它，並串流手機的姿態與輸入。
- Android：使用 `teleop` 套件（WebXR）。啟動 Python 行程時，它會印出一個本機 URL。在手機上開啟這個連結，點選 Start，再使用 Move 串流姿態。

連結：

- Android WebXR 函式庫：[PyPI 上的 `teleop`](https://pypi.org/project/teleop/)
- iOS app：[HEBI Mobile I/O](https://docs.hebi.us/tools.html#mobile-io)

### 手機方向與控制[[phone-orientation-and-controls]]

- 方向：手持手機時，讓螢幕朝上，頂端朝向與機器人夾爪相同的方向。這能確保校正時，手機的座標系與機器人的座標系對齊，讓動作感覺自然，請參考下方的圖片。
- 啟用／停用：
  - iOS：按住 `B1` 啟用遙操作，放開即停止。第一次按下時會擷取參考姿態。
  - Android：按住 `Move` 按鈕，放開即停止。第一次按下時會擷取參考姿態。
- 夾爪控制：
  - iOS：類比輸入 `A3` 以速度輸入的方式控制夾爪。
  - Android：按鈕 `A` 與 `B` 的作用類似遞增／遞減（A 張開、B 閉合）。你可以在 `GripperVelocityToJoint` 步驟中調整速度。

### 步驟 1：選擇平台[[step-1-choose-the-platform]]

修改範例，在 `PhoneConfig` 中使用 `PhoneOS.IOS` 或 `PhoneOS.ANDROID`。各平台的 API 完全相同，只有輸入來源不同。所有範例都在 `examples/` 底下，並各有 `phone_so100_*.py` 版本。

遙操作範例：

```python
from lerobot.teleoperators.phone import Phone, PhoneConfig
from lerobot.teleoperators.phone.config_phone import PhoneOS

teleop_config = PhoneConfig(phone_os=PhoneOS.IOS)  # 或 PhoneOS.ANDROID
teleop_device = Phone(teleop_config)
```

### 步驟 2：連接與校正[[step-2-connect-and-calibrate]]

建立 `Phone(teleop_config)` 並呼叫 `connect()` 時，會自動提示進行校正。依照上述方向手持手機，然後：

- iOS：按住 `B1` 以擷取參考姿態。
- Android：在 WebXR 頁面按下 `Move` 按鈕以擷取參考姿態。

為什麼要校正？我們會擷取目前的姿態，讓之後的姿態都以與機器人對齊的座標系表示。當你再次按下按鈕啟用控制時，會重新擷取位置，避免停用期間移動手機而造成漂移。

### 步驟 3：執行範例[[step-3-run-an-example]]

執行其中一個範例腳本，即可進行遙操作、錄製資料集、重播資料集或評估策略。

所有腳本都假設你已經設定好機器人（例如 SO-100 從臂），並設定了正確的序列埠。

此外，你需要**將機器人的 URDF 複製到 examples 資料夾中**。以本教學的範例（使用 SO100/SO101）來說，請將 [SO-ARM100 儲存庫](https://github.com/TheRobotStudio/SO-ARM100/blob/main/Simulation/SO101)中的 `SO101` 資料夾複製到 `examples/phone_to_so100/` 目錄，讓 URDF 檔案的路徑變成 `examples/phone_to_so100/SO101/so101_new_calib.urdf`。

- 執行這個範例進行遙操作：

  ```bash
  cd examples/phone_to_so100
  python teleoperate.py
  ```

執行範例後：

- Android：啟動腳本後，在手機上開啟印出的本機 URL，點選 Start，然後按住 Move。
- iOS：先開啟 HEBI Mobile I/O；B1 啟用動作，A3 控制夾爪。

此外，你可以編輯範例中的處理器步驟，自訂對應方式或安全限制。你也可以重新對應輸入（例如改用其他類比輸入），或修改輸入與運動學的步驟，將管線調整為適用於其他機器人（例如 LeKiwi）。更多相關內容，請參閱[機器人與遙操作器的處理器](./processors_robots_teleop)指南。

- 執行這個範例錄製資料集，它會儲存絕對的末端執行器觀測與動作：

  ```bash
  cd examples/phone_to_so100
  python record.py
  ```

- 執行這個範例重播已錄製的回合：

  ```bash
  cd examples/phone_to_so100
  python replay.py
  ```

- 執行這個範例評估預訓練的策略：

  ```bash
  cd examples/phone_to_so100
  python evaluate.py
  ```

### 重要的管線步驟與選項[[important-pipeline-steps-and-options]]

- 運動學會用在多個步驟中。我們使用 [Placo](https://github.com/Rhoban/placo) 處理運動學，它是 Pinocchio 的包裝器。建構運動學物件時，需要傳入機器人的 URDF 與目標座標系。我們將 `target_frame_name` 設為夾爪的座標系。

  ```python
  kinematics_solver = RobotKinematics(
    urdf_path="./SO101/so101_new_calib.urdf",
    target_frame_name="gripper_frame_link",
    joint_names=list(robot.bus.motors.keys()),
  )

  ```

- `MapPhoneActionToRobotAction` 步驟會將校正後的手機姿態與輸入，轉換為目標增量與夾爪命令，以下是這個步驟的輸出。

  ```python
  action["enabled"] = enabled
        action["target_x"] = -pos[1] if enabled else 0.0
        action["target_y"] = pos[0] if enabled else 0.0
        action["target_z"] = pos[2] if enabled else 0.0
        action["target_wx"] = rotvec[1] if enabled else 0.0
        action["target_wy"] = rotvec[0] if enabled else 0.0
        action["target_wz"] = -rotvec[2] if enabled else 0.0
        action["gripper_vel"] = gripper_vel  # 停用時仍會送出夾爪動作
  ```

- `EEReferenceAndDelta` 步驟會將目標增量轉換為絕對的 EE 目標姿態，並在啟用時儲存參考姿態；`end_effector_step_sizes` 是 EE 姿態的步長，修改它即可改變動作速度。

  ```python
  EEReferenceAndDelta(
      kinematics=kinematics_solver,
      end_effector_step_sizes={"x": 0.5, "y": 0.5, "z": 0.5},
      motor_names=list(robot.bus.motors.keys()),
      use_latched_reference=True,
  ),
  ```

- `EEBoundsAndSafety` 步驟會將 EE 的動作限制在工作空間內，並檢查 EE 是否有過大的跳動，以確保安全。`end_effector_bounds` 是 EE 姿態的邊界，修改它可以改變工作空間；`max_ee_step_m` 是 EE 姿態的步長上限，修改它可以改變安全限制。

  ```python
  EEBoundsAndSafety(
      end_effector_bounds={"min": [-1.0, -1.0, -1.0], "max": [1.0, 1.0, 1.0]},
      max_ee_step_m=0.10,
  )
  ```

- `GripperVelocityToJoint` 步驟會根據目前量測到的狀態，將類似速度的夾爪輸入轉換為絕對的夾爪位置。`speed_factor` 是速度要乘上的係數。

  ```python
  GripperVelocityToJoint(speed_factor=20.0)
  ```

#### 不同的 IK 初始猜測值[[different-ik-initial-guesses]]

我們在不同的運動學步驟中使用不同的 IK 初始猜測值：可能是目前量測到的關節位置，也可能是前一次的 IK 解。

- 閉迴路（用於錄製／評估）：設定 `initial_guess_current_joints=True`，讓 IK 每一個影格都從量測到的關節位置開始。

  ```python
  InverseKinematicsEEToJoints(
      kinematics=kinematics_solver,
      motor_names=list(robot.bus.motors.keys()),
      initial_guess_current_joints=True,  # 閉迴路
  )
  ```

- 開迴路（用於重播）：設定 `initial_guess_current_joints=False`，讓 IK 從前一次的 IK 解繼續，而不是從量測到的狀態開始。在沒有回饋的情況下重播時，這能維持動作的穩定性。

  ```python
  InverseKinematicsEEToJoints(
      kinematics=kinematics_solver,
      motor_names=list(robot.bus.motors.keys()),
      initial_guess_current_joints=False,  # 開迴路
  )
  ```

### 管線步驟說明[[pipeline-steps-explained]]

- MapPhoneActionToRobotAction：將校正後的手機姿態與輸入，轉換為目標增量與夾爪命令。動作只有在啟用訊號開啟時才會作用（iOS 上為 B1，Android 上為 Move）。
- EEReferenceAndDelta：在啟用時鎖定一個 EE 參考姿態，並與目標增量結合，在每一個影格產生絕對的 EE 目標姿態。停用時，會持續送出最後一次命令的姿態。
- EEBoundsAndSafety：將 EE 姿態限制在工作空間內，並限制跳動的速率以確保安全。同時也會宣告 `action.ee.*` 特徵。
- InverseKinematicsEEToJoints：以 IK 將 EE 姿態轉換為關節位置。閉迴路控制建議使用 `initial_guess_current_joints=True`；開迴路重播時，為了穩定請設為 `False`。
- GripperVelocityToJoint：根據目前量測到的狀態，將類似速度的夾爪輸入積分為絕對的夾爪位置。
- ForwardKinematicsJointsToEE：從觀測到的關節計算 `observation.state.ee.*`，用於記錄，以及以 EE 狀態進行訓練。

### 疑難排解[[troubleshooting]]

- 找不到 iOS 裝置：確認 HEBI Mobile I/O 已開啟，且筆電與手機在同一個網路上。
- 無法連上 Android 的 URL：確認你使用的是 `https` 而不是 `http`，並使用腳本印出的確切 IP，同時讓瀏覽器略過憑證問題繼續進入。
- 動作方向相反：調整 `MapPhoneActionToRobotAction` 中的正負號，或交換座標軸，以符合你的設定。
