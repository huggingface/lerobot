# MolmoAct2 策略[[molmoact2-policy]]

MolmoAct2 是 LeRobot 對
[MolmoAct2](https://allenai.org/blog/molmoact2) 的策略實作（policy implementation），已移植到 LeRobot 的
訓練、評估、檢查點（checkpoint）與資料集介面，讓它更容易搭配
LeRobot 資料集使用。

這個實作目前支援一般
MolmoAct2 模型的訓練與評估。支援自適應深度推理（adaptive depth reasoning）的 MolmoAct2-Think
尚未納入這個 LeRobot 策略。

若要取得論文中所回報實驗使用的原始 MolmoAct2 訓練程式碼，
請參閱 [allenai/molmoact2](https://github.com/allenai/molmoact2)。

## 安裝需求[[installation-requirements]]

安裝 LeRobot 與 MolmoAct2 的可選相依套件：

```bash
uv sync --locked --extra molmoact2
```

要執行這個儲存庫中的模型，你需要一張 NVIDIA GPU。目前的
混合精度（mixed precision）路徑會以 fp32 儲存完整的 action expert，並以 bf16 儲存大型 VLM
矩陣。`policy.compile_model=true` 可選擇編譯 action
expert 的區塊，同時讓 VLM、vision tower、connector 與策略包裝器
維持 eager 模式。這個邊界通過了相同起點下的輸出、梯度與優化器更新
一致性檢查（parity check）；編譯 bf16 VLM 路徑則沒有通過。

透過 `accelerate` 進行多 GPU 訓練，可以提升吞吐量（throughput）與全域批次
大小。這個路徑已在雙節點、八 GPU 的 GB200 執行上驗證過，但這個
LeRobot 移植版並未提供原始 MolmoAct2 的 `fsdp_devices`
模型平行（model parallel）訓練路徑。在單 GPU 的 GB200 上，以兩種實際的提示寬度重播時，
只產生一個編譯後的動作計算圖（action graph），沒有任何 graph break，記憶體峰值與 eager 執行相同，皆為 55.15 GiB，
穩態下也有些許加速。請將這些結果視為
實作上的檢查，而非可移植的吞吐量或 ETA 宣稱。

這個儲存庫已在 Ubuntu 22.04 上測試過。

## 使用方式[[usage]]

若要在 LeRobot 的訓練設定中使用 MolmoAct2，請設定：

```bash
--policy.type=molmoact2
```

## 訓練[[training]]

MolmoAct2 可以從已發布的 MolmoAct2 Hugging Face
檢查點（checkpoint）格式，或從 LeRobot 已儲存的檢查點開始微調（fine-tune）。兩種方式都使用
相同的 LeRobot 訓練迴圈、資料集轉換（transform）、檢查點儲存與
記錄（logging）機制，差別只在於初始策略權重與處理器（processor）
狀態的載入方式。

LeRobot 預設會停用資料集的影像擴增（image augmentation）。在 MolmoAct2 的訓練指令中，
請保留 `--dataset.image_transforms.enable=true`。
原始 MolmoAct2 的轉換配方（recipe）並不是 LeRobot 通用的預設轉換，
因此第一個指令也明確固定了它的 95% 裁切、5 度旋轉與色彩
抖動（color jitter）。原始配方還會另外套用高斯模糊（Gaussian blur），
機率為 0.2；而 LeRobot 通用的轉換子集設定
無法表達這個可選的第四種轉換，除非有時捨棄
三種必要轉換中的某一種。

### 使用原始 MolmoAct2 權重訓練[[training-with-original-molmoact2-weight]]

從已發布的 MolmoAct2 檢查點開始時，請使用 `policy.checkpoint_path`，
例如 `allenai/MolmoAct2` 或 `allenai/MolmoAct2-LIBERO`。LeRobot 會載入
原始的 HF 模型檔案，接著根據
資料集中繼資料與下方的策略選項，建立自己的策略處理器。

以下指令示範從已發布的基礎檢查點，在合併後的 LIBERO 資料集上進行完整微調。它使用
bf16 載入模型、8 個 flow timestep、
官方的 LIBERO 分位數（quantile）統計量、影像擴增，以及 LeRobot 的
檢查點／記錄路徑。請勿以 `lerobot/libero` 的近似
中繼資料分位數取代已發布的 `norm_stats.json`；兩者的 q01/q99 值
並不相同。

```bash
accelerate launch \
  --num_processes=8 \
  --mixed_precision=bf16 \
  -m lerobot.scripts.lerobot_train \
  --dataset.repo_id=lerobot/libero \
  --dataset.root=/path/to/lerobot/libero \
  --dataset.video_backend=pyav \
  --dataset.image_transforms.enable=true \
  --dataset.image_transforms.max_num_transforms=3 \
  --dataset.image_transforms.random_order=false \
  --dataset.image_transforms.tfs='{"crop":{"weight":1.0,"type":"RandomResizedCrop","kwargs":{"size":[256,256],"scale":[0.9025,0.9025],"ratio":[1.0,1.0]}},"rotation":{"weight":1.0,"type":"RandomRotation","kwargs":{"degrees":[-5.0,5.0],"interpolation":2}},"color":{"weight":1.0,"type":"ColorJitter","kwargs":{"brightness":0.2,"contrast":[0.8,1.2],"saturation":[0.8,1.2],"hue":0.05}}}' \
  --policy.type=molmoact2 \
  --policy.checkpoint_path=allenai/MolmoAct2 \
  --policy.device=cuda \
  --policy.action_mode=continuous \
  --policy.norm_tag=libero \
  --policy.norm_stats_path=/path/to/MolmoAct2-LIBERO/norm_stats.json \
  --policy.train_mode_vlm=fft \
  --policy.chunk_size=10 \
  --policy.n_action_steps=10 \
  --policy.setup_type="single franka robotic arm in libero" \
  --policy.control_mode="delta end-effector pose" \
  --policy.image_keys='["observation.images.image","observation.images.image2"]' \
  --policy.dtype=bfloat16 \
  --policy.num_flow_timesteps=8 \
  --policy.gradient_checkpointing=true \
  --policy.compile_model=true \
  --policy.freeze_embedding=true \
  --policy.normalize_gripper=false \
  --policy.enable_knowledge_insulation=false \
  --policy.push_to_hub=false \
  --wandb.enable=true \
  --wandb.entity=<wandb_entity> \
  --wandb.project=<wandb_project> \
  --job_name=<job_name> \
  --output_dir=outputs/<job_name> \
  --steps=10000 \
  --batch_size=32 \
  --num_workers=4 \
  --log_freq=20 \
  --env_eval_freq=-1 \
  --save_checkpoint=true \
  --save_freq=2000
```

### 使用 LeRobot MolmoAct2 權重訓練[[training-with-lerobot-molmoact2-weight]]

從 LeRobot 儲存的 MolmoAct2 檢查點開始時，不論是本機的
`pretrained_model` 目錄或 Hub 上的檢查點，請使用 `policy.path`。這會
還原已儲存的 LeRobot 策略設定、模型權重、處理器與
正規化統計量。你仍然可以覆寫訓練時的選項，例如
`batch_size`、`steps` 或 `policy.action_mode`。檢查點的載入是嚴格的，並且會
保留已儲存的 FFT 或 LoRA 拓撲，因此使用 `policy.path` 時，請勿覆寫
`policy.train_mode_vlm`。若要開始新的 LoRA 訓練，
請改用 `policy.checkpoint_path` 從 HF 權重初始化，例如
搭配 `--policy.type=molmoact2`、
`--policy.checkpoint_path=allenai/MolmoAct2` 與
`--policy.train_mode_vlm=lora`。

```bash
accelerate launch \
  --num_processes=8 \
  --mixed_precision=bf16 \
  -m lerobot.scripts.lerobot_train \
  --dataset.repo_id=allenai/MolmoAct2-LIBERO-Dataset \
  --dataset.root=/path/to/lerobot/data/allenai/MolmoAct2-LIBERO-Dataset \
  --dataset.video_backend=pyav \
  --dataset.image_transforms.enable=true \
  --policy.path=/path/to/pretrained_model \
  --policy.device=cuda \
  --policy.action_mode=continuous \
  --policy.chunk_size=10 \
  --policy.n_action_steps=10 \
  --policy.dtype=bfloat16 \
  --policy.num_flow_timesteps=8 \
  --policy.gradient_checkpointing=true \
  --policy.compile_model=true \
  --wandb.enable=true \
  --wandb.entity=<wandb_entity> \
  --wandb.project=<wandb_project> \
  --job_name=<job_name> \
  --output_dir=outputs/<job_name> \
  --steps=10000 \
  --batch_size=32 \
  --num_workers=4 \
  --log_freq=20 \
  --env_eval_freq=-1 \
  --save_checkpoint=true \
  --save_freq=2000
```

### 常見做法[[common-practices]]

在相對較小的資料集上微調時，例如單一 LIBERO 任務套件
或少於 200 筆示範的真實世界資料集，全域批次大小
設為 16 到 32 是不錯的起點。在這些情況下，我們建議使用
`policy.train_mode_vlm=lora`（預設值），它的效能通常與 `fft` 相近，甚至
更好。此外，`policy.train_mode_vlm=freeze` 也是
實用的選擇。在所有模式中，我們都刻意讓 action expert 保持
完全可訓練，我們發現這對模型效能至關重要。對於較大的
微調資料集，通常會偏好較大的全域批次大小與完整的 VLM 微調
（`policy.train_mode_vlm=fft`）。

### 常見策略選項[[common-policy-options]]

- `policy.checkpoint_path`：用來初始化的原始 MolmoAct2 HF 檢查點。
  已發布的 MolmoAct2 權重請使用這個選項。
- `policy.path`：用來初始化的 LeRobot 檢查點。由 LeRobot 訓練建立的檢查點
  請使用這個選項。
- `policy.action_mode`：訓練目標，可為 `continuous`、`discrete` 或
  `both`。官方的 MolmoAct2 機器人微調使用 `continuous`。已發布的
  檢查點保留了離散動作的權重；`both` 可用來進行
  流匹配（flow matching）加上動作 token 的聯合消融實驗（ablation）。
- `policy.train_mode_vlm`：控制 VLM 的微調模式，可為 `fft`、
  `lora` 或 `freeze`。`fft` 會完整微調 VLM，`lora` 會在 VLM 的線性層上訓練 LoRA
  adapter，`freeze` 則會凍結 VLM。action expert
  在三種模式中都會完整微調。預設為 `lora`。`freeze`
  需要搭配 `policy.action_mode=continuous`。
- `policy.enable_knowledge_insulation`：設為 `true` 時，會在計算動作損失之前，將 action expert
  的 context K/V 狀態分離（detach）。預設為 `false`。
- `policy.chunk_size`：策略使用的動作時域（action horizon）。LIBERO 我們使用
  `10`。這個 LeRobot 移植版會以這個值覆寫所載入檢查點的
  `max_action_horizon`。
- `policy.n_action_steps`：每個預測的區塊（chunk）中，
  在再次查詢策略之前實際使用的動作數。LIBERO 請設為 `chunk_size`。
- `policy.setup_type`：插入提示（prompt）中、用來描述機器人與
  場景的文字，例如 `single franka robotic arm in libero`。更多範例列在
  以下檔案的 `metadata_by_tag` 項目中：
  [`norm_stats.json`](https://huggingface.co/allenai/MolmoAct2/blob/main/norm_stats.json)。
- `policy.control_mode`：插入提示中、用來描述動作
  空間的文字，例如 `delta end-effector pose` 或 `absolute joint pose`。
- `policy.image_keys`：傳給處理器的 LeRobot 影像觀測鍵名（image observation key），
  順序有意義。
- `policy.dtype`：Pi0.5 風格的精度切換。`bfloat16` 會對大型 VLM 矩陣使用 bf16
  autocast 與儲存，同時讓完整的 action
  expert 與數值敏感的模組保留在 fp32。`float32` 會停用
  autocast，並將整個模型保留在 fp32。低記憶體的 `bfloat16` 設定
  刻意與原始 MolmoAct2 的 FP32-master AMP 執行方式不同：
  AdamW 的動量（moment）會跟隨每個參數的儲存 dtype，因此大型 bf16 VLM
  參數的動量也是 bf16。完整微調時，會為每個帶有梯度的 bf16 參數延遲配置一個 bf16
  補償張量，讓
  小於一個參數 ULP 的更新能延續到後續的步驟。這並不是
  fp32 的主副本（master copy）。LoRA adapter、action expert 與明確標示為敏感的
  模組會保留 fp32 的參數與優化器狀態；在
  LoRA 模式中，凍結的 VLM 參數不會配置任何補償張量。
- `policy.compile_model`：啟用 MolmoAct2 的逐區塊（block-wise）`torch.compile` 路徑。
  完整微調與 LoRA 都只會編譯 action expert 的 transformer
  區塊。VLM／ViT／connector 以 eager 模式執行，可以避免編譯器造成的 BF16
  activation 與梯度漂移，同時保留每個 flow timestep 都會執行的動作
  路徑的加速效果。Inductor 也會被指示
  在融合運算之間保留 eager 的 BF16 向下／向上轉型邊界。這是
  一個固定的精度安全邊界，不會再新增其他編譯選項。
  編譯預設為停用；請在長時間的 GPU 訓練中啟用。
  動作區塊使用 PyTorch 的自動形狀策略。啟用梯度
  檢查點（gradient checkpointing）時，只有長度可變的 encoder context 序列維度會標記為
  動態；批次大小、動作時域與 flow timestep 數量則維持靜態。
  在該模式下，Dynamo 的計算圖快取重排序與額外的 DDP 圖分割器都會停用，
  讓反向傳播重新計算時，選用與前向傳播相同的區塊計算圖。
  批次內的文字／動作序列會在插入 BOS 之前，左側填補至內部設定的
  8 的倍數。這最多只會增加七個被遮罩的 token，卻能大幅
  減少特定形狀的編譯暖機；這不是提供給使用者的選項。
- `policy.num_flow_timesteps`：訓練時每個範例取樣的
  流匹配 timestep 數量。微調時我們使用 `8`。
- `policy.num_inference_steps`：可選，覆寫推論（inference）時連續動作
  的生成步數。
- `policy.gradient_checkpointing`：在 VLM／動作路徑中啟用 checkpointing，
  以降低 activation 所需的記憶體。
- `policy.freeze_embedding`：凍結輸入的嵌入向量（embedding）。預設為 `true`。
- `policy.normalize_gripper`：控制夾爪維度是否納入
  狀態／動作的分位數正規化。預設為 `false`。
- `policy.normalize_language`：在建構提示之前，先正規化任務字串。
  預設為 `true`。
- `policy.mask_action_dim_padding`：在 flow 損失中遮罩填補的維度。
  已發布的檢查點使用 `policy.expected_max_action_dim=32`。
- `policy.max_sequence_length`：可選，手動設定序列長度上限。不設定時，會根據影像、
  狀態維度、動作維度、動作時域與
  離散動作模式自動推算。

### 學習率[[learning-rates]]

MolmoAct2 依參數群組設定不同的學習率，以符合原始 MolmoAct2 的
微調實驗。

- 完整微調時，VLM 使用 `policy.optimizer_lr=1e-5`，
  vision tower 使用 `policy.optimizer_vit_lr=5e-6`，
  影像 connector 層使用 `policy.optimizer_connector_lr=5e-6`，
  action expert 使用 `policy.optimizer_action_expert_lr=5e-5`。
- LoRA VLM 微調（`policy.train_mode_vlm=lora`）會將 VLM、vision 與 connector 的 LoRA 參數群組
  學習率都設為 `5e-5`；action expert 仍然
  以 `policy.optimizer_action_expert_lr` 完整微調。
- 凍結 VLM 的微調使用 `policy.train_mode_vlm=freeze`，只訓練
  action expert，並使用 `policy.optimizer_action_expert_lr=5e-5`。
- `policy.optimizer_grad_clip_norm` 會分別套用到 LLM、vision
  tower、影像 connector 與 action expert 的各個參數群組，與
  原始 MolmoAct2 的優化器一致，而不是整個模型共用的單一梯度範數。

你可以用以下參數覆寫完整微調與 action expert 的學習率：
`policy.optimizer_lr`、`policy.optimizer_vit_lr`、
`policy.optimizer_connector_lr` 與 `policy.optimizer_action_expert_lr`。
排程器（scheduler）的設定可以透過 `policy.scheduler_warmup_steps`、
`policy.scheduler_decay_steps` 與 `policy.scheduler_decay_lr` 調整。預設的
24,000 步衰減時域與官方
[`train_lerobot.py`](https://github.com/allenai/molmoact2/blob/5aac8f8a1180d79757ce500f819a02217079811c/experiments/launch_scripts/train_lerobot.py#L867-L868)
的配方一致。

### 資料集分位數統計量[[dataset-quantile-statistics]]

MolmoAct2 預設對狀態與動作特徵使用分位數正規化（quantile normalization）。如果
你的資料集尚未轉換、沒有分位數統計量，可以用以下指令
加入：

```bash
python src/lerobot/scripts/augment_dataset_quantile_stats.py \
  --repo-id=your_dataset
```

錄製、接續錄製與合併資料集時，分位數是從各回合（episode）的摘要彙整而來，因此 `meta/stats.json` 最後存放的是保守的包絡值（`q <= 50` 取 `min`，`q > 50` 取 `max`），而不是整個資料集的分位數。若要估計後者，請以累進直方圖掃描每個回合：

```bash
python src/lerobot/scripts/augment_dataset_quantile_stats.py \
  --repo-id=your_dataset \
  --overwrite \
  --skip-images
```

`--skip-images` 會保留既有的影像統計量；當只需要重新計算 `STATE`/`ACTION` 時，可以避免下載或解碼影片資料。`--root` 則會讀取本機資料集，而不是 Hub 上的資料集。這些數值是直方圖估計值，會受到離散化與重新分箱誤差的影響，因此可能與保守值不同。這會改變 MolmoAct2 正規化後的目標值，進而改變它的損失尺度。已存放在既有檢查點內的統計量則不受影響。

或者，你也可以用平均值／標準差正規化（mean/std normalization）訓練 MolmoAct2：

```bash
--policy.normalization_mapping='{"ACTION": "MEAN_STD", "STATE": "MEAN_STD", "VISUAL": "IDENTITY"}'
```

## 評估[[evaluation]]

評估同樣支援 LeRobot 儲存的檢查點（checkpoint）與原始 MolmoAct2
HF 檢查點。若要重現 LIBERO 的結果，請固定 EGL 渲染環境，
並使用 `policy.per_episode_seed=true`。

**重要：** 我們發現 `num_steps_wait=10` 無法穩定地讓
LIBERO 場景靜止下來，可能會降低量測到的成功率。這裡回報的所有 LIBERO 評估
結果都使用 `num_steps_wait=50`。

### 使用 LeRobot MolmoAct2 權重評估[[evaluation-with-lerobot-molmoact2-weight]]

LeRobot 儲存的檢查點請使用 `policy.path`。已儲存的處理器與
正規化統計量會與模型一起還原。

```bash
export MUJOCO_GL=egl
export PYOPENGL_PLATFORM=egl
export OMP_NUM_THREADS=1
export MKL_NUM_THREADS=1

lerobot-eval \
  --policy.path=allenai/MolmoAct2-LIBERO-LeRobot \
  --policy.inference_action_mode=continuous \
  --policy.dtype=bfloat16 \
  --policy.enable_inference_cuda_graph=true \
  --policy.device=cuda \
  --policy.per_episode_seed=true \
  --policy.eval_seed=1000 \
  --env.type=libero \
  --env.task=libero_10,libero_goal,libero_object,libero_spatial \
  --env.camera_name_mapping='{"agentview_image":"image","robot0_eye_in_hand_image":"wrist_image"}' \
  --eval.batch_size=1 \
  --eval.n_episodes=50 \
  --seed=1000
```

### 使用原始 MolmoAct2 權重評估[[evaluation-with-original-molmoact2-weight]]

你可以直接評估已發布的 Hugging Face 檢查點，不需要先
將它轉換為 LeRobot 檢查點。此時，請將
`policy.checkpoint_path` 設為 HF 模型儲存庫，並提供 `policy.norm_tag`。
以 LIBERO 為例，`policy.norm_tag=libero` 會從檢查點的 `norm_stats.json` 載入 LIBERO 的動作／狀態
正規化統計量、動作時域（action horizon）、提示中繼資料，
以及影像鍵名的順序。

若要以已發布的 Hugging Face 檢查點完整重現 MolmoAct2 論文的結果，
我們建議使用固定在 v0.5.1 的
[`allenai/lerobot` `molmoact2-hf-inference`](https://github.com/allenai/lerobot/tree/molmoact2-hf-inference)
分支。這個分支與回報數據時所使用的
原始評估設定一致。

```bash
export MUJOCO_GL=egl
export PYOPENGL_PLATFORM=egl
export OMP_NUM_THREADS=1
export MKL_NUM_THREADS=1

lerobot-eval \
  --policy.type=molmoact2 \
  --policy.checkpoint_path=allenai/MolmoAct2-LIBERO \
  --policy.norm_tag=libero \
  --policy.inference_action_mode=continuous \
  --policy.dtype=float32 \
  --policy.enable_inference_cuda_graph=true \
  --policy.device=cuda \
  --policy.per_episode_seed=true \
  --policy.eval_seed=1000 \
  --env.type=libero \
  --env.task=libero_goal \
  --env.camera_name_mapping='{"agentview_image":"image","robot0_eye_in_hand_image":"wrist_image"}' \
  --eval.batch_size=1 \
  --eval.n_episodes=50 \
  --seed=1000
```

使用 `--env.task=libero_10,libero_goal,libero_object,libero_spatial` 即可執行
完整的 LIBERO 任務套件。只要所指定的 `policy.norm_tag` 存在於該檢查點的
`norm_stats.json` 中，同樣的指令也適用於其他已發布的 MolmoAct2
檢查點。

### 常見評估選項[[common-evaluation-options]]

- `policy.inference_action_mode`：執行 rollout 時必須設定。流匹配推論請使用 `continuous`，
  動作 token 推論請使用 `discrete`。它必須與檢查點中
  儲存的訓練時 `policy.action_mode`
  相容。
- `policy.path`：LeRobot 檢查點路徑或 Hub 儲存庫。LeRobot 儲存的檢查點
  請使用這個選項。
- `policy.checkpoint_path`：原始 MolmoAct2 HF 檢查點的路徑或 Hub 儲存庫。
  請搭配 `policy.type=molmoact2` 與 `policy.norm_tag` 使用。
- `policy.norm_tag`：從原始檢查點的 `norm_stats.json` 選擇正規化統計量、提示中繼資料、
  影像鍵名順序與動作時域。
  直接評估原始 HF 檢查點時，
  必須設定這個選項。
- `policy.dtype`：模型的儲存／autocast 設定。一般的 GPU 評估請使用 `bfloat16`。
  只有在明確需要完整 fp32 推論時，才使用 `float32`。
- `policy.enable_inference_cuda_graph`：啟用 MolmoAct2 的推論 CUDA
  graph 路徑，加快重複執行連續動作 rollout 的速度。
- `policy.per_episode_seed` 與 `policy.eval_seed`：讓隨機的連續動作生成
  在每個回合中都是確定性的，以便重現結果。
- `env.task`：以逗號分隔的多個 LIBERO 任務套件，或單一任務套件。
  完整的基準測試請使用 `libero_10,libero_goal,libero_object,libero_spatial`。
- `env.camera_name_mapping`：將 LIBERO 的相機名稱對應到
  策略處理器預期的影像鍵名。

## 效能結果[[performance-results]]

### LIBERO 基準測試結果[[libero-benchmark-results]]

MolmoAct2 在 LIBERO 基準測試（benchmark）任務套件上表現優異。為了
比較並測試它的 LeRobot 實作，我們以
[`allenai/MolmoAct2-LIBERO`](https://huggingface.co/allenai/MolmoAct2-LIBERO) 為起點，
在 8 張 H100 GPU 上、以每張 GPU 32 的批次大小，於 LIBERO 資料集上額外微調 10k 步，
再將結果與原始 MolmoAct2 的
參考結果比較。

這裡回報的 LeRobot 微調檢查點可在
[`allenai/MolmoAct2-LIBERO-LeRobot`](https://huggingface.co/allenai/MolmoAct2-LIBERO-LeRobot) 取得，
訓練資料集為
[`allenai/MolmoAct2-LIBERO-Dataset`](https://huggingface.co/datasets/allenai/MolmoAct2-LIBERO-Dataset)。

| 基準測試       | LeRobot 實作 | MolmoAct2 原始實作 |
| -------------- | -----------: | -----------------: |
| LIBERO Spatial |        98.4% |              97.8% |
| LIBERO Object  |       100.0% |             100.0% |
| LIBERO Goal    |        98.0% |              97.8% |
| LIBERO 10      |        96.6% |              93.2% |
| 平均           |       98.25% |             97.20% |

這些結果顯示 MolmoAct2 在多樣的機器人
操作任務上都有優異的表現。若要重現這些結果，請依照 LIBERO
評估一節的說明操作。

## 硬體部署（lerobot-rollout）[[hardware-deployment-lerobot-rollout]]

Hub 上提供了 LeRobot 格式的檢查點，可以直接搭配
`lerobot-rollout` 使用。每個檢查點都使用特定的相機名稱，必須
與你的機器人相機設定一致。

### 相機命名慣例[[camera-naming-convention]]

每個檢查點都預期特定的 `observation.images.*` 鍵名。
如果你的機器人相機名稱不同，請使用 `--rename_map` 進行對應：

| 檢查點                        | 相機鍵名               | 說明                |
| ----------------------------- | ---------------------- | ------------------- |
| MolmoAct2-LIBERO-LeRobot      | `image`、`wrist_image` | LIBERO 模擬相機     |
| MolmoAct2-BimanualYAM-LeRobot | `top`、`left`、`right` | YAM 三相機設定      |
| MolmoAct2-DROID-LeRobot       | `cam0`、`cam1`         | 外部相機 + 腕部相機 |
| MolmoAct2-SO100_101-LeRobot   | `cam0`、`cam1`         | 主要視角 + 次要視角 |

以下範例使用一台配有上方與側面相機的 SO-100 機器人：

```bash
lerobot-rollout \
  --policy.path=lerobot/MolmoAct2-SO100_101-LeRobot \
  --rename_map='{"observation.images.top": "observation.images.cam0", "observation.images.side": "observation.images.cam1"}' \
  --robot.type=so100_follower \
  --robot.port=/dev/ttyACM0 \
  --robot.cameras='{
      top: {type: opencv, index_or_path: 0, width: 640, height: 480, fps: 30},
      side: {type: opencv, index_or_path: 2, width: 640, height: 480, fps: 30}
  }' \
  --task="pick up the red cube" --duration=30
```

若要改用腕部相機，只要修改重新命名對應即可：

```bash
--rename_map='{"observation.images.top": "observation.images.cam0", "observation.images.wrist": "observation.images.cam1"}'
```

### 關節座標系轉換（SO-100/101 零樣本）[[joint-frame-transform-so-100101-zero-shot]]

<Tip warning={true}>
MolmoAct2-SO100_101 檢查點的訓練資料，所使用的關節校正慣例
與 LeRobot >= 0.5.0 不同。若沒有進行座標系
修正，手臂可能會往錯誤的方向移動。

這會同時影響從原始檢查點進行的**零樣本部署**（zero-shot deployment）與
**微調**。預訓練權重預期的是舊的慣例，因此
所有關節資料（觀測與動作）都必須轉換成對應的慣例。

轉換後的 LeRobot 檢查點（`lerobot/MolmoAct2-SO100_101-LeRobot`）
已在處理器管線中包含這項修正。如果你要自行轉換
或微調這個檢查點，請在策略設定（`configuration_molmoact2.py`）中設定以下項目：

- `joint_signs`：`[1, -1, 1, 1, 1, 1]`（反轉 shoulder_lift 的方向）
- `joint_offsets`：`[0, 90, 90, 0, 0, 0]`（將 shoulder_lift 與 elbow_flex 偏移 90°）

關於校正方式變更的詳細說明，請參閱
[向下相容性指南](./backwardcomp)。

</Tip>

## 與原始實作的差異[[differences-from-the-original-implementation]]

這個 LeRobot 移植版的目標是重現 MolmoAct2 的行為，同時使用 LeRobot 的
資料集、訓練、評估、檢查點與記錄基礎設施。與原始訓練儲存庫的
主要差異如下：

- 原始論文的訓練架構會保留 fp32 的主參數，並在
  bf16 AMP 下訓練。這個 LeRobot 移植版使用 `policy.dtype=bfloat16` 來降低
  記憶體用量：大型 VLM 矩陣以 bf16 儲存，action expert 與
  數值敏感的模組則保留在 fp32，可支援的運算子會在
  bf16 autocast 下執行。bf16 更新補償張量可以減少完整微調時的參數
  捨入損失，但它的 bf16 Adam 動量仍然無法
  完全重現原始的 fp32 優化器狀態。
- 原始儲存庫使用自己的 FSDP／模型平行訓練路徑。
  LeRobot 移植版使用標準的 LeRobot／Accelerate 訓練路徑，尚未
  在多節點訓練上測試過。
- 原始儲存庫支援序列打包（sequence packing）。LeRobot 移植版
  每個項目只訓練一個 LeRobot 樣本，並使用批次內填補，搭配推算出的
  最大序列長度上限作為保護。
- LeRobot 移植版遵循 LeRobot 的優化器、排程器、檢查點儲存、
  資料集轉換、影像擴增與 Weights & Biases 記錄
  慣例。
- 原始訓練路徑支援混合的動作時域：做法是填補至
  `max_action_horizon`，並在 action expert 的自注意力中遮罩填補的時域槽位。
  這在跨多個控制頻率不同的資料集訓練時很有用。
  LeRobot 移植版目前以單一資料集的
  微調為目標，因此 `policy.chunk_size` 會覆寫檢查點的
  `max_action_horizon`，時域遮罩也尚未實作。
  混合時域路徑的支援已在規劃中。
