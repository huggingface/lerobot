# ROBOMETER[[robometer]]

ROBOMETER 是一個**通用的影片-語言機器人獎勵模型**。它根據一段軌跡影片與任務描述，預測密集的逐影格任務進度，以及逐影格的成功與否。

**論文**：[ROBOMETER: Scaling General-Purpose Robotic Reward Models via Trajectory Comparisons](https://arxiv.org/abs/2603.02115)
**專案**：[robometer.github.io](https://robometer.github.io/)
**原始程式碼**：[github.com/robometer/robometer](https://github.com/robometer/robometer)
**檢查點（checkpoint）**：[lerobot/Robometer-4B](https://huggingface.co/lerobot/Robometer-4B)

## 概覽[[overview]]

ROBOMETER 以 `Qwen/Qwen3-VL-4B-Instruct` 為基礎，另外加上三個輕量的預測頭（head）：

- **進度頭**：預測每個影格的任務進度，範圍為 `[0, 1]`。
- **成功頭**：預測每個影格的任務成功機率。
- **偏好頭**：在訓練期間預測兩條軌跡中，哪一條更好地完成任務。

論文以一個複合的目標函數訓練 ROBOMETER：

```text
L = L_pref + L_prog + L_succ
```

LeRobot 的整合目前**只能用於推論**。它保留了偏好頭，讓已發布的 `Robometer-4B` 檢查點不需重新對應就能載入，但 `compute_reward()` 只會使用進度頭或成功頭。

## LeRobot 整合涵蓋的內容[[what-the-lerobot-integration-covers]]

- 透過 LeRobot 使用標準的 `reward_model.type=robometer` 設定。
- 透過 `RobometerEncoderProcessorStep` 進行 Qwen3-VL 的影像與文字預處理。
- 透過 `PreTrainedRewardModel` 使用 LeRobot 獎勵模型的儲存／載入 API。
- 在內部產生密集的逐影格進度與成功預測。
- 透過 `compute_reward()` 產生一個純量獎勵，供下游的 LeRobot 獎勵模型使用。

本頁著重於將已發布的 ROBOMETER 檢查點作為零樣本（zero-shot）獎勵模型使用。從頭訓練 ROBOMETER 不在目前 LeRobot 整合的範圍內。

## 安裝需求[[installation-requirements]]

1. 依照[安裝指南](./installation)安裝 LeRobot。
2. 安裝 ROBOMETER 的相依套件：

```bash
pip install -e ".[robometer]"
```

若你直接在原始碼目錄中使用 `uv`：

```bash
uv sync --extra robometer
```

ROBOMETER 使用 Qwen3-VL-4B 作為骨幹網路（backbone），因此強烈建議使用 GPU 推論。

## 模型輸入與輸出[[model-inputs-and-outputs]]

ROBOMETER 需要：

- 一段軌跡影片或影格序列。
- 一段自然語言的任務描述。

對於 LeRobot 資料集，預處理器會讀取：

| 設定欄位                  | 預設值                   | 意義                                               |
| ------------------------- | ------------------------ | -------------------------------------------------- |
| `reward_model.image_key`  | `observation.images.top` | ROBOMETER 使用的相機／影片觀測                     |
| `reward_model.task_key`   | `task`                   | 補充資料（complementary data）中存放任務字串的鍵名 |
| `reward_model.max_frames` | `8`                      | 傳給 ROBOMETER 的最大影格數                        |

模型會在內部預測每個影格的進度與成功，而 LeRobot 的獎勵 API 會為每個樣本回傳一個純量：

- `reward_output="progress"`（預設）：回傳最後一個影格的進度，並限制在 `[0, 1]` 範圍內。
- `reward_output="success"`：若最後一個影格的成功機率高於 `success_threshold`，回傳 `1.0`，否則回傳 `0.0`。

## 用法[[usage]]

### 直接載入獎勵模型[[load-the-reward-model-directly]]

```python
from lerobot.rewards.robometer import RobometerConfig, RobometerRewardModel

cfg = RobometerConfig(
    pretrained_path="lerobot/Robometer-4B",
    device="cuda",
    reward_output="progress",
)
reward_model = RobometerRewardModel.from_pretrained(cfg.pretrained_path, config=cfg)
```

### 編碼影格並計算獎勵[[encode-frames-and-compute-a-reward]]

若要直接在 Python 中呼叫，請以形狀為 `(T, H, W, C)` 的 `uint8` 陣列提供影格，並提供任務字串：

```python
from lerobot.rewards.robometer.modeling_robometer import ROBOMETER_FEATURE_PREFIX
from lerobot.rewards.robometer.processor_robometer import RobometerEncoderProcessorStep

# frames: np.ndarray，形狀 (T, H, W, C)，dtype uint8
# task: str
encoder = RobometerEncoderProcessorStep(
    base_model_id=cfg.base_model_id,
    use_multi_image=cfg.use_multi_image,
    use_per_frame_progress_token=cfg.use_per_frame_progress_token,
    max_frames=cfg.max_frames,
)

encoded = encoder.encode_samples([(frames, task)])
batch = {f"{ROBOMETER_FEATURE_PREFIX}{key}": value for key, value in encoded.items()}

reward = reward_model.compute_reward(batch)
```

`reward` 是形狀為 `(batch_size,)` 的張量。

### 使用獎勵工廠[[use-the-reward-factory]]

你也可以透過獎勵工廠建立 ROBOMETER 的實例：

```python
from lerobot.rewards import make_reward_model, make_reward_model_config, make_reward_pre_post_processors

cfg = make_reward_model_config(
    "robometer",
    pretrained_path="lerobot/Robometer-4B",
    device="cuda",
    image_key="observation.images.top",
)
reward_model = make_reward_model(cfg)
preprocessor, postprocessor = make_reward_pre_post_processors(cfg)
```

預處理器會將 Qwen-VL 張量寫入 `observation.robometer.*` 命名空間，而 `compute_reward()` 會讀取這些已編碼的張量。

## 設定注意事項[[configuration-notes]]

### 骨幹網路與詞彙表[[backbone-and-vocabulary]]

已發布的檢查點使用 Qwen3-VL-4B 骨幹網路。ROBOMETER 會依固定順序，在 tokenizer 中新增五個特殊 token：

```text
<|split_token|>
<|reward_token|>
<|pref_token|>
<|sim_token|>
<|prog_token|>
```

`<|prog_token|>` 會插入在每個影格之後，它所在位置的隱藏狀態，就是用來預測該影格進度與成功的依據。`<|split_token|>` 與 `<|pref_token|>` 用於論文中成對比較軌跡的偏好目標函數。`<|reward_token|>` 與 `<|sim_token|>` 則是為了與檢查點相容而保留。

LeRobot 的設定會儲存一份序列化的 `vlm_config`，其中包含調整大小後的詞彙表，讓模型能直接從 `config.json` 重新載入，不必先下載基礎的 Qwen 權重。以 `Qwen/Qwen3-VL-4B-Instruct` 來說，tokenizer 長度為 `151669`，加上五個 ROBOMETER token 後，檢查點的詞彙表大小為 `151674`。

### 進度預測[[progress-prediction]]

在已發布的檢查點中，進度是離散的：進度頭會針對 `[0, 1]` 之間 `progress_discrete_bins=10` 個均勻分布的區間中心輸出 logits。LeRobot 會先套用 softmax，再對區間中心取期望值，把 logits 轉換為連續值，做法與上游的 ROBOMETER 實作一致。

### 成功預測[[success-prediction]]

成功頭會為每個影格輸出原始的 logits，LeRobot 以 `sigmoid` 將它們轉換為機率。當 `reward_output="success"` 時，`compute_reward()` 會以 `success_threshold` 對最後一個影格的成功機率做閾值判斷。

## 限制[[limitations]]

- 目前 LeRobot 的整合只能用於推論；並未實作 ROBOMETER 的訓練或偏好配對訓練。
- 雖然 ROBOMETER 在內部會預測每個影格的進度與成功，`compute_reward()` 為了配合 LeRobot 獎勵模型的 API，只會為每個樣本回傳一個純量。
- ROBOMETER 以影片與語言為基礎；它不會使用特權式的機器人狀態，例如接觸力或物件姿態。
