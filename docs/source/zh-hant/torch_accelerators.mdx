# PyTorch 加速器[[pytorch-accelerators]]

LeRobot 的訓練與推論都支援多種硬體加速選項。

這些選項包括：

- **CPU**：所有運算都由 CPU 執行，不使用專用的加速器
- **CUDA**：使用 NVIDIA GPU 加速，並可透過 ROCm 使用 AMD GPU 加速（請參閱 [AMD GPU](#amd-gpus-rocm)）
- **MPS**：使用 Apple Silicon GPU 加速
- **XPU**：使用 Intel 內建與獨立 GPU 加速

## 開始使用[[getting-started]]

要使用特定的加速器，需要安裝對應版本的 PyTorch。

CPU、CUDA 與 MPS 後端請依照 [PyTorch 安裝頁面](https://pytorch.org/get-started/locally)的說明操作。
XPU 後端請依照 [PyTorch 文件](https://docs.pytorch.org/docs/stable/notes/get_start_xpu.html)的說明操作。

### AMD GPU（ROCm）[[amd-gpus-rocm]]

PyTorch 的 ROCm 建置會透過 `torch.cuda` 命名空間公開 HIP 執行環境，因此
`--policy.device=cuda` 會選取 AMD GPU，且不需要在 LeRobot 端做任何變更。若要選取特定顯示卡，建議使用 `HIP_VISIBLE_DEVICES` 而非 `CUDA_VISIBLE_DEVICES`。

在現有的 ROCm PyTorch 上安裝 LeRobot 時需要特別留意：LeRobot 會固定
`torch<2.12`、`torchvision<0.27` 與 `numpy<2.3`，這些版本都低於目前 ROCm 映像檔
所隨附的版本，而且 `[tool.uv.sources]` 會從 CUDA 的 `cu128` 索引解析 torch，因此
未受限的安裝會取代 ROCm 建置，並使 GPU 無法使用。請使用
`uv pip install --override` 固定這些套件，讓其餘相依樹能正常解析。
[`docker/Dockerfile.rocm`](https://github.com/huggingface/lerobot/blob/main/docker/Dockerfile.rocm)
即可完成上述操作，是取得可用環境最快的方式；請參閱
[docker/README.md](https://github.com/huggingface/lerobot/blob/main/docker/README.md)
了解 ROCm 所需的執行旗標。

### 驗證安裝[[verifying-the-installation]]

安裝完成後，可以執行以下程式碼，確認加速器是否可用

```python
import torch
print(torch.<backend_name>.is_available())  # <backend_name> 為 cuda、mps 或 xpu
```

## 如何執行訓練或評估[[how-to-run-training-or-evaluation]]

若要選擇想使用的加速器，請在執行 `lerobot-train` 或 `lerobot-eval` 時使用 `--policy.device` 旗標。例如，要在 Apple Silicon 上使用 MPS，請執行：

```bash
lerobot-train
    --policy.device=mps ...
```

```bash
lerobot-eval \
    --policy.device=mps ...
```

不過在大多數情況下，系統會自動偵測是否有加速器，因此 CLI 指令中可以省略 `policy.device` 參數。

## 混合精度[[mixed-precision]]

訓練精度由 `--accelerator.mixed_precision` 控制，可接受 `no`（預設）、`bf16` 與 `fp16`：

```bash
lerobot-train \
    --policy.type=act \
    --accelerator.mixed_precision=bf16 ...
```

`fp16` 需要加速器：在 `--policy.device=cpu` 上會被拒絕，因為這時 accelerate 不會建立損失縮放器（loss scaler），執行會在不知不覺中退回完整精度。`bf16` 在 CPU 上也能 autocast，因此不受此限制。

`bf16` 需要硬體支援（NVIDIA GPU 需為 Ampere 或更新的架構）。在 V100 或 T4 等較舊的加速器上，請使用 `fp16`。

### fp16 與損失縮放器[[fp16-and-the-loss-scaler]]

`fp16` 的指數範圍比 `bf16` 小得多，因此梯度會在反向傳播之前放大，並在優化器更新之前縮回。LeRobot 將這項工作交給 accelerate 的 `GradScaler`，它也會偵測溢位的梯度，並跳過那些優化器更新。在分片訓練下，梯度是 `DTensor`，PyTorch 會在整個裝置網格（device mesh）上歸約溢位旗標，因此只要有一個 rank 溢位，所有 rank 都會跳過該次更新。

跳過更新是正常的，尤其是在最初幾步，縮放值會從初始值逐步往下調整。在記錄中，這會表現為 `scale` 指標下降。縮放值會隨每個檢查點一起儲存（`training_state/scaler_state.json`），並在接續訓練時還原，因此接續的訓練不必重新調整。

如果預設值不適合某個策略（policy），可以調整縮放器：

```bash
lerobot-train \
    --policy.type=act \
    --accelerator.mixed_precision=fp16 \
    --accelerator.grad_scaler.init_scale=1024 \
    --accelerator.grad_scaler.growth_interval=2000 ...
```
