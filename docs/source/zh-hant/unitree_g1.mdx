# Unitree G1[[unitree-g1]]

<img
  src="https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/lerobot/unitree_thumbnail.jpg"
  alt="Unitree G1 locomanipulation demo"
  style={{ width: "100%" }}
/>

LeRobot 現在支援 Unitree G1 人形機器人！你可以進行遙操作、訓練移動操作（locomanipulation）策略（policy）、在模擬中測試等。29 與 23 自由度（DoF）兩種版本都有支援。

---

## 第 1 部分：開始使用[[part-1-getting-started]]

### 安裝 Unitree SDK[[install-the-unitree-sdk]]

請依照 [unitree_sdk2_python 安裝指南](https://github.com/unitreerobotics/unitree_sdk2_python#installation)操作。已使用 `unitree_sdk2py==1.0.1` 與 `cyclonedds==0.10.2` 測試過：

```bash
conda create -y -n lerobot python=3.12
conda activate lerobot
git clone https://github.com/unitreerobotics/unitree_sdk2_python.git
cd unitree_sdk2_python
pip install -e .
cd ..
```

### 安裝 LeRobot[[install-lerobot]]

```bash
conda install ffmpeg -c conda-forge
conda install -c conda-forge "pinocchio>=3.0.0,<4.0.0"
git clone https://github.com/huggingface/lerobot.git
cd lerobot
pip install -e '.[unitree_g1]'
```

<Tip>
  目前 pinocchio 必須從 conda-forge 安裝（而不是 pip），才會包含手臂 IK 所需的
  CasADi 綁定（binding）。
</Tip>

### 測試安裝（模擬）[[test-the-installation-simulation]]

模擬環境有自己的相依套件，請參閱模擬環境的相依套件說明：[Unitree G1 Mujoco EnvHub](https://huggingface.co/lerobot/unitree-g1-mujoco/tree/main)。

```bash
pip install mujoco loguru msgpack msgpack-numpy
```

```bash
lerobot-teleoperate \
  --robot.type=unitree_g1 \
  --robot.is_simulation=true \
  --teleop.type=unitree_g1 \
  --teleop.id=wbc_unitree \
  --robot.cameras='{"global_view": {"type": "zmq", "server_address": "localhost", "port": 5555, "camera_name": "head_camera", "width": 640, "height": 480, "fps": 30, "warmup_s": 5}}' \
  --display_data=true \
  --robot.controller=GrootLocomotionController
```

這會為 G1 啟動一個 [MuJoCo 模擬實例](https://huggingface.co/lerobot/unitree-g1-mujoco/tree/main)。你可以在啟動前將遊戲手把接上電腦，以便在模擬中控制機器人的移動。我們透過 `--robot.controller` 同時支援 [HolosomaLocomotionController](https://github.com/amazon-far/holosoma) 與 [GrootLocomotionController](https://github.com/NVlabs/GR00T-WholeBodyControl)。

- 按 `9` 釋放機器人
- 按 `7` / `8` 提高／降低腰部高度

#### 選擇末端執行器[[choosing-the-end-effector]]

`--robot.end_effector` 指定手臂所搭載的末端執行器（end effector）：`dex1` 為平行夾爪（預設），`dex3` 為三指手，`dummy` 則是沒有末端執行器的裸手腕。在模擬中，它會決定要使用哪個 MuJoCo 模型，進而決定手指的致動器，以及場景中有哪些相機；腕部相機安裝在末端執行器上，因此 `dummy` 只有 `head_camera`。

```bash
lerobot-teleoperate \
  --robot.type=unitree_g1 \
  --robot.is_simulation=true \
  --robot.end_effector=dex3 \
  --teleop.id=wbc_unitree \
  --robot.controller=GrootLocomotionController
```

模擬會透過 ZMQ，在 `--robot.sim_camera_port`（預設為 5555）上發布模型的相機影像，`--robot.cameras` 中的 `zmq` 相機就是從這裡讀取。若改為傳入 `--robot.sim_publish_images=false`，則會開啟 MuJoCo 的互動視窗：模擬只會渲染相機或視窗其中之一，不會同時渲染兩者，因為離屏（offscreen）的渲染情境屬於建立它的執行緒，而不屬於檢視器的執行緒。`--robot.sim_onscreen` 可以直接指定這個選擇，而不是交由相機設定決定；同時要求兩者會被拒絕。將它與 `--robot.sim_publish_images` 都設為 false，就兩者都不渲染，這也是沒有顯示器的機器唯一能用的做法。

### 連接到實體機器人[[connect-to-the-physical-robot]]

G1 的乙太網路 IP 固定為 `192.168.123.164`。你的電腦必須在同一個子網路上設定靜態 IP：`192.168.123.x`，其中 `x ≠ 164`。

```bash
# 將 'enp131s0' 替換為你的乙太網路介面名稱（以 `ip a` 查看）
sudo ip addr flush dev enp131s0
sudo ip addr add 192.168.123.200/24 dev enp131s0
sudo ip link set enp131s0 up
```

### 以 SSH 連線到機器人[[ssh-into-the-robot]]

```bash
ssh unitree@192.168.123.164
# 密碼：123
```

### 透過乙太網路分享網際網路[[share-internet-via-ethernet]]

G1 需要網際網路才能 clone 儲存庫與安裝套件。請透過乙太網路分享你筆電的網路連線：

**在你的筆電上：**

```bash
sudo sysctl -w net.ipv4.ip_forward=1

# 將 wlp132s0f0 替換為你的 WiFi 介面名稱
sudo iptables -t nat -A POSTROUTING -o wlp132s0f0 -s 192.168.123.0/24 -j MASQUERADE
sudo iptables -A FORWARD -i wlp132s0f0 -o enp131s0 -m state --state RELATED,ESTABLISHED -j ACCEPT
sudo iptables -A FORWARD -i enp131s0 -o wlp132s0f0 -j ACCEPT
```

**在 G1 上：**

```bash
sudo ip route del default 2>/dev/null || true
sudo ip route add default via 192.168.123.200 dev eth0
echo "nameserver 8.8.8.8" | sudo tee /etc/resolv.conf

# 驗證
ping -c 3 8.8.8.8
```

### 在機器人上啟用 WiFi（可選）[[optional-enable-wifi-on-the-robot]]

若要以無線方式 SSH 連線，可以在 G1 上啟用 WiFi（預設為封鎖）：

```bash
sudo rfkill unblock all
sudo ip link set wlan0 up
sudo nmcli radio wifi on
sudo nmcli device set wlan0 managed yes
sudo systemctl restart NetworkManager
```

**連接到 WiFi 網路：**

```bash
nmcli device wifi list

sudo nmcli connection add type wifi ifname wlan0 con-name "YourNetwork" ssid "YourNetwork"
sudo nmcli connection modify "YourNetwork" wifi-sec.key-mgmt wpa-psk
sudo nmcli connection modify "YourNetwork" wifi-sec.psk "YourPassword"
sudo nmcli connection modify "YourNetwork" connection.autoconnect yes
sudo nmcli connection up "YourNetwork"

ip a show wlan0
```

之後就可以改用 WiFi，而不是乙太網路進行 SSH 連線：

```bash
ssh unitree@<ROBOT_WIFI_IP>
# 密碼：123
```

## 第 2 部分：遙操作與移動[[part-2-teleoperation-locomotion]]

### 執行機器人伺服器[[run-the-robot-server]]

在機器人上（於 `~/lerobot` 目錄中）：

```bash
cd ~/lerobot
python src/lerobot/robots/unitree_g1/run_g1_server.py --camera
```

### 執行移動策略[[run-the-locomotion-policy]]

你可以從筆電透過乙太網路、透過 WiFi（實驗性），或直接在機器人上執行遙操作用戶端。請留意網路可能造成的延遲。

**在你的筆電上：**

```bash
lerobot-teleoperate \
  --robot.type=unitree_g1 \
  --robot.is_simulation=false \
  --robot.robot_ip=<ROBOT_IP> \
  --teleop.type=unitree_g1 \
  --teleop.id=wbc_unitree \
  --robot.cameras='{"global_view": {"type": "zmq", "server_address": "<ROBOT_IP>", "port": 5555, "camera_name": "head_camera", "width": 640, "height": 480, "fps": 30}}' \
  --display_data=true \
  --robot.controller=HolosomaLocomotionController
```

我們透過 `--robot.controller` 同時支援 [GrootLocomotionController](https://github.com/NVlabs/GR00T-WholeBodyControl) 與 [HolosomaLocomotionController](https://github.com/amazon-far/holosoma)。

## 第 3 部分：使用 Homunculus 外骨骼進行移動操作[[part-3-loco-manipulation-with-the-homunculus-exoskeleton]]

我們透過 Homunculus 外骨骼提供移動操作（loco-manipulation）的解決方案。這是一款用於全身控制的開源 7 自由度外骨骼，請到[這裡](https://github.com/nepyope/hmc_exo)查看。

### 校正[[calibrate]]

```bash
lerobot-calibrate \
  --teleop.type=unitree_g1 \
  --teleop.left_arm_config.port=/dev/ttyACM1 \
  --teleop.right_arm_config.port=/dev/ttyACM0 \
  --teleop.id=exo
```

校正期間，請讓每個關節走完完整的活動範圍。擬合完成後，將關節移到中立位置，再按 `n` 繼續。

### 錄製資料集[[record-a-dataset]]

```bash
lerobot-record \
  --robot.type=unitree_g1 \
  --robot.is_simulation=true \
  --robot.cameras='{"global_view": {"type": "zmq", "server_address": "localhost", "port": 5555, "camera_name": "head_camera", "width": 640, "height": 480, "fps": 30}}' \
  --teleop.type=unitree_g1 \
  --teleop.left_arm_config.port=/dev/ttyACM1 \
  --teleop.right_arm_config.port=/dev/ttyACM0 \
  --teleop.id=exo \
  --dataset.repo_id=your-username/dataset-name \
  --dataset.single_task="Test" \
  --dataset.num_episodes=2 \
  --dataset.episode_time_s=5 \
  --dataset.reset_time_s=5 \
  --dataset.push_to_hub=true \
  --dataset.streaming_encoding=true \
  --dataset.encoder_threads=2
```

> **注意：** 如果你只使用搖桿，請省略 `--teleop.left_arm_config.port` 與 `--teleop.right_arm_config.port`。

範例資料集：[nepyope/unitree_box_move_blue_full](https://huggingface.co/datasets/nepyope/unitree_box_move_blue_full)

## 第 4 部分：訓練與推論[[part-4-training-inference]]

### 訓練[[train]]

```bash
python src/lerobot/scripts/lerobot_train.py \
  --dataset.repo_id=your-username/dataset-name  \
  --policy.type=pi05 \
  --output_dir=./outputs/pi05_training \
  --job_name=pi05_training \
  --policy.repo_id=your-username/your-repo-id \
  --policy.pretrained_path=lerobot/pi05_base \
  --policy.compile_model=true \
  --policy.gradient_checkpointing=true \
  --wandb.enable=true \
  --policy.dtype=bfloat16 \
  --policy.freeze_vision_encoder=false \
  --policy.train_expert_only=false \
  --steps=3000 \
  --policy.device=cuda \
  --batch_size=32
```

### 使用 RTC 進行推論[[inference-with-rtc]]

相容的已訓練策略可以使用本機推論階段的 RTC：

```bash
lerobot-rollout \
  --strategy.type=base \
  --policy.path=your-username/your-repo-id \
  --policy.device=cuda \
  --robot.type=unitree_g1 \
  --robot.is_simulation=false \
  --robot.controller=HolosomaLocomotionController \
  --robot.cameras='{"global_view": {"type": "zmq", "server_address": "<ROBOT_IP>", "port": 5555, "camera_name": "head_camera", "width": 640, "height": 480, "fps": 30}}' \
  --task="task_description" \
  --duration=1000 \
  --fps=30 \
  --inference.type=rtc
```

G1 的移動控制器未宣告 rollout 的可恢復等待機制所使用的保留目標契約。動作開始後，若其動作緩衝區耗盡，會造成終止性故障，而不是寬限期等待。請求期限與觀測資料的時效上限（observation-age limits）同樣適用。使用此做法前，請先驗證策略可用的區塊能涵蓋推論延遲；參見[本機 RTC 等待與預算](./inference#inference-backends)。SONIC 有另一套保留 token 契約，說明如下。

## 第 5 部分：SONIC 全身控制（latent token 策略）[[part-5-sonic-whole-body-control-latent-token-policies]]

LeRobot 現在將 NVIDIA [SONIC](https://nvlabs.github.io/GEAR-SONIC/) 全身控制部署架構中的**解碼器**部分，移植為 `SonicWholeBodyController`。策略不再直接命令各個關節，而是在每個控制週期輸出 64 維的 **latent motion token**（`motion_token.{i}.pos`）；SONIC 解碼器會將這個 token 與近期的本體感覺（proprioception）歷史，對應成一個殘差動作（action），經過縮放後加到站立姿態上，為全部 29 個自由度產生 50 Hz 的關節位置目標。

控制器會從 [`lerobot/sonic_decoder`](https://huggingface.co/lerobot/sonic_decoder) 載入 ONNX 解碼器與所有部署常數（PD 增益、`default_angles`、`action_scale` 以及中性 token）。這個儲存庫也提供蒸餾過的低延遲解碼器，可透過控制器的 `policy_type="low_latency"` 引數選用（預設為 `"default"`）。

### 在模擬中測試[[test-in-simulation]]

任何以 SONIC motion token 訓練、會輸出 token 的策略（例如 [`nepyope/sonic_walk`](https://huggingface.co/nepyope/sonic_walk)）都可以驅動它：

```bash
lerobot-rollout \
  --strategy.type=base \
  --policy.path=nepyope/sonic_walk \
  --policy.device=cuda \
  --robot.type=unitree_g1 \
  --robot.is_simulation=true \
  --robot.controller=SonicWholeBodyController \
  --robot.cameras='{"ego_view": {"type": "zmq", "server_address": "localhost", "port": 5555, "camera_name": "head_camera", "width": 640, "height": 480, "fps": 30, "warmup_s": 15}}'
```

### 在實體機器人上執行[[run-on-the-physical-robot]]

在 GPU 機器上執行[遠端推論](./remote_inference)策略伺服器，並將機器人橋接器、SONIC 解碼器與 rollout 用戶端留在 G1 Jetson 上。只有 64 維的 token 區塊會經過網路；解碼器與 50 Hz 的 `rt/lowcmd` 迴圈仍留在機器人上。

在兩台機器上安裝 remote 額外套件。在 G1 上則保留 Unitree 額外套件：

```bash
# GPU 機器
python -m pip install -e '.[remote]'

# G1 Jetson
python -m pip install -e '.[unitree_g1,remote]'
```

在 GPU 機器上，從儲存庫根目錄啟動策略伺服器。維護中的設定檔對應 `nepyope/sonic_walk`；若要改用其他策略，請一併複製並更新其檢查點與特徵契約。

```bash
lerobot-policy-server \
  --config_path=examples/remote_inference/unitree_g1_sonic.yaml
```

在 G1 上，讓橋接器與相機保持執行：

```bash
python src/lerobot/robots/unitree_g1/run_g1_server.py --camera
```

接著在 G1 的第二個終端機中啟動 rollout 使用者端，並將 `<GPU_MACHINE_IP>` 替換掉：

```bash
lerobot-rollout \
  --strategy.type=base \
  --inference.type=remote \
  --inference.endpoint=tcp/<GPU_MACHINE_IP>:7447 \
  --inference.deployment=g1-sonic \
  --inference.semantics=unitree-g1-sonic-motion-token-v1 \
  --inference.encoding=jpeg \
  --inference.action_starvation_grace_s=1.0 \
  --robot.type=unitree_g1 \
  --robot.is_simulation=false \
  --robot.robot_ip=127.0.0.1 \
  --robot.controller=SonicWholeBodyController \
  --robot.cameras='{"ego_view": {"type": "zmq", "server_address": "127.0.0.1", "port": 5555, "camera_name": "head_camera", "width": 640, "height": 480, "fps": 30, "warmup_s": 5}}' \
  --task='walk forward' \
  --fps=30 \
  --return_to_initial_position=false \
  --interactive=true
```

只有在 G1 可安全移動後，才輸入 `/start`。SONIC 宣告支援等待，因為重新傳送最後一個完整 token 可讓機上解碼器維持平衡。在第一個策略結果出現之前，rollout 會傳送解碼器的中性 token。如果動作緩衝區耗盡，它會重複最後套用的 token，最多持續 `action_starvation_grace_s`（上述為一秒）；如果沒有新的預測送達，rollout 會發生故障，並依照其設定的關閉／中斷連線路徑處理。G1 移動控制器仍不受支援，因為其搖桿速度無法以這種方式保留。

此做法會停用返回初始位置：透過 SONIC 的 latent token 空間進行插值，並不是經過驗證的實體歸位軌跡。基於相同理由，請避免使用 `/reset`，因為它會將 token 掃回連線時的值。`/stop` 仍會關閉遠端工作階段，並透過一般控制器關閉路徑中斷與機器人的連線。

使用 `SonicWholeBodyController` 時，觀測狀態是 64 維的 token 回傳值，而不是 29 個關節位置，因此相容的檢查點必須以該狀態訓練。連線時，機器人會先讓關節平順地移動到解碼器的 `default_angles`，控制器才接手。
