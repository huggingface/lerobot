# 在真實世界機器人上進行模仿學習[[imitation-learning-on-real-world-robots]]

本教學將說明如何訓練神經網路，讓它自主控制真實的機器人。

**你將學到：**

1. 如何錄製並視覺化你的資料集。
2. 如何用你的資料訓練策略（policy），並為評估做好準備。
3. 如何評估你的策略並視覺化結果。

完成這些步驟後，你就能重現各種任務，例如以很高的成功率撿起樂高積木並放進箱子裡，如下方影片所示。

## 設定與校正[[set-up-and-calibrate]]

## 遙操作[[teleoperate]]

在這個範例中，我們會示範如何遙操作（teleoperate）SO101 機器人。每個指令也都附有對應的 API 範例。

請注意，機器人的 `id` 會用來儲存校正檔案。在同一套設定下進行遙操作、錄製與評估時，務必使用相同的 `id`。

<hfoptions id="teleoperate_so101">
<hfoption id="Command">
```bash
lerobot-teleoperate \
    --robot.type=so101_follower \
    --robot.port=/dev/tty.usbmodem58760431541 \
    --robot.id=my_awesome_follower_arm \
    --teleop.type=so101_leader \
    --teleop.port=/dev/tty.usbmodem58760431551 \
    --teleop.id=my_awesome_leader_arm
```
</hfoption>
<hfoption id="API example">

<!-- prettier-ignore-start -->
```python
from lerobot.teleoperators.so_leader import SO101Leader, SO101LeaderConfig
from lerobot.robots.so_follower import SO101Follower, SO101FollowerConfig

robot_config = SO101FollowerConfig(
    port="/dev/tty.usbmodem5AB90687491",
    id="my_follower_arm",
)

teleop_config = SO101LeaderConfig(
    port="/dev/tty.usbmodem5AB90689011",
    id="my_leader_arm",
)

robot = SO101Follower(robot_config)
teleop_device = SO101Leader(teleop_config)
robot.connect()
teleop_device.connect()

while True:
    action = teleop_device.get_action()
    robot.send_action(action)
```
<!-- prettier-ignore-end -->

</hfoption>
</hfoptions>

1. 找出尚未完成的校正，並啟動校正程序。
2. 連接機器人與遙操作裝置，並開始遙操作。

## 搭配相機進行遙操作[[teleoperate-with-cameras]]

使用 `rerun`，你可以在遙操作的同時，即時視覺化相機畫面與關節位置。這個範例使用的是 Koch 手臂。

<hfoptions id="teleoperate_koch_camera">
<hfoption id="Command">
```bash
lerobot-teleoperate \
    --robot.type=so101_follower \
    --robot.port=/dev/tty.usbmodem5AB90687491 \
    --robot.id=my_follower_arm \
    --robot.cameras="{front: {type: opencv, index_or_path: 0, width: 640, height: 480, fps: 30}}" \
    --teleop.type=so101_leader \
    --teleop.port=/dev/tty.usbmodem5AB90689011 \
    --teleop.id=my_leader_arm \
    --display_data=true
```
</hfoption>
<hfoption id="API example">

<!-- prettier-ignore-start -->
```python
import time
from lerobot.teleoperators.so_leader import SO101Leader, SO101LeaderConfig
from lerobot.robots.so_follower import SO101Follower, SO101FollowerConfig
from lerobot.cameras.opencv import OpenCVCameraConfig
from lerobot.utils.visualization_utils import init_visualization, log_visualization_data, shutdown_visualization

robot_config = SO101FollowerConfig(
    port="/dev/tty.usbmodem5AB90687491",
    id="my_follower_arm",
    cameras={
        "wrist": OpenCVCameraConfig(index_or_path=0, width=640, height=480, fps=30),
        "top": OpenCVCameraConfig(index_or_path=1, width=640, height=480, fps=30)
    }
)

teleop_config = SO101LeaderConfig(
    port="/dev/tty.usbmodem5AB90689011",
    id="my_leader_arm",
)

init_visualization("rerun", session_name="teleoperation")  # 傳入 "foxglove" 可改為串流到 Foxglove

robot = SO101Follower(robot_config)
teleop_device = SO101Leader(teleop_config)
robot.connect()
teleop_device.connect()

TARGET_HZ = 30
TIME_PER_FRAME = 1.0 / TARGET_HZ

while True:
    start_time = time.perf_counter()

    observation = robot.get_observation()
    action = teleop_device.get_action()
    robot.send_action(action)
    log_visualization_data("rerun", observation=observation, action=action)

    elapsed_time = time.perf_counter() - start_time
    sleep_time = TIME_PER_FRAME - elapsed_time
    if sleep_time > 0:
        time.sleep(sleep_time)
```

## 錄製資料集[[record-a-dataset]]

熟悉遙操作之後，就可以錄製你的第一個資料集（dataset）。

我們使用 Hugging Face Hub 的功能上傳資料集。如果你之前沒用過 Hub，請確認你能透過 CLI，使用具寫入權限的存取權杖（access token）登入。存取權杖可在 [Hugging Face 設定](https://huggingface.co/settings/tokens)頁面產生。

執行以下指令，將你的存取權杖加入 CLI：

```bash
hf auth login --token ${HUGGINGFACE_TOKEN} --add-to-git-credential
```

接著將你的 Hugging Face 儲存庫名稱存入變數：

```bash
HF_USER=$(NO_COLOR=1 hf auth whoami | awk -F': *' 'NR==1 {print $2}')
echo $HF_USER
```

現在可以開始錄製資料集了。若要錄製 5 個回合（episode）並將資料集上傳到 Hub，請依你的機器人調整下方程式碼，再執行指令或 API 範例。

<hfoptions id="record">
<hfoption id="Command">
```bash
lerobot-record \
    --robot.type=so101_follower \
    --robot.port=/dev/tty.usbmodem585A0076841 \
    --robot.id=my_awesome_follower_arm \
    --robot.cameras="{ front: {type: opencv, index_or_path: 0, width: 1920, height: 1080, fps: 30}}" \
    --teleop.type=so101_leader \
    --teleop.port=/dev/tty.usbmodem58760431551 \
    --teleop.id=my_awesome_leader_arm \
    --display_data=true \
    --dataset.repo_id=${HF_USER}/record-test \
    --dataset.num_episodes=5 \
    --dataset.single_task="Grab the black cube" \
    --dataset.streaming_encoding=true \
    --dataset.encoder_threads=2
# 可選：--dataset.rgb_encoder.vcodec=auto
```
</hfoption>
<hfoption id="API example">

<!-- prettier-ignore-start -->
```python
from lerobot.cameras.opencv import OpenCVCameraConfig
from lerobot.datasets.lerobot_dataset import LeRobotDataset
from lerobot.utils.feature_utils import hw_to_dataset_features
from lerobot.robots.so_follower import SO101Follower, SO101FollowerConfig
from lerobot.teleoperators.so_leader.config_so_leader import SO101LeaderConfig
from lerobot.teleoperators.so_leader.so_leader import SO101Leader
from lerobot.common.control_utils import init_keyboard_listener
from lerobot.utils.utils import log_say
from lerobot.utils.visualization_utils import init_visualization
from lerobot.scripts.lerobot_record import record_loop
from lerobot.processor import make_default_processors

NUM_EPISODES = 5
FPS = 30
EPISODE_TIME_SEC = 60
RESET_TIME_SEC = 10
TASK_DESCRIPTION = "My task description"

def main():
    # 建立機器人設定
    robot_config = SO101FollowerConfig(
        port="/dev/tty.usbmodem5AB90687491",
        id="my_follower_arm",
        cameras={
            "wrist": OpenCVCameraConfig(index_or_path=0, width=640, height=480, fps=30),
            "top": OpenCVCameraConfig(index_or_path=1, width=640, height=480, fps=30)
        }
    )

    teleop_config = SO101LeaderConfig(
        port="/dev/tty.usbmodem5AB90689011",
        id="my_leader_arm",
    )

    # 初始化機器人和遙操作器
    robot = SO101Follower(robot_config)
    teleop = SO101Leader(teleop_config)

    # 設定資料集特徵
    action_features = hw_to_dataset_features(robot.action_features, "action")
    obs_features = hw_to_dataset_features(robot.observation_features, "observation")
    dataset_features = {**action_features, **obs_features}

    # 建立資料集
    dataset = LeRobotDataset.create(
        repo_id="<hf_username>/<dataset_repo_id>",
        fps=FPS,
        features=dataset_features,
        robot_type=robot.name,
        use_videos=True,
        image_writer_threads=4,
    )

    # 初始化鍵盤監聽器和 rerun 視覺化
    _, events = init_keyboard_listener()
    init_visualization("rerun", session_name="recording")

    # 連接機器人和遙操作器
    robot.connect()
    teleop.connect()

    # 建立所需的處理器
    teleop_action_processor, robot_action_processor, robot_observation_processor = make_default_processors()

    episode_idx = 0
    while episode_idx < NUM_EPISODES and not events["stop_recording"]:
        log_say(f"Recording episode {episode_idx + 1} of {NUM_EPISODES}")

        record_loop(
            robot=robot,
            events=events,
            fps=FPS,
            teleop_action_processor=teleop_action_processor,
            robot_action_processor=robot_action_processor,
            robot_observation_processor=robot_observation_processor,
            teleop=teleop,
            dataset=dataset,
            control_time_s=EPISODE_TIME_SEC,
            single_task=TASK_DESCRIPTION,
            display_data=True,
        )

        # 如果不是停止錄製或重新錄製，則重設環境
        if not events["stop_recording"] and (episode_idx < NUM_EPISODES - 1 or events["rerecord_episode"]):
            log_say("Reset the environment")
            record_loop(
                robot=robot,
                events=events,
                fps=FPS,
                teleop_action_processor=teleop_action_processor,
                robot_action_processor=robot_action_processor,
                robot_observation_processor=robot_observation_processor,
                teleop=teleop,
                control_time_s=RESET_TIME_SEC,
                single_task=TASK_DESCRIPTION,
                display_data=True,
            )

        if events["rerecord_episode"]:
            log_say("Re-recording episode")
            events["rerecord_episode"] = False
            events["exit_early"] = False
            dataset.clear_episode_buffer()
            continue

        dataset.save_episode()
        episode_idx += 1

    # 完成資料集
    log_say("Finalizing dataset...")
    dataset.finalize()
    # 清理資源
    log_say("Stop recording")
    robot.disconnect()
    teleop.disconnect()
    dataset.push_to_hub()


if __name__ == "__main__":
    main()
```

#### 資料集上傳[[dataset-upload]]

資料集在本機會儲存在這個資料夾：`~/.cache/huggingface/lerobot/{repo-id}`。錄製結束後，資料集會上傳到你的 Hugging Face 頁面（例如 `https://huggingface.co/datasets/${HF_USER}/record-test`），你可以執行以下指令取得網址：

```bash
echo https://huggingface.co/datasets/${HF_USER}/record-test
```

你的資料集會自動標上 `LeRobot` 標籤，方便社群找到；你也可以加上自訂標籤（例如這裡的 `tutorial`）。

你可以在 Hub 上搜尋 `LeRobot` [標籤](https://huggingface.co/datasets?other=LeRobot)，瀏覽其他 LeRobot 資料集。

你也可以手動將本機資料集推送到 Hub，執行：

```bash
hf upload ${HF_USER}/record-test ~/.cache/huggingface/lerobot/{repo-id} --repo-type dataset
```

#### 錄製功能[[record-function]]

`record` 功能提供了一套在機器人運作期間擷取與管理資料的工具：

##### 1. 資料儲存[[1-data-storage]]

- 資料以 `LeRobotDataset` 格式儲存，並在錄製期間寫入磁碟。
- 預設情況下，錄製完成後資料集會推送到你的 Hugging Face 頁面。
  - 若要停用上傳，請使用 `--dataset.push_to_hub=False`。

##### 2. 檢查點的建立與接續[[2-checkpointing-and-resuming]]

- 錄製過程中會自動建立檢查點（checkpoint）。
- 如果發生問題，或你想在同一個資料集中錄製更多回合（episode），可以加上 `--resume=true` 重新執行相同的指令來接續（resume）錄製。接續錄製時，`--dataset.num_episodes` 必須設定為**這次要額外錄製的回合數**，而不是資料集的目標總回合數！同時也請設定 `--dataset.root="local_path"`，這是存放資料集新增部分的本機路徑，接續錄製時必須提供。
- 若要從頭開始錄製，請**手動刪除**資料集目錄。

##### 3. 錄製參數[[3-recording-parameters]]

使用命令列引數設定資料錄製的流程：

- `--dataset.episode_time_s=60`
  每個錄製回合的時長（預設：**60 秒**）。
- `--dataset.reset_time_s=60`
  每個回合結束後重設環境的時長（預設：**60 秒**）。
- `--dataset.num_episodes=50`
  要錄製的總回合數（預設：**50**）。

##### 4. 錄製期間的鍵盤控制[[4-keyboard-controls-during-recording]]

使用鍵盤快捷鍵控制資料錄製流程：

- 按下**右方向鍵（`→`）**或 **`n`**：提早結束目前的回合或重設時間，並進入下一個。
- 按下**左方向鍵（`←`）**或 **`r`**：取消目前的回合並重新錄製。
- 按下 **Escape（`ESC`）**或 **`q`**：立即停止錄製工作階段，編碼影片並上傳資料集。

<Tip>

這些流程控制快捷鍵在 **X11、Wayland 以及無頭（headless）／SSH** 工作階段上都能使用。若無法使用全域鍵盤後端（Wayland、無頭機器，或未授予輔助使用權限的 macOS），`lerobot-record` 會自動改從終端機讀取相同的按鍵——請從互動式終端機啟動它，並保持該視窗在前景。你也可以使用對應的字母鍵 **`n`**（下一個，等同 `→`）、**`r`**（重新錄製，等同 `←`）以及 **`q`**（結束，等同 `ESC`）。不需要設定 `$DISPLAY`。

這只適用於錄製的流程控制。鍵盤**遙操作**（用鍵盤操控機器人）仍需要全域的按鍵後端，因此只能在 X11 工作階段、Windows 桌面，或已授予輔助使用／輸入監控權限的 macOS 上使用，無法在 Wayland 或無頭工作階段上使用。

</Tip>

#### 收集資料的技巧[[tips-for-gathering-data]]

熟悉資料錄製之後，就可以建立更大的資料集來訓練。一個很好的入門任務，是在不同位置抓取物體並放進箱子裡。我們建議至少錄製 50 個回合，每個位置 10 個回合。錄製過程中請保持相機固定，抓取動作也要一致。同時也要確認你操作的物體在相機畫面中看得到。一個實用的判斷原則是：只看相機畫面，你自己也能完成這個任務。

在接下來的章節中，你將訓練自己的神經網路。抓取表現穩定之後，就可以在收集資料時逐步加入更多變化，例如更多抓取位置、不同的抓取方式，以及改變相機位置。

不要太快加入太多變化，否則可能會影響結果。

如果想更深入了解這個重要主題，可以參考我們寫的[部落格文章](https://huggingface.co/blog/lerobot-datasets#what-makes-a-good-dataset)，說明怎樣才是好的資料集。

#### 節奏回報[[cadence-reporting]]

`lerobot-record` 會依 `--dataset.fps` 控制迴圈的節奏，並回報實際達到的成果：每個保留下來的回合都會有一行摘要；錄製結束時（包括按下 `Ctrl-C`），則會輸出一段涵蓋整個工作階段的報告。

```
Cadence (episode 0): 29.88 Hz vs 30 Hz target · 600 ticks, 20.0 s measured · 8/599 ticks over the 33.3 ms budget (work mean 18.4 ms, worst 45.1 ms)
Cadence (episode 1): 29.88 Hz vs 30 Hz target · 600 ticks, 20.0 s measured · 8/599 ticks over the 33.3 ms budget (work mean 18.4 ms, worst 45.1 ms)
Cadence summary — whole run, 2 episodes · target 30 Hz (33.3 ms budget per tick): 1200 ticks, 1198 judged
  effective cadence: 29.88 Hz over 40.1 s measured
  ticks over the 33.3 ms work budget: 16/1198 (1.3%) — work mean 18.4 ms, worst 45.1 ms
  loop-body steps (share of measured work):
    observe      mean  13.65 ms · worst  40.20 ms ·  74.4% of work · 1200 calls
    process_obs  mean   0.30 ms · worst   0.30 ms ·   1.6% of work · 1200 calls
    teleop       mean   1.80 ms · worst   1.80 ms ·   9.8% of work · 1200 calls
    send         mean   0.90 ms · worst   0.90 ms ·   4.9% of work · 1200 calls
    record       mean   1.70 ms · worst   1.90 ms ·   9.3% of work · 1200 calls
  pacing headroom: 15.1 ms slept per tick on average (max 16.7 ms) — near zero means the loop is saturated
```

在用這個資料集訓練之前，很值得先讀一下這份報告。影格的時間戳記是由索引推算出來的，因此一個實際以 25 Hz 執行的工作階段，產生的資料集仍會*標示*為 30——錄下來的動作就會比實際更快。在上面的例子中，`observe` 佔了迴圈工作量的 74%，其 `worst` 為 40 ms，而預算只有 33.3 ms：讓那 16 個控制週期（tick）超時的正是相機。**pacing headroom** 接近零，代表已經沒有餘裕吸收一次較慢的控制週期。

回合之間的重設階段也以相同方式控制節奏，但因為不會錄製任何內容，所以刻意不計入這些數字。`lerobot-teleoperate` 與 `lerobot-replay` 也以相同方式回報，而 `lerobot-rollout` 會額外加上[節奏回報](./inference#cadence-reporting)中說明的內插相關資訊。

#### 疑難排解[[troubleshooting]]

- 在 Linux 上，只要 `lerobot-record` 在互動式終端機中執行，錄製流程的控制按鍵（方向鍵、Escape）在 X11、Wayland 與無頭／SSH 工作階段上都能使用，不需要設定 `$DISPLAY`。如果按鍵沒有反應，請確認你使用的是互動式（TTY）終端機，而不是管線或非 TTY 的工作階段，而且該視窗在前景；也可以改用對應的字母鍵 `n` / `r` / `q`。鍵盤*遙操作*（而非錄製流程控制）仍需要全域的按鍵後端，也就是 X11 工作階段、Windows 桌面，或已授予輔助使用／輸入監控權限的 macOS，無法在 Wayland 或無頭機器上使用。請參閱 [pynput 的限制](https://pynput.readthedocs.io/en/latest/limitations.html#linux)。

## 視覺化資料集[[visualize-a-dataset]]

## 回合重播[[replay-an-episode]]

`replay` 是一個很實用的功能，可以重播你錄製的任何回合，或任何現有資料集中的回合。它能幫你測試機器人動作的可重複性，並評估同型號機器人之間的可轉移性。

你可以使用以下指令或 API 範例，在機器人上重播第一個回合：

<hfoptions id="replay">
<hfoption id="Command">
```bash
lerobot-replay \
    --robot.type=so101_follower \
    --robot.port=/dev/tty.usbmodem58760431541 \
    --robot.id=my_awesome_follower_arm \
    --dataset.repo_id=${HF_USER}/record-test \
    --dataset.episode=0 # 選擇你想要重播的回合
```
</hfoption>
<hfoption id="API example">

<!-- prettier-ignore-start -->
```python
import time

from lerobot.datasets import LeRobotDataset
from lerobot.robots.so_follower import SO100Follower, SO100FollowerConfig
from lerobot.utils.robot_utils import precise_sleep
from lerobot.utils.utils import log_say

episode_idx = 0

robot_config = SO100FollowerConfig(port="/dev/tty.usbmodem5AB90687491", id="my_follower_arm")

robot = SO100Follower(robot_config)
robot.connect()

dataset = LeRobotDataset("<hf_username>/<dataset_repo_id>", episodes=[episode_idx])
actions = dataset.select_columns("action")

log_say(f"Replaying episode {episode_idx}")
for idx in range(dataset.num_frames):
    t0 = time.perf_counter()

    action = {
        name: float(actions[idx]["action"][i]) for i, name in enumerate(dataset.features["action"]["names"])
    }
    robot.send_action(action)

    precise_sleep(max(1.0 / dataset.fps - (time.perf_counter() - t0), 0.0))

robot.disconnect()
```
<!-- prettier-ignore-end -->

</hfoption>
</hfoptions>

你的機器人應該會重現與錄製時相似的動作。例如，可以看看[這段影片](https://x.com/RemiCadene/status/1793654950905680090)，我們在 [Trossen Robotics](https://www.trossenrobotics.com) 的 Aloha 機器人上使用了 `replay`。

## 訓練策略[[train-a-policy]]

若要訓練策略（policy）來控制你的機器人，請使用 [`lerobot-train`](https://github.com/huggingface/lerobot/blob/main/src/lerobot/scripts/lerobot_train.py) 腳本，並提供幾個必要的引數。以下是範例指令：

```bash
lerobot-train \
  --dataset.repo_id=${HF_USER}/record-test \
  --policy.type=act \
  --output_dir=outputs/train/act_so101_test \
  --job_name=act_so101_test \
  --policy.device=cuda \
  --wandb.enable=true \
  --policy.repo_id=${HF_USER}/my_policy
```

我們來說明這個指令：

1. 我們以 `--dataset.repo_id=${HF_USER}/record-test` 指定稍早錄製的資料集。
2. 我們以 `policy.type=act` 指定策略，這會從 [`configuration_act.py`](https://github.com/huggingface/lerobot/blob/main/src/lerobot/policies/act/configuration_act.py) 載入設定。重要的是，這個策略會自動配合資料集中記錄的機器人馬達狀態數、馬達動作數與相機（例如 `laptop` 和 `phone`）。
3. 因為我們使用 Nvidia GPU 訓練，所以設定 `policy.device=cuda`；若要在 Apple silicon 上訓練，可以改用 `policy.device=mps`。
4. 我們設定 `wandb.enable=true`，使用 [Weights and Biases](https://docs.wandb.ai/quickstart) 視覺化訓練曲線。這是可選的，但若要使用，請先執行 `wandb login` 登入。

訓練需要數小時。檢查點（checkpoint）會存放在 `outputs/train/act_so101_test/checkpoints`。

若要從檢查點接續（resume）訓練，以下範例指令會從 `act_so101_test` 策略的 `last` 檢查點接續：

```bash
lerobot-train \
  --config_path=outputs/train/act_so101_test/checkpoints/last/pretrained_model/train_config.json \
  --resume=true
```

`--config_path` 也接受 **Hub repo id**：如果某次執行已將檢查點推送到 Hub（使用 `--save_checkpoint_to_hub=true`），就可以直接從該儲存庫接續訓練。它會下載最新的檢查點並繼續訓練，同時還原優化器、排程器、步數計數與資料順序：

```bash
lerobot-train --config_path=${HF_USER}/my_policy --resume=true
```

如果訓練後不想將模型推送到 Hub，請使用 `--policy.push_to_hub=false`。

此外，你可以為模型加上額外的 `tags`、指定 `license`，或將模型儲存庫設為 `private`：`--policy.private=true --policy.tags=\[ppo,rl\] --policy.license=mit`

#### 使用 Google Colab 訓練[[train-using-google-colab]]

如果你的電腦沒有強大的 GPU，可以依照 [ACT 訓練 notebook](./notebooks#training-act)，使用 Google Colab 訓練模型。

#### 使用 Hugging Face Jobs 訓練[[train-using-hugging-face-jobs]]

Hugging Face Jobs 讓你能輕鬆選擇硬體，並在雲端執行訓練。所以如果你沒有強大的 GPU、需要更多 VRAM，或只是想更快訓練模型，就用 HF Jobs 吧！它採用依用量計費，只需為實際使用的每一秒付費，價格與其他資訊請參閱[這裡](https://huggingface.co/docs/hub/jobs)。

`lerobot-train` 預設會在本機執行。若要在 Hugging Face 的 GPU 上執行，請傳入 `--job.target` 並指定硬體 flavor 名稱：

```bash
lerobot-train \
  --dataset.repo_id=${HF_USER}/record-test \
  --policy.type=act \
  --policy.repo_id=${HF_USER}/my_policy \
  --job.target=a10g-small
```

執行 `hf jobs hardware` 可列出可用的 flavor 與價格。執行時會將日誌串流到你的終端機；按下 Ctrl-C 可中斷連線（Job 仍會在雲端繼續執行）。若要重新連線或取消，請使用：

```bash
hf jobs logs <job-id>
hf jobs cancel <job-id>
```

如果你的資料集只存在本機（尚未上傳到 Hub），它會自動推送到一個**私有**的 Hub 儲存庫，讓 Job 能透過 `repo_id` 下載（不會公開任何內容）。訓練好的模型會在執行結束時推送到模型儲存庫。若希望每個中間檢查點在儲存時也推送到 Hub（方便在執行過程中監控進度），請加上 `--save_checkpoint_to_hub=true`，這需要使用包含此功能的執行環境映像檔（runtime image）。

每個 Job（以及執行時推送的資料集）都會標上 `lerobot` 標籤，方便在 Hub 上尋找。你可以用 `--job.tags '["my-tag"]'` 加上自己的標籤。

Job 預設的實際執行時間上限是 `2d`（48 小時）。你可以用 HF Jobs 的時長字串覆寫，例如 `--job.timeout=4h` 讓失敗的執行更快結束，或 `--job.timeout=7d` 執行更久。

> **注意：** 模型儲存庫會事先建立（裡面存放 Job 執行時使用的訓練設定）。如果某次執行在模型推送前就失敗，該儲存庫會留在 Hub 上供你檢查；它不會自動刪除，所以多次失敗可能會留下空的儲存庫。可以用 `hf repo delete <repo-id>` 刪除。

**事前準備：** 提交前請先執行 `hf auth login`。若要整合 Weights & Biases，請執行 `wandb login`，或在你的機器上設定 `WANDB_API_KEY`——這個金鑰會自動傳給 Job。

**在 Job 上接續訓練。** 在接續指令中加上 `--job.target`，就會改在雲端接續訓練——同一個指令在本機或遠端都能使用。檢查點儲存庫是唯一的依據，新的檢查點會繼續存放在同一個儲存庫中：

```bash
# 在 Job 上接續一個 Hub 執行（其檢查點已在 Hub 上）
lerobot-train --config_path=${HF_USER}/my_policy --resume=true --job.target=a10g-small

# 在 Job 上接續一個本機執行；檢查點會先被上傳到一個私有的 Hub 儲存庫，
# 接著 Job 從它接續（僅存於本機的資料集也以相同方式上傳）
lerobot-train \
  --config_path=outputs/train/act_so101_test/checkpoints/last/pretrained_model/train_config.json \
  --resume=true \
  --job.target=a10g-small
```

Job 的設定取自目前的指令，因此請視需要覆寫 `--job.target`、`--job.timeout` 等；若希望接續後的執行之後也能再接續，請保留 `--save_checkpoint_to_hub=true`。

#### 上傳策略的檢查點[[upload-policy-checkpoints]]

訓練完成後，使用以下指令上傳最新的檢查點：

```bash
hf upload ${HF_USER}/act_so101_test \
  outputs/train/act_so101_test/checkpoints/last/pretrained_model
```

你也可以上傳中間的檢查點：

```bash
CKPT=010000
hf upload ${HF_USER}/act_so101_test${CKPT} \
  outputs/train/act_so101_test/checkpoints/${CKPT}/pretrained_model
```

## 執行推論並評估你的策略[[run-inference-and-evaluate-your-policy]]

使用 `lerobot-rollout` 在你的機器人上部署訓練好的策略。你可以依需求選擇不同的執行策略（strategy）：

下方範例會從 `--policy.path` 載入模型。若要指定某個已推送的版本（在 `--save_checkpoint_to_hub=true` 提交了多個檢查點後特別有用），請加上 `--policy.pretrained_revision`，並提供 commit hash、分支或標籤。每個推送的檢查點都會以其步數作為標籤（例如 `--policy.pretrained_revision=010000`），因此可以直接依步數取回檢查點，不必查詢 commit sha。

<hfoptions id="eval">
<hfoption id="Base mode (no recording)">
```bash
lerobot-rollout \
  --strategy.type=base \
  --policy.path=${HF_USER}/my_policy \
  --robot.type=so100_follower \
  --robot.port=/dev/ttyACM1 \
  --robot.cameras="{ up: {type: opencv, index_or_path: /dev/video10, width: 640, height: 480, fps: 30}, side: {type: intelrealsense, serial_number_or_name: 233522074606, width: 640, height: 480, fps: 30}}" \
  --task="Put lego brick into the transparent box" \
  --duration=60
```
</hfoption>
<hfoption id="Sentry mode (with recording)">
```bash
lerobot-rollout \
  --strategy.type=sentry \
  --strategy.upload_every_n_episodes=5 \
  --policy.path=${HF_USER}/my_policy \
  --robot.type=so100_follower \
  --robot.port=/dev/ttyACM1 \
  --robot.cameras="{ up: {type: opencv, index_or_path: /dev/video10, width: 640, height: 480, fps: 30}, side: {type: intelrealsense, serial_number_or_name: 233522074606, width: 640, height: 480, fps: 30}}" \
  --dataset.repo_id=${HF_USER}/eval_so100 \
  --dataset.single_task="Put lego brick into the transparent box" \
  --duration=600
```
</hfoption>
</hfoptions>

`--strategy.type` 旗標用來選擇執行模式：

- `base`：不錄製資料的自主 rollout（適合快速評估）
- `sentry`：持續錄製並自動上傳（適合大規模評估）
- `highlight`：以環形緩衝區錄製，按鍵即可儲存（適合擷取有趣的事件）
- `dagger`：人在迴圈（human-in-the-loop）的資料收集（請參閱 [HIL 資料收集](./hil_data_collection)）
- `episodic`：以回合為單位執行策略並錄製，回合之間有重設階段

所有執行策略都支援 `--inference.type=rtc`，讓速度較慢的 VLA 模型（Pi0、Pi0.5、SmolVLA）也能流暢執行。
