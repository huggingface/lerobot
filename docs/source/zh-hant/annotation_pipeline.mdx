# 標註管線[[annotation-pipeline]]

`lerobot-annotate` 會以視覺語言模型（VLM）觀看每個回合（episode）的
影片，並將自然語言標註寫回你的資料集。它會把
[語言欄位與配方](./language_and_recipes)頁面所介紹的
兩個語言欄位——`language_persistent` 與
`language_events`——直接寫入
`data/chunk-*/file-*.parquet`。

簡單來說：把它指向一個 LeRobot 資料集，它就會加入子任務、規劃、
記憶、插話、語音與視覺問答，讓策略（policy）可以
用來訓練。

## 各部分如何組合[[how-it-fits-together]]

```text
  your dataset                  lerobot-annotate
  (LeRobot v3.1)
        │
        ▼
  ┌─────────────────────────────────────────────────────┐
  │                    read episodes                     │
  └──────────────────────────┬──────────────────────────┘
                             │
        ┌────────────────────┼────────────────────┐
        ▼                    ▼                     ▼
  ┌──────────┐      ┌───────────────┐        ┌──────────┐       one shared Qwen-VL
  │   plan   │      │ interjections │        │   vqa    │  ◀──   server (vLLM, OpenAI
  └────┬─────┘      └───────┬───────┘        └────┬─────┘        API) drives all three
       └────────────────────┼─────────────────────┘
                            │   each module stages raw JSONL
                            ▼   into .annotate_staging/
                  ┌─────────────────┐
                  │    validator    │  ◀──  checks everything
                  └────────┬────────┘
                           ▼
                  ┌─────────────────┐
                  │     writer      │
                  └────────┬────────┘
                           ▼
              data/chunk-*/file-*.parquet
              (+ meta/info.json tools)
```

三個模組（`plan`、`interjections`、`vqa`）全都與**同一個**共用的
VLM 溝通。每個模組會先把輸出暫存到磁碟，經過驗證器檢查後，再由
單一的寫入器就地改寫資料集的分片（shard）。

## 管線產生什麼[[what-the-pipeline-produces]]

每個模組會產生幾種標註（稱為「樣式」，style），並寫入兩個語言欄位
其中之一：

| 樣式／atom                                      | 欄位                  | 模組            |
| ----------------------------------------------- | --------------------- | --------------- |
| `subtask`（Pi0.7 風格的「怎麼做，而非做什麼」） | `language_persistent` | `plan`          |
| `plan`（初始 + 插話時更新）                     | `language_persistent` | `plan`          |
| `memory`（MEM 風格的壓縮）                      | `language_persistent` | `plan`          |
| `task_aug`（改寫後的任務描述）                  | `language_persistent` | `plan`          |
| `interjection`                                  | `language_events`     | `interjections` |
| 語音工具呼叫 atom（`style=null`、`say`）        | `language_events`     | `interjections` |
| `vqa`（user / assistant 配對）                  | `language_events`     | `vqa`           |

### 子任務如何產生[[how-subtasks-are-generated]]

`plan` 模組不會一次就向 VLM 要出所有子任務，而是
採用兩步驟的**描述 → 切分**流程：

1. **描述**——VLM 只敘述它在所選相機中實際看到的內容
   （不去猜測任務是什麼）。
2. **切分**——再把這段描述交回給 VLM，由它將
   回合切分成連續的基本子任務。

兩個步驟看到的回合，都是**加上時間戳記的縮圖拼貼（contact sheet）**——
以 `frames_per_second`（預設 0.5 秒）取樣影格，再拼成 JPEG
網格，並在每個影格的角落標上時間，讓 VLM 能直接
引用確切的分界時間。這比每個影格各送一張影像，省下大量的視覺 token，
因此可以維持密集的取樣；超過
`max_frames_per_prompt` 的回合，會以相同的密度切成多個視窗後再
合併。兩個提示中也都包含一個因果的**事件分界**定義（當物體被抓住、
被放開、移到新位置、蓋子開關狀態改變，或內容物移動時，
就算是新事件的開始），讓切分點落得更準確。

你也可以選擇加入第三個**以既有標籤為基礎的重新標註**步驟（`--plan.subtask_seeded_relabel`），
它會搭配每個區段前一段、目前與下一段的縮圖拼貼
重新檢視該區段，並以第一次的標籤作為參考，只做最小幅度的
修正——分界維持不變，只讓措辭更精確，
代價是每個子任務多呼叫一次。

得到的區段接著會被拼接成沒有空隙、涵蓋整個回合的
範圍，因此**每個影格都恰好有一個生效中的子任務**。
正式使用的設定（單一相機、加上時間戳記的縮圖拼貼、
自動分窗的子任務產生）請參閱
[在 Hugging Face Jobs 上執行](#running-on-hugging-face-jobs)。

### 工具[[tools]]

寫入器**不會**在 parquet 中新增 `tools` 欄位，工具
目錄改為存放在 `meta/info.json["tools"]` 中（請參閱[工具](./tools)）。
每次執行後，管線都會確保標準的 `say` schema 存在於
這份清單中，並保留你事先宣告的其他工具。

想新增自己的工具嗎？直接編輯 `meta/info.json["tools"]` 即可——
管線會保留原本就有的內容。這會讓工具出現在聊天範本中，
讓模型學會*產生*這個呼叫。真正*執行*所產生呼叫的
執行期層（`src/lerobot/tools/` 底下的 `Tool`
協定 / `TOOL_REGISTRY`）不屬於這個 PR——
[工具](./tools)文件已將這些部分標示為
尚未實作。

## 在 Hugging Face Jobs 上執行[[running-on-hugging-face-jobs]]

標註真實的資料集，需要一張大到足以運行 VLM 的 GPU，因此
`lerobot-annotate` 可以把自己交給
[Hugging Face Jobs](https://huggingface.co/docs/hub/en/jobs)——與
`lerobot-train` 相同。在你原本要在本機執行的指令上加上
`--job.target=<flavor>`，就會改在該硬體上執行：

```bash
hf auth login   # 執行一次

uv run lerobot-annotate \
    --repo_id=user/my_dataset \
    --new_repo_id=user/my_dataset_annotated \
    --push_to_hub=true \
    --vlm.model_id=Qwen/Qwen3.6-27B \
    --vlm.num_gpus=1 \
    --vlm.serve_command="vllm serve Qwen/Qwen3.6-27B --tensor-parallel-size 1 \
        --max-model-len 32768 --gpu-memory-utilization 0.8 \
        --uvicorn-log-level warning --port {port}" \
    --vlm.serve_ready_timeout_s=1800 \
    --vlm.chat_template_kwargs='{"enable_thinking": false}' \
    --job.target=h200
```

這會提交一個單 GPU 的 `h200` Job，它會：

1. 從 `vllm/vllm-openai` 映像檔開始，並在上面安裝 `lerobot`，
2. 在每張 GPU 上啟動一個 vLLM 伺服器，並透過與 OpenAI 相容的 API 操作它，
3. 在整個資料集上執行 `plan` / `interjections` / `vqa` 模組，
4. 若設定 `--push_to_hub=true`，就把結果上傳到 `--new_repo_id`（若未設定，
   則原地寫回 `--repo_id`）。

這個指令會串流顯示 Job 的日誌；按 `Ctrl-C` 只會中斷連線，不會取消 Job。
執行 `hf jobs hardware` 可列出可用的 flavor 與價格。

<Tip warning={true}>

Qwen3.6 預設會開啟思考（thinking）模式，這會用掉標註器產生 JSON 答案所需的
token 額度——`--vlm.chat_template_kwargs='{"enable_thinking": false}'`
可以將它關閉。若沒有設定 `--push_to_hub=true`，標註後的資料集會在
pod 結束時被丟棄。

</Tip>

### 工作選項[[job-options]]

| 旗標                | 預設值                    | 作用                                                                                |
| ------------------- | ------------------------- | ----------------------------------------------------------------------------------- |
| `--job.target`      | `local`                   | 要執行的 HF Jobs flavor（例如 `h200`、`h200x4`）。省略或設為 `local` 時在本機執行。 |
| `--job.image`       | `vllm/vllm-openai:latest` | pod 使用的執行環境映像檔。                                                          |
| `--job.timeout`     | `2h`                      | 實際執行時間的上限。資料集較大時請調高。                                            |
| `--job.detach`      | `false`                   | 提交後就結束，不串流顯示日誌。                                                      |
| `--job.lerobot_ref` | `main`                    | 安裝在 pod 上的 lerobot 的 Git ref——指向某個分支即可測試修改。                      |
| `--job.tags`        | `[]`                      | 加在 Job 及其推送的資料集上的額外標籤（一律會加上 `lerobot`）。                     |

若要處理更大的資料集，請改用 `h200x4`，並相應調高
`--vlm.parallel_servers` / `--vlm.num_gpus`，同時以例如 `--job.timeout=8h`
給 Job 更多時間。

遠端執行時需要 `--repo_id`（pod 會從 Hub 下載資料集；
`--root` 指的是只有你的電腦上才有的目錄）。只存在於本機快取中的
資料集，會先推送到一個**私有**的儲存庫。

## 貢獻新模組[[contributing-new-modules]]

這個管線（pipeline）的設計就是要持續擴充，**非常歡迎大家貢獻**——
無論是全新的模組（例如軌跡描繪或 affordance 標註）、新的提示
範本、更聰明的對應流程，或是對既有的
`plan` / `interjections` / `vqa` 模組做品質修正。

每個模組都放在
`src/lerobot/annotations/steerable_pipeline/modules/`，共用 VLM
用戶端與關鍵影格快取，將原始輸出寫入暫存
目錄，並以獨立的階段接上執行器。有想法嗎？歡迎到
[repo](https://github.com/huggingface/lerobot) 上開啟 issue 或 PR。

## 配方如何消費輸出[[how-recipes-consume-the-output]]

這些標註是設計給配方（recipe）讀取的（請參閱
[語言欄位與配方](./language_and_recipes)）。通常：

- 低階／高階／記憶更新的分支會從 `language_persistent` 讀取
  `subtask` / `plan` / `memory`。
- 插話回應的分支會讀取 `interjection` 事件，加上
  配對的語音 atom（透過 `tool_calls_from` 合併成一個 assistant 回合），
  以及同一個時間戳記上對應的 `plan` 更新。
- VQA 分支會從 `language_events` 讀取 `(vqa, user)` 與
  `(vqa, assistant)` 配對。

## 為何將狀態與事件分開[[why-state-and-events-are-split]]

這個設計基於兩個概念：

1. **持續狀態與確切事件。** 持續型的資料列（`subtask`、
   `plan`、`memory`）適用於整個回合，回答的是「現在的狀態是什麼？」。事件型的資料列（`interjection`、`vqa`、語音）只會出現在
   時間戳記完全相符的那一個影格上。時間戳記直接
   從來源 parquet 複製而來，絕不會以浮點數重新計算。
2. **只跑一次 VLM。** 三個模組共用同一個 VLM 用戶端（
   與 Job 的 vLLM 伺服器溝通、和 OpenAI 相容的用戶端），因此你
   每個資料集只需載入一次模型，而不是三次。

## 重新執行單一模組[[re-running-a-single-module]]

每個模組會將原始輸出暫存到
`<root>/.annotate_staging/episode_{N:06d}/<module>.jsonl`。這讓
反覆調整提示的成本很低：重新執行一個模組，只會覆寫它自己的
JSONL，之後再由寫入器重新組合出最終的 parquet。用 `--plan.enabled=false`
停用你不需要的模組（其他模組也有
`--interjections.enabled` / `--vqa.enabled`），即可一次測試一個。

## 驗證器檢查什麼[[what-the-validator-checks]]

在寫入器執行之前，`StagingValidator` 會確認：

- 每個事件列都恰好落在真實的影格時間戳記上；
- 沒有落單、缺少另一半的語音／插話配對；
- 每個插話的時間點上，`plan` 都有更新；
- `memory` 列落在子任務的分界上（這是警告，不是錯誤）；
- 每個 VQA assistant 的 `content` 都是符合
  bbox / keypoint / count / attribute / spatial 其中一種格式的有效 JSON；
- 每一列都寫入 `column_for_style(style)` 所指定的欄位。

任何錯誤都會讓寫入器中止。除錯時，可以傳入 `--skip_validation=true`
略過這項檢查。

## 每個模組的構想來自何處[[where-each-modules-ideas-come-from]]

- **`plan`——子任務。** Hi Robot（[Shi 2025](https://arxiv.org/abs/2502.19417)）
  提供基本動作的粒度（「拿起一片生菜」、「把碗放進
  盒子」）；Pi0.7（[Physical Intelligence 2025](https://pi.website/pi07)）
  提供「描述怎麼做，而不是做什麼」的細節。
- **`plan`——記憶。** MEM（[Torne 2026](https://arxiv.org/abs/2603.03596)）：
  只保留最少的相關資訊——保留結果，捨棄
  特定的屬性細節。
- **`interjections`。** Hi Robot 的情境分類：否定任務、
  情境中的修正、特定的限制條件、偏好。語音是一種
  只包含工具呼叫的 atom
  （tool-call-only atom，`tool_calls=[{type:function, function:{name:"say", arguments:{text:...}}}]`）。
- **`vqa`。** ECoT（[Zawalski 2024](https://arxiv.org/abs/2407.08693)）提供
  與畫面對應的特徵（bounding box `[x_min, y_min, x_max, y_max]` 與
  關鍵點，以 [0, 1] 的影像比例儲存），Steerable VLA Policies
  （[Zhao 2025](https://arxiv.org/abs/2509.07626)）則提供多個抽象層級的
  對應方式。Pi0.7 也會在不同的抽象層級上，讓答案與畫面對應。

改進某個模組時，請調整它在
`src/lerobot/annotations/steerable_pipeline/prompts/` 中的提示範本，而不是
從頭重寫。

## 大致的成本[[roughly-how-much-it-costs]]

每個回合，管線大約會進行 `max_steps` 次規劃呼叫、
`max_interjections_per_episode` 次插話呼叫，以及
`vqa_emission_hz × episode_seconds` 次 VQA 呼叫。以預設值（8
個子任務、1 次插話、1 Hz × 3 個配對）處理一個 30 秒的回合，大約是
50 次 VLM 呼叫。

儲存空間也很小：`language_persistent` 每個回合最多只有數十 KB
（parquet 會對各影格重複的同一筆資料使用字典編碼），
而 `language_events` 在大多數影格上都是空的，大小只會隨
實際產生的數量增加，而不是 `num_frames × num_emissions`。
