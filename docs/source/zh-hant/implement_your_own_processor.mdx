# 實作你自己的機器人處理器[[implement-your-own-robot-processor]]

在本教學中，你將學習如何實作自己的機器人處理器（robot processor）。
我們會先說明為什麼需要自訂處理器，接著以 `NormalizerProcessorStep` 作為貫穿全文的範例，說明如何實作、設定與序列化一個處理器。最後列出 LeRobot 內建的所有輔助處理器。

## 為什麼你會需要自訂處理器？[[why-would-you-need-a-custom-processor]]

在大多數情況下，從感測器讀取原始資料，或模型輸出動作（action）時，你都需要處理這些資料，讓它們與目標系統相容。例如，一個常見的需求是將資料範圍正規化（normalization），讓它適合神經網路使用。

LeRobot 的 `NormalizerProcessorStep` 就是負責這項關鍵任務：

```python
# 輸入：原始關節位置，範圍 [0, 180] 度
raw_action = torch.tensor([90.0, 45.0, 135.0])

# 處理後：正規化至 [-1, 1] 範圍以供模型訓練使用
normalizer = NormalizerProcessorStep(features=features, norm_map=norm_map, stats=dataset_stats)
normalized_result = normalizer(transition)
# ...
```

其他常見的處理需求包括：

- **放到裝置上**：在 CPU/GPU 之間移動張量，並轉換資料型別
- **格式轉換**：在不同的資料結構之間轉換
- **組成批次**：為了配合模型而新增或移除批次維度
- **安全限制**：對機器人命令施加限制

```python
# 組合多個處理器的管線範例
pipeline = PolicyProcessorPipeline([
    RenameObservationsProcessorStep(rename_map={}),
    AddBatchDimensionProcessorStep(),
    NormalizerProcessorStep(features=features, stats=stats),
    DeviceProcessorStep(device="cuda"),
    # ...
])
```

LeRobot 提供了管線（pipeline）機制，讓你為輸入資料與輸出動作實作一連串的處理步驟，並能輕鬆地以正確的順序組合這些轉換，以達到最佳效能。

## 如何實作你自己的處理器？[[how-to-implement-your-own-processor]]

我們以 `NormalizerProcessorStep` 作為主要範例，因為它展示了你經常會用到的核心處理器模式，包括狀態管理、設定的序列化，以及張量處理。

先規劃好你的問題需要哪些處理步驟。一個處理器步驟是實作以下方法的類別：

- `__call__`：對輸入的 transition 執行處理步驟。
- `get_config`：取得處理器步驟的設定。
- `state_dict`：取得處理器步驟的狀態。
- `load_state_dict`：載入處理器步驟的狀態。
- `reset`：重設處理器步驟的狀態。
- `feature_contract`：呈現處理器步驟對特徵空間所做的修改。

### 實作 `__call__` 方法[[implement-the-call-method]]

`__call__` 方法是處理器步驟的核心，它接收一個 `EnvTransition`，並回傳修改後的 `EnvTransition`。以下是 `NormalizerProcessorStep` 的運作方式：

```python
@dataclass
@ProcessorStepRegistry.register("normalizer_processor")
class NormalizerProcessorStep(ProcessorStep):
    """使用資料集統計值正規化觀測／動作。"""

    features: dict[str, PolicyFeature]
    norm_map: dict[FeatureType, NormalizationMode]
    stats: dict[str, dict[str, Any]] | None = None
    eps: float = 1e-8
    _tensor_stats: dict = field(default_factory=dict, init=False, repr=False)

    def __post_init__(self):
        """將統計值轉換為張量，以提升運算效率。"""
        self.stats = self.stats or {}
        self._tensor_stats = to_tensor(self.stats, device=self.device, dtype=torch.float32)

    def __call__(self, transition: EnvTransition) -> EnvTransition:
        new_transition = transition.copy()
        # 正規化觀測
        # ...
        # 正規化動作
        # ...
        return new_transition

```

完整實作細節請參閱 `src/lerobot/processor/normalize_processor.py`。

**關鍵原則：**

- **一律使用 `transition.copy()`**，避免副作用
- 以一致的方式**同時處理觀測（observation）與動作**
- **將設定與狀態分開**：`get_config()` 回傳可序列化為 JSON 的參數，`state_dict()` 回傳張量
- 在 `__post_init__()` 中**將統計值轉換為張量**，以提升運算效率

### 設定與狀態管理[[configuration-and-state-management]]

處理器透過三個方法支援序列化，將設定與張量狀態分開。`NormalizerProcessorStep` 正好完整示範了這一點：它在狀態中保存資料集的統計值（張量），在設定中保存超參數：

```python
# 接續 NormalizerProcessorStep 範例...

def get_config(self) -> dict[str, Any]:
    """可 JSON 序列化的設定（無張量）。"""
    return {
        "eps": self.eps,
        "features": {k: {"type": v.type.value, "shape": v.shape} for k, v in self.features.items()},
        "norm_map": {ft.value: nm.value for ft, nm in self.norm_map.items()},
        # ...
    }

def state_dict(self) -> dict[str, torch.Tensor]:
    """只包含張量狀態（例如資料集統計值）。"""
    flat: dict[str, torch.Tensor] = {}
    for key, sub in self._tensor_stats.items():
        for stat_name, tensor in sub.items():
            flat[f"{key}.{stat_name}"] = tensor.cpu() # 一律儲存到 CPU
    return flat

def load_state_dict(self, state: dict[str, torch.Tensor]) -> None:
    """在執行期還原張量狀態。"""
    self._tensor_stats.clear()
    for flat_key, tensor in state.items():
        key, stat_name = flat_key.rsplit(".", 1)
        # 載入到處理器設定的裝置上
        self._tensor_stats.setdefault(key, {})[stat_name] = tensor.to(
            dtype=torch.float32, device=self.device
        )
        # ...
```

**使用方式：**

```python
# 儲存（例如在策略內部）
config = normalizer.get_config()
tensors = normalizer.state_dict()

# 還原（例如載入預訓練的策略）
new_normalizer = NormalizerProcessorStep(**config)
new_normalizer.load_state_dict(tensors)
# 現在 new_normalizer 擁有相同的統計值與設定
```

### 轉換特徵[[transform-features]]

`transform_features` 方法定義了你的處理器如何轉換特徵（feature）的名稱與形狀。這對策略（policy）的設定與除錯都非常重要。

以 `NormalizerProcessorStep` 來說，特徵通常會維持不變，因為正規化不會改變鍵名或形狀：

```python
def transform_features(self, features: dict[PipelineFeatureType, dict[str, PolicyFeature]]) -> dict[PipelineFeatureType, dict[str, PolicyFeature]]:
    """正規化保留所有特徵定義。"""
    return features  # 不改變特徵結構
    # ...
```

當你的處理器會重新命名或改變資料形狀時，請實作這個方法，反映出對應關係，供下游元件使用。例如，一個簡單的重新命名處理器：

```python
def transform_features(self, features: dict[str, PolicyFeature]) -> dict[str, PolicyFeature]:
    # 簡單的重新命名
    if "pixels" in features:
        features["observation.image"] = features.pop("pixels")

    # 基於模式的重新命名
    for key in list(features.keys()):
        if key.startswith("env_state."):
            suffix = key[len("env_state."):]
            features[f"observation.{suffix}"] = features.pop(key)
            # ...

    return features
```

**關鍵原則：**

- 使用 `features.pop(old_key)` 移除並取得舊的特徵
- 使用 `features[new_key] = old_feature` 加入重新命名後的特徵
- 一律回傳修改後的特徵字典
- 在 docstring 中清楚記錄轉換內容

### 使用覆寫值[[using-overrides]]

你可以在載入時透過 `overrides` 覆寫步驟的參數。這對無法序列化的物件，或依場地而異的設定特別方便。它在策略工廠與 `DataProcessorPipeline.from_pretrained(...)` 中都能使用。

**調整基礎模型**：使用基礎的預訓練策略時，你通常拿不到原始訓練時的統計值，這時這個功能就特別有用。你可以注入自己資料集的統計值，讓正規化器適應你特定的機器人或環境資料。

範例：在機器人上評估策略時，覆寫裝置與重新命名對應表。
這可以讓以 CUDA 訓練的策略在只有 CPU 的機器人上執行，或在機器人使用的名稱與資料集不同時，重新對應相機鍵名。

直接使用 `from_pretrained`：

```python
from lerobot.processor import RobotProcessorPipeline

# 載入在多樣化機器人資料上訓練的基礎策略
# 但將正規化適配到你特定的機器人/環境
new_stats = LeRobotDataset(repo_id="username/my-dataset").meta.stats
processor = RobotProcessorPipeline.from_pretrained(
    "huggingface/foundational-robot-policy",  # 預訓練的基礎模型
    overrides={
        "normalizer_processor": {"stats": new_stats},     # 注入你的機器人統計值
        "device_processor": {"device": "cuda:0"},         # 已註冊步驟的註冊名稱
        "rename_processor": {"rename_map": robot_key_map}, # 對應你的機器人觀測鍵名
        # ...
    },
)
```

## 最佳實務[[best-practices]]

以下是根據分析所有 LeRobot 處理器實作所整理出的關鍵模式與做法：

### 1. **安全的資料處理**[[1-safe-data-handling]]

一律為輸入資料建立副本，避免意外的副作用。使用 `transition.copy()` 與 `observation.copy()`，而不是就地修改資料，以免你的處理器不小心影響到管線中的其他元件。

處理前先檢查需要的資料，並妥善處理缺少資料的情況。如果你的處理器需要特定的鍵名（例如影像處理用的 `"pixels"`），請先確認它們存在。對於可選的資料，請使用 `transition.get()` 這類安全的存取方式，並適當處理 `None` 值。

資料驗證失敗時，請提供清楚且具體可行的錯誤訊息，幫助使用者了解發生了什麼問題，以及如何修正。

### 2. **選擇適當的基底類別**[[2-choose-appropriate-base-classes]]

LeRobot 提供了專門的基底類別，可以減少樣板程式碼並確保一致性。只需要修改觀測時，使用 `ObservationProcessorStep`；只處理動作時，使用 `ActionProcessorStep`；處理以字典表示的機器人動作時，則使用 `RobotActionProcessorStep`。

只有在你需要完全控制整個 transition，或要同時處理 transition 的多個部分時，才直接繼承 `ProcessorStep`。專門的基底類別會替你處理 transition 的管理，並提供型別安全。

### 3. **註冊與命名**[[3-registration-and-naming]]

使用 `@ProcessorStepRegistry.register()`，以具描述性且帶命名空間的名稱註冊你的處理器。請加上組織前綴，例如 `"robotics_lab/safety_clipper"` 或 `"acme_corp/vision_enhancer"`，以避免名稱衝突。避免使用 `"processor"` 或 `"step"` 這類可能與其他實作衝突的通用名稱。

良好的註冊方式能讓你的處理器容易被找到，並在儲存與載入管線時，順利完成序列化與反序列化。

### 4. **狀態管理模式**[[4-state-management-patterns]]

請區分設定參數（可序列化為 JSON 的值）與內部狀態（張量、緩衝區）。對於不應出現在建構子或字串表示中的內部狀態，請使用帶有 `init=False, repr=False` 的 dataclass 欄位。

實作 `reset()` 方法，在回合（episode）之間清除內部狀態。這對會隨時間累積資料的有狀態處理器非常重要，例如移動平均或時間濾波器。

請記得，`get_config()` 只應回傳可序列化為 JSON 的設定，張量狀態則交給 `state_dict()` 另外處理。

### 5. **輸入驗證與錯誤處理**[[5-input-validation-and-error-handling]]

處理前先驗證輸入的型別與形狀。檢查張量的 `dtype` 與維度等屬性，確保與你的演算法相容。對於機器人動作，請確認必要的姿態分量或關節值都存在，而且位於預期的範圍內。

對於不需要處理的邊界情況，請提早返回。提供清楚、具描述性的錯誤訊息，並註明預期與實際的資料型別或形狀，讓使用者更容易除錯。

### 6. **裝置與資料型別感知**[[6-device-and-dtype-awareness]]

設計你的處理器，讓它自動配合輸入張量的裝置與 dtype。內部張量（例如正規化的統計值）應與輸入張量的裝置與 dtype 一致，以確保能相容多 GPU 訓練、混合精度與分散式環境。

實作 `to()` 方法，將處理器的內部狀態移到指定的裝置上。在執行期檢查裝置與 dtype 是否相容，必要時自動移轉內部狀態。這種做法能讓處理器在不同的硬體配置之間順利運作，不需要手動介入。

## 結論[[conclusion]]

你現在已經具備在 LeRobot 中實作自訂處理器的所有工具！關鍵步驟如下：

1. 將你的處理器**定義**為 dataclass，並實作必要的方法（`__call__`、`get_config`、`state_dict`、`load_state_dict`、`reset`、`transform_features`）
2. 使用 `@ProcessorStepRegistry.register("name")` **註冊**，讓它可以被找到
3. 將它與其他處理步驟一起**整合**到 `DataProcessorPipeline` 中
4. 盡可能**使用** `ObservationProcessorStep` 等**基底類別**，減少樣板程式碼
5. **配合裝置與 dtype**，支援多 GPU 與混合精度的環境

處理器系統的設計是模組化且可組合的，讓你能用簡單、專一的元件，組出複雜的資料處理管線。無論是為了訓練而前處理感測器資料，或是為了讓機器人執行而後處理模型的輸出，自訂處理器都能讓你靈活處理機器人應用所需的任何資料轉換。

穩健處理器的關鍵原則：

- **配合裝置與 dtype**：內部張量應與輸入張量一致
- **清楚的錯誤訊息**：幫助使用者了解發生了什麼問題
- **使用基底類別**：善用專門的基底類別，減少樣板程式碼
- **特徵契約**：使用 `transform_features()` 宣告資料結構的變化

從簡單的開始，充分測試，並確保你的處理器能在不同的硬體配置之間順利運作！
