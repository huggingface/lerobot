# 從 Hub 載入環境[[loading-environments-from-the-hub]]

**EnvHub** 功能讓你只要一行程式碼，就能直接從 Hugging Face Hub 載入模擬環境（simulation environment）。這開啟了一種強大的全新協作模式：環境不再被鎖在龐大的單體函式庫中，任何人都可以發布自訂環境，並與社群分享。

## 什麼是 EnvHub？[[what-is-envhub]]

EnvHub 讓你能以自己的機器人模型與情境，建立自訂的機器人模擬環境，並透過 LeRobot 框架讓任何人都能輕鬆使用。

EnvHub 套件儲存在 Hugging Face Hub 上，只要一行程式碼，就能透過 LeRobot 無縫下載，並用在你的 AI 機器人專案中。

有了 EnvHub，你可以：

1. **建立並發布環境**：以 Git 儲存庫（repository）的形式發布到 Hugging Face Hub，散布複雜的物理模擬，不必為打包傷腦筋
2. **動態載入環境**，不需要將它們安裝成套件
3. 使用 Git 的語意，對環境的變更進行**版本控制與追蹤**
4. **探索**社群分享的新模擬任務

這樣的設計讓你在 Hub 上發現有趣的環境後，幾秒內就能開始執行實驗；你也可以建立自己的自訂機器人與環境，不必擔心相依性衝突或繁複的安裝程序。

建立 EnvHub 套件時，你可以在裡面放入任何想要的內容，並使用任何喜歡的模擬工具：這是你自由發揮的空間。唯一的要求是，套件中必須包含一個 `env.py` 檔案，用來定義環境，讓 LeRobot 能載入並使用你的 EnvHub 套件。

這個 `env.py` 檔案需要提供一個小型 API，讓 LeRobot 能載入並執行它。具體來說，你必須提供一個 `make_env(n_envs: int = 1, use_async_envs: bool = False)` 或 `make_env(n_envs: int = 1, use_async_envs: bool = False, cfg: EnvConfig)` 函式，作為 LeRobot 的主要進入點。它應該回傳以下其中一種：

- 一個 `gym.vector.VectorEnv`（最常見）
- 單一的 `gym.Env`（會自動包裝）
- 一個對應 `{suite_name: {task_id: VectorEnv}}` 的字典（用於多任務基準測試）

你也可以將 `EnvConfig` 物件傳給 `make_env` 來設定環境（例如環境數量、任務、相機名稱、初始狀態、控制模式、回合長度等）。

最後，你的環境必須實作標準的 `gym.vector.VectorEnv` 介面，包括 `reset` 與 `step` 等方法，才能與 LeRobot 搭配使用。

## 快速開始[[quick-start]]

從 Hub 載入環境非常簡單：

```python
from lerobot.envs import make_env

# 載入 hub 環境（需要明確同意執行遠端程式碼）
env = make_env("lerobot/cartpole-env", trust_remote_code=True)
```

<Tip warning={true}>
  **安全性注意事項**：從 Hub 載入環境，會執行來自第三方儲存庫（repository）的
  Python 程式碼。請只對你信任的儲存庫使用 `trust_remote_code=True`。
  我們強烈建議固定到特定的 commit 雜湊值， 以確保可重現性與安全性。
</Tip>

## 儲存庫結構[[repository-structure]]

要讓你的環境可以從 Hub 載入，你的儲存庫（repository）至少必須包含：

### 必要檔案[[required-files]]

**`env.py`**（或自訂的 Python 檔案）

- 必須提供 `make_env(n_envs: int, use_async_envs: bool)` 函式
- 這個函式應該回傳以下其中一種：
  - 一個 `gym.vector.VectorEnv`（最常見）
  - 單一的 `gym.Env`（會自動包裝）
  - 一個對應 `{suite_name: {task_id: VectorEnv}}` 的字典（用於多任務基準測試）

### 可選檔案[[optional-files]]

**`requirements.txt`**

- 列出你的環境所需的任何額外相依套件
- 使用者需要在載入你的環境之前，手動安裝這些套件

**`README.md`**

- 說明你的環境：它實作了什麼任務、觀測／動作空間、獎勵等
- 附上使用範例與任何特殊的設定說明

**`.gitignore`**

- 將不必要的檔案排除在儲存庫之外

### 儲存庫結構範例[[example-repository-structure]]

```
my-environment-repo/
├── env.py                 # 主要環境定義（必要）
├── requirements.txt       # 相依套件（可選）
├── README.md             # 說明文件（建議）
├── assets/               # 圖片、影片等（可選）
│   └── demo.gif
└── configs/              # 設定檔（如有需要，可選）
    └── task_config.yaml
```

## 建立你的環境儲存庫[[creating-your-environment-repository]]

### 步驟 1：定義你的環境[[step-1-define-your-environment]]

建立一個包含 `make_env` 函式的 `env.py` 檔案：

```python
# env.py
import gymnasium as gym

def make_env(n_envs: int = 1, use_async_envs: bool = False):
    """
    為你的自訂任務建立向量化環境。

    Args:
        n_envs: 平行環境數量
        use_async_envs: 是否使用 AsyncVectorEnv 或 SyncVectorEnv

    Returns:
        gym.vector.VectorEnv 或對應套件名稱到向量化環境的字典
    """
    def _make_single_env():
        # 建立你的自訂環境
        return gym.make("CartPole-v1")

    # 選擇向量環境類型
    env_cls = gym.vector.AsyncVectorEnv if use_async_envs else gym.vector.SyncVectorEnv

    # 建立向量化環境
    vec_env = env_cls([_make_single_env for _ in range(n_envs)])

    return vec_env
```

### 步驟 2：在本機測試[[step-2-test-locally]]

上傳之前，先在本機測試你的環境：

```python
from lerobot.envs.utils import _load_module_from_path, _call_make_env, _normalize_hub_result

# 載入你的模組
module = _load_module_from_path("./env.py")

# 測試 make_env 函式
result = _call_make_env(module, n_envs=2, use_async_envs=False)
normalized = _normalize_hub_result(result)

# 驗證是否正常運作
suite_name = next(iter(normalized))
env = normalized[suite_name][0]
obs, info = env.reset()
print(f"Observation shape: {obs.shape if hasattr(obs, 'shape') else type(obs)}")
env.close()
```

### 步驟 3：上傳到 Hub[[step-3-upload-to-the-hub]]

將你的儲存庫上傳到 Hugging Face：

```bash
# 如有需要，安裝 huggingface_hub
pip install huggingface_hub

# 登入 Hugging Face
hf auth login

# 建立新的儲存庫
hf repo create my-org/my-custom-env

# 初始化 git 並推送
git init
git add .
git commit -m "Initial environment implementation"
git remote add origin https://huggingface.co/my-org/my-custom-env
git push -u origin main
```

或者，也可以使用 `huggingface_hub` 的 Python API：

```python
from huggingface_hub import HfApi

api = HfApi()

# 建立儲存庫
api.create_repo("my-custom-env", repo_type="space")

# 上傳檔案
api.upload_folder(
    folder_path="./my-env-folder",
    repo_id="username/my-custom-env",
    repo_type="space",
)
```

## 從 Hub 載入環境[[loading-environments-from-the-hub-1]]

### 基本用法[[basic-usage]]

```python
from lerobot.envs import make_env

# 從 hub 載入
envs_dict = make_env(
    "username/my-custom-env",
    n_envs=4,
    trust_remote_code=True
)

# 存取環境
suite_name = next(iter(envs_dict))
env = envs_dict[suite_name][0]

# 像使用任何 gym 環境一樣使用它
obs, info = env.reset()
action = env.action_space.sample()
obs, reward, terminated, truncated, info = env.step(action)
```

### 進階：固定到特定版本[[advanced-pinning-to-specific-versions]]

為了可重現性與安全性，請固定到特定的 Git 版本（revision）：

```python
# 固定到特定分支
env = make_env("username/my-env@main", trust_remote_code=True)

# 固定到特定 commit（論文/實驗建議使用）
env = make_env("username/my-env@abc123def456", trust_remote_code=True)

# 固定到標籤
env = make_env("username/my-env@v1.0.0", trust_remote_code=True)
```

### 自訂檔案路徑[[custom-file-paths]]

如果你的環境定義不在 `env.py` 中：

```python
# 從自訂檔案載入
env = make_env("username/my-env:custom_env.py", trust_remote_code=True)

# 結合版本固定
env = make_env("username/my-env@v1.0:envs/task_a.py", trust_remote_code=True)
```

### 非同步環境[[async-environments]]

使用多個環境時，若要取得更好的效能：

```python
envs_dict = make_env(
    "username/my-env",
    n_envs=8,
    use_async_envs=True,  # 使用 AsyncVectorEnv 進行平行執行
    trust_remote_code=True
)
```

## URL 格式參考[[url-format-reference]]

Hub URL 格式支援以下幾種模式：

| 模式                 | 說明                      | 範例                                   |
| -------------------- | ------------------------- | -------------------------------------- |
| `user/repo`          | 從 main 分支載入 `env.py` | `make_env("lerobot/pusht-env")`        |
| `user/repo@revision` | 從特定版本載入            | `make_env("lerobot/pusht-env@main")`   |
| `user/repo:path`     | 載入自訂檔案              | `make_env("lerobot/envs:pusht.py")`    |
| `user/repo@rev:path` | 特定版本 + 自訂檔案       | `make_env("lerobot/envs@v1:pusht.py")` |

## 多任務環境[[multi-task-environments]]

對於包含多個任務的基準測試（例如 LIBERO），請回傳巢狀字典：

```python
def make_env(n_envs: int = 1, use_async_envs: bool = False):
    env_cls = gym.vector.AsyncVectorEnv if use_async_envs else gym.vector.SyncVectorEnv

    # 回傳字典：{suite_name: {task_id: VectorEnv}}
    return {
        "suite_1": {
            0: env_cls([lambda: gym.make("Task1-v0") for _ in range(n_envs)]),
            1: env_cls([lambda: gym.make("Task2-v0") for _ in range(n_envs)]),
        },
        "suite_2": {
            0: env_cls([lambda: gym.make("Task3-v0") for _ in range(n_envs)]),
        }
    }
```

## 安全性考量[[security-considerations]]

<Tip warning={true}>
  **重要**：執行來自 Hub 的環境程式碼時，必須使用 `trust_remote_code=True`
  旗標。這是基於安全性的刻意設計。
</Tip>

從 Hub 載入環境時：

1. **先檢閱程式碼**：載入之前，先造訪儲存庫並檢查 `env.py`
2. **固定到 commit**：使用特定的 commit 雜湊值，以確保可重現性
3. **檢查相依套件**：檢查 `requirements.txt` 中是否有可疑的套件
4. **使用可信任的來源**：優先選擇官方組織或知名研究者
5. **必要時使用沙箱**：在隔離的環境（容器、虛擬機）中執行不受信任的程式碼

安全用法範例：

```python
# ❌ 錯誤：未經檢查即載入
env = make_env("random-user/untrusted-env", trust_remote_code=True)

# ✅ 正確：檢閱程式碼後，固定到特定 commit
# 1. 造訪 https://huggingface.co/trusted-org/verified-env
# 2. 檢閱 env.py 檔案
# 3. 複製 commit 雜湊值
env = make_env("trusted-org/verified-env@a1b2c3d4", trust_remote_code=True)
```

## 範例：從 Hub 載入 CartPole[[example-cartpole-from-the-hub]]

以下是使用參考 CartPole 環境的完整範例：

```python
from lerobot.envs import make_env
import numpy as np

# 載入環境
envs_dict = make_env("lerobot/cartpole-env", n_envs=4, trust_remote_code=True)

# 取得向量化環境
suite_name = next(iter(envs_dict))
env = envs_dict[suite_name][0]

# 執行一個簡單的回合
obs, info = env.reset()
done = np.zeros(env.num_envs, dtype=bool)
total_reward = np.zeros(env.num_envs)

while not done.all():
    # 隨機策略
    action = env.action_space.sample()
    obs, reward, terminated, truncated, info = env.step(action)
    total_reward += reward
    done = terminated | truncated

print(f"Average reward: {total_reward.mean():.2f}")
env.close()
```

## EnvHub 的優點[[benefits-of-envhub]]

### 對環境作者而言[[for-environment-authors]]

- **散布容易**：不需要打包成 PyPI 套件
- **版本控制**：使用 Git 管理環境版本
- **快速迭代**：推送後立即更新
- **說明文件**：Hub 上的 README 會漂亮地呈現
- **社群**：直接觸及 LeRobot 使用者

### 對研究者而言[[for-researchers]]

- **快速實驗**：一行程式碼載入任何環境
- **可重現性**：固定到特定的 commit
- **探索**：在 Hub 上瀏覽各種環境
- **沒有衝突**：不需要安裝互相衝突的套件

### 對社群而言[[for-the-community]]

- **持續成長的生態系**：更多元的模擬任務
- **標準化**：共通的 `make_env` API
- **協作**：fork 並改進既有的環境
- **易於取用**：降低分享研究成果的門檻

## 疑難排解[[troubleshooting]]

### 「Refusing to execute remote code」[[refusing-to-execute-remote-code]]

你必須明確傳入 `trust_remote_code=True`：

```python
env = make_env("user/repo", trust_remote_code=True)
```

### 「Module X not found」[[module-x-not-found]]

這個 Hub 環境有需要你自行安裝的相依套件：

```bash
# 檢查儲存庫的 requirements.txt 並安裝相依套件
pip install gymnasium numpy
```

### 「make_env not found in module」[[makeenv-not-found-in-module]]

你的 `env.py` 必須提供 `make_env` 函式：

```python
def make_env(n_envs: int, use_async_envs: bool):
    # 你的實作
    pass
```

### 環境回傳了錯誤的類型[[environment-returns-wrong-type]]

`make_env` 函式必須回傳：

- 一個 `gym.vector.VectorEnv`，或
- 單一的 `gym.Env`，或
- 一個字典 `{suite_name: {task_id: VectorEnv}}`

## 最佳實務[[best-practices]]

1. **為你的環境撰寫說明**：在 README 中說明觀測／動作空間、獎勵結構與終止條件
2. **加入 requirements.txt**：列出所有相依套件及其版本
3. **充分測試**：推送之前，先確認環境在本機可以正常運作
4. **使用語意化版本**：以版本號標記各次發布
5. **加入範例**：在 README 中附上使用範例
6. **保持簡單**：盡可能減少相依套件
7. **為你的作品加上授權**：加入 LICENSE 檔案，說明使用條款

## 未來方向[[future-directions]]

EnvHub 生態系帶來了許多令人期待的可能性：

- **GPU 加速的物理模擬**：分享 Isaac Gym 或 Brax 環境
- **擬真渲染**：散布具備進階圖形效果的環境
- **多代理情境**：複雜的互動任務
- **真實世界模擬器**：實體裝置的數位分身
- **程序化生成**：無限的任務變化
- **領域隨機化（domain randomization）**：預先設定好的 DR 管線

隨著越來越多研究者與開發者投入貢獻，可用環境的多樣性與品質都會持續提升，讓整個機器人學習社群受益。
