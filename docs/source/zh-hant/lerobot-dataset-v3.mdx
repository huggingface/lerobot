# LeRobotDataset v3.0[[lerobotdataset-v30]]

`LeRobotDataset v3.0` 是機器人學習資料的標準化格式。它提供統一的方式存取多模態時間序列資料、感測與運動訊號（sensorimotor signals）以及多相機影片，並附有豐富的中繼資料（metadata），方便在 Hugging Face Hub 上建立索引、搜尋與視覺化。

若想在閱讀格式說明之前，先看看這種格式的資料集包含哪些內容，可以在 [LeRobot Dataset Visualizer](https://huggingface.co/spaces/lerobot/visualize_dataset?path=/lerobot/svla_so101_pickplace/episode_0) 中開啟一個資料集，直接在瀏覽器裡查看相機錄影、同步的狀態（state）與動作（action）圖表，以及每一個回合（episode）。請參閱[在瀏覽器中探索資料集](./using_dataset_tools#explore-a-dataset-in-the-browser)。

本文件將引導你：

- 了解 v3.0 的設計與目錄結構
- 錄製資料集並推送到 Hub
- 使用 `LeRobotDataset` 載入資料集以進行訓練
- 使用 `StreamingLeRobotDataset` 串流資料集，不必先下載
- 在訓練期間套用影像轉換，進行資料增強
- 將既有的 `v2.1` 資料集遷移至 `v3.0`
- 試用其他 `LeRobotDataset` 格式與實作，例如 Lance

## `v3` 有哪些新功能[[whats-new-in-v3]]

- **以檔案為單位的儲存**：每個 Parquet/MP4 檔案包含多個回合（episode）；v2 則是每個回合一個檔案。
- **關聯式中繼資料（relational metadata）**：回合的邊界與查找都透過中繼資料解析，而不是依賴檔名。
- **原生支援從 Hub 串流**：使用 `StreamingLeRobotDataset` 直接從 Hub 讀取資料集。
- **降低檔案系統負擔**：檔案更少、更大 ⇒ 初始化更快，大規模使用時問題也更少。
- **統一的組織方式**：目錄結構清楚，資料與影片都採用一致的路徑範本（path template）。
- **資料集儲存後端**：資料集也可以儲存為 [LanceDB](https://lancedb.com) 資料表，直接從物件儲存（object storage）進行隨機存取與建立索引（請參閱 [LanceDB 資料集後端](#lancedb-dataset-backend)）。

## 格式設計[[format-design]]

v3 的核心原則是**將儲存方式與使用者 API 解耦**：資料以高效率的方式儲存（少量的大型檔案），而公開的 API 則提供直覺的、以回合（episode）為單位的存取方式。

`v3` 有三大支柱：

1. **表格資料**：低維度、高頻率的訊號（狀態、動作、時間戳記）儲存在 **Apache Parquet** 中，透過記憶體對映（memory-mapped）或 `datasets` 套件串流存取。
2. **視覺資料**：相機影格（frame）串接後編碼為 **MP4**。同一個回合的影格會放在一起；影片則依相機切分成大小合適的分片（shard）。
3. **中繼資料（metadata）**：以 JSON/Parquet 記錄資料結構（特徵名稱、dtype、shape）、影格率、正規化統計值，以及**回合切分資訊**（在共用 Parquet/MP4 檔案中的起訖偏移量）。

> 為了擴展到數百萬個回合，多個回合的表格資料列與影片影格會**串接**成更大的檔案。每個回合的內容則**透過中繼資料**重建，而不是依賴檔案邊界。

### 目錄結構（簡化版）[[directory-layout-simplified]]

- **`meta/info.json`**：標準的資料結構定義（特徵、shape/dtype）、FPS、程式碼庫版本，以及用來定位資料／影片分片（shard）的**路徑範本**。
- **`meta/stats.json`**：用於正規化（normalization）的全域特徵統計值（mean/std/min/max），可透過 `dataset.meta.stats` 取得。
- **`meta/tasks.jsonl`**：以自然語言描述的任務，對應到整數 ID，供以任務為條件的策略（task-conditioned policy）使用。
- **`meta/episodes/`**：每個回合的記錄（長度、任務、偏移量），以**分塊的 Parquet** 儲存，方便擴展。
- **`data/`**：逐影格的 **Parquet** 分片；每個檔案通常包含**多個回合**。
- **`videos/`**：每台相機各自的 **MP4** 分片；每個檔案通常包含**多個回合**。

## 載入資料集以進行訓練[[load-a-dataset-for-training]]

`LeRobotDataset` 會回傳由 PyTorch 張量組成的 Python 字典，並可與 `torch.utils.data.DataLoader` 搭配使用。以下是使用範例：

```python
import torch
from lerobot.datasets import LeRobotDataset

repo_id = "yaak-ai/L2D-v3"

# 1) 從 Hub 載入（會在本地快取）
dataset = LeRobotDataset(repo_id)

# 2) 依索引隨機存取
sample = dataset[100]
print(sample)
# {
#   'observation.state': tensor([...]),
#   'action': tensor([...]),
#   'observation.images.front_left': tensor([C, H, W]),
#   'timestamp': tensor(1.234),
#   ...
# }

# 3) 透過 delta_timestamps 取得時間視窗（相對於 t 的秒數）
delta_timestamps = {
    "observation.images.front_left": [-0.2, -0.1, 0.0]  # 目前影格前 0.2 秒與 0.1 秒
}

dataset = LeRobotDataset(repo_id, delta_timestamps=delta_timestamps)

# 現在存取某個索引會回傳指定鍵的堆疊
sample = dataset[100]
print(sample["observation.images.front_left"].shape)  # [T, C, H, W]，其中 T=3

# 4) 以 DataLoader 包裝以進行訓練
batch_size = 16
data_loader = torch.utils.data.DataLoader(dataset, batch_size=batch_size)

device = "cuda" if torch.cuda.is_available() else "cpu"
for batch in data_loader:
    observations = batch["observation.state"].to(device)
    actions = batch["action"].to(device)
    images = batch["observation.images.front_left"].to(device)
    # model.forward(batch)
```

## 在訓練期間串流資料集[[stream-a-dataset-during-training]]

設定 `--dataset.streaming=true`，即可在訓練時不必先下載資料集的 Parquet 與影片檔案。回合會即時抓取到有限的記憶體池中，而且在每個 epoch 中，每個被選取的影格仍只會被造訪一次：

```bash
lerobot-train \
  --dataset.repo_id=yaak-ai/L2D-v3 \
  --dataset.streaming=true \
  --policy.type=act \
  --output_dir=outputs/train/act_streaming
```

同樣的讀取器也可以在 Python 中使用，適用於 Hub 資料集，以及儲存在 [HF Storage Bucket](https://huggingface.co/docs/hub/storage-buckets) 中的資料集：

```python
from lerobot.datasets import StreamingLeRobotDataset

dataset = StreamingLeRobotDataset("yaak-ai/L2D-v3")
bucket_dataset = StreamingLeRobotDataset("my-org/my-bucket", repo_type="bucket")
```

在命令列介面上，可以使用 `--dataset.repo_type=bucket` 或 `--dataset.root=hf://buckets/my-org/my-bucket` 來選擇 bucket。

關於 worker 與分片（shards）如何對應到串流的並行處理、MP4 sidecar 索引、記憶體設定、接續訓練與疑難排解，請參閱[訓練資料集串流](./training_dataset_streaming)。

## 影像轉換[[image-transforms]]

影像轉換（image transform）是在訓練期間套用到相機影格上的資料增強（data augmentation），用來提升模型的穩健性與泛化能力。LeRobot 支援多種轉換，包括亮度、對比、飽和度、色相與銳利度的調整。

### 在資料集建立/錄製期間使用轉換[[using-transforms-during-dataset-creationrecording]]

目前轉換**只在訓練時**套用，錄製時不會套用。建立或錄製資料集時，原始影像會以未經轉換的形式儲存，所以之後可以嘗試不同的增強方式，不必重新錄製資料。

### 為既有資料集加入轉換[[adding-transforms-to-existing-datasets-api]]

載入資料集進行訓練時，使用 `image_transforms` 參數：

```python
from lerobot.datasets import LeRobotDataset
from lerobot.transforms import ImageTransforms, ImageTransformsConfig, ImageTransformConfig

# 選項 1：使用預設的轉換設定（預設為停用）
transforms_config = ImageTransformsConfig(
    enable=True,  # 啟用轉換
    max_num_transforms=3,  # 每個影格最多套用 3 個轉換
    random_order=False,  # 以標準順序套用
)
transforms = ImageTransforms(transforms_config)

dataset = LeRobotDataset(
    repo_id="your-username/your-dataset",
    image_transforms=transforms
)

# 選項 2：建立自訂的轉換設定
custom_transforms_config = ImageTransformsConfig(
    enable=True,
    max_num_transforms=2,
    random_order=True,
    tfs={
        "brightness": ImageTransformConfig(
            weight=1.0,
            type="ColorJitter",
            kwargs={"brightness": (0.7, 1.3)}  # 調整亮度範圍
        ),
        "contrast": ImageTransformConfig(
            weight=2.0,  # 權重越高 = 越可能被選中
            type="ColorJitter",
            kwargs={"contrast": (0.8, 1.2)}
        ),
        "sharpness": ImageTransformConfig(
            weight=0.5,  # 權重越低 = 越不可能被選中
            type="SharpnessJitter",
            kwargs={"sharpness": (0.3, 2.0)}
        ),
    }
)

dataset = LeRobotDataset(
    repo_id="your-username/your-dataset",
    image_transforms=ImageTransforms(custom_transforms_config)
)

# 選項 3：使用純 torchvision 轉換
from torchvision.transforms import v2

torchvision_transforms = v2.Compose([
    v2.ColorJitter(brightness=0.2, contrast=0.2, saturation=0.2, hue=0.1),
    v2.GaussianBlur(kernel_size=3, sigma=(0.1, 2.0)),
])

dataset = LeRobotDataset(
    repo_id="your-username/your-dataset",
    image_transforms=torchvision_transforms
)
```

### 可用的轉換類型[[available-transform-types]]

LeRobot 提供以下幾種轉換類型：

- **`ColorJitter`**：調整亮度、對比、飽和度與色相
- **`SharpnessJitter`**：隨機調整影像銳利度
- **`RandomAffine`**、**`RandomRotation`**：幾何擾動
- **`GaussianNoise`**、**`MotionBlur`**、**`JPEGCompression`**、**`GaussianPatchBrightness`**、**`RandomShadow`**、**`CoarseDropout`**、**`GammaCorrection`**、**`PlanckianJitter`**：真實機器人上會看到的相機與光線效果
- **`Identity`**：不做任何轉換（適合測試使用）

其他任何 `torchvision.transforms.v2` 類別也可以指定為 `type`（例如 `RandomResizedCrop` 或 `GaussianBlur`）；它會一次套用一個樣本。你也可以直接把 torchvision 轉換傳給 `image_transforms` 參數。

現在每個轉換都會以批次方式處理，而且兩個後端都會執行相同的批次轉換。以單一樣本為單位的類別（`SharpnessJitter`、`GaussianNoise`、`MotionBlur`、`GaussianPatchBrightness`、`RandomShadow`、`CoarseDropout`、`GammaCorrection`、`PlanckianJitter`、`RandomSubsetApply`）與 `make_transform_from_config` 仍可匯入，但已棄用，只是其 `Batched*` 替代版本的前端，使用時會發出警告；它們將在未來的版本中移除。`ImageTransforms` 是單純的 `torch.nn.Module`，接受 `(C, H, W)` 或 `(T, C, H, W)` 張量。以 `type` 指定轉換的設定不受影響。

<Tip warning={true}>

**既有 recipe 的行為變更。** 訓練會以 `uint8` 讀取影格，而 LeRobot 中除了 `ColorJitter`、`RandomAffine` 與 `RandomRotation` 之外的轉換，過去會將非浮點數的輸入原樣回傳。因此，啟用 `GaussianNoise`、`MotionBlur`、`GaussianPatchBrightness`、`RandomShadow`、`CoarseDropout`、`GammaCorrection` 或 `PlanckianJitter` 的 recipe，實際上是在沒有套用這些轉換的情況下進行訓練。現在它們在兩個後端上都會生效，因此這類 recipe 的訓練結果會與以往不同：它會得到自己所要求的資料增強。已經在套用的轉換除了捨入之外沒有改變，因為批次路徑以浮點數計算，且只在最後捨入一次，而不是在每次轉換之後都捨入。

</Tip>

### 設定選項[[configuration-options]]

- **`enable`**：啟用或停用轉換（預設：`False`）
- **`max_num_transforms`**：每個影格最多套用的轉換數量（預設：`3`）
- **`random_order`**：以隨機順序或標準順序套用轉換（預設：`False`）
- **`weight`**：每種轉換被選中的機率（數值越高越容易被選中；若權重總和不為 1，會自動正規化）
- **`kwargs`**：各轉換專屬的參數（例如亮度範圍）
- **`backend`**：轉換在訓練期間的執行位置，可為 `"dataloader"`（預設）或 `"gpu"`；詳見下文
- **`gpu_compile`**：在 `"gpu"` 後端上，對批次轉換使用 `torch.compile`（預設：`True`）
- **`gpu_chunk_size`**：在 `"gpu"` 後端上，一次增強這麼多個樣本，以限制暫時性的記憶體用量（預設：`32`）

### 在 GPU 上執行轉換[[running-transforms-on-the-gpu]]

預設情況下，轉換會在 DataLoader worker 中逐樣本執行。當相機數量較多時，這往往是 worker 最耗費資源的工作，GPU 也因此閒置等待資料。設定 `backend=gpu`，讓 worker 只負責解碼，並在策略裝置上對每個批次套用相同的轉換：

```bash
lerobot-train \
  --dataset.repo_id=your-username/your-dataset \
  --dataset.image_transforms.enable=true \
  --dataset.image_transforms.backend=gpu \
  --policy.type=act \
  --policy.device=cuda
```

隨機化的方式維持不變：每個樣本會自行抽選轉換與參數，而同一台相機歷史中的影格則共用這些轉換與參數。資料增強只會套用到訓練批次，且在策略的前處理器之前進行；評估批次、rollout 與已儲存的檢查點都不受影響。

需要注意的事項：

- 需要加速器；`--policy.device=cpu` 會被拒絕。以手工建立、帶有自己 `image_transforms` 可呼叫物件的資料集也會被拒絕，因為那些會在 worker 中執行。
- 支援 dataloader 後端所支援的每一種轉換類型。沒有批次實作的類型（`JPEGCompression`，以及 `ColorJitter`、`RandomAffine`、`RandomRotation` 與 `Identity` 以外的 torchvision 類別）會在批次內一次套用一個樣本，因此無法獲得加速；`JPEGCompression` 還會經過 CPU 來回處理。會改變影格大小的轉換，在超過一個樣本的批次上會被拒絕。
- 可透過 `--seed` 重現，每個行程會使用不同的種子。資料增強不會消耗策略的隨機串流，而 `gpu_compile` 與 `gpu_chunk_size` 也不會改變實際套用的內容。
- 兩個後端都會以浮點數執行相同的批次轉換，並在最後取整數（round）一次，因此在相同參數下，同一個樣本在其中一個後端增強的結果，會等於在另一個後端增強的結果。
- `gpu_compile` 每種影像尺寸會花費 15-30 秒（僅一次）。尖峰記憶體約為批次影像的兩份浮點副本，再加上一個區塊的數份副本；若記憶體吃緊，請調低 `gpu_chunk_size`。`random_order=true` 會讓轉換時間乘以 `max_num_transforms`。

## 遷移 `v2.1` → `v3.0`[[migrate-v21-v30]]

轉換器會將每個回合各自的檔案彙整成更大的分片（shard），並寫入回合的偏移量與中繼資料。請依照以下說明轉換你的資料集。

```bash
# 具備 v3 支援的預發布版本建置：
pip install "https://github.com/huggingface/lerobot/archive/33cad37054c2b594ceba57463e8f11ee374fa93c.zip"

# 轉換一個託管在 Hub 上的既有 v2.1 資料集：
python -m lerobot.scripts.convert_dataset_v21_to_v30 --repo-id=<HF_USER/DATASET_ID>
```

**轉換器會做什麼**

- 彙整 parquet 檔案：`episode-0000.parquet`、`episode-0001.parquet`、… → **`file-0000.parquet`**、…
- 彙整 mp4 檔案：`episode-0000.mp4`、`episode-0001.mp4`、… → **`file-0000.mp4`**、…
- 更新 `meta/episodes/*`（分塊的 Parquet），寫入每個回合的長度、任務，以及位元組／影格偏移量。

## 常見問題[[common-issues]]

### 推送前務必呼叫 `finalize()`[[always-call-finalize-before-pushing]]

建立或錄製資料集時，你**必須**呼叫 `dataset.finalize()`，才能正確關閉 parquet writer。更多細節請參閱 [PR #1903](https://github.com/huggingface/lerobot/pull/1903)。

```python
from lerobot.datasets import LeRobotDataset

# 建立資料集並錄製回合
dataset = LeRobotDataset.create(...)

for episode in range(num_episodes):
    # 錄製影格
    for frame in episode_data:
        dataset.add_frame(frame)
    dataset.save_episode()

# 錄製完成後、push_to_hub() 之前呼叫 finalize()
dataset.finalize()  # 關閉 parquet writer，寫入中繼資料的 footer
dataset.push_to_hub()
```

**為什麼需要這麼做？**

為了提升效率，資料集 v3.0 會先緩衝中繼資料（metadata），再以漸進的方式寫入 parquet。`finalize()` 方法會：

- 將所有緩衝中的回合中繼資料寫入磁碟
- 關閉 parquet writer 並寫入 footer 中繼資料，否則 parquet 檔案會損毀
- 確保資料集可以正確載入

如果沒有呼叫 `finalize()`，parquet 檔案會不完整，資料集也無法正常載入。

## 其他格式與實作[[other-formats-and-implementations]]

### LanceDB 資料集後端[[lancedb-dataset-backend]]

`v3` 資料集也可以儲存為 [LanceDB](https://lancedb.com) 資料表。LanceDB 是建構在 Lance 格式上的多模態 data lakehouse，專為 AI 的存取模式設計：可以快速隨機存取任一資料列及其影片位元組，並在同一批資料表上建立純量、向量與全文索引，因此 EDA、資料探勘、資料整理與訓練都能直接在物件儲存（object storage）上進行。這種結構會保留 `meta/` 不變，另外新增存放表格資料的 `frames` 資料表，以及以 blob 形式存放 MP4 的 `videos` 資料表。`meta/info.json` 中的 `"storage_format": "lance"` 決定要使用哪個讀取器；`LeRobotDataset` API、資料項目與訓練管線都維持不變。

- **直接從 Hub 或 HF Storage Buckets 訓練，GPU 不必空等資料。** 隨機影格會就地讀取，而且只讀取每個批次所需的位元組，因此每個批次都是全域洗牌（global shuffle），也不需要事先下載任何資料。
- **轉換成本約等於複製檔案。** 影片不會重新編碼，因此資料項目與來源的位元完全相同。DROID 只需 34 分鐘即可轉換完成。
- **零複製的特徵工程。** 你可以在訓練器讀取的資料表中加入分數、嵌入向量或修正後的標籤等欄位，不必重寫影片或複製資料集，再透過索引進行篩選與搜尋。讀取器會忽略它不認得的欄位。

運作原理、基準測試與範例，請參閱 [LanceDB LeRobot 指南](https://docs.lancedb.com/training/lerobot)。

相機特徵必須以影片儲存。以影像形式儲存相機影格的資料集，讀取器不支援，必須先重新編碼為影片再轉換。

讀取 Lance 資料集需要 `lancedb` 額外套件（`pip install "lerobot[lancedb]"`）。此格式為唯讀：請以預設格式錄製與編輯資料集，再使用 [`lerobot-lancedb`](https://pypi.org/project/lerobot-lancedb/) 套件轉換：

```bash
pip install "lerobot-lancedb"
lerobot-lance-convert --repo-id lerobot/pusht --out ./pusht-lance  # 或 --root <本機資料集目錄>
```

載入時使用相同的類別：

```python
from lerobot.datasets import LeRobotDataset

# Hub 資料集儲存庫
dataset = LeRobotDataset("lance-format/pusht-lance")

# HF Storage Bucket，就地讀取
dataset = LeRobotDataset("my-org/pusht-lance", repo_type="bucket")

# 同一個 bucket 作為 root URI（其他物件儲存 URI 的運作方式相同）
dataset = LeRobotDataset("lerobot/pusht", root="hf://buckets/my-org/pusht-lance")
```

HF Storage Bucket 選項也可在 `lerobot-train` 中使用：

```bash
lerobot-train \
  --dataset.repo_id=my-org/pusht-lance \
  --dataset.repo_type=bucket \
  --policy.type=act
```

兩種檢視器都能用來視覺化。`lerobot-dataset-viz --repo-id lance-format/pusht-lance --episode-index 0` 會像平常一樣在 Rerun 中開啟一個回合，而 `--display-mode foxglove` 則會透過 WebSocket 將它提供給 [Foxglove](https://foxglove.dev)。無論哪一種方式，都只會擷取畫面上顯示的影格，不需要匯出或下載 MCAP。
