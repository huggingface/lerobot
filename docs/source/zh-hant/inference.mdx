# 策略部署（policy deployment, lerobot-rollout）[[policy-deployment-lerobot-rollout]]

`lerobot-rollout` 是在真實機器人上部署訓練好的策略（deploying trained policies）的單一 CLI。它支援多種執行策略（execution strategies）與推論後端（inference backends），從快速評估（evaluation）到連續錄製（recording），以及人在迴圈的資料收集（human-in-the-loop data collection）。

## 快速開始（quick start）[[quick-start]]

除了你的機器人與策略額外套件（policy extras）之外，不需要額外的相依套件（extra dependencies）。

```bash
lerobot-rollout \
    --strategy.type=base \
    --policy.path=lerobot/act_koch_real \
    --robot.type=koch_follower \
    --robot.port=/dev/ttyACM0 \
    --task="pick up cube" \
    --duration=30
```

這會執行策略（policy）30 秒，且不錄製（record）。

### 選擇裝置[[choosing-a-device]]

傳入 `--device=cpu` 或 `--device=cuda`，即可在該裝置可用的主機上覆寫檢查點裝置（checkpoint device）。
解析出的裝置會在載入策略（policy）與建構其處理器（processor）之前，套用到策略設定（policy configuration）中。
例如，若策略支援 CPU 執行，可在上述指令中加入 `--device=cpu`，在僅有 CPU 的主機上執行以 CUDA 訓練的檢查點。
在機器人上部署前，請確認 CPU 推論（inference）能達到你所需的控制頻率（control rate）。

若省略 `--device`，rollout 會使用策略設定中的裝置（若有設定），否則自動選擇可用的裝置。
搭配 `build_rollout_context` 使用 `RolloutConfig(device=...)` 時，行為亦同。

## 策略（strategies）[[strategies]]

以 `--strategy.type=<name>` 選擇執行策略（strategy）。每種執行策略定義一個不同的控制迴圈（control loop），具有其自身的錄製（recording）與互動語意（interaction semantics）。

### Base（`--strategy.type=base`）[[base---strategytypebase]]

自主的策略（policy）執行，不錄製（record）資料。用於快速評估、示範，或當你只需要觀察機器人時。

```bash
lerobot-rollout \
    --strategy.type=base \
    --policy.path=${HF_USER}/my_policy \
    --robot.type=so100_follower \
    --robot.port=/dev/ttyACM0 \
    --robot.cameras="{ front: {type: opencv, index_or_path: 0, width: 640, height: 480, fps: 30}}" \
    --task="Put lego brick into the box" \
    --duration=60
```

| 旗標（flag）     | 描述（description）                                                    |
| ---------------- | ---------------------------------------------------------------------- |
| `--duration`     | 執行時間（秒，0 = 無限）                                               |
| `--task`         | 傳給策略（policy）的任務描述（task description）                       |
| `--display_data` | 將觀測/動作（observations/actions）串流（stream）到 Rerun 以進行視覺化 |

### Sentry（`--strategy.type=sentry`）[[sentry---strategytypesentry]]

連續的自主錄製（recording），並定期上傳到 Hugging Face Hub。回合邊界（episode boundaries）會從攝影機解析度（camera resolution）與 FPS 自動計算，使每個儲存的回合都產生一個完整的影片檔案，讓上傳保持高效。

策略狀態（policy state，隱藏狀態 hidden state、RTC 佇列 queue）會跨回合邊界（episode boundaries）持續存在：機器人在回合之間不會重設。

```bash
lerobot-rollout \
    --strategy.type=sentry \
    --strategy.upload_every_n_episodes=5 \
    --policy.path=${HF_USER}/my_policy \
    --robot.type=so100_follower \
    --robot.port=/dev/ttyACM0 \
    --robot.cameras="{ front: {type: opencv, index_or_path: 0, width: 640, height: 480, fps: 30}}" \
    --dataset.repo_id=${HF_USER}/rollout_eval_data \
    --dataset.single_task="Put lego brick into the box" \
    --duration=3600
```

| 旗標（flag）                           | 描述（description）                                                  |
| -------------------------------------- | -------------------------------------------------------------------- |
| `--strategy.upload_every_n_episodes`   | 每 N 個回合（episode）推送到 Hub（預設：5）                          |
| `--strategy.target_video_file_size_mb` | 回合輪替（episode rotation）的目標影片檔案大小（預設：自動）         |
| `--dataset.repo_id`                    | **必填。** 錄製資料集（recorded dataset）的 Hub 儲存庫（repository） |
| `--dataset.push_to_hub`                | 是否在收尾（teardown）時推送到 Hub（預設：true）                     |

### Highlight（`--strategy.type=highlight`）[[highlight---strategytypehighlight]]

自主 rollout，透過一個記憶體有界的環形緩衝區（ring buffer）按需錄製（on-demand recording）。機器人持續執行，同時緩衝區擷取最近 N 秒的遙測資料（telemetry）。按下儲存鍵以刷新緩衝區（flush the buffer）並開始即時錄製；再按一次以儲存該回合（episode）。

```bash
lerobot-rollout \
    --strategy.type=highlight \
    --strategy.ring_buffer_seconds=30 \
    --strategy.save_key=s \
    --strategy.push_key=h \
    --policy.path=${HF_USER}/my_policy \
    --robot.type=koch_follower \
    --robot.port=/dev/ttyACM0 \
    --dataset.repo_id=${HF_USER}/rollout_highlight_data \
    --dataset.single_task="Pick up the red cube"
```

**鍵盤控制：**

| 鍵（key）                  | 動作（action）                                    |
| -------------------------- | ------------------------------------------------- |
| `s`（可設定 configurable） | 開始錄製（刷新緩衝區）/ 停止並儲存回合（episode） |
| `h`（可設定 configurable） | 將資料集（dataset）推送到 Hub                     |
| `ESC`                      | 停止工作階段（session）                           |

| 旗標（flag）                           | 描述（description）                   |
| -------------------------------------- | ------------------------------------- |
| `--strategy.ring_buffer_seconds`       | 緩衝遙測的時長（預設：30）            |
| `--strategy.ring_buffer_max_memory_mb` | 環形緩衝區的記憶體上限（預設：2048）  |
| `--strategy.save_key`                  | 切換錄製（record）的按鍵（預設：`s`） |
| `--strategy.push_key`                  | 推送到 Hub 的按鍵（預設：`h`）        |

### DAgger（`--strategy.type=dagger`）[[dagger---strategytypedagger]]

人在迴圈的資料收集（human-in-the-loop data collection）。在自主策略執行（autonomous policy execution）與透過遙操作器的人為介入（human intervention via a teleoperator）之間交替。介入影格（intervention frames）會被標記為 `intervention=True`。需要一個遙操作器（teleoperator, `--teleop.type`）。

詳細操作步驟請參閱[人在迴圈中的資料收集（Human-In-the-Loop data collection）](./hil_data_collection)指南。

**僅修正模式（預設，corrections-only mode）**：只錄製（recorded）人為修正的窗口（human correction windows）。每次修正成為一個回合（episode）。

```bash
lerobot-rollout \
    --strategy.type=dagger \
    --strategy.num_episodes=20 \
    --policy.path=outputs/pretrain/checkpoints/last/pretrained_model \
    --robot.type=bi_openarm_follower \
    --teleop.type=bi_openarm_mini \
    --dataset.repo_id=${HF_USER}/rollout_hil_data \
    --dataset.single_task="Fold the T-shirt"
```

**連續錄製模式（continuous recording mode, `--strategy.record_autonomous=true`）**：自主與修正影格（autonomous and correction frames）皆會錄製（recorded），並採用以時間為基礎的回合輪替（time-based episode rotation，與 Sentry 相同）。

```bash
lerobot-rollout \
    --strategy.type=dagger \
    --strategy.record_autonomous=true \
    --strategy.num_episodes=50 \
    --policy.path=${HF_USER}/my_policy \
    --robot.type=so100_follower \
    --robot.port=/dev/ttyACM0 \
    --teleop.type=so101_leader \
    --teleop.port=/dev/ttyACM1 \
    --dataset.repo_id=${HF_USER}/rollout_dagger_data \
    --dataset.single_task="Grasp the block"
```

**鍵盤控制**（預設輸入裝置）：

| 鍵（key） | 動作（action）                                            |
| --------- | --------------------------------------------------------- |
| `Space`   | 暫停 / 恢復（pause / resume）策略執行（policy execution） |
| `Tab`     | 開始 / 停止（start / stop）人為修正（human correction）   |
| `Enter`   | 將資料集（dataset）推送到 Hub（僅修正模式）               |
| `ESC`     | 停止工作階段（session）                                   |

也可透過 `--strategy.input_device=pedal` 支援腳踏板輸入（foot pedal input）。以 `--strategy.pedal.*` 旗標（flag）設定踏板代碼（configure pedal codes）。

| 旗標（flag）                         | 描述                                                                                                                                         |
| ------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------- |
| `--strategy.num_episodes`            | 要錄製的修正回合數量（預設：10）                                                                                                             |
| `--strategy.record_autonomous`       | 也錄製自主影格（autonomous frames，預設：false）                                                                                             |
| `--strategy.upload_every_n_episodes` | 每 N 個回合推送到 Hub（預設：5）                                                                                                             |
| `--strategy.input_device`            | 輸入裝置：`keyboard` 或 `pedal`（預設：keyboard）                                                                                            |
| `--strategy.smooth_handover`         | 在暫停 / 修正開始時平滑地移交控制權（預設：true）。對於在接合時會以目前機器人姿勢重新建立參考的離合器式遙操作（clutch-style teleop），請停用 |
| `--teleop.type`                      | **必填。** 遙操作器（Teleoperator）類型                                                                                                      |

### Episodic（`--strategy.type=episodic`）[[episodic---strategytypeepisodic]]

以回合為導向的錄製（episode-oriented recording），鏡像（mirrors） `lerobot-record` 的行為。策略（policy）在每個回合（episode）驅動機器人；一個可選的遙操作器（teleoperator）可在回合之間的重設階段（reset phase）驅動機器人。

```bash
lerobot-rollout \
    --strategy.type=episodic \
    --policy.path=${HF_USER}/my_policy \
    --robot.type=so100_follower \
    --robot.port=/dev/ttyACM0 \
    --teleop.type=so100_leader \
    --teleop.port=/dev/ttyACM1 \
    --dataset.repo_id=${HF_USER}/my_eval_data \
    --dataset.num_episodes=20 \
    --dataset.episode_time_s=30 \
    --dataset.reset_time_s=10 \
    --dataset.single_task="Pick up the red cube"
```

遙操作（teleop）是可選的 — 若省略，機器人會在重設階段（reset phase）維持其位置（position）。

**鍵盤控制：**

| 鍵（key） | 動作（action）                                        |
| --------- | ----------------------------------------------------- |
| `→`（右） | 提早結束（end）目前的回合（current episode）          |
| `←`（左） | 捨棄回合（discard episode）並重新錄製（re-record it） |
| `ESC`     | 停止（stop）錄製階段（recording session）             |

| 旗標（flag）                                    | 描述（description）                                                                                                                                  |
| ----------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--dataset.num_episodes`                        | 要錄製的回合數量                                                                                                                                     |
| `--dataset.episode_time_s`                      | 以秒為單位的每個錄製回合的時長。當 `--duration` 已設定而此項未設定時，預設為 `--duration`                                                            |
| `--dataset.reset_time_s`                        | 以秒為單位的回合之間重設階段的時長                                                                                                                   |
| `--teleop.type`                                 | 可選。在重設期間（reset phase）驅動機器人的遙操作器（teleoperator）                                                                                  |
| `--strategy.reset_to_initial_position`          | 是否在回合（episode）之間將機器人重設（reset）到其初始位置（initial position）                                                                       |
| `--strategy.smooth_leader_to_follower_handover` | 是否開啟或關閉主臂（leader）-> 從臂（follower）的平滑交接行為。                                                                                      |
| `--strategy.smooth_handover`                    | 在重設開始時平滑地將控制權移交給遙操（預設：true）。對於在接合時會以目前機器人姿勢重新建立參考的離合器式遙操作（clutch-style teleops），請停用此選項 |

### 自帶策略（Bring your own strategy）[[bring-your-own-strategy]]

`--strategy.type` 接受環境中註冊的任何策略（strategy），不限於上述內建項目。一個策略是位於可用 pip 安裝之套件中的兩個類別：一個註冊在 `RolloutStrategyConfig` 上的設定（config），以及一個名稱去掉 `Config` 尾綴的 `RolloutStrategy` 子類（subclass） —— 與[自訂硬體（custom hardware）](./integrate_hardware#the-4-core-conventions)相同的 `SomethingConfig`/`Something` 慣例，會從設定所屬的模組或套件解析。

```python
from dataclasses import dataclass
from typing import ClassVar

from lerobot.rollout import RolloutContext, RolloutStrategy, RolloutStrategyConfig


@RolloutStrategyConfig.register_subclass("patrol")
@dataclass
class PatrolStrategyConfig(RolloutStrategyConfig):
    dataset_mode: ClassVar[str] = "required"  # 引擎會為你建立資料集
    legs: int = 2  # 會變成 --strategy.legs


class PatrolStrategy(RolloutStrategy):
    def run(self, ctx: RolloutContext) -> None:
        ...  # 有節奏的控制迴圈：請參閱 RolloutStrategy.run 上的契約

    def teardown(self, ctx: RolloutContext) -> None:
        ctx.data.dataset.finalize()
        self._teardown_hardware(ctx.hardware, ctx.runtime.cfg.return_to_initial_position)
```

設定（config）會宣告引擎要為策略（strategy）安排哪些事項，因此 LeRobot 中沒有任何部分需要知道它的型別：

| 宣告（declaration）             | 效果                                                                                                                             |
| ------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `dataset_mode`                  | `"none"`（預設）會拒絕 `--dataset.*` 旗標，`"optional"` 在提供這些旗標時進行錄製，`"required"` 則讓 `--dataset.repo_id` 成為必填 |
| `requires_teleop`               | 讓 `--teleop.type` 成為必填                                                                                                      |
| `supports_interactive`          | 允許 `--interactive=true`；此時 `run()` 必須遵守記錄在 `RolloutStrategy` 上的可重新啟動契約                                      |
| `requires_streaming_encoding()` | 當影格（frames）是從控制迴圈內部寫入時回傳 `True`：`--dataset.streaming_encoding` 會被強制開啟                                   |
| `extra_dataset_features()`      | 策略擁有的資料集欄位（例如 DAgger 的 `intervention`）；每個錄製的影格都必須帶有這些欄位                                          |

將發行版（distribution）命名為 `lerobot_strategy_<name>`，`lerobot-rollout` 便會在解析 CLI 之前匯入該套件 —— 只會執行其 `__init__.py`，因此請在該處匯入設定（config）。若套件名稱不同，可使用 `--strategy.discover_packages_path=<package>` 載入該套件（包含子模組）。策略的 dataclass 欄位會變成 `--strategy.*` 旗標：

```bash
lerobot-rollout \
    --strategy.type=patrol \
    --strategy.legs=3 \
    --policy.path=${HF_USER}/my_policy \
    --robot.type=so100_follower \
    --robot.port=/dev/ttyACM0 \
    --dataset.repo_id=${HF_USER}/rollout_patrol \
    --dataset.single_task="patrol the aisle"
```

`SentryStrategy`（會錄製、可安全用於互動模式）與 `BaseStrategy`（不錄製）是可供複製的參考實作；`lerobot.rollout.strategies` 中的 `send_next_action`、`safe_push_to_hub` 與 `estimate_max_episode_seconds` 則是它們所建構於其上的輔助函式。

## 推論後端（inference backends）[[inference-backends]]

以 `--inference.type=<name>` 選擇後端（backend）。所有策略（policy）皆可搭配兩種後端運作。

### 預設：同步（sync）[[sync-default]]

每個控制刻（control tick）一次策略呼叫（policy call）。主迴圈會阻塞（main loop blocks），直到動作（action）被計算出來。

適用於所有策略（policy）。不需要額外旗標（flag）。

### 即時分塊（real-time chunking, `--inference.type=rtc`）[[real-time-chunking---inferencetypertc]]

一個背景執行緒（background thread）非同步（asynchronous）地產生動作區塊（action chunks）。主控制迴圈輪詢（main control loop polls）下一個就緒的動作（next ready action），同時策略（policy）在平行地（paraller）計算下一個區塊（next chunk）。

在大型、緩慢的 VLA 模型（Pi0、Pi0.5、SmolVLA）上使用 RTC，即可在高推論延遲（high inference latency）下仍達成平滑、連續的動作（smooth, continuous motion）。

```bash
lerobot-rollout \
    --strategy.type=base \
    --inference.type=rtc \
    --inference.rtc.execution_horizon=10 \
    --inference.rtc.max_guidance_weight=10.0 \
    --policy.path=${HF_USER}/pi0_policy \
    --robot.type=so100_follower \
    --robot.port=/dev/ttyACM0 \
    --robot.cameras="{ front: {type: opencv, index_or_path: 0, width: 640, height: 480, fps: 30}}" \
    --task="Pick up the cube" \
    --duration=60 \
    --device=cuda
```

| 旗標（flag）                                | 描述（description）                                                                      |
| ------------------------------------------- | ---------------------------------------------------------------------------------------- |
| `--inference.rtc.execution_horizon`         | 要與前一個區塊混合的步數（steps to blend with previous chunk，預設：依策略 policy 而異） |
| `--inference.rtc.mode`                      | `guided`（預設）或用於相容 Pi05 檢查點的已訓練前綴（trained-prefix）`trained`            |
| `--inference.rtc.max_guidance_weight`       | 一致性強制的強度（consistency enforcement strength，預設：依策略 policy 而異）           |
| `--inference.rtc.prefix_attention_schedule` | 混合排程（blend schedule）：`LINEAR`、`EXP`、`ONES`、`ZEROS`                             |
| `--inference.queue_threshold`               | 背壓閾值（backpressure threshold）；已訓練的 RTC 至少需要其最大延遲                      |

調校 RTC 參數（parameters）的細節請參閱[即時分塊（Real-Time Chunking）](./rtc)指南。

## 互動工作階段（interactive sessions）[[interactive-sessions]]

加入 `--interactive=true`，即可從終端機驅動 rollout，而不是立即啟動。硬體會照常連線，策略（policy）也會照常載入，但**在你輸入 `/start` 之前機器人會保持靜止** —— 當你想先擺設場景、在多次嘗試之間重新下指令給策略，或在不重複付出載入時間的情況下執行多次拍攝時，這很實用。

```bash
lerobot-rollout \
    --strategy.type=base \
    --policy.path=${HF_USER}/my_smolvla_policy \
    --robot.type=so100_follower \
    --robot.port=/dev/ttyACM0 \
    --robot.cameras="{ front: {type: opencv, index_or_path: 0, width: 640, height: 480, fps: 30}}" \
    --task="pick up the cube" \
    --interactive=true
```

| 指令（command）     | 動作（action）                                                                                                                         |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `/start`            | 開始（或重新開始）策略控制迴圈                                                                                                         |
| `/subtask <text>`   | 在不停止的情況下變更策略遵循的指令（instruction）。不帶引數時會印出目前的任務。只會影響以語言為條件的策略（SmolVLA、π0/π0.5 等類似者） |
| `/vqa <text>`       | 針對策略目前所見向它提問。僅在執行進行中可用，且僅適用於具有 text head 的策略                                                          |
| `/autosteer <goal>` | 交給策略一個高階目標，讓它自行選擇子任務。`/autosteer off` 會交還控制權；不帶引數時會回報目前的目標                                    |
| `/reset`            | 停止移動、將機器人返回其啟動位置，並還原 `--task` 指令                                                                                 |
| `/stop`             | 結束工作階段並執行一般的關閉程序                                                                                                       |
| `/help`             | 列出指令                                                                                                                               |

以 `>` 開頭的行是你輸入的內容；工作階段本身不會顯示提示符號。

`Ctrl-C` 仍會照常關閉，而關閉 stdin（`Ctrl-D`，或管線腳本的結束）會結束工作階段 —— 因此管線腳本必須在預期的期間內保持 stdin 開啟：

```bash
(printf '/start\n'; sleep 60; printf '/stop\n') | lerobot-rollout ... --interactive=true
```

**`/subtask`** 會從下一次推論（inference）起生效。使用 `--inference.type=sync` 時，預先計算好的區塊動作（chunk actions）會被丟棄，因此切換會落在下一個控制刻（control tick）；使用 `rtc` 時，新區塊會與前一區塊剩餘的前綴（leftover prefix）混合，因此會在單次推論內生效，動作也保持連續（使用 `--inference.rtc.enabled=false` 時，佇列中的區塊會先耗盡，使切換延遲最多一個區塊）。

使用 `--use_torch_compile=true` 時，若某個指令 tokenize 後的長度不同，可能觸發重新編譯（recompilation），使推論暫停與原本暖機（warm-up）一樣長的時間 —— 若你預期會經常重新下指令，請保持關閉編譯。

`/vqa` 與 `/autosteer` 需要具有 text head 的策略（即 `PreTrainedPolicy.generate_text()` 的實作）；目前內建的 LeRobot 策略尚未提供，因此除非你的策略有，否則這兩個指令都會被拒絕。

**`/vqa`** 會依據下一次觀測（observation）作答，並在就緒時輸出，因此你可以同時繼續輸入；同一時間只會有一個問題在處理中（autosteer 自己的查詢會共用該 slot）。文字生成遠比一個控制刻（control tick）慢，因此機器人會先消化佇列中的動作，然後保持位置直到答案產生，而這段時間會計入 `--duration`。只有在執行進行中才會接受提問 —— 閒置的引擎沒有目前的視野 —— 而當某個區段（segment）結束時仍未回答的問題會被丟棄並回報。

**`/autosteer`** 會交給策略一個目標，並每隔 `--autosteer_interval_s` 秒（預設 10）向它索取下一個子任務，透過與 `/subtask` 相同的路徑套用每個子任務，並在對話中公告。每個查詢都是一次完整的文字生成，因此該間隔是成本的調節旋鈕：較低的值會更早重新規劃，但會讓迴圈花更多時間在生成文字而非採取行動。計畫進度存在於策略（policy）中，而非 rollout 中，因此計畫會隨著區段結束而消失；序列器（sequencer）也會在 `/reset`、`/subtask`、`/autosteer off` 以及第一次規劃失敗時停止。

**工作階段執行期間，ERROR 以下的日誌會被靜音**，以免例行輸出與你正在輸入的內容交錯；錯誤與致命的推論失敗仍會顯示，而工作階段結束後會恢復正常記錄。[節奏摘要（cadence summaries）](#cadence-reporting)則會改為印在對話中；若不使用 `--interactive` 執行，就會恢復即時日誌。

工作階段可透過 SSH 以及在無頭（headless）機器上運作 —— 不需要顯示伺服器。

**互動模式下錄製。** `--strategy.type=sentry` 也接受 `--interactive=true`，並在你操控期間持續錄製：每個 `/start`…`/reset` 區段都會儲存完整的回合（episode），外加一個最後的部分回合，而資料集會保持開啟直到關閉。影格（frame）會帶有實際送出之動作的任務來源（task provenance），因此已在舊任務下排入佇列或內插的動作會保留舊標籤。

```bash
lerobot-rollout \
    --strategy.type=sentry \
    --policy.path=${HF_USER}/my_smolvla_policy \
    --robot.type=so100_follower \
    --robot.port=/dev/ttyACM0 \
    --dataset.repo_id=${HF_USER}/rollout_cube_sessions \
    --task="pick up the cube" \
    --interactive=true
```

其他錄製策略（episodic、DAgger、highlight）不支援此模式：它們會綁定自己的鍵盤控制，並在 `run()` 結束時完成資料集（finalize），因此無法逐區段重新啟動。

### 程式化控制（Programmatic control）[[programmatic-control]]

`RolloutController` 以函式庫 API 的形式提供相同的操作 —— 執行緒安全的（thread-safe）`start()` / `reset()` / `stop()` / `set_task()`，外加一個 `RolloutEvent` 回呼（callback），且不附帶 stdin、輸出或日誌靜音功能：

```python
from threading import Event, Thread

from lerobot.rollout import (
    LinkedEvent,
    RolloutController,
    RolloutEvent,
    build_rollout_context,
    create_strategy,
)

parent = Event()  # 你應用程式的關閉訊號
ctx = build_rollout_context(cfg, LinkedEvent(parent))  # 載入策略、連接機器人
strategy = create_strategy(cfg.strategy)
strategy.setup(ctx)

controller = RolloutController(strategy, ctx, on_event=print)  # 或你自己的觀察者
serve_thread = Thread(target=controller.serve)  # serve() 會阻塞；可在任何你喜歡的地方執行
serve_thread.start()

controller.start()                        # 機器人開始執行策略
controller.set_task("grab the red cube")  # 在執行中重新下指令
controller.reset()                        # 停止移動、返回原點、保持暖機
controller.stop()                         # 結束 serve()

serve_thread.join()
strategy.teardown(ctx)  # 收尾（teardown）仍由呼叫端負責
```

`RolloutController` 要求情境的關閉事件（context’s shutdown event）必須是 `LinkedEvent`，並如上所示建構：控制器會透過其本機旗標結束執行區段，而你的 `parent` 事件仍會強制執行完整關閉。除非你想要語音公告（vocal announcements），否則請設定 `play_sounds=False`。

## 節奏回報（cadence reporting）[[cadence-reporting]]

每個策略（strategy）都會回報其控制迴圈（control loop）實際達到的成果，`lerobot-record`、`lerobot-teleoperate` 與 `lerobot-replay` 亦然 —— 它們全都透過同一個計時器（timer）來調整節奏。每個儲存的回合都會有一行摘要，而當迴圈結束時 —— 包括按下 `Ctrl-C` —— 則會有一個涵蓋整次執行的區塊：

```
Cadence (episode 1): 29.84 Hz policy vs 30 Hz target · 1200 ticks, 20.1 s measured · 6/598 cycles over the 33.3 ms budget (work mean 18.7 ms, worst 48.1 ms)
Cadence (episode 2): 29.84 Hz policy vs 30 Hz target · 1200 ticks, 20.1 s measured · 6/599 cycles over the 33.3 ms budget (work mean 18.7 ms, worst 48.1 ms)
Cadence summary — whole run, 2 episodes · target 30 Hz × 2 (16.7 ms tick slot, 33.3 ms cycle budget): 2400 ticks, 1197 cycles judged
  effective cadence: 29.84 Hz policy / 59.67 Hz commands over 40.2 s measured
  cycles over the 33.3 ms work budget: 12/1197 (1.0%) — work mean 18.7 ms, worst 48.1 ms
  ticks over their 16.7 ms slot: 40/2400 (costs interpolation smoothness only)
  loop-body steps (share of measured work):
    observe      mean   3.13 ms · worst   9.00 ms ·  31.7% of work · 2400 calls
    process_obs  mean   0.50 ms · worst   1.00 ms ·   5.1% of work · 2400 calls
    infer        mean   5.18 ms · worst  40.00 ms ·  52.4% of work · 2400 calls
    send         mean   0.40 ms · worst   0.40 ms ·   4.1% of work · 2400 calls
    record       mean   0.67 ms · worst 620.00 ms ·   6.8% of work · 2402 calls
  pacing headroom: 7.4 ms slept per tick on average (max 13.0 ms) — near zero means the loop is saturated
```

由上而下閱讀：**effective cadence** 是你相對於 `--fps` 實際達到的成果，**cycles over budget** 是迴圈無法維持目標的頻率，**step breakdown** 說明時間花在哪裡，而 **pacing headroom** 接近零表示已沒有餘裕吸收一次緩慢的刻（tick）。`infer` 佔比偏高指向策略（policy）或裝置；`observe` 佔比偏高則指向相機。某個步驟的 `worst` 遠高於其 `mean` 屬於一次性事件 —— 在上例中，`record` 每格為 0.67 ms，而 620 ms 的離群值（outlier）是關閉某個回合時造成阻塞的 `save_episode`。

這裡的一個 _cycle_ 是相當於一個策略動作的刻數（`--interpolation_multiplier` 個刻）。只有整個 cycle 超出 `1/fps` 預算時才會讓你掉影格（frame）；單一控制刻超出其時槽只會讓內插後的動作較不平順，這也是兩者分開計算的原因。若未使用內插，一個 cycle 就是單一刻，因此報告會省略這項區分，全程以刻（tick）計算。

在[互動工作階段（interactive sessions）](#interactive-sessions)中，每個 `/start` 區段都有自己的計時器，因此報告會每個區段（`/reset`、`/stop` 或 `--duration`）在對話中出現一次，而不是每個行程（process）一次。

## 程式化用法（programmatic usage）[[programmatic-usage]]

對於自訂部署（custom deployments，例如搭配運動學處理器 kinematics processors），請直接使用 rollout 模組 API（rollout module API）：

```python
from lerobot.rollout import BaseStrategyConfig, RolloutConfig, build_rollout_context
from lerobot.rollout.inference import SyncInferenceConfig
from lerobot.rollout.strategies import BaseStrategy
from lerobot.utils.process import ProcessSignalHandler

cfg = RolloutConfig(
    robot=my_robot_config,
    policy=my_policy_config,
    strategy=BaseStrategyConfig(),
    inference=SyncInferenceConfig(),
    fps=30,
    duration=60,
    task="my task",
)

signal_handler = ProcessSignalHandler(use_threads=True)
ctx = build_rollout_context(
    cfg,
    signal_handler.shutdown_event,
    robot_action_processor=my_custom_action_processor,       # 選用
    robot_observation_processor=my_custom_obs_processor,     # 選用
)

strategy = BaseStrategy(cfg.strategy)
try:
    strategy.setup(ctx)
    strategy.run(ctx)
finally:
    strategy.teardown(ctx)
```

搭配運動學處理器（kinematics processors）的完整範例，請參閱 `examples/so100_to_so100_EE/rollout.py` 與 `examples/phone_to_so100/rollout.py`。
