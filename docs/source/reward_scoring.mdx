# Offline Reward-Model Scoring

LeRobot's offline scoring workflow runs a reward model over dataset episodes and writes frame-aligned signals to a versioned Parquet sidecar. A sidecar is a separate file that joins back to source frames through `index`, `episode_index`, and `frame_index`. The source dataset is not modified, and filtering remains a downstream decision.

```text
  LeRobotDataset                  reward model
        │                              │
        └──────────────┬───────────────┘
                       ▼
             ┌───────────────────┐
             │ model-specific    │
             │ frame scorer      │
             └─────────┬─────────┘
                       │ FrameSignals for one episode
                       ▼
             ┌───────────────────┐
             │ shared runner     │
             │ validate + resume │
             └─────────┬─────────┘
                       │ atomic episode parts
                       ▼
            reward_signals/robometer.parquet
              (versioned signal sidecar)
                       │
                       ▼
       annotation / filtering / weighting / evaluation
```

The model-specific scorer owns sampling, preprocessing, and conversion from native predictions to `FrameSignals`. The shared runner selects episodes and validates the returned signals. The writer owns atomic episode parts, resume, deterministic streaming merge, and final publication.

## Score a Dataset

The scoring command currently supports RoboMeter:

```bash
uv run lerobot-score-dataset \
    --dataset_repo_id=lerobot/libero_10_image \
    --reward_model_path=lerobot/Robometer-4B \
    --device=cuda
```

By default, the sidecar is written to `reward_signals/robometer.parquet` under the local dataset root. Use `--output_path=/path/signals.parquet` to choose another location and `--episodes='[0,1]'` to select episodes.

Pass `--push_to_hub=true` to upload the completed sidecar to `reward_signals/robometer.parquet` in the dataset repository. Atomic episode parts are local staging data: they remain available after an interrupted run and are removed after the final sidecar is published successfully.

For an immutable run, pass commit hashes through `--dataset_revision` and `--reward_model_revision`. The requested revisions are stored in provenance and must match when resuming.

The command is resumable by default. Every completed episode is first written atomically under a hidden `.parquet.parts` directory. A retry skips those episodes only when the dataset revision, model revision, scorer options, episode selection, and schema are unchanged. Completed parts are streamed into the final Parquet file in episode order, so finalization holds only one episode at a time in memory. An identical rerun validates and reuses the published sidecar without rescoring it.

## Python API

```python
from pathlib import Path

from lerobot.rewards.robometer import score_robometer_dataset
from lerobot.rewards.scoring import (
    get_scoring_provenance,
    get_signal_descriptors,
    read_frame_signals,
)

summary = score_robometer_dataset(
    dataset,
    reward_model,
    output_path=Path("reward_signals/robometer.parquet"),
    model_id="lerobot/Robometer-4B",
)

table = read_frame_signals(summary.output_path)
descriptors = get_signal_descriptors(table)
provenance = get_scoring_provenance(table)
```

Application code for RoboMeter should use `score_robometer_dataset()`. Scorer authors use `score_dataset(dataset, scorer, ...)`, and consumers use `read_frame_signals()`.

A scorer returns one `FrameSignals` object per episode. Frame indices may be dense or sparse, but must be episode-local, unique, strictly increasing, and aligned with one-dimensional numeric signal arrays.

## Output Contract

Every new sidecar contains:

- `index`, `episode_index`, and `frame_index` identity columns;
- namespaced signal columns such as `reward.robometer.progress`;
- semantic descriptors: a description, optimization direction, optional unit, bounds and comparison scope, plus whether NaN is allowed;
- provenance for the dataset, model, scorer options, and LeRobot version.

`bounds` describes the signal's theoretical or semantic range, not the minimum and maximum observed in one run. `comparison_scope` states whether direct comparisons are meaningful within an episode, task, dataset, or globally. Signals reject NaN by default; a scorer may explicitly allow it when missing frames are meaningful, as in some legacy SARM outputs.

Descriptors and provenance are encoded in the Parquet schema metadata. They are not repeated as columns on every frame row.

The reader also recognizes older LeRobot `progress_sparse` and `progress_dense` Parquet sidecars. It preserves their column names and attaches explicit legacy provenance rather than pretending they were produced by the new schema.

## Scope

Offline scoring is for annotation, inspection, filtering, and later relabeling. It is not used inside the environment control loop. Online RL will call the same native model APIs through a transition-time consumer, without Parquet IO or sidecar merging.
