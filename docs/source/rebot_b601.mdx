# reBot B601

The reBot B601 is an open-source, low-cost robot arm from Seeed Studio for embodied-AI and imitation learning. It comes as a **follower** arm (a 6-DOF arm plus gripper driven by CAN motors) and a **leader** arm (the `StarArm102` / `reBot Arm 102`, driven by FashionStar UART smart servos) used to teleoperate it.

The follower ships in two builds with the same joint topology but different geometry and actuators, selected in LeRobot with a single argument, `--robot.motor_family`:

| Build                                                              | `motor_family` | Motors                                   | Default transport      |
| ------------------------------------------------------------------ | -------------- | ---------------------------------------- | ---------------------- |
| [B601-DM](https://wiki.seeedstudio.com/rebot_arm_b601_dm_lerobot/) | `dm`           | Damiao (`4340P` base, `4310` wrists)     | Damiao serial bridge   |
| [B601-RS](https://wiki.seeedstudio.com/rebot_arm_b601_rs_lerobot/) | `rs`           | RobStride (`rs-06` base, `rs-00` wrists) | MotorBridge native CAN |

The software workflow and joint names are shared, while each build keeps its own motor models, limits and tuning.

This page covers **calibration** and **teleoperation** for both single-arm and bimanual (dual-arm) setups.

## Install LeRobot 🤗

Follow our [Installation Guide](./installation), then install the reBot support:

```bash
pip install -e ".[rebot]"
```

This installs `motorbridge` for the B601 follower and `motorbridge-smart-servo` for the reBot Arm 102 leader. The Damiao serial bridge does not need a native CAN interface. For native CAN, MotorBridge uses SocketCAN on Linux and PCAN-compatible backends on macOS and Windows; the required adapter and system runtime may need to be installed separately.

## Registered device types

| Type                     | Kind                                         |
| ------------------------ | -------------------------------------------- |
| `rebot_b601_follower`    | single-arm B601 follower robot               |
| `bi_rebot_b601_follower` | bimanual (dual-arm) follower robot           |
| `rebot_102_leader`       | single-arm reBot Arm 102 leader teleoperator |
| `bi_rebot_102_leader`    | bimanual (dual-arm) leader teleoperator      |

Both follower builds share the `rebot_b601_follower` type. `motor_family` defaults to `dm`; select RS explicitly with `--robot.motor_family=rs`.

The bimanual types compose two single-arm instances and namespace each arm's
observation/action keys with a `left_` / `right_` prefix. Per-arm settings are
passed through nested `left_arm_config.*` / `right_arm_config.*` arguments. Each
arm selects its own motor family and transport.

## Connect the follower

The follower talks to its motors over CAN. DM supports its serial bridge (`--robot.can_adapter=damiao`) or MotorBridge's native CAN transport (`--robot.can_adapter=socketcan`). RS uses native CAN. Although the option is named `socketcan`, MotorBridge selects the platform backend, so it also works on macOS and Windows. The default is `damiao` for DM and `socketcan` for RS.

The `can0` channel used below is a Linux example. On macOS or Windows, pass the channel identifier expected by the installed MotorBridge CAN backend.

For a serial bridge, find the USB port with:

```bash
lerobot-find-port
```

On Linux, list the available SocketCAN channels and bring the interface up:

```bash
ip -details link show type can
sudo ip link set can0 up type can bitrate 1000000
```

The leader is always a USB serial device; find its port with `lerobot-find-port`.

<Tip warning={true}>
  On Linux, remove `brltty` (`sudo apt remove brltty`) so it does not hold the
  leader's USB serial port. You may also need to grant access to the serial
  devices: `sudo chmod 666 /dev/ttyACM* /dev/ttyUSB*`.
</Tip>

## Calibration

Calibration sets each motor's zero position and saves a LeRobot calibration file. When prompted to run calibration, **manually move the arm to its zero position** (the default sit-down pose shown above, gripper fully closed) and press <kbd>ENTER</kbd>. Later connections reuse the saved calibration file and do not automatically re-zero the motors.

### Follower

<hfoptions id="calibrate-follower">
<hfoption id="Single arm (DM)">

```bash
lerobot-calibrate \
    --robot.type=rebot_b601_follower \
    --robot.motor_family=dm \
    --robot.port=/dev/ttyACM0 \
    --robot.id=follower
```

</hfoption>
<hfoption id="Single arm (RS)">

```bash
lerobot-calibrate \
    --robot.type=rebot_b601_follower \
    --robot.motor_family=rs \
    --robot.port=can0 \
    --robot.id=follower
```

</hfoption>
<hfoption id="Dual arm">

Connect the bimanual follower; calibration runs for the left arm, then the right arm.

```bash
lerobot-calibrate \
    --robot.type=bi_rebot_b601_follower \
    --robot.id=bi_follower \
    --robot.left_arm_config.motor_family=dm \
    --robot.left_arm_config.port=/dev/ttyACM0 \
    --robot.right_arm_config.motor_family=dm \
    --robot.right_arm_config.port=/dev/ttyACM1
```

Per-arm calibration files are saved with `_left` / `_right` suffixes on the id.

</hfoption>
</hfoptions>

## Teleoperation

Once both arms are calibrated, drive the follower with the leader.

<hfoptions id="teleoperate">
<hfoption id="Single arm (DM)">

```bash
lerobot-teleoperate \
    --robot.type=rebot_b601_follower \
    --robot.motor_family=dm \
    --robot.port=/dev/ttyACM0 \
    --robot.id=follower \
    --teleop.type=rebot_102_leader \
    --teleop.port=/dev/ttyUSB0 \
    --teleop.id=leader
```

</hfoption>
<hfoption id="Single arm (RS)">

```bash
lerobot-teleoperate \
    --robot.type=rebot_b601_follower \
    --robot.motor_family=rs \
    --robot.port=can0 \
    --robot.id=follower \
    --teleop.type=rebot_102_leader \
    --teleop.port=/dev/ttyUSB0 \
    --teleop.id=leader
```

</hfoption>
<hfoption id="Dual arm">

The bimanual leader and follower reuse the single-arm classes; each arm is
configured through nested `left_arm_config.*` / `right_arm_config.*` arguments,
so a bimanual reBot Arm 102 leader drives a bimanual B601 follower.

```bash
lerobot-teleoperate \
    --robot.type=bi_rebot_b601_follower \
    --robot.id=bi_follower \
    --robot.left_arm_config.motor_family=dm \
    --robot.left_arm_config.port=/dev/ttyACM0 \
    --robot.right_arm_config.motor_family=dm \
    --robot.right_arm_config.port=/dev/ttyACM1 \
    --teleop.type=bi_rebot_102_leader \
    --teleop.id=bi_leader \
    --teleop.left_arm_config.port=/dev/ttyUSB0 \
    --teleop.right_arm_config.port=/dev/ttyUSB1
```

</hfoption>
</hfoptions>

## Family-specific controls

Both builds expose the same joint names and degree-based public coordinate frame. LeRobot applies each build's installed motor directions in both actions and observations, so policies and teleoperators do not need to convert motor signs.

- DM uses MIT control for the arm and `force_pos` for the gripper by default. `gripper_torque_ratio` defaults to `0.07`; DM also supports `--robot.control_mode=pos_vel`.
- RS uses MIT control and a force-limited impedance gripper. Its torque command is capped at `3.5` N·m while moving and `1.0` N·m while holding by default.
- Joint tuning such as `mit_kp`, `mit_kd` and `pos_vel_velocity` accepts either one scalar for every joint or a mapping keyed by joint name.
- `max_relative_target` optionally caps each command's change in degrees. For example, `--robot.max_relative_target=5.0` applies a five-degree cap to every joint.

MotorBridge provides native `force_pos` control for Damiao motors, but not for
RobStride motors. The RS gripper therefore uses MIT mode to compute a bounded
torque from its position and velocity error. If gripper feedback fails, LeRobot
attempts to command zero gripper torque, then disables the arm.

The leader's `joint_directions` remain configurable if a teleoperation joint moves in the wrong direction.

<Tip warning={true}>
  DM and RS use the same coordinate convention, but their geometry, gains and
  dynamics differ. Validate policies and datasets before transferring them
  between builds.
</Tip>

## Recording datasets

Swap `lerobot-teleoperate` for `lerobot-record` (with the same `--robot.*` / `--teleop.*` arguments, plus `--dataset.*`) to record demonstrations for training. See [Imitation Learning for Robots](./il_robots) for the full workflow.

For hardware assembly and wiring, see the Seeed Studio wiki for your build: [B601-DM](https://wiki.seeedstudio.com/rebot_arm_b601_dm_lerobot/) or [B601-RS](https://wiki.seeedstudio.com/rebot_arm_b601_rs_lerobot/).
